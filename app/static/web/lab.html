检索实验室

使用前必读

怎么验证它真的做完了

同一个问题，五条链各跑一次 —— 它们的分数口径不同（余弦得分 / RRF 融合分 / Cross-Encoder logits），⛔ 不能横向比大小，只能各自看排序。

5 条接口都只检索你自己名下的文档 ⇒ 先到「知识库」传一篇，这里才有命中。

纯向量检索 pg_search

pgvector 余弦打分（similarity），不做关键词、不改写、不重排 —— 这是对照组。

混合检索 hybrid_search

向量 + BM25 关键词，RRF 融合（k=60）。分数是 rrf_score，很小，⛔ 别拿阈值卡它。

Cross-Encoder 精排 rerank_search

⚠️ 它要跑 Cross-Encoder（torch），而演示镜像里没装 torch 系（DEC-034） ⇒ 在演示机上大概率跑不了。真跑不了时下面会说清是环境限制，⛔ 不是功能坏了。

查询改写 + 混合检索 rewrite_search

先用 LLM 改写再检索 ⇒ 这条真花钱；它按 thread_id 计入会话额度。

综合检索（四模式） /rag/search

一条链把改写 / 扩展 / BM25 / 精排四段按 mode 拼起来，并回各段耗时。 ⚠️ accurate 与 full 含精排 ⇒ 同样受上面那条环境限制。

fast = 向量 + BM25 + RRF · accurate = 加改写与精排 · accurate_norerank = 加改写、不重排 · full = 再加查询扩展。
