## 〇 · 🔴 第一版错在哪（**业务方当场指出，本版是更正**）

> **业务方原话（2026-10-09）**：
> 「**这份首页是从哪里定的，CLAUDE.md 文件读了吗，关于前端页面我的要求，比如【全部接口都要】，
> 和之前定好的记录，你是参考哪里的内容**」

| | |
|---|---|
| **第一版怎么编的** | 只照着**现有页面在用的接口**（**7 条**）——chat / approvals / trace / eval 那几条 |
| 🔴 **错在哪** | 那是「**现在有什么**」的视角；而**最高判据要的是「该让访客看见什么」** |
| **漏掉的规模** | 全仓 **66 条真实路由**（OpenAPI 里 **60 个操作**），第一版只覆盖 **7 条** ⇒ **漏了 ~89%** |

**漏掉的正是 `CLAUDE.md` 顶部那条最高判据**（⛔ 我读到了却没拿它当输入）：

> 「**demo 只有一页有什么用呢，95% 的人不会去看代码**……只会看你**做了哪些功能、哪些接口**」
> 「**如果做成一页、什么都放后端，demo 就是空虚的**：你知道有这些接口和功能，**别人无法点击使用**，
> **95% 的人会直接当你没做**。」

| ❌ 不算「有」 | ✅ 才算「有」 |
|---|---|
| 后端有这条路由 | 页面上**有入口、能点** |
| 代码里实现了 | 页面上**看得见结果** |
| 文档里写了 | 访客**不读文档就能用** |
| **`/docs` 里列着** | **一屏之内**能自己摸到 |

⇒ 🔴 **本版把「全部接口都要有可点入口」写成硬约束第 0 条**，并把 **60 条接口逐条归位**（§二）。

## 一 · 硬约束（⛔ 一条都不许破）

| # | 约束 | 出处 |
|---|---|---|
| **0** | 🔴🔴 **每个能力都要有【可点入口】** —— 后端有路由 **⛔ 不算**，`/docs` 里列着 **⛔ 也不算** | **`CLAUDE.md` 最高判据**（业务方第 3 次强调） |
| 1 | **无构建 · 无 `package.json` · 无 npm** | 本仓全仓无构建，CI 是纯 Python + `node --test` |
| 2 | **⛔ 无外网 CDN 外链**（字体 / CSS / JS 一律本地） | demo 要在**离线容器**里起 |
| 3 | **⛔ 不改文案口径**（熔断「这不是故障」· 拒答「资料里没有」…） | `DEC-090` / `DEC-091`，**改样式 ≠ 可以改字** |
| 4 | **⛔ 不改接口路径 / 请求方式 / class 名 / id** | 页面脚本按 id 建元素；`test_web_pages.py` 扫 URL 前缀 |
| 5 | **动效必带 `prefers-reduced-motion`** | `ui-ux-pro-max` 7 号规则把它列为**反模式** |
| 6 | **⛔ 不许印"没有数据源"的数** | `trace.html` 那两格"总 Token / 总花费"的前科（守卫在 `api/test_trace_page.py`） |

### 3.0 🆕 **总览首页**（`GET /` → `web/index.html`）—— 🔴 **本版新增，它才是"首页"**

| | |

| **为什么要有** | 最高判据要的是「**一屏之内**能自己摸到」⇒ **必须有一页把全部能力摊开** |

| **主次怎么分（⬜ 我拟的，待业务方改）** | **主要功能** = 演示的核心闭环：**RAG 对话（流式 + 引用）· 检索三模式 · 人工接管 · 成本可见 · 执行轨迹**<br>**其他功能** = 能力证明但非演示主线：**知识库管理 · 工具/MCP · 记忆 · 执行器 · 预算/熔断 · 系统状态 · 评测 · 运维探针**<br>⚠️ **划分要业务方拍** —— 我按"演示价值"拟的，⛔ 不代表他的判断 |

## 四 · 状态矩阵（**每页都要有，⛔ 不许只做默认态**）

| 状态 | 底线 |
|---|---|
| **首次** | 说清**这是什么**；未登录 ⇒ 登录面（⚠️ 但**总览首页不要求登录**）；已登录无数据 ⇒ **空态带"为什么空"** |
