## 🔴 先说清楚：`F2` 原话里的「span 树 + 每步 token/耗时/成本」**没有单一数据源**

`docs/待办总表.md` §三·附2 对 `F2` 的措辞暗示"一个请求的每一步都带 token/耗时/成本"。
**实测：这两样东西在两条轴上，而且拼不成一棵树。**

| | **追踪轴** | **成本轴** |
|---|---|---|
| 存储 | `api/tool_visualizer.py` 的 `_traces` —— **进程内存** | PG `token_usage_logs` 表 |
| 粒度 | **工具调用**（`tool_name` / `duration_ms` / `result[:500]`） | **模型调用**（`model` / `purpose` / `prompt_tokens` / `cost`） |
| 谁在写 | **只有 `mcp_agent_chat` / `mcp_agent_chat_stream` 两条链**（`start_trace` 全仓 2 个调用点） | **所有花钱的地方**（`embedding` / `answer_generation` / `agent_decision` / …） |
| 能不能对上 | ⛔ **对不上** —— 没有共同的 step id | ⛔ 同上 |

⇒ **业务方 2026-10-06 已裁定：改成【两轴分屏】。**
上半天画追踪轴（一步步的**耗时**），下半天画成本轴（一笔笔的 **token / 花费**），
**⛔ 不硬凑成一棵树**（凑出来的层级是编的）。

## ⚠️ 本单对 `DEC-093` 的四处**具体化**（不是改裁定，是把它落到实处）

| # | `DEC-093` 的措辞 | 本单落地成 | 为什么 |
|---|---|---|---|
| **A** | 「取数函数放进**既有模块** `token_tracker.py`」 | 新函数叫 `thread_cost_breakdown(user_name, thread_id)`，**⛔ 不碰** 旁边那个 `get_thread_cost(thread_id)` | `get_thread_cost` 实测**只有 1 个调用点**（`token_tracker.py:888`，线程预算检查，用的是调用者**自己的** thread_id）⇒ **它不是洞**，只是**签名看起来像洞**。⛔ 不改它 = 不给预算逻辑引入回归；两版**并排放着**，下一个读到的人自然会看见差别 |
| **B** | 「时间要显式处理」 | 后端回 **ISO-8601 带显式 `+00:00`**，前端 `new Date(iso)` 按**浏览器本地时区**渲染 | PG 容器实测 `SHOW timezone` = **`Etc/UTC`**，而 `created_at` 是 **`TIMESTAMP`（无时区）** ⇒ 存的是**裸的 UTC**。若原样回 `2026-10-06T13:14:21`，JS 会当**本地时间**解析 ⇒ **静默差 8 小时**（同族前科：`logs/api_*.log 混了两套时区`）。⚠️ 注意 `approval_audit` 用的是 `TIMESTAMPTZ`、**天生带区**，⛔ 别照抄它的 `.isoformat()` |
| **C** | 「thread_id 要防空串」 | **本端点不需要** —— 它是 **path 参数**，空串在 URL 里变成 `/agent/trace//cost`，**根本匹配不到这条路由**（自带 404）。`F6` 那两条是 **query** 参数，才是真会传空串的地方 | ⛔ 不无脑抄 `Query("default", min_length=1)` —— 那会给一个**已经不会发生的**错误加一道守卫，读代码的人会以为这里真会空 |
| **D** | 「删掉两个假卡」 | 删的是**概览里的**「总 Token」/「总花费」两格（数据在成本轴、概览拿不到）；**耗时**与**工具次数**两格**留着**（追踪轴真有） | 概览那一栏的来源只有追踪轴。留着两格永远为假的数 = 把「假完成」印在页面上给人看（硬门 C 的原话就是「**最容易假完成**」） |
