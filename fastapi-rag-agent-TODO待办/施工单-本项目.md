## 阶段 ⑦｜开通路（路线 C：Cloudflare 隧道）

```yaml
# 在云主机的 docker-compose.yml 里加这个服务
  cloudflared:
    image: cloudflare/cloudflared:latest
    container_name: rag-tunnel
    restart: unless-stopped
    network_mode: "service:api"        # 与 api 共用网络栈
    command: tunnel --no-autoupdate run --token ${TUNNEL_TOKEN}
```

**步骤**：
1. Cloudflare Zero Trust → `Networks → Tunnels → Create a tunnel` → 选 `Cloudflared` → 命名 → 复制 token
2. token 放进云主机的 `.env`（`TUNNEL_TOKEN=...`）
3. `docker compose up -d cloudflared`
4. 在 Tunnel 的 **Public Hostname** 里配：子域名 + 你的域名 + Type `HTTP` + URL **`http://localhost:8000`**
5. 状态变 `HEALTHY` 即可访问

### ⚠️ 三条硬要求

| # | 要求 | 原因 |
|---|---|---|
| 1 | 🔴 **必须用「命名隧道」，不能用「快速隧道」** | **快速隧道会缓冲 SSE，直接废掉硬门 A（流式输出）**；且地址每次重启就变 |
| 2 | ⚠️ **token 是敏感凭据** | 拿到它的人都能开隧道 —— 与密钥同级，**绝不入库** |
| 3 | ✅ **安全组可全关** | 隧道是出站连接 ⇒ **云主机不用开任何入站端口** |

> 📌 **这一步才第一次"能打开"。**

|---|---|---|
| **R1.1** | 单次请求有 **token 硬上限** | 诱导超长输出的请求 → 输出在设定上限处**截断**，不会无限生成 |
| **R1.2** | 单会话有**累计 token 上限** | 同会话连续对话超过累计阈值 → 被拒或降级，**且有明确提示** |
| **R1.3** | 单用户 / 单 IP 有**频率限制** | **以未登录身份**快速连发 → 在阈值处被拒 |
| **R1.4** | 全局**每日总额**有硬上限 | 累计到日上限 → **触发熔断**（见 R2） |

> 🔴 **R1.3 的关键：必须对匿名 / 未登录请求也生效。**
> 公网暴露时对方可能根本没登录 —— **只对登录用户限额 = 没限。**

#### 要求 R2｜熔断

| # | 要求 | 验收标准 |
|---|---|---|
| **R2.1** | 到达日上限时**熔断**，而不只是限速 | 总额触顶后，新请求被**拒绝**（不是变慢） |
| **R2.2** | 熔断有明确的**恢复条件** | 能说清何时恢复（跨天 / 手动 / 阈值回落），且**实际会恢复** |

#### 要求 R3｜熔断必须「说出来」🔴

| # | 要求 | 验收标准 |
|---|---|---|
| **R3.1** | 熔断时返回**结构化错误** | 响应里带**可识别的错误码 + 恢复时间**，不是裸 500 |
| **R3.2** | 前端渲染**明确卡片** | 证据：卡片上写清四件事 —— **现状 / 这不是故障 / 何时恢复 / 怎么联系** |
| **R3.3** | ⛔ **不许**退化成 500、白屏、或通用错误页 | 同上，用**同一份证据**对照 |

> 📌 **R3 的意义**：一个会熔断但**不说**的系统，和会熔断并**说清楚**的系统，
> 对方对后者的信任度**更高**，而不是更低。这跟该仓 README 里 🔻 标注边界的调性是一致的。

#### 要求 R4｜成本与 token 可见

| # | 要求 | 验收标准 |
|---|---|---|
| **R4.1** | 每次调用可见 **token 数与估算花费** | 界面或 trace 上能直接看到数字 |
| **R4.2** | 有**全局用量视图** | 能回答"今天花了多少、还剩多少" |

#### 证据要求

项目侧完成后，需提供：

1. **逐条验收标准的实测证据**（截图 / 录屏 / 命令输出）
2. 未完成项的**如实标注** —— **不许假装全绿**

#### 附带一条约束

⚠️ **评估跑分与熔断会互相影响**（见 §8.2）。
**要求：评估用的调用不占用、也不触发面向外部的每日额度。**

| # | 判断点 | 为什么容易踩空 |

| 2 单会话 | 会话级累计 token 上限 |
| 3 单用户 / 单 IP | 限流件需**覆盖匿名请求** |
| 4 全局日级 | **新增**每日总 token / 花费上限 + 熔断 |

##### D. 熔断提示的参考形态

**后端**返回结构化错误，例如：


**前端**照它渲染一张**明确卡片**，写清四件事：**现状 / 这不是故障 / 何时恢复 / 怎么联系**。
⛔ **不许**让它退化成 500、白屏、或通用错误页。

> **把"我不能"说清楚，比假装能用可信得多。**

## 本项目已知的坑（部署时会复现）

| # | 症状 | 根因 | 处置 |
|---|---|---|---|
| 1 | judge 全挂 `CERTIFICATE_VERIFY_FAILED` | 本机有 TLS 拦截，其 CA 只在系统信任库 | 设 `SSL_CERT_FILE=/etc/ssl/cert.pem` |
| 2 | 前几条成功后 `Connection reset by peer` | `localhost` 解析到 **IPv6**（`::1`），被别的进程占着 | base_url 用 **`127.0.0.1`** 而非 `localhost` |
| 3 | 模型名报不存在 / 行为变化 | 模型名被官方停用 | 换现行名；⚠️ **网关可能不校验模型名，返回 200 不代表名字有效** |
| 4 | 升级后 API 启动即崩、报缺 `python-multipart` | 跑的是旧镜像，代码已修但镜像没重建 | `docker compose build api` |
