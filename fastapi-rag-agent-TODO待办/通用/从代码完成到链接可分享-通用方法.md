# 从「代码完成」到「链接可分享」（通用方法）

> **这份文档是「通用」的** —— 讲的是**方法与取舍**，不绑定任何具体项目。
> 项目侧的具体命令、坑位、实测数据，见 `fastapi-rag-agent-TODO待办/施工单-本项目.md`。
>
> **它回答的问题**：我本机跑起来的东西，怎么变成一个「别人点开就能用」的链接？
> 为什么中间要买机器、要不要域名、HTTPS 从哪来、为什么买了机器还是打不开。

---

## 1. 全书核心：四个环节，断一个就打不开

```
【域名】demo.abc.com        ← 给人看的、好记的名字
      ↓ DNS 解析（把名字翻译成 IP）
【公网 IP】47.98.12.34      ← 机器在互联网上的真实门牌号
      ↓
【安全组】允许 8000 吗？     ← 门口保安。默认只开 22（SSH）
      ↓
【服务】api:8000            ← 你的程序
```

> **四个环节，断任何一个都打不开。**
> 这就是那个常见困惑的答案：**"我机器也买了，怎么还是打不开？"** —— 因为后面几环还没接上。

---

## 2. 为什么 `127.0.0.1` 别人打不开

> `127.0.0.1` 的意思是 **「我自己」**。**任何一台电脑上**，`127.0.0.1` 都指它自己。
>
> - 你打开 `127.0.0.1:8000` → **你电脑**上的 8000 → 有东西 ✅
> - 别人打开 `127.0.0.1:8000` → **他自己电脑**上的 8000 → **空的** ❌
>
> ⇒ 必须换成一个**"全世界都指向你那台机器"**的地址 —— 这就是**公网 IP** 和**域名**的作用。

## 3. 三个最容易混的概念

### 3.1 域名 ≠ HTTPS

| | 是什么 | 类比 |
|---|---|---|
| **域名** | 一个**名字**（`demo.abc.com`） | **门牌号** |
| **HTTPS** | **加密**（内容别人偷看不到） | **门上的防盗锁** |

- 可以**有域名但没 HTTPS**（走 HTTP 明文）
- 也可以**没域名但有 HTTPS**（用 IP 申请证书，但基本没有机构给你签）
- **真正的关系**：
  ```
  想要 HTTPS  ⇒  需要「证书」
                    ↓
               签证书的机构（CA）要求：你有域名
                    ↓
        ⇒ 域名是 HTTPS 的【前提】，不是 HTTPS 本身
  ```

### 3.2 HTTPS 不是"在域名控制台点一下就有"

- **域名控制台只管 DNS 解析**，不管加密。
- 自建 HTTPS 的完整动作是：**申请证书 → 下载 → 装到服务器上**（改 Web 服务器配置）—— **是要动服务器配置的**。
- ⚠️ **免费证书普遍只有 3 个月**（主流云厂商自 2023-11 起从 12 个月缩短），**多数不可续费** ⇒ 到期要**重新申请 + 重新部署**。想 1 年通常要付费。
- ⚠️ **免费证书通常不支持通配符 `*.abc.com`** ⇒ "一个域名挂多个子域名"要**付费证书或多张证书**。
- ✅ **例外**：用带自动 HTTPS 的边缘平台（如 Cloudflare），证书由平台自动签发和续期，**你不用管**。

### 3.3 域名可以对应多个后端 ✅

```
子域名法（最简单）                     路径法
rag.abc.com   → 服务 A                abc.com/api1 → 服务 A
agent.abc.com → 服务 B                abc.com/api2 → 服务 B
（各一条 DNS 记录）                    （需要一层反向代理）
```

> 📌 **这是展示时的隐藏加分项**：第二、三个作品做出来，**一个域名 + 不同子域名**就能挂上去 —— **一个域名展示多个作品**。

## 4. 路线选择：这一步决定后面所有事

### 4.1 先认识那条"墙"：ICP 备案

> 🔴 **中国大陆节点 + 域名 + 80/443 提供 Web 服务 = 必须 ICP 备案。**
> 未备案时，云厂商监测系统会**阻断域名访问**，80/443 被强制拦截；**备案审核期间不允许提前上线**。
> 备案是**数周**流程，且需要主体资质。
> **非中国内地地域（香港/海外）不需要备案。**

⚠️ 常见误解：**以为"在云厂商那里买了域名就能自己搞定 HTTPS、绕开备案"** —— 不行。
备案备的是「域名 + 服务器」，跟 HTTPS 怎么来无关。**换个地方买域名，绕不过备案这个墙。**

### 4.2 四条路线

| 路线 | 备案 | HTTPS | 成本 | 评价 |
|---|---|---|---|---|
| **A. 大陆节点 + 域名 + 自装证书** | 🔴 **必须，数周** | 自己装，**3 个月过期** | 域名 + 服务器 | 🔴 **会把时间窗口吃掉** |
| **B. 香港/海外节点 + 域名 + 自装证书** | ✅ 不用 | 自己装，3 个月过期 | 域名 + **更贵**的服务器 | 🟡 可行，要维护证书 |
| **C. 域名 + Cloudflare 隧道** | ✅ 不用 | ✅ **自动，永不过期** | 域名 + 服务器 | ✅ **一次解决两个问题** |
| **D. 不用域名，直接用 IP** | ✅ 不用 | ❌ **没有** | 只要服务器 | ✅ **最省** |

> ✅ 依据：**备案备的是域名，与 IP 没有直接关系** —— 直接用 `IP:端口` 访问**不需要备案**。

### 4.3 判断依据

| 你的偏好 | 选 |
|---|---|
| 要省事 + 要 HTTPS | **路线 C** —— 自动证书、免费口令、不用开入站端口 |
| 要最省 + 能接受没 HTTPS | **路线 D** —— 不需要域名、不需要备案、不需要证书 |
| 一定要自建 HTTPS + 不要边缘平台 | **必经路线 B（香港/海外节点）** —— 走 A 会撞备案 |

## 5. 完整 8 阶段（通用骨架）

```
① 代码完成
      ↓
② 本机验证跑通          ← 不花钱。问题在本地暴露最便宜
      ↓
③ 做前端                ← 演示的载体是浏览器界面，前端是从零做，不是部署能带出来的
      ↓
④ 实测资源 → 定机器      ← 实测峰值 × 1.5 = 要买多少
      ↓
⑤ 买域名（若要 HTTPS）    ← 🔴 先回看 §4 定路线
      ↓
⑥ 代码搬上云
      ↓
⑦ 开通路（二选一）        ← 🔴 **这一步才第一次"能打开"**
      ↓
⑧ 加保护 → 自验 → 发链接
```

### 5.1 阶段 ⑥ 的四个动作

```
① 云主机上装 docker
② 把代码传上去        git clone，或 scp -r 整个文件夹
③ 把配置/密钥传上去    ⚠️ 别用公开渠道传，别提交进 git
④ 构建并启动           ⚠️ 这一步不能只跑不构建
```

> ⚠️ **做完这一步，外部仍然打不开** —— 服务在跑了，但"路"还没通。

### 5.2 阶段 ⑦ 开通路，二选一

**走法 A：直接开端口**
```
别人 → http://47.98.12.34:8000 → 云主机 8000 → 服务
```
- 做：**安全组放行端口**
- ❌ 没有 HTTPS（明文）· ✅ 不需要域名、不需要备案

**走法 B：Cloudflare 隧道**（= 路线 C）
```
别人 → https://demo.abc.com
            ↓
      Cloudflare 边缘（HTTPS 在这里终止，证书自动）
            ↑ 隧道（客户端主动连出去，不是等外面进来）
      云主机上的隧道客户端 → 服务:8000
```
- 做：边缘平台建隧道拿 token → 加一个隧道容器 → 配 Public Hostname
- ✅ **云主机完全不用开任何入站端口**（安全组可全关，公网 IP 不暴露）
- ✅ **HTTPS 自动**，证书不用管（**不会 3 个月过期**）
- ✅ **访问控制免费** —— 正好解决"不想对全世界开放"
- ⚠️ **必须用「命名隧道」，不能用「快速隧道」** ——
  **快速隧道会缓冲 SSE，直接废掉硬门 A（流式输出）**，且地址每次重启就变

```yaml
# 在云主机的 docker-compose.yml 里加这个服务
  tunnel:
    image: cloudflare/cloudflared:latest
    container_name: app-tunnel
    restart: unless-stopped
    network_mode: "service:api"        # 与服务共用网络栈
    command: tunnel --no-autoupdate run --token ${TUNNEL_TOKEN}
```
> `network_mode: "service:api"` 的好处：边缘平台里 URL 直接填 `http://localhost:8000`，不用琢磨容器名。
> ⚠️ **token 是敏感凭据**（拿到它的人都能开隧道）—— 与密钥同级对待，**绝不入库**。

### 5.3 隧道跑在哪台机器上，决定成败

| 跑在哪 | 结果 |
|---|---|
| 🔴 **你自己的电脑** | 你关机/睡眠/断网 → **链接死**。只适合**当面演示那一天** |
| ✅ **云主机** | 云主机 7×24 → **链接一直活着**。**完全可用，且是好方案** |

> ⚠️ **别把"隧道"这个技术一起否掉** —— 否掉的只是"跑在自己电脑上"。

## 7. 阶段 ⑧：发链接前的保护清单（**别跳过**）

| # | 事 | 为什么 |
|---|---|---|
| 1 | 🔴 **密钥绝不入库** —— 确认 `.env` 在 `.gitignore` | 公开仓库上的活凭据是最常见的事故 |
| 2 | 🔴 **每日成本硬上限 + 熔断** | 公开 URL = **陌生人、爬虫、扫描器都会烧你的额度** |
| 3 | 🔴 **访问口令** | **不用对全世界开放**：不烧钱的页（trace / 评测跑分）公开；**烧钱的对话页加口令** |
| 4 | 🟡 **跑一次干净压测** | 上线后别人第一件事就是压它。**一份自己标注"不可采信"的旧记录，比没有更糟** |
| 5 | 🟡 **如实标注未启用的能力** | 例如"线上为 fast 模式；重排序未启用" —— **别到线上就假装全绿** |
| 6 | ⭐ **录一份快照兜底** | 让评测能**改走快照回放** ⇒ **被测挂了也能演示** |
| 7 | ✅ **L2 自验** | **换一台设备 / 无痕窗口**，你自己点一遍 —— **不需要你在场解说**才算过 |

### 7.1 🔴 限额 · 熔断 · 提示（**最关键的一节**）

> ⚠️ **先把话说死**：这是**关键功能**，不是"以后再说"。
> 一个公开 URL 没有限额 = **陌生人、爬虫、扫描器都会烧你的额度** —— 账单失控，链接被迫下线。
>
> 🔷 **本节写的是「要求」，不是「实现」。** 怎么写代码由实施方决定；
> 本节负责把**做到什么算过**说清楚。

#### 四层限额（**缺一层就漏一层**）

| 层 | 限什么 | 典型做法 | 缺了会怎样 |
|---|---|---|---|
| **1 单次请求** | 单次生成的最大 token 数 | 请求参数里设 `max_tokens` 硬上限 | 一次生成无限长 → 一次请求烧掉一天额度 |
| **2 单会话** | 一个会话累计 token / 轮次 | 会话级计数，超了拒绝或降级 | 一个人聊一下午把额度聊完 |
| **3 单用户 / 单 IP** | 时间窗内请求数 | rate limit（如每分钟 N 次） | 爬虫 / 脚本瞬间打满 |
| **4 全局日级** | 每日总 token / 总花费 | **硬上限 + 熔断** | **账单失控** |

> ⚠️ **第 1 层和第 3、4 层的区别最容易搞混**：
> 单次上限只管"**一次别太长**"，**不阻止"反复来很多次"** —— 后者要靠 3、4 层。
> **只做第 1 层是最常见的错觉：以为设了 `max_tokens` 就安全了。**

#### 熔断的四个要素（**缺任何一个都不算做完**）

| # | 要素 | 说明 |
|---|---|---|
| 1 | **阈值** | 按什么算（token 数 or 金额）· 多少触发 · 谁能调 |
| 2 | **触发动作** | 拒绝新请求 ／ 降级到便宜模型 ／ 转人工 |
| 3 | **🔴 可见提示** | **熔断时必须让对方看到明确提示** —— 见下 |
| 4 | **恢复** | 怎么复位：自然跨天 ／ 手动 ／ 阈值回落 |

#### 🔴 要素 3 单独展开：**熔断必须"说出来"**

**静默失败是最伤的失败。**

| ❌ 熔断时静默 / 白屏 / 500 | ✅ 熔断时明确提示 |
|---|---|
| 对方以为 **你的系统坏了** | 对方知道 **是预设的保护起作用了** |
| 他会反复重试，或直接判定"这东西不能用" | 他知道什么时候能再用 |
| 你事后解释"其实是额度用完了" —— **已经晚了** | 不用解释 |

**提示里必须写清四件事**：

1. **现状** —— 例如"今日演示额度已用尽"
2. **这不是故障** —— "这是预设的保护机制，不是系统出错"
3. **什么时候恢复** —— "将于 X 小时后自动恢复" / "请稍后再试"
4. **替代路径** —— 联系方式 / 另约时间 / 备用入口

> 📌 **为什么这条是硬要求，不是锦上添花**：
> 这跟"如实标注边界"是**同一件事** —— **把"我不能"说清楚，比假装能用可信得多。**
> 一个会熔断但**不说**的系统，和一个会熔断并**说清楚**的系统，
> 对方对后者的信任度**更高**，而不是更低。

**具体做法（任选）**：
- 后端返回**结构化错误**：`{"code": "QUOTA_EXCEEDED", "message": ..., "retry_after": ...}`
- 前端**照它渲染一张明确的卡片**，而不是通用错误页
- 走边缘平台的话，可用其规则直接返回自定义页面

#### ✅ 验收标准（做到什么算过）

| # | 要求 | 怎么验 |
|---|---|---|
| **R1.1** | 单次请求有 token 硬上限 | 诱导超长输出 → 在设定上限处**截断**，不会无限生成 |
| **R1.2** | 单会话有累计 token 上限 | 同会话连续对话超阈值 → 被拒或降级，**有明确提示** |
| **R1.3** | 单用户 / 单 IP 有频率限制 | 🔴 **以未登录身份**快速连发 → 在阈值处被拒 |
| **R1.4** | 全局**每日总额**有硬上限 | 累计到日上限 → **触发熔断** |
| **R2** | 到达日上限时**熔断**（不是仅限速），有明确恢复条件 | 总额触顶后新请求被**拒绝**；能说清何时恢复，且**实际会恢复** |
| **R3.1** | 熔断返回**结构化错误** | 响应带**可识别错误码 + 恢复时间**，不是裸 500 |
| **R3.2** | 前端渲染**明确卡片** | 证据：卡片写清四件事（现状 / 不是故障 / 何时恢复 / 怎么联系） |
| **R3.3** | ⛔ 不许退化成 500 / 白屏 / 通用错误页 | 用同一份证据对照 |
| **R4** | 成本与 token **可见** | 界面或 trace 上直接看到数字；能回答"今天花了多少、还剩多少" |

> 🔴 **R1.3 最容易漏**：公网暴露时对方可能根本没登录 —— **只对登录用户限额 = 没限。**
> 🔴 **R3 最容易漏**：这一条**不会在演示时暴露**，但会在你不知情时把印象做坏。

### 7.2 「关键功能」这四个字怎么定义

> **判据一句话**：**「如果这条缺了，别人点开会发生什么坏事？」**
> **答不出坏事的 → 它就不是关键功能**，是锦上添花。

按这个判据，本场景的**关键功能最小集**：

| # | 关键功能 | 缺了会发生什么坏事 |
|---|---|---|
| 1 | **四层限额 + 熔断 + 可见提示** | 账单失控 ／ 对方以为系统坏了 |
| 2 | **成本与 token 可见** | 你自己都不知道钱花在哪，无法优化、也无法解释 |
| 3 | **访问口令 / 鉴权** | 任何人都能烧额度、看数据 |
| 4 | **失败可解释** | 出问题定位不到是哪一步，"全都红了" |
| 5 | **日志 / trace** | 事故无法复盘；对方报的问题你复现不了 |

> ⚠️ **"关键功能必须开发"的含义**：上面这些**不是可选项**。
> 一个没有限额、没有提示、没有日志的公开 demo，**技术再强也不该发出去** ——
> 因为它会在你不知情的时候，**替你把钱烧掉、把印象做坏**。

## 8. ⛔ 常见排除项

### 8.1 判据：**什么该上云，什么不该上云**

> **凡是「你自己用来把关 / 分析」的工具，不上云；**
> **凡是「别人要自己点开验」的东西，才上云。**
> **工具类只把「产出」渲染成静态页展示。**

| 类别 | 上云？ | 例子 |
|---|---|---|
| 别人要打开用的**产品本身** | ✅ **上** | 被测系统、前端页面 |
| 你自己用来**把关 / 分析**的工具 | ❌ **不上** | 评测门、静态检查、各种脚本 |
| 工具的**产出**（报告 / 分数 / 图表） | ✅ **展示**（渲染成静态页） | 评测报告 → Eval 页 |
| 需要**长期持有密钥**的服务 | ⚠️ **谨慎** | 上云 = **多一个泄漏点**，而密钥通常能直接烧钱 |

**一条配套推论**：

> **凡是无服务端、零依赖的 CLI 工具，都不该为它单独养机器。**
> `git clone` + 装依赖就能跑的东西，部署的收益是负的。

> 📌 **实例**：`agent-eval-gate` 就是一个 CLI 工具（零运行时依赖、无服务端）——
> 决策为**不上云**，只把它的报告渲染成静态 Eval 页。
> 详见 `fastapi-rag-agent-TODO待办/agent-eval-gate-TODO待办/部署决策.md`。

### 8.2 排除清单

| 排除了什么 | 理由 |
|---|---|
| **GPU 租用平台**（炼丹用） | 定位是跑训练任务；关机就换机器/换地址；**当不了 7×24 的 Web 主机** |
| **云开发机 / 云端 IDE** | 公网访问方式是"连本地 IDE"，面向的不是浏览器；**关机常会释放固定公网 IP** ⇒ 一关机地址就变 |
| **函数计算 / Serverless** | 与 **SSE 长连接 + WebSocket + 向量库 + 缓存**这类有状态组件不兼容 |
| **虚拟主机** | 给建站用的，**装不了 docker** |
| **把隧道跑在自己电脑上** | 关机/睡眠/断网 → 链接死，而对方可能半夜点开 ⇒ **比不给链接更差** |
| **给纯 CLI 工具硬造网页** | 它的说服力在**退出码**上，包装成网页是自降身价 |

**选机器的判据 5 条**（满足才是你要的）：
1. 一台**完整的 Linux 机器** 2. 有 **root/sudo** 3. **能装 docker** 4. 有**公网 IP** 5. **7×24 开着**
