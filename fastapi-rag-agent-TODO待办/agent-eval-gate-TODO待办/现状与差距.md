## 3. 能力现状（**已具备**）

### 3.1 判分链路五段

```
评测集 → ① schema 校验（零模型调用即失败，省 token）
      → ② 调被测（适配器统一「输入→输出」）
      → ③ 确定性规则（注入/越权/拒答/格式，不用 LLM，~0ms）
      → ④ LLM-as-Judge（结构化出参；非 JSON → flag，不静默给分）
      → ⑤ 聚合 → 阈值 → exit code → 报告 + Trace
```

> 📌 **关键语义**（契约 `评测-evals-schema.md:30`）：`expected.answer_contains` 是「**含其一即符**」——
> 命中任一即算满足，**不是"必须全含"**。

### 3.2 exit code 语义（**它的核心产出**）

| code | 含义 | CI 处置 |
|---|---|---|
| `0` | 全绿 | merge 放行 |
| `1` | **block**（l2 低于阈值 / 红队被突破） | **阻断** |
| `2` | conditional / human（judge 存疑 flag） | 人工复核 |
| `3` | 运行错误 / 熔断 degraded（如被测配额耗尽 `E_SUT_QUOTA` → 整批 aborted） | **不算全绿，告警** |

> ✅ **「不假装全绿」**：exit 3 时阈值判定作废（`blockers` 置空），只告警。

### 3.3 CLI

| 命令 | 作用 |
|---|---|
| `eval-gate run` | 跑一轮评测并出 exit code（`--evals` / `--mode good\|bad` / `--threshold` / `--offline` / `--report-dir`） |
| `eval-gate trace` | 打印 Trace（span 树）视图 |

## 5. 已知的坑（**该仓原文记录，本侧未复现**）

`docs/部署.md` §6 自述「全部真实踩过」：

| # | 症状 | 根因 | 处置 |
|---|---|---|---|
| 1 | judge 全挂 `CERTIFICATE_VERIFY_FAILED: self-signed certificate in certificate chain` | 本机有 TLS 拦截，其 CA 只在系统信任库，不在 venv 默认 CA 集合 | 设 `SSL_CERT_FILE=/etc/ssl/cert.pem`（备选 certifi 的 `cacert.pem`） |
| 2 | 前几条成功后 `Connection reset by peer` | `localhost` 解析到 **IPv6**，而 `::1:8000` 被别的进程占着 | base_url 用 **`127.0.0.1`** 而非 `localhost` |
| 3 | `pip install` 卡在源码编译 `cryptography` | Intel Mac + 新版只发 arm64 wheel + 本机无 Rust | `pip install --prefer-binary` |
| 4 | 安装/构建极慢（单包 ~80 kB/s） | 国内镜像链路差 | 择源 |
| 5 | 本地服务反复被顶掉 | 同端口有**崩溃重启**的容器周期性抢占 | 先 `docker stop <该容器>` |
| 6 | judge 报模型不存在 / 行为变化 | 模型名被官方**停用** | 换现行名；⚠️ **网关可能不校验模型名，返回 200 不代表名字有效** |

**另有故障排查速查**（同文件 §7）：
- `exit 3 / degraded` → 先查被测配额（`E_SUT_QUOTA`）—— **属熔断，不是"门坏了"**
- 大量 case 记 fail 且理由含"被测调用失败" → 看**真实异常类型**，可能是配置问题
- 阈值没生效 → 报告里的 `applied_thresholds` **就是运行值**
