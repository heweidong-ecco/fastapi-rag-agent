# 代码执行器进容器 · 施工单（批②）

> **For agentic workers:** 按 task 顺序做，每个 task 自己带测试周期。步骤用 `- [ ]` 勾。

**Goal:** `execute_python` **不再在任何"与宿主同权限"的地方执行** —— 改为进**独立执行器容器**；
**应用绝不碰 `docker.sock`**。

**Architecture:**
- 新增一个**常驻的极小 HTTP 服务**（下称"执行器"），跑在自己的容器里 —— 它就是**热启动/预先加载**的落点。
- 每次请求，执行器**在自己容器内起一个新的子进程**跑代码，跑完即回收
  ⇒ 既拿到"常驻不冷启动"，又保住**进程级干净**（原先"每次销毁容器"买到的那条）。
- 应用侧**多一条远端路径**：`EXECUTOR_URL` 有值 ⇒ 走 HTTP；没值 ⇒ **回落**到现在的本地子进程
  ⇒ **本机开发 / 离线测试 / CI 不受影响**。

**Tech Stack:** Python 3.10 · FastAPI（执行器侧）· Docker Compose · 现有的 `_SANDBOX_CHILD` 白名单**照用**

**Spec:** 本次新建一份 DEC（`docs/decisions/` 下，主题「代码执行器进容器」；
号在动手时取 —— 跑 `ls -1 docs/decisions/ | sort | tail -1` 加一）。见 Task 7。
⚠️ **这里⛔ 不写死那个 `.md` 路径** —— 它还不存在，而**断链门会红**（本仓踩过）。

### 🔴 为什么不是「应用挂 `docker.sock`、每次 `docker run` 一个新容器」

这个方案**看起来最干净**（每次全新容器 = 最强隔离），但它有一个**致命的反向代价**：

> **`/var/run/docker.sock` = 宿主 root 等价。** 拿到它就能起特权容器、把宿主根文件系统挂进来。

而本应用**自己就跑在容器里**（`api/Dockerfile` + `docker-compose.yml` 的 `api` 服务）
⇒ 要让它 `docker run`，就得把 sock 挂进**它**。

⇒ **等于把"代码执行逃逸"的洞，换成了"容器逃逸"的洞** —— 而后者**更大**：
前者要绕过白名单，后者**只要拿到那个文件**。

**⇒ 选「独立执行器容器」：应用只发 HTTP，⛔ 不认识 Docker。**
