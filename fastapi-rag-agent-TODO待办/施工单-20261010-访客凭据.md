## 第 2 步 · 后端：那条端点本身的规格（**已按此实现**）

```
POST /api/v1/demo/claim     body: {"visitor_id": "<8~64 位 [A-Za-z0-9_-]>"}
⇒ 200 {"api_key": "...", "user_name": "demo-<visitor_id>", "expires_in_days": N}
⇒ 422 visitor_id 形状不对        ⇒ 本仓那条路上：404（整条路由不存在）
```

**四件事，顺序不能换：**
1. **校验 `visitor_id` 形状** —— 它会**拼进 `user_name`**，不校验 = 往库里灌任意垃圾。
2. **先撤旧的**（`_revoke`）⇒ 保证「一个访客最多一把活着的」。
3. **发新的**：`create_user_api_key(user_name, expire_days=N)`，⚠️ **`role` 刻意不传**
   （⇒ 库里写 `NULL` ⇒ 读侧回退 ⇒ 非 admin ⇒ FREE）。⛔ **别填 `"free"`**（`auth.py` 的 docstring 明写）。
4. **只回那一把明文** —— 库里只有哈希，**之后找不回来**。

⚠️ **是 422 ⛔ 不是 400**：本仓 `ErrorCode.PARAM_INVALID` 在 `core/exceptions.py` 里映射 **422**。
⚠️ **"同一个访客再领回同一把"【做不到】**（库里只存哈希）⇒ **"只领一把"是【前端】的职责**。

🔴 **这条路由 ⛔ 不进无鉴权基线**（`scripts/route-auth-baseline.txt`）——
那份基线是**静态文件、没有"环境"这一维**；而这条只在 demo 入口里存在，
**CI 跑的是本仓那条路，根本扫不到它**。⛔ 别为了"看着整齐"把它写进基线。

```js
'use strict';
/* 访客凭据的**唯一一份**取法（`DEC-143`）。⛔ 本文件不碰 DOM。 */
const KEY_STORE = 'rag_api_key';        // ⚠️ 与今天同一个键（⛔ 不换名 —— 换名 = 老访客的凭据白丢）
const VID_STORE = 'rag_visitor_id';
```

| 函数 | 干什么 |
|---|---|
| `RagSession.key()` | **同步**返回本地那把（没有就 `''`）—— 与今天的 `key()` **逐字同签名** |
| `RagSession.ensureKey()` | **异步**：本地有 ⇒ 直接回；没有 ⇒ 去领一把存下来再回 |
| `RagSession.save(k)` / `RagSession.clear()` | 存 / 清 |
| `RagSession.isDemo()` | 本仓那条路上**没有那条端点** ⇒ 领会 404 ⇒ **静默退回今天的"自己填"** |

⚠️ `visitor_id` 用 `crypto.randomUUID()`（不支持就退回到随机串）—— ⛔ **别用指纹**（那是隐私面）。
🔴 **领不到时不报错** —— 退回"页面自己有一个输入框"，即**今天的行为**。

**判据：** `node --test app/static/js/session.test.js` ⇒ 含「本地有 ⇒ **不发任何请求**」·
