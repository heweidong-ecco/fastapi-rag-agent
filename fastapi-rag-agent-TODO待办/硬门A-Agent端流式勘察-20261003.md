## 4 · `/agent/langgraph_chat/stream` 已经做对了什么 —— 提炼 diff 形状

**图那侧的 diff 形状（提交 `d185eab`，`DEC-050`）** —— 只有这一个函数变了：

```python
# 改前（api/agent_graph.py:110 区）
def agent_decide(state: AgentState):
    response = llm_with_tools.invoke(state["messages"])

# 改后
def agent_decide(state: AgentState, config: RunnableConfig):
    response = None
    for chunk in llm_with_tools.stream(state["messages"], config=config):
        response = chunk if response is None else response + chunk
    return {"messages": [response]}
```

四条**要照抄的约束**（都在 `api/agent_graph.py:110-149` 的 docstring 里，且有实测支撑）：

1. **必须保留同步 `def`** —— 改成 `async def` 会让**同步的** `graph.invoke()` 直接抛 `TypeError: No synchronous function provided to "agent"`。⇒ 对甲档 #1/#7（走 `invoke`）**不能**学 `mcp_chat` 那种 async 节点。
2. **聚合必须用 `AIMessageChunk.__add__`（`+`）** —— 手拼 `content` 会丢 `tool_calls` ⇒ `should_continue` 判不出 `approval` ⇒ **B4 审批静默失效**而接口正常。守卫 `api/test_agent_sse.py::test_agent_decide_preserves_tool_calls`。
3. **端点侧的 `meta.get("langgraph_node") != "agent"` 过滤不能省** —— 不过滤会把 `tools` 节点的 `ToolMessage` 混进正文（`api/api_v1_agent.py:244`，实测）。
4. **收尾 `summary` 必须取 `aget_state()`，⛔ 不能攒流式块** —— 攒块会跨多轮累积（`api/api_v1_agent.py:282-298`，真服务实测）。

**「单开图 vs 改共享图」的判定证据**：
```bash
grep -n "agent_graph" api/api_v1_agent.py   # :18 导入、:151 invoke、:235 astream、:297 aget_state —— 同一个对象
git show d185eab -- api/agent_graph.py | grep -n "def agent_decide"
```
⇒ `:151` 与 `:235` 是**同一个 `agent_graph`**，改动落在共享节点 `agent_decide` 上。**`DEC-050` §备选方案 明确把「丙 · 另起一个流式专用图」否掉了**，采纳「甲 · 只改节点取流方式」。
