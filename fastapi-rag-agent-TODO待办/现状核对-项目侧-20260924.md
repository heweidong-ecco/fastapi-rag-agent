### 1.1 🔴 第 1 条拆开看 —— 这是最致命的一条

上游原话：**「公网暴露时对方可能根本没登录 —— 只对登录用户限额 = 没限。」**

**实测：这两句在这个仓里【分别】成立：**

```python
# main.py:150  RateLimitMiddleware（频率）
if not user_name:
    user_name = "anonymous"        # ⇒ 匿名【有】限流 ✅
#    ⚠️ 但所有匿名【共用同一个桶】—— 不是按 IP。一个爬虫就能打满全体匿名的份额。

# main.py:222  QuotaMiddleware（配额）
if user_name:                      # ⇒ 匿名【完全跳过】配额检查 🔴
    quota = get_user_quota(user_name)
```

| | 匿名请求 |
|---|---|
| **频率限流** | ✅ **生效**（归入 `anonymous` 桶，3 次/秒）⚠️ 但**不按 IP**，全员共享 |
| **每日配额** | 🔴 **完全不检查** —— 匿名请求**绕过整个配额中间件** |

⇒ **F1 结论：匿名可无限量打（只受 3 次/秒 的共享桶约束）。** 这正是上游警告的那件事。

### 1.2 🔴 第 3 条：四层限额的**第 4 层（全局日级）不存在**

`api/quota_limiter.py` **全文 80 行**，只有 `QuotaLimiter` 一个类，方法三个：
`increment_and_check(user_name, daily_limit)` · `get_remaining(...)` · `get_quota_info(...)`。
**每一个的第一个参数都是 `user_name`** —— **没有任何全局 / 跨用户的记账键**。

⇒ **F2 结论：没有第 4 层。** 上游通用方法 §7.1 说的「**只做第 1 层是最常见的错觉**」在这里更严重 ——
**第 4 层完全没有**，且**第 1 层也不全**（见 F3）。

### 1.3 🔴 第 4 条：一条**文案自相矛盾**的错误 —— 直接踩中 R3.3

```python
# main.py:126  全局限流触发时
JSONResponse(status_code=429, content={
    "error": "Internal server error",        # ← ⚠️ 说"内部服务器错误"，但它是 429、且不是错误
    "code": ErrorCode.RATE_LIMITED.value,
    "status_code": 429,
})
```

⇒ 上游 R3.3 原话：「⛔ **不许**退化成 500、白屏、或通用错误页」。
这条**不是 500**（状态码是对的 429），**但文案把"限流"说成了"内部服务器错误"** ——
⚠️ **对方看到 "Internal server error" 的第一反应就是"你的系统坏了"**，正是 R3 要防的那件事。

**对照：配额那条的文案是对的** ✅

```python
content={"error": "今日调用次数已用完，您的角色为 X，每日限额 N 次。",
         "code": ErrorCode.QUOTA_EXCEEDED.value, "status_code": 429, "extra": {...}}
```
⚠️ 但**同样缺 `retry_after` / 恢复时间** ⇒ R3.1（「可识别错误码 **+ 恢复时间**」）**只满足一半**。
