## 一 · 先纠正一个前提：**换的不是 URL**

> 业务方原话：「**api URL 更换，没额度就换**」。

| | |
|---|---|
| 阿里云百炼**所有模型共用同一个**端点 | `https://dashscope.aliyuncs.com/compatible-mode/v1`<br>（`api/embedding_client.py:12` **已在用这个**） |

## 四 · 🔴 三个**查出来的坑**（它们直接决定方案形态，不是背景补充）

> 来源：[百炼新人免费额度全流程](https://developer.aliyun.com/article/1765371) ·
> [Model Studio CLI 用量与配额](https://www.alibabacloud.com/help/en/model-studio/cli/usage-quota.md) ·
> [百炼 DashScope 免费额度用完了怎么办](https://zhuanlan.zhihu.com/p/2049232259492864886)
> ⚠️ **这三条来自公开文档检索，本仓未实测** —— 落地前应在控制台核一遍。

### 坑① **没有「查免费额度余额」的 REST API**

| 能查什么 | 怎么查 |
|---|---|
| ✅ **免费额度余额** | **控制台 →「模型用量」面板**（唯一权威）· CLI `bl usage free` |
| ❌ 不是余额 | `GET /api/v1/quotas` —— 查的是 **RPM/TPM 速率限制**，**不是余额** |

⇒ **「额度探测」只能做成【被动探测】**：调用回来才知道。**主动轮转做不到。**

### 坑② **额度耗尽的错误码是确定的 —— 但极易认错**

| 情况 | 返回 | 该怎么处置 |
|---|---|---|
| **额度真耗尽** | **`403` + `AllocationQuota.FreeTierOnly`** | ✅ **换下一个模型** |
| **限流** | `RateLimitExceeded` | ⏳ **等一下/重试** —— ⛔ **不该拉黑** |
| **密钥错** | `InvalidApiKey` | ⛔ **不该换模型** —— 这是**全局**问题 |

⇒ **黑名单判据必须【精确匹配 `AllocationQuota.FreeTierOnly`】**。
笼统「403 就拉黑」会把**限流**误判成额度耗尽，**把好模型也拉黑**。

### 坑③ **两个会让你「以为在省钱、实际在扣钱」的开关**

1. **「用完即停」默认关闭** ⇒ 额度耗尽后**自动转付费扣款**
2. **API Key 必须勾选目标模型** ⇒ 没勾的模型**不走免费池，直接走付费通道**

⇒ **这两条不先处理，策略会从「用掉免费额度」变成「悄悄花钱」。**

## 五 · 三档方案

| 档 | 做什么 | 优点 | 代价 |
|---|---|---|---|
| **甲 · 最轻** | 不建配置中心。`.env` 放候选模型列表 + `switch_model.sh` 换 + 重启 | ✅ 半天可完 | ❌ **无黑名单、无降级** —— 额度用完就报错 |
| **乙 · 薄路由层 ⭐** | 新增 `api/llm_router.py`：**注册表 + 候选链 + 按错误码分流 + 内存黑名单（带 TTL）**；17 个构造点改读 router。**只换 `model`，不动 URL** | ✅ 一套机制 · ✅ **可与 B11 熔断合并** | ❌ 要动 17 处接线 |
| **丙 · 完整配置中心** | 外置配置（DB/文件）+ 热加载 + 管理端点 + `bl` CLI 拉余额 + 定时校验 + Grafana 卡片 | ✅ 最完整 | ❌ **与 `DEC-033 🅱️`「后端先行」+「减法优先」正面冲突** |

### ⭐ 推荐：**甲（零代码）+ 把「黑名单 / 降级」并进 `B11` · 不为免费额度单开一轮**

> ⚠️ **2026-09-30 业务方推翻了我上一版推荐（原推荐"乙"）**，理由两条，**都成立**：
> ①「**改 model list 这样会不会太麻烦**」②「**如果是单为这个做太多改动没什么价值**」。

**先分清两件事 —— 它们的"贵"完全不同：**

| 需求 | 贵不贵 | 属于谁 |
|---|---|---|
| **「换 model 名」本身** | ⭐ **零代码** —— `LLM_MODEL_FAST` / `LLM_MODEL_CHAT` **本来就是 `.env` 变量**（`api/config.py:53/54`）<br>⇒ 换模型 = **改 `.env` + 重启**，**一行代码都不用动** | 免费额度 |
| **「熔断 / 降级 / 黑名单」** | 🔴 **贵** —— 17 个构造点**全在 import 时**建好客户端 ⇒ 运行时切换**必须逐个改** | **`B11 · R2 熔断`** |

**⇒ 三条结论：**

1. **「用掉免费额度」只值第一行。** ⇒ **甲档足够**，**不必上乙**。
   我上一版把「**合并**（别把同一套机制建两遍）」写成了「**一起做**」——
   那等于**让"想省 free tier 的钱"这个理由去背 `B11` 的改动量**。**这是错的。**
2. **第二行本来就该做** —— `ROADMAP` 功能现状表里 **熔断 = ❌ 完全没有**，
   但**它的理由是「线上需要」，不是「想用掉免费额度」** ⇒ **归 `B11`，不归本文**。
3. ⇒ **「十几个 model 候选」的正确形态是【顺带】**：
   **做 `B11` 时顺手让注册表支持多 model 候选**，**⛔ 不为它单开一轮**。

**⇒ 我早先那句仍然成立、只是从"推荐"降为"约束"**：
**同一套机制别建两遍**（`DEC-029` 已有两套口径差 35 倍 · 待办 §一 决策一 在问"三套怎么合"）。
**它不是"现在就做乙"的理由，它是"乙真要做时只能并进 B11"的约束。**
