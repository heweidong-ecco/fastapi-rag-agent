## 1. 内存账

### 1.1 先看这台机器要同时跑什么

从 `fastapi-rag-agent/docker-compose.yml` 核出的 **5 个服务**：

| 服务 | 镜像 | 说明 |
|---|---|---|
| `api` | 自建 `fastapi-rag-agent:latest` | FastAPI + Python |
| `postgres` | `pgvector/pgvector:pg17` | 带向量扩展的库 |
| `redis` | `redis:7-alpine` | 缓存 |
| `prometheus` | `prom/prometheus:latest` | 监控 |
| `grafana` | `grafana/grafana:latest` | 看板 |

### 1.2 关键变量：**重排序模型要不要跑**

`.env.example` 里有 `RERANKER_MODEL_NAME=bge-reranker-v2-m3`。
而 `README` 自述：**本机 8GB 都跑不了 `mode=accurate/full` 与重排序**（装不下 torch + 2.3GB 模型）。

⇒ **这一个开关，决定内存需求差一整个档位。** 下面分三档算。

### 1.3 三档内存估算

| 档位 | 跑什么 | 估算合计 | 结论 |
|---|---|---|---|
| **档 1｜裁件（推荐）** | `api`(fast 模式，**不装 reranker**) + `postgres` + `redis` | **~0.8 – 2 GB** | ✅ **2核4G 够** |
| **档 2｜+ 监控** | 档 1 + `prometheus` + `grafana` | **~1.5 – 2.8 GB** | 🟡 4G 偏紧 / 8G 舒适 |
| **档 3｜全量（含重排序）** | 档 2 + `bge-reranker-v2-m3`(≈2.3GB) + torch | **~4.5 – 6 GB** | ⚠️ **必须 4核8G**，且**很可能仍不够**（你本机 8G 就跑不动） |

> 📌 **推算依据**（可复核）：`api` ≈ 0.5–1GB（Python + 框架 + 缓存）· `postgres` ≈ 0.15–1GB（随 HNSW 索引增长）·
> `redis` ≈ 30–50MB · `prometheus` ≈ 0.2–0.4GB · `grafana` ≈ 0.2–0.4GB。

### 1.4 ⚠️ 别信我这张表 —— 这么实测

```bash
# 服务全起来之后，看每个容器的真实占用
docker stats --no-stream --format 'table {{.Name}}\t{{.MemUsage}}\t{{.CPUPerc}}'

# 系统总览
docker system df
free -h
```

**下单公式**：**实测峰值 × 1.5 = 你要买的内存**。
（1.5 的余量留给：知识库长大、并发、pgvector 索引膨胀。）

## 3. DevBox 评估：❌ **不满足，排除**

> **问题**：阿里云 DevBox 能不能当这个 web 服务主机？
> **答**：**不能（不合适）。** 4 条理由，第 2 条是致命的。

### 3.1 DevBox 是什么

**基于 ECS 实例**、预置了常用开发环境（Python / Java / Node.js / Go + FastAPI / LangChain 等框架 + Claude Code / Codex 等 AI 工具）的**云开发机**。
创建后**一键连接本地 IDE**（VSCode / Qoder / Cursor / Trae），代码、依赖、构建产物都在云端。

### 3.2 ❌ 四条排除理由

| # | 理由 | 说明 |
|---|---|---|
| **1** | **定位不对** | 它是"**云开发机**"，公网访问方式是「获取访问地址 → 用 URL 连**本地 IDE**」—— 服务对象是 **IDE**，不是浏览器。<br>要当 web 主机，得自己开安全组、确认有公网 IP，**属于它的非设计用途**。 |
| **2** | 🔴 **关机就换地址** | 「节省停机模式」下，停止实例会**释放固定公网 IP**。<br>而你要的恰恰是「**一条能发出去、一直有效的链接**」—— **直接对撞**。<br>（它确实有"关机后 CPU/内存暂停计费"的好处，但代价是地址没了。） |
| **3** | 🔴 **7×24 场景下它最贵** | 0.1 元/小时 × 720 小时 = **72 元/月**（**仅计算资源**）。<br>而轻量 **2核4G** 活动价 **~29 元/月** —— **更便宜，内存还翻倍**。<br>**按量付费只在"每天只开几小时"时划算；你要 7×24，正好是最不划算的用法。** |
| **4** | **价格不止 0.1 元/小时** | 官方明说：参考价**只含 vCPU + 内存**；最终价 = 计算 + **系统盘**（默认 40GiB ESSD）+ **公网流量**（**单独计费**）。 |

### 3.3 ✅ DevBox 适合做什么（别浪费）

- **云端干净的开发环境** —— 尤其适合**跑 `agent-eval-gate`**：它本来就是 **CLI 工具、零运行时依赖**，DevBox 的环境正好。
- **快速验证 / 轻薄本开发**（官方原话）。
- ⇒ **它跟"部署对外 web 服务"是两件事，不是一件事的两个选项。**

### 3.4 结论

> **DevBox 排除。URL 主机用「轻量应用服务器」。**
> 如果你仍想用 DevBox（比如手上有额度），**必须先自己确认**这三点：
> ① 有没有**对公网稳定入口**？ ② 关机后**公网 IP 是否被释放**？ ③ 7×24 的实际月账单是多少？
> —— 第 ② 条若为"是"，**直接放弃**。

## 4. 下单建议（按顺序）

1. **先做施工单 A**（本机跑通）—— 不花钱、不依赖选型。做完你才有**实测内存**。
2. **实测内存**（§1.4 的命令）→ 算出 `峰值 × 1.5`。
3. **按实测值下单**：
   - 落在 2G 内 → **2核4G**
   - 落在 3–4G → **4核8G**（或裁掉监控压回 2核4G）
   - **重排序（档 3）建议线上直接不做** —— 你本机 8G 都跑不动，8G 云机同样够呛
4. **买 1 个月**（不是 1 年）—— 覆盖投递 + 展示窗口即可。
5. **同步做两件保护**：每日成本硬上限 + 演示口令（缺口 2 文档 §8.1）。
