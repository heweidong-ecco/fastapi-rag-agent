### 目的

> **让你在展示时，有一个「其他人能自己点开验」的东西。**
> 把 **"我说我会做 AI 应用"** 变成 **"你自己看"**。

### 为什么必须做

| 你已经有的 | 你缺的 |
|---|---|
| 15 个仓 · 187 commits · 覆盖率 94.57% · 工程深度够 | **只有你能打开** |

⇒ **一个 URL 把「需要读代码才能判断」变成「点一下就能判断」。**

> 📌 附带说明：**这也是"缺口 1（被别人用过）"的前置条件** —— 没有 URL，"被别人用"无从谈起。

### 过程（依赖顺序 —— 只有第 0 步卡着）

```
0. 定机器（先算内存）        ← 唯一的阻塞项，【未定】
1. 部署后端  → 拿到 URL       ← 依赖 0
2. 写前端    → 挂到 URL 上     ← 可与 1 并行（前端托管独立，见 §4.4）
3. 补四个硬门 A/B/C/D         ← 依赖 1 + 2（要有界面才能演示）
4. 接 eval 门跑分             ← 加分项，依赖 1
5. 换一台设备，自己点一遍       ← 最终验收
```

### 需要做的（就 4 件，不是 20 件）

1. **写前端**（4 个页面：对话 / 接管 / Trace / Eval）
2. **部署后端**，拿到一个能活 1–4 周的 URL
3. **补四个硬门**：A 流式 · B 引用 · C 中断 · D 接管
4. **（加分）** 接 `agent-eval-gate` 跑分

> §9 那张 20 行的表，是这 4 件事拆到可勾选的粒度 —— **不是 20 件事**。

### 做成什么样（验收场景）

> 其他人收到一条链接，**你不在场**，他一个人能做完这 5 件事：

1. 问一句 → **答案一个字一个字打出来**，他能切到 Network 看到那条连接**没断**
2. 点答案里的 `[1]` → **弹出原文、高亮命中段**
3. 生成到一半点 **"停止"** → 停住，且能看到 token 计数**停在哪**
4. 问一个敏感的 → **系统自己停下来**说"需人工确认" → 有个地方能看到待接管、能批准
5. 看到一个 **Trace 面板**：每次调用多少 token / 多少钱 / 走了哪几步

**全程你不需要解说。** 这就叫"补上了"。

### 为什么是这些做法（而不是别的）

| 决定 | 理由 |
|---|---|
| **用现成的 `fastapi-rag-agent`，不新写** | 已有 87 commits 的深度，新写=扔掉，时间也不够 |
| **前端必须新写** | 现有只有 3 个**调试用**测试页（`stream_test.html` 等），不是产品界面 |
| **eval 不部署** | 它是 CLI（**无服务端**），部署没意义；它的说服力在退出码 `0/1/2/3` |

| **不注册域名** | 绑大陆服务器要 ICP 备案（数周）；平台自带地址够用 |
| **对话页加演示口令** | 完全公开 = 陌生人和爬虫烧你的 LLM 额度；而 L2 只需**其他人**能验 |

## 1. 验收定义：怎样才算"缺口 2 补上了"

分三层。**只到 L0 不算补上**——v2 里踩过这个坑：「写在 README 里不算数」。

| 层 | 判定 | 硬指标 |
|---|---|---|
| **L0 有地址** | 一个能发出去的 URL | HTTPS、公网可达、**陌生人不看说明就能打开**（不需要注册/不需要你本地起服务） |
| **L1 四硬门能演示** | A/B/C/D 四个动作在浏览器里**逐个走通** | 每个硬门有"证明是真的"的手段（见 §5），**不是口头承诺** |
| **L2 其他人能自己验** | 把 URL 发过去，对方**自己点**也能验 | 不需要你在场解说；有独立可点的入口（trace 面板 / eval 面板 / 接管队列） |

> **L2 是真正的分水岭**。v2 类型 2 里「不合格长什么样」写的都是同一件事：**只有你能演示**。

## 3. 结论：两个仓不是二选一，是上下游

> **推荐：`fastapi-rag-agent` 当"面"，`agent-eval-gate` 当"底"。**

理由不是偏好，是**两个仓自己的设计就是这么写的**：

- `agent-eval-gate` README 原文：**"给其它 Agent 系统做生产就绪评测门"**、**"被测经适配器取（HTTP / 快照 / 回放）"** ⇒ **它天生要有一个被测**。
- `fastapi-rag-agent` 就是它最自然的被测 —— 而这不是我猜的：`agent-eval-gate/docs/部署.md` §5 的标题就是
  **「接入一个真实被测（以 `01.FastAPI RAG Agent` 为例）」**，且仓里已有 `eval/fastapi_rag_golden.evals.json`（17KB）。

**分工**：

| 仓 | 承担 | 命中 |
|---|---|---|
| **fastapi-rag-agent** | **线上地址** + 四硬门 A/B/C/D 的演示现场 | v2 **类型 2**（JD-7） |
| **agent-eval-gate** | 给上面那个地址**跑分出 exit code** + trace 面板 | v2 **类型 6**（JD-8）的"可评测 / 可观测 / 可复现" |
| 两者合起来 | 一次覆盖 **类型 2 四个硬门 + 类型 6 前 5 条** | 这是缺口 2 的**最大杠杆** |

> ⛔ **不要**给 `agent-eval-gate` 硬造一个网页当地址 —— 它是 CLI + exit code 的工具，**无服务端**，它的说服力在"**0/1/2/3 的退出码**"上。**把它包装成网页反而是自降身价。**

## 4. 部署形态：先定 4 个决定

> 这一节回答「前端 + URL + 域名 + 服务器一直开着」这一串疑问。**4 个决定里，2 个可以省。**

### 4.1 先纠正一个前提

> **你要的不是"服务器一直开着"，是"投递到展示那段窗口内，链接有效"。**

这个区别值钱：它把"永久成本"变成"**一次性 ~1 个月的成本**"。

### 4.2 决定 1｜域名：**不用注册** ✅ 省钱省事

- 平台给的地址就够（云主机的公网 IP、Cloudflare Pages 自带的 `*.pages.dev`）。
- ⚠️ **大陆节点绑自定义域名必须 ICP 备案**（数周 + 主体资质）⇒ **不注册域名 = 省掉整个备案流程**。
- 大陆节点**直接用 IP 访问通常可行、无需备案**；若担心 80/443 被拦，可用非标端口，**或直接选香港/境外节点**（无需备案，代价是国内访问稍慢）。
- **域名的唯一收益是"好看"。** 对 L0/L1/L2 三层验收**没有任何贡献**。

### 4.3 决定 2｜服务器要不要常开：**要，但只买 1 个月**

- 真实需求 = **投递到展示那段窗口（约 1–4 周）**。
- ❌ **本机 + 隧道（Cloudflare Tunnel / frp / ngrok）不能在投递期发链接** —— 你电脑一关链接就死，HR 半夜点开打不开。**这比不给链接更差**（L0 判据是"陌生人不看说明就能打开"）。
- ✅ 本机 + 隧道**只适合当面演示那天**：你人在场、当场演示时用。

### 4.4 决定 3｜前端放哪：**第一版建议前后端放一起**

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A（第一版推荐）** | 前端静态文件**由后端一起托管**（`fastapi-rag-agent` 的 `StaticFiles` **已经挂了**，见 §2） | **一个地址、零跨域配置、一台机器** | 前端跟着后端一起活、一起死 |
| B（可选） | 前端放 **Cloudflare Pages / Vercel** | 免费、**自带 HTTPS 域名**、前端永不掉线 | **两个地址** ⇒ 要配 **CORS**，多一处出错点 |

> 📌 **这里修正我上一轮的建议。** 我先前推荐 B（Cloudflare Pages）。
> 对你的场景再想了一遍：**第一版走 A 更省事。**
> 因为 B 的"前端永不掉线"在你这里**没多大意义**（后端挂了页面照样没数据），
> 却要多付一份跨域配置的复杂度。**A 的理由只有"出问题的地方更少"一条 —— 但这够了。**

### 4.5 决定 4｜后端放哪：**这里有个硬约束会推翻廉价方案** ⚠️

| 方案 | 常开？ | 成本量级 | 适不适合 | 关键问题 |
|---|---|---|---|---|
| **云主机**（轻量应用服务器 / ECS） | 要 | 几十元/月 | ✅ **推荐** | 内存够不够（见下） |
| Cloudflare Tunnel + 本机 | 你开机才在 | 0 | 🟡 **仅当面演示那天** | 投递期发链接 = 死链 |
| 阿里云函数计算 FC（Serverless） | 不常开、按调用 | 低 | ❌ **不建议** | 本项目要 **SSE 长连接 + WebSocket + pgvector + Redis**，Serverless 对长连接与状态不友好，改造成本极高 |
| **阿里云 DevBox** | ？ | ？ | ⚠️ **待你核实** | 见下 |

> ⚠️ **关于 DevBox 我不能确证，请你核这三点**：
> 1. 它有没有**对公网的稳定入口**（还是一个只有你能访问的开发环境）？
> 2. **闲置会不会休眠**？（开发环境常见策略 —— 一休眠链接就死）
> 3. 计费方式（按开发环境计费 vs 按在线服务计费）？
>
> **常识判断**：**"开发环境"通常不是"对外长期在线的服务"的合适载体。** 如果它是给你写代码用的云端机器，
> 那它顶多**替代"本机+隧道"**，**替代不了"云主机"**。

#### 🔴 决定 4 的硬约束 —— 内存，**先算再下单**

- 你 README 自述：**本机 8GB 都跑不了** `mode=accurate/full` 与重排序（装不下 torch + 2.3GB 模型）。
- 线上还要**同时跑 pgvector + Redis**（compose 里还有 Grafana + Prometheus）。
- ⇒ **2核2G 的入门轻量服务器大概率装不下。** 两条路：
  - **(a)** 买 **4核8G+**（贵）
  - **(b)** 线上**裁件**：只跑 fast 模式 + 去掉 Grafana/Prometheus 等非必需件，**并在页面上如实标注**
    （延续你 profile README 的 🔻 调性 —— 别到线上就"假装全绿"）
- **先算清这条再下单，否则买了装不上。**

### 4.6 推荐形态（一句话）

> **一台按内存选型的云主机**（买 1 个月）· **前后端一起放** · **不注册域名**。
> 成本量级：**几十元/月 × 1–2 个月** · **LLM 额度是唯一必须设上限的**。

### 4.7 ⚠️ 一个反直觉的建议：**不要对全世界开放**

"别人点开就能用" = 陌生人和爬虫也能烧你的 LLM 额度。而 **L2 只需要「其他人能自己验」**，不是"全世界能验"。

**折中**：
- **不烧钱的页公开**：trace 展示页、eval 跑分页（静态数据，随便点）→ 直接过 L2
- **烧钱的对话页加一道口令**（演示码即可，不需要完整注册体系）
- 一举两得：既过 L2，又不至于账单失控

### 4.8 完整流程：从 clone 到"把地址发出去"

> ⚠️ 这一步最容易混 —— **`git clone` 和 `docker compose` 是两个动作，不是一件事。**
> `docker-compose` 不是用来下载代码的，是用来**同时拉起 postgres + redis + api 三个容器**的。

```
① 取代码    git clone <repo>                        → 得到一个文件夹
② 本机跑通  cd 文件夹 && docker compose up -d
            → 打开 http://127.0.0.1:8000 自己看，确认能跑
③ 写前端    放进后端的静态目录（方案 A）
④ 上云      云主机装 docker → 同一套 compose 拉起来 → 拿到【公网地址】
⑤ 发出去    把那个地址发给其他人
```

**两个必须分清的点：**

**（a）本机部署 vs 云部署 —— 不是二选一，是两步。**
本机那步**必须做**（先确认能跑，别把一堆问题带上云），但它**不是最终形态** —— 它只有你能打开。

**（b）🔴 内网穿透（Cloudflare Tunnel / frp / ngrok）—— 对你这个场景是错的选择。**

| | 内网穿透 | 云主机 |
|---|---|---|
| 链接什么时候活着 | **只有你电脑开着时** | **一直活着** |
| 你关机 / 睡眠 / 断网 | **链接死掉** | 不受影响 |
| 地址稳定性 | 常常变（随机串） | 固定 |
| 适合的场景 | **当面演示那天，你人在场当场演示** | **投递期，随时可能被点开** |

> 你的场景是**投递期把链接发出去** —— HR / 其他人可能半夜、周末点开。
> **你电脑不会 7×24 开着 ⇒ 他点开是打不开 ⇒ 比不给链接更差。**
> ⇒ **穿透只做"当面演示那天"用；投递必须用云主机。**

## 5. 四个硬门：逐个拆成施工项

图例：✅ 已具备 ｜ 🟡 有地基/部分 ｜ ❌ 缺

### 硬门 A｜流式输出

| 项 | 内容 |
|---|---|
| **判定** | 答案逐字出现；DevTools → Network 里那条 `text/event-stream` **连接保持不关闭**、chunk 持续到达 |
| **现状** | 🟡 `api_v1_rag.py` 已用 `StreamingResponse` + `text/event-stream`；🔴 **`api_v1_agent.py` 不流式** |
| **差距** | ① Agent 接口也要流式（否则演示 Agent 就露馅）② 需要一个**像样的对话前端**，不是 `stream_test.html` |
| **怎么演示** | 发一问 → 答案逐字出现 → **当场切 Network 面板，指着那条未关闭的连接** |
| **怎么证明是真的** | ① Network 里 chunk 时间戳**是递增的、不是一次性** ② 后端日志里那条请求的 token 计数**随 chunk 增长** |
| **反例（会被抓穿）** | 前端 `setInterval` 切字符 / 先拿完整 response 再假打字 —— Network 里是**一次性 response** |

### 硬门 B｜引用溯源

| 项 | 内容 |
|---|---|
| **判定** | 答案里的 `[1][2]` **点开能展开原文片段并高亮命中段**，再点能跳到知识库原文位置 |
| **现状** | 🟡 ✅ 后端 `api/answer_with_citations.py` 存在；🔴 **无可点界面** |
| **差距** | 前端：引用徽标 + 展开原文 + 高亮命中段 + 跳转；**外加"无据拒答"**（问库里没有的 → 说"资料中没有"而不是编） |
| **怎么演示** | 问一个**库里确实 covered** 的问题 → 点 `[1]` 展开 → 高亮那一段；<br>再问一个**库里没有**的 → 明确拒答 |
| **怎么证明是真的** | 引用**由检索结果注入**、不是模型自由生成；点开能看到 **chunk id + 相似度分** |
| **反例** | 引用是模型自己编号的，点不开或点开对不上原文 |

### 硬门 C｜生成中断

| 项 | 内容 |
|---|---|
| **判定** | 点"停止" → 前端停输出，**且后端 LLM 调用真的终止** |
| **现状** | ❌ 未见实现 |
| **差距** | ① 前端停止按钮 ② **服务端 cancel 传播**：必须让 LLM 的 HTTP 流也终止 |
| **怎么演示** | 生成途中点"停止" → 前端立刻停 → **切到后端日志，展示那条 cancel 记录** |
| **怎么证明是真的** | 后端日志有 cancel 事件，**或 token 计数在该时间点停止增长** |
| **反例（v2 点名的坑）** | **只做前端 `abort()`，服务端还在烧 token** —— 账单继续涨 |

> ⚠️ **实现要点（这是个真坑）**：FastAPI 的 `StreamingResponse` 在客户端断连时，generator 会收到 `GeneratorExit`/`CancelledError`，
> **但底层 LLM 的 httpx 流不一定跟着停** —— 取决于那个 stream 是否活在 generator 的 `with` 上下文里。
> **必须实测**（断连后看上游计费/日志），不能靠"我写了 abort"就当完成。

### 硬门 D｜人工接管

| 项 | 内容 |
|---|---|
| **判定** | Agent 走到某步**主动停下**（低置信度 / 敏感操作 / 需审批）转人工；人工在同一会话回复；**AI 拿回上下文继续** |
| **现状** | 🟡 ✅ `agent_checkpointer.py` 已存在（LangGraph checkpointer = 状态持久化与恢复的天然基础）；🔴 无接管队列、无界面 |
| **差距** | ① 触发条件（低置信度阈值 / 敏感工具白名单 → 暂停）② **接管队列界面** ③ 接管后上下文续跑 ④（加分）**接管结果回流成新评测用例** |
| **怎么演示** | 构造一个会被判为需接管的请求 → 系统**自动暂停** → 接管队列出现待处理项 → 点开后**能看到完整上下文**、能改写答案 → 提交 → AI 续跑 |
| **怎么证明是真的** | 接管事件有记录（**谁、何时、为什么**）；接管后会话**上下文连续** |
| **反例** | 口头说"可以人工介入"，界面上找不到 |

## 6. 真正的工作量在哪：前端

> **这是缺口 2 里最大的一块，而且不是"部署"能解决的。**
> **2026-09-24 已确认：前端要重新写。**

v2 类型 2 的判据是「**必须当场演示**」，而**演示的载体是浏览器界面**。现状是：

- `api/static/` 只有 3 个**测试页**（`stream_test.html` / `trace_viewer.html` / `websocket_test.html`）—— 它们是自己人调试用的裸页，**不是产品界面**。
- **全仓无 `package.json`、无其他 HTML 页面** ⇒ 严格说，`fastapi-rag-agent` 目前是"**后端 + 测试页**"，**不满足 v2 类型 2 的「全栈 AI 应用（带前端）」**。

**最小够用的前端（能过 L1/L2 即可，不求好看）**：

1. **对话页**：输入框 + 流式输出 + `[n]` 引用徽标（点开展开/高亮）+ **停止按钮** + 每轮 **token/费用/首字延迟**
2. **接管页**：待接管队列 + 点开看完整上下文 + 改写/批准 + 提交续跑
3. **Trace 页**：现有 `trace_viewer.html` 升级 —— 能点开一条看到 span 树 + 每步 token/耗时/成本
4. **Eval 页**（与 agent-eval-gate 的 CLI 输出对接）：跑分 + **与上一版的对比箭头**

> 💡 **省力判断**：`trace_viewer.html` 已经存在 ⇒ 第 3 项是**改造**不是新建。真正的从零工作是第 1、2 项。
>
> 💡 **形态建议**：既然要重写，**建议做成一个纯静态的单页应用（SPA）**（React/Vue 皆可，甚至零构建的原生 JS 也行）——
> 这样它就能**直接托管到 Cloudflare Pages**（见 §4.4），与后端解耦，**前端永远不会因为后端重启而打不开**。

| 5 | **跑** `python -m eval_gate run --evals eval/fastapi_rag_golden.evals.json` | 产出 exit code + 报告 + trace → 就是 §6 第 4 项要喂给 Eval 页的东西 |

### 7.3 对准公网后新增的三个注意点

1. **🔴 配额打架（新）** —— eval 跑全量**会消耗被测额度**。如果按 §8.1 给线上设了每日成本上限，
   **跑分可能触发 `E_SUT_QUOTA` → 整批 aborted → exit 3**。
   ⇒ **给 eval 用单独 API Key + 预留额度**，或把熔断阈值设在 eval 单次消耗之上。
2. **快照兜底（强烈建议）** —— `.env` 里的 `EVAL_SUT_FASTAPI_SNAPSHOT` 可**改走快照回放**（总纲 D-5 三种取法之一）。
   ⇒ **被测挂了也能演示。** 展示时后端出问题，这是保险 —— **提前录一份快照备用**。
3. **TLS 坑会变** —— 你 §6-2 那个 `localhost` → IPv6 的坑在公网下消失；但**公网证书链**可能出现新坑
   （你 §6-1 的 `SSL_CERT_FILE` 那套经验要保留）。

### 7.4 为什么这条线性价比最高

它把 `agent-eval-gate` 的 **exit code 0/1/2/3** 变成**对着你自己线上系统的真实判分** ——
一次同时喂 **v2 类型 2（评测面板）** 和 **类型 6（可评测 / 可复现 / 可观测）**。
且它**不需要部署**（纯 CLI、零运行时依赖）⇒ **不增加服务器成本，也不增加运维面**。

## 8. 上线前必须先解决的几件事（风险，别跳过）

### 8.1 🔴 公开 URL = 任何人都能烧你的 API 额度

- 现状：`quota_limiter.py` 只有 **2.6KB**，`rate_limiter.py` 存在，但这是**公网暴露**的场景。
- embedding **固定走 DashScope**（要密钥），生成 LLM 可配。
- **必须**：① 密钥**绝不入库**（`.env.example` 已有模板，确认 `.env` 在 `.gitignore`）② **配额/限速对陌生人生效**（不是只对登录用户）③ 设**每日成本硬上限**，超了熔断 ④ 演示口令 + 限额说明写在页面上。
- 判据：**把 URL 发到公开场合，第二天账单不炸。**
- 配套：见 §4.7（烧钱的页加口令）。

### 8.2 🔴 一上线，别人第一件事就是压它 —— 而性能数字全部未实测

- README 自述：**性能三行"是目标不是指标"，每一格"现状"都是 ⬜**；旧压测记录（2026-06-25）**跑在坏环境上**（同日日志 113 条未捕获异常，错误率 77%–97%），**方向甚至相反**。
- ⇒ **上线前先跑一次干净压测**，把 P99 / 失败率 / 缓存命中率填上。
- 否则：其他人打开 URL 随手一压，**你唯一能拿出的数据是一份自己标注"不可采信"的旧记录** —— 比没有更糟。

### 8.3 🟡 本机装不下的部分，线上要如实标

- README 明写：`mode=accurate/full` 与**重排序在本机跑不了**（装不下 torch + 2.3GB 模型）。
- ⇒ 线上若也只跑 `fast` 模式，**页面上要写明"线上为 fast 模式；accurate/重排序未启用"**。
- 这正是你 profile README 已经建立的调性（🔻 标边界）—— **保持一致。**

### 8.4 🟡 eval 跑分与成本熔断会互相打架

见 §7.3 第 1 条。**别让"上线保护"把"跑分"锁死。**
