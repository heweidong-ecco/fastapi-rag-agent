# ── ⑪ 指向【有意 gitignore 的内容】—— 那段内容**本来就不该随 clone 下来**（2026-10-05 加）──
# 🔴 **背景：这一节是门【换了判据】之后才需要存在的。**
#    本条加进来的同一天，`check_doc_links.sh` 把"目标存在吗"的口径从
#    **`os.path.exists()`（问磁盘）** 改成 **`git ls-files`（问"克隆者拿得到什么"）**。
#    改之前，本机报「✅ 0 处」，**CI 报 10 处** —— 因为磁盘上有没入库的东西。
#    ⇒ 改完之后本机也报这 10 处，**两台机器口径一致**（这才是加此节的代价与理由）。
#    📄 裁定 ⇒ `docs/decisions/DEC-076-三门进CI与凭据门diff模式.md` §2.9
#
# ⚠️ **为什么这不算缺陷**（逐条给能打印的理由，⛔ 不是"懒得修"）：
#    这些链接的**语义是「本机有一份归档/清单」，不是「点开它」**；
#    而那段内容被 `.gitignore` **有意**排除 ⇒ **克隆者那里本来就不该有**
#    ⇒ 拿"克隆者能不能解析"去判它，是**拿错了尺子**。
#
#    🔴 **约束（否则这一节会掩盖真问题）**：
#      **这两条 gitignore 一旦取消，就删掉对应那行** —— 到那时这些路径必须真能解析。
#      📌 判据（可打印）：`git check-ignore -v archive/ GIT_CHECKLIST.md`
#         **有输出 ⇒ 仍是有意排除 ⇒ 本行还该在**；**无输出 ⇒ 已解除 ⇒ 删掉本行**。

^GIT_CHECKLIST\.md$          # `.gitignore:27` —— `docs/文档地图.md` §T5 已登记「在盘上但未入库」
