# `.claude/` —— 本仓的**门**都在这里

> ## 这份文件是什么
>
> **本仓挂了哪些自动门、在哪、拦什么。**
>
> 📌 **为什么要有它**：门**挂在别处就等于没有门**（`docs/复盘/2026-09-16-八个PR跳过了留痕门.md`）——
> 而**新会话不会主动去看 `.claude/` 里有什么**。

---

## 一 · 本仓挂的门（**7 道** —— 提交前 7 + 编辑后的提醒）

### ① 提交前的门 —— `.claude/hooks/pre-commit-gates.py`

**触发**：`PreToolUse` 匹配 `Bash` ⇒ 命令里含 **`git commit`** 时。
**做**：跑下面**六道检查 + 一道内联门**，**任一不通过就阻止提交**（exit 2）。

| # | 门 | 脚本 | 拦住什么 | 拦不拦 |
|---|---|---|---|---|
| 1 | **凭据门** | `scripts/check_secrets.sh` | PUBLIC 仓里混进**明文凭据**（**进了历史就改不掉**） | 🛑 拦 |
| 2 | **链接检查** | `scripts/check_doc_links.sh` | 文档里**指向不存在的路径** | 🛑 拦 |
| 3 | **孤儿检查** | `scripts/check_doc_orphans.sh` | 建了文档**但没人指向它**（索引挂空） | 🛑 拦 |
| 4 | 🆕 **模块 spec 门** | **内联在 hook 里**（不调外部脚本） | **新增了 `app/X.py` 但 `docs/specs/` 下与模块同名的那个 不存在** | 🛑 **拦** |
| 5 | **路由鉴权门** | `scripts/check_route_auth.py --baseline` | **新引入了没有鉴权依赖的路由**（比基线**变多**） | 🛑 拦 |
| 6 | **静态检查门**（2026-10-07） | `scripts/check_lint_baseline.sh` | `ruff` 的 `E9`/`F` **比基线变多**（存量认下 ⇒ ⛔ 不是"一条都没有"） | 🛑 拦 |
| 7 | 🆕 **过期导入门**（2026-10-09） | `scripts/check_stale_imports.sh` | **`app/` 之外的 .py 里，模块搬了家但导入没改**（`from auth import …`） | 🛑 拦 |

> 🔴 **第 ⑦ 道为什么必须有**（`N21`）：2026-10-09 当天 `#123` 模块化重构**静默打断两个活工具**
> （其中一个是**发凭据**的 `issue_api_key.py`），而**两道防线都照不到**：
> **913 条 pytest**（脚本不在 `app/tests/` 采集范围）· **CI 的 `compileall`**（只查语法，
> 而这是**导入期**错）。📄 背景 ⇒ `docs/复盘/2026-10-09-测试全绿而活路径坏了两次.md`
> ⚠️ **它 exit 2 = 「判不了」**（拿不到 git / `app/` 不在）——
> 与「干净」分开，口径同下面第 ⑥ 道那条。
> ⚠️ **它【不覆盖】字符串里的陈旧路径**（例如 `API_DIR = REPO_ROOT / "api"`）——
> 拿字符串猜路径**误报太高**，本门**故意不猜**（见脚本头「不覆盖什么」）。
> 📌 **它只看【入库了】的 `.py`**（`git ls-files`）⇒ 新文件**要先 `git add`** 才在射程内。

> 🔴 **第 ⑥ 道的口径与其余五道【不一样】，⛔ 别读混** —— 前五道是「**一条都不许有**」，
> 它是「**不许比基线多**」（存量 **40 组 / 103 行**按 `T6`「先挂起」认下）。
> 📄 为什么这么设计 ⇒ `scripts/check_lint_baseline.sh` 脚本头。
> ⚠️ **它还单开一个退出码 3 = 「本门没跑」**（没装 ruff / 基线没了 / ruff 自己出错）——
> 本地的汇总行会把它标 **⏭ 未跑**，⛔ **不是 ✅**（否则"没跑"与"跑了且干净"在痕迹上一模一样）。

> ⚠️ **它只管 `git commit`** —— 不拦 `add` / `push` / `status`。
> ⚠️ **门本身跑不起来时不阻止**（只警告）—— 否则 hook 坏了会把人锁死。
> ⚠️ **第 ④ 道门只管【新增】模块**（`--diff-filter=A`）——
> **改已有模块要不要更新 spec 是【判断】，机械判不了** ⇒ 交给下面那个 PostToolUse hook **提醒**。

### ①·5 · 写完 `app/*.py` 之后的**提醒** —— `.claude/hooks/spec-remind.py`

**触发**：`PostToolUse` 匹配 `Edit|Write|NotebookEdit`。
**做**：如果动的是 **`app/` 下的 `.py`、且不是测试** ⇒ 打一行：

```
有 spec 的： 📋 你动了 `app/rag/reranker.py` —— 记得更新 `app/rag/specs/reranker.md`（⭐ 关键节：「看代码会误判的地方」）
没 spec 的： 📋 你动了 `app/core/db.py` —— ⚠️ **它还没有 spec**……做完记得建一份
其它（文档/测试/脚本）： 静默
```

> ⛔ **它不阻止** —— `PostToolUse` 拦不住已经发生的编辑，而且写代码时会频繁触发。
> 📌 **这是有意的分工**：**能机械判的（新增）⇒ 硬拦；判不了的（要不要更新）⇒ 提醒。**

### ①·6 · 🆕 改**路由文件**之后的提醒 —— `.claude/hooks/route-auth-remind.py`

**触发**：`PostToolUse` 匹配 `Edit|Write|NotebookEdit`，**且**改的是
**`app/` 下的路由文件**（**脚本自己按【形状】判** —— 见下面那条更正）。
**做**：跑 `scripts/check_route_auth.py --baseline` ⇒ **只报「比基线【变多】」**：

```
🔴 路由鉴权检查：**新引入了没有鉴权依赖的路由**
❌ 比基线【多了 1 条】—— 新引入了没鉴权的路由：
     + /api/v1/debug/cache_stats
⇒ 要么给它加 `Depends(get_current_user_hybrid)`（或 require_admin），
   要么确认它确实该无鉴权 —— 后者请跑 `--write-baseline` 把它写进基线并注明理由。
```

> ### 为什么要有它（**这是本仓一条教训的落地**）
> 核 `api_v1.py` 时**手工扫"哪些路由没鉴权"，第一版扫出 0 条** ——
> 因为 `FastAPI 0.141` 起 `include_router` 的结果被包成 `_IncludedRouter`。
>
> 🔴 **那个坑【仓里早就写着】**（`app/tests/test_public_paths.py:17-20`）——
> **知识在，但挂在一个谁都不会去读的地方**（一个测试文件的 docstring 里），**我当天踩了两次**。
>
> ⇒ **不是再写一条规矩**（那天规矩写了三条、犯了五次），
> 是**把它挪到"一定会撞上"的位置** —— **改路由文件 ⇒ 自动跑一次检查**。
> 📄 复盘：`docs/复盘/2026-09-30-判据在手边却没查.md` · 规矩：`docs/规范/开发规范.md` **§1.5**

⚠️ **性能取舍（实测）**：
· 改**非**路由文件 ⇒ **0.05s**，静默退出
· 改**路由**文件 ⇒ **约 9–13s**（要 import `main` 拿真实路由表）
⇒ ⛔ **所以它【先判路径】** —— 不然每次编辑都付 10 秒。
📌 另外那条 91s→9s 的提速，靠的是**在 import 前关掉遥测**（`GRADIO_ANALYTICS_ENABLED` 等），
   根因与 `app/conftest.py:20` 记的**是同一个**。

> ⛔ **它不阻止**（`PostToolUse` 拦不住已发生的编辑）—— 价值是**把话说到眼前**。
> 📌 与 ①·5 的分工一致：**能机械判的 ⇒ 硬拦；判不了的 ⇒ 提醒。**

> 🔴 **2026-10-05（批 4 · `N10`）判据由【清单】改成【形状】** —— 此前写死 4 个文件名
> （`main.py` / `api_v1.py` / `api_v1_rag.py` / `api_v1_agent.py`）⇒ **新建第 5 个路由文件时
> 这个 hook 静默不跑**，而"**静默不跑**"与"跑过了没发现问题"在机器痕迹上**完全一样**（`DEC-061`）。
> 现改为**问文件内容**：`app/` 下的 `.py`，只要出现 `APIRouter(` / `@router.` / `@app.` 就算路由文件
> ⇒ **新建文件自动被覆盖，⛔ 不需要谁记得改清单**。
> ⚠️ **同一个盲区在提交门那侧也犯过**（`DEC-074`：触发取范围而非文件名清单）—— **这是第二次**。

### ①·7 · 🆕 改完 `.py` 当场**编译一次** —— `.claude/hooks/py-compile-remind.py`

**触发**：`PostToolUse` 匹配 `Edit|Write|NotebookEdit`，**且**改的是 `.py`（判据在脚本里）。
**做**：`python3 -m py_compile <那个文件>`，**不过就说**：

```
🔴 **编译不过**：app/xxx.py —— 这个文件现在不是合法 Python。
   （SyntaxError 那几行）
📌 本仓纪律：**「我写进去了」≠「它能用」** —— 判据是【跑一次】，⛔ 不是【我改了】。
```

> **为什么**（`docs/待办总表.md` §五·4 · 出处 `docs/复盘/2026-09-20-docstring里嵌三引号截断了字符串.md`）：
> 那次我在 docstring 里嵌了引号把字符串截断了，**改完没跑任何东西** ⇒ 直到提交前才报出来。
> ⇒ **错误在"写下去"和"被发现"之间躺了很久，而这段时间里它看起来已经做完了。**
> ⚠️ **只编译刚改的那一个文件**（全仓 `compileall` 几秒，单文件几十毫秒）—— 所以它敢挂在**每次编辑后**。
> 😅 **它上线当天就抓到自己的作者**：本文件初稿的 docstring 里嵌了那三个引号 ⇒ 整个文件 `SyntaxError`，
> **是 `scripts/test_remind_hooks.sh` 的 T1 抓出来的**（见下）。
> ⛔ **不管** `venv/` 与 `.claude/worktrees/`（两者都不是本仓源码）。

### ①·8 · 🆕 写「不存在 / 是唯一的」之前的**提醒** —— `.claude/hooks/claim-evidence-remind.py`

**触发**：`PostToolUse` 匹配 `Edit|Write|NotebookEdit`，**且**这次写入里出现了**全称否定**
（`不存在` / `从来没有` / `没有任何` / `都没有` / `是唯一的` / `唯一一X` / `从未`），
**且**全文**找不到一条命令**（⛔ 只认**代码块/行内代码**里的 `grep` / `ls` / `curl` …，散文"我查过了"不算）。
**做**：指出是第几行，并给判据：

```
🟡 **规则 1 提醒** —— `app/billing/specs/breaker.md` 这次写入里有 **2 处全称否定**，但**没看到任何命令**：
   ⇒ 全称否定**没法用「我看到过」证明**，只能靠**穷举** ——
     判据是**一条能打印出来的命令**（`grep -n` / `ls` / `curl`），**把输出贴进结论里**。
```

> **为什么**（`docs/待办总表.md` §五·1 · 出处 `docs/复盘/2026-09-29-结果为空就断言能力不存在.md`）：
> 那天我从「响应里 `answer` 字段是空的」**直接推出三句全称否定**（`/rag/ask` **不存在** …）——
> 🔴 **三句全错**，且**写进了 4 处**（含 **git 提交信息，改不掉**）。**同一天同族又犯了三次。**
> ⇒ 本仓的结论：**这类规矩要【做成命令】，不能只写在文档里**（开发规范 §3.2 末尾原话）。
>
> ⚠️ **专用旁路**：文本里带上「**全称否定**」四个字 ⇒ 静默 ——
> **复盘 / DEC / 规范本来就要引用这些错误原话**，否则每写一次复盘就被提醒一次
> （本仓栽过：**太宽的 grep 会刷出 40 处噪音**）。
> ⛔ **不管** `docs/复盘/` · `CHANGELOG.md` · `.claude/`（前两者是历史记录、**明文不改写**）。

> ### 📌 ①·7 与 ①·8 的**自测** —— `scripts/test_remind_hooks.sh`（**10 条**，~1s）
> ```bash
> bash scripts/test_remind_hooks.sh                      # ⇒ 10 通过 / 0 失败
> ```
> ⛔ **别空跑**：两个 hook 都**只从 stdin 读 hook JSON**，没输入时**静默 exit 0**
> ⇒ 直接 `python3 x.py` 会"全绿"，那是**静默假通过**（本仓 `pre-commit-gates.py` 的前科）。
> ⚠️ **还要在副本里跑一遍**（`mktemp -d` 复制 hooks + 自测）—— macOS 上 `/var` 是 `/private/var` 的软链，
> **真仓绿、副本红**（实测），照出来的正是"按路径前缀的豁免**静默失效**"这种不报错的坏。
> 🔬 **变异自证已做**（改坏 ⇒ 必红 ⇒ 还原）：`has_evidence` 恒 True ⇒ **T6** 红 ·
> `!= 0` 改 `== 0` ⇒ **T2** 红 · 删 `is_file()` ⇒ **T4** 红 · `relpath_of` 退回裸 `relative_to` ⇒ **T9** 红（副本里）。

## 四 · ⚠️ 一条已知的**结构弱点**（业务方 2026-09-29 裁「**甲**」：就这样）

> **这些门本身就在仓里 ⇒ 写它的 Agent 有权限改它。**

```
.claude/hooks/pre-commit-gates.py   ← 能改
scripts/check_secrets.sh            ← 能改
.claude/settings.json               ← 能删
```

**⇒ 理论上，AI 能让自己面前的门失效，而没有任何机制会拦。**

**为什么仍然选「甲」**（业务方裁定）：
* ✅ **能提交进 git ⇒ 可审查**（改了什么看得见）
* ✅ **克隆的人也有门**
* ⚠️ 反面是「乙：放 `~/.claude/`」—— AI 碰不到，但**不入库、别人看不到、也审不了**

📌 **依据**：那份《多项目 + 多 worktree》文档说，方案乙**唯一的理由**是
「**不想让 AI 碰得到约束自己用的规则**」。业务方权衡后**选了甲**。

> ### ⭐ 所以这里有一条**结构性补偿**
>
> **门改没改，是可以用命令查的**：
> ```bash
> git log --oneline -- .claude/ scripts/check_*.sh     # 谁什么时候动过门
> git diff HEAD -- .claude/ scripts/check_*.sh         # 有没有未提交的改动
> ```
> ⇒ **选甲的前提是【改动能被看见】** —— 而不是"相信不会改"。
