# 交接：把这次会话**记下来**，让下次能接上

> 用户可能要休息了。**你的任务不是继续干活，是【让下次的会话能接上】。**
>
> ⚠️ **做完这 6 步再回话。别只说"已记录" —— 要给得出证据。**

---

## 🔴 两条铁律（**本仓用血换的，先读再动手**）

### 铁律 1 · **别看记忆，看 `git`**

「我记得这次改了 X」**不算证据**。先跑命令：

```bash
git status --short
git log --oneline origin/main..HEAD
git diff --stat origin/main..HEAD
bash scripts/check_remote_sync.sh     # ⭐ 「本地是不是真跟远端一致」—— 见铁律 1·补
```

> ⚠️ **上面那三条都是【本地】的账，证明不了"远端也是这个样"** ——
> `origin/main` 是**本地视图**，**上一次 `fetch` 失败时它不会自己声明**。
> ⇒ 真要判"推没推上去"，跑 **`bash scripts/check_remote_sync.sh`**
> （三方比对：本地 / 本地视图 / **远端真值**）。
> 🔴 **它的退出码 `3` = 取不到真值（未知），⛔ 不是通过** —— 别当 0 读。
> 📄 出处：`docs/复盘/2026-09-20-同源的两个输入不能互相作证.md` · `DEC-069`

### 铁律 2 · **数字不要写死 —— 写成命令**

本仓实测：`ROADMAP` 里写过「**8+ 个 commit 未推送**」，而实际是 **15** —— **写死的数字必然过期**。
⇒ 凡是要写"几个 / 多少 / 第几次"，**写那条能算出它的命令**。

---

## 第 1 步 · 先看这次到底改了什么（**别凭记忆**）

跑上面两条铁律里的命令。然后**逐条**问自己：

```
□ 这次有没有【做完但没记】的事？
□ 有没有【等某人一句话】的事？   ← 最容易忘，下次会卡在这
□ 有没有【发现一个坑但没登记】的？
□ 有没有【改了状态但 ROADMAP 没跟上】的？
```

---

## 第 2 步 · 逐类判断「该记到哪」—— **本仓的四本账**

| 本次发生了什么 | **记到哪** | **判据（问自己）** |
|---|---|---|
| **状态 / 进度 / 下一步变了** | ⭐ **`ROADMAP.md`** | 「下次会话**第一眼**该看到的变化」 |
| 做了**选择**（有备选方案） | `docs/decisions/` 下**新起一份** `DEC-nnn` | 「**有没有在多个方案间选过？**」<br>⚠️ 没有 ⇒ 在 commit message 里写明「**本次无决策事项**」 |
| 犯了错 / 发现一个坑 | `docs/复盘/YYYY-MM-DD-<主题>.md` | 「**有没有一条该防重犯的？**」<br>⚠️ **根因不同就分记**，别塞进同一份 |
| **代码/文档的改动** | `CHANGELOG.md` | 「用户能感知的变化」 |
| 一条**新规矩 / 新禁令** | `CLAUDE.md`（必守的）或 `docs/规范/`（完整的） | 「**下次不遵守会出事**」 |
| 新加了文档 | ⭐ **它所在目录的 `CLAUDE.md`**（加一行） | 「**别人找得到它吗？**」（有 `check_doc_orphans.sh` 兜底） |
| 一篇长文档被拆了 | 同步**所有**引用它的人 | ⚠️ **拆完必须逐主题核"内容还在不在"**——本仓 **丢过两次** |

> 📌 **不确定记哪** ⇒ 从**各层 `CLAUDE.md`** 往下找（每层一份索引）；
> 或查 `docs/文档地图.md`（⚠️ 已瘦成指针页，只剩判据 + 欠账清单）。

---

## 第 3 步 · ⭐ 更新 `ROADMAP.md` 的**接续状态**（**最重要的一步**）

**为什么最重要**：它是**唯一的状态权威**，也是下次会话**第一眼**看的东西。
⚠️ 本仓踩过：**锚点停在 09-24，而 09-29 一整天的工作一条没记** ⇒ 下次会话从**过期的锚点**接续。

**至少更新这四块**：

```
□ 🧭 一屏总览 · ④「做到哪了」   —— 阶段变了吗？
□ 🧭 一屏总览 · ⑤「下一步 + 阻塞项」 —— 下一步变了吗？谁在等谁？
□ 📋 待办总账                   —— 做完的划掉了吗？新冒出来的加了吗？
□ 📊 进度留痕表                 —— 对应的行改状态了吗？
```

⛔ **不要把"数字"写进去** —— 见铁律 2。

---

## 第 4 步 · 跑三道门（**别跳过**）

```bash
bash scripts/check_secrets.sh        # ① 凭据门
bash scripts/check_doc_links.sh      # ② 链接检查（改了文档才需要）
bash scripts/check_doc_orphans.sh    # ③ 孤儿检查（加了文档才需要）
```

> ⚠️ **凭据门只扫 `staged` 的新增行** —— 没 `git add` 就跑，会打印「staged 区为空」然后 **exit 0**。
> **那不是"通过"，是"没扫"。**
> 📌 这三道门**也挂在 `.claude/hooks/pre-commit-gates.py` 上**（提交时自动跑）。

---

## 第 5 步 · 提交

```bash
git add -A
git status --short          # ⚠️ 必须重看：每行第 1 列要有字母（= 已暂存）
git commit
```

> ⚠️ **`git stash`/`pop` 会丢索引** ⇒ **提交前必须重看 `git status`**。

---

## 第 6 步 · 回话（**给两样东西**）

### ① 一句结论
`做了什么 / 记到哪了 / 还等谁`

### ② ⭐ 一段「下次从这里接」（**照抄下面这个格式**）

```markdown
## 下次从这里接

**读**：`ROADMAP.md` 第一屏（🧭 一屏总览）

**当前**：(一句话 —— 到哪一步了)
**下一步**：(一句话 —— 具体该干什么)
**卡在**：(等谁 / 等什么 —— 没有就写"无")
**未推送**：`git rev-list --count origin/main..HEAD`   ← ⚠️ 跑命令，别写数字
```

> ⛔ **别只说"记录完成"** —— **要能让用户【照着这段直接接上】。**

## ⚠️ 最后：三条本仓的常见漏记（**照着自查一遍**）

| # | 常漏的 | 今天真发生过 |
|---|---|---|
| 1 | **"等某人一句话"的事** | 从清单里捞回 33 条活待办之前，**没人知道它们还在** |
| 2 | **改了口径但别处没跟上** | `README` 里「三种模式」「真中断」**留了几天没人发现** |
| 3 | **拆/移了文件但引用没全改** | 拆 `CLAUDE.md` 时**丢了 2 处内容 + 1 条死指针** |

**⇒ 这三条各自跑一条命令就能查：**

```bash
# ① 谁在等谁 —— ⚠️ 必须排除【说这句话本身】的地方（索引/复盘/命令自己的说明），
#    否则会刷出 40 处噪音（实测）。只留【活文档里的待裁项】：
grep -rn "⬜ \*\*等业务方\|等业务方逐条裁\|⬜ 未核" --include="*.md" \
  ROADMAP.md docs/说明 docs/契约 fastapi-rag-agent-TODO待办/后端补齐清单*.md \
  | grep -v 归档

# ② 旧口径残留 —— ⚠️ 同理：排除"在说这个词已被删"的地方（否则全是复盘/CHANGELOG）
#    ⚠️ 再排除【规则自己在举例】的那行（CLAUDE.md 的「改口径立刻全仓搜那个词」）
grep -rn "三种模式\|真中断\|支持点击" --include="*.md" . \
  | grep -vE "归档|CHANGELOG|docs/复盘/|docs/decisions/|规范/开发规范|commands/|更正|不成立|原文写|改口径"

# ③ 引用断没断 —— 这条本来就准
bash scripts/check_doc_links.sh
```

> 📌 **这三条命令本身也踩过「结果为空就断言」的坑**（2026-09-29）：第一版**太宽**，
> 刷出 40 处噪音 ⇒ **反而会让人不看**。⇒ **grep 的范围要收到"只看活文档"。**
