# 怎么用这个包（**开新项目时 3 步**）

> 🔴 **整包拷出去就能用** —— `新项目骨架/` 里的文件**已经按"新项目"裁好了**，⛔ 不用改任何代码。
> 📌 **本文的每一步都实测过**（2026-10-10：在 temp 目录建了个假项目跑通，**当天全绿**）。

## 第 1 步 · 建仓

```bash
mkdir -p <新项目目录> && cd <新项目目录>
git init -b main
```

## 第 2 步 · 把「新项目骨架」整份拷进去

```bash
cp -R <本包路径>/新项目骨架/.  <新项目目录>/
```

⚠️ **拷的是 `新项目骨架/` 里面的点(`.`)** —— 那样 `.claude/` `scripts/` `.github/` 会**正好落到新项目根**。
⛔ **别把整个包拷进去**（`怎么用.md` / `移植清单.md` / `CLAUDE.md` 是给你读的，不是给新项目用的）。

> 🔴 **如果新项目已经有 `CLAUDE.md` / `scripts/` / `.claude/`** —— 拷之前先看清楚，
> 这步会**覆盖同名文件**（对本骨架里那几份，是多数的预期行为；但你自己的东西会被盖掉）。

## 第 3 步 · 一条本地命令 + 验一次

```bash
touch .env                                    # ⚠️ 【必须】见下
git add -A && git commit -m "chore: 初始化（可移植骨架）"

# 🔴 验一次 —— 装完就跑，**看到它绿**，才知道门是活的
bash scripts/check_layered_claude_md.sh              # ⇒ exit 0
bash scripts/check_layered_claude_md.sh --self-test  # ⇒ 5 通过 / 0 失败
bash scripts/check_doc_links.sh                      # ⇒ 0 断链
bash scripts/check_doc_orphans.sh                    # ⇒ 0 孤儿
python3 scripts/check_ci_job_timeouts.py             # ⇒ 1 个 job 全带超时
```

### ⚠️ 为什么必须 `touch .env`

**凭据门**（`scripts/check_secrets.sh`）要拿 `.env` 当**比对基准**；没有它 ⇒ **`exit 2`** ⇒
按本仓约定那是**「判不了」**，hook 会把它当**失败** ⇒ **你的第一次提交会被挡住**。
- ⛔ **`.env` 不会随仓下来**（它在 `.gitignore` 里，**故意的** —— 那里面装的是密钥）
- ✅ 所以这一步**只能本机做**，一条 `touch` 就够（空文件也过；之后往里填真值）
- 📄 另一种走法：设 `SECRETS_GATE_ALLOW_NO_ENV=1` ⇒ 门会**降级为部分覆盖**并在结论行**写明**
  ⚠️ 但它**不会**和真凭据逐字比过 —— 别把"通过"读成"查干净了"

## 你会得到什么

```
<新项目>/
├── CLAUDE.md                     ← 🔴 **叫 CLAUDE.md，⛔ 不用改名**（里面有 3 处 <占位> 要填）
├── .claude/
│   ├── CLAUDE.md
│   ├── settings.json             ← **hooks 在这里注册**（⚠️ 放盘上不注册 = 没装）
│   └── hooks/
│       ├── CLAUDE.md
│       ├── pre-commit-gates.py         ← 提交前的门（**骨架版：启用 4 道**）
│       ├── claim-evidence-remind.py    ← 写「不存在 / 唯一」前先出一条命令
│       └── py-compile-remind.py        ← 改完 .py 当场编译一次
├── .github/
│   ├── CLAUDE.md
│   └── workflows/
│       ├── CLAUDE.md
│       └── ci.yml                ← CI 骨架：把四道门接进去（⚠️ 不接 CI 就不是门）
└── scripts/
    ├── CLAUDE.md
    ├── check_layered_claude_md.sh          ← ⑧ 每个目录层都必须有 CLAUDE.md（+ `--self-test`）
    ├── check_doc_links.sh                  ← ② 文档里不许有指向不存在路径的引用
    ├── check_doc_orphans.sh                ← ③ 建了文档但没人指向它
    ├── check_secrets.sh                    ← ① 明文凭据不许进仓
    ├── check_ci_job_timeouts.py            ← 每个 CI job 必须有超时
    ├── doc-links-ignore.txt                ← 断链门的豁免清单（⚠️ **骨架里已带一条**：`~/.claude/`）
    └── secret-denylist.txt.template        ← 凭据黑名单（空模板；重命名成 `.secret-denylist`）
```

## 🔴 启用了几道门 / 没启用哪几道

| 门 | 状态 | 为什么 |
|---|---|---|
| ① 凭据 · ② 链接 · ③ 孤儿 · ⑧ 分层CLAUDE | ✅ **已启用** | **与语言 / 框架无关** —— 只依赖 `git` 和 `.md` |
| ④ 模块 spec · ⑤ 路由鉴权 · ⑥ 静态检查 · ⑦ 过期导入 | ⬜ **未启用**（hook 里显示 `⏭ 未启用`） | ✅ **强相关源项目**（`app/` 容器 · FastAPI · ruff · Python 导入）<br>⇒ 🔴 **照搬过来它们【永远不触发】** ⇒ 变成**一道恒绿的门** —— **恒绿的门 = 没有门** |

⇒ 等你长出对应的形状（模块约定 / 路由 / 语言基线），**再各造各的**。📄 详见 `移植清单.md` §一。

## ⚠️ 三件**别做**

1. ⛔ **别一开始就照搬七组目录** —— 源项目是**长到 60 个模块**才拆的；体量小的时候拆组是**过度设计**
   ⇒ **机制从第一天就有；分组等到该分的时候再分**
2. ⛔ **别用 `@import` 减重** —— 官方实测：**导入的文件照样在启动时全量加载**，不省上下文
3. ⛔ **别让规矩只活在文字里** —— 写一条，同批问「**它该由哪道门执守？**」
