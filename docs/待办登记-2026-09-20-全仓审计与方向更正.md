**从代码上看不出来**（"白名单里没有异常类"是**沉默的** —— 没人会去数那 40 个名字缺了什么）。
⇒ 它会直接影响「**LLM 写出来的代码能不能跑**」。

**为什么没修**：放开异常类 = **改沙箱的安全边界** ⇒ 必须业务方裁。
（评估要点：异常类本身**不提供逃逸能力**，放开它们大概率是安全的；但与"最小权限"原则有取舍。）

**3.9 ~~N16 · 令牌桶不回填~~ 🔴 已撤回 —— 我核错了，它不是 bug**（2026-09-20）

**原报**：`rate_limiter.py` 的 `get_quota_info()` 读出了 `last_time` 却从不用它回填 ⇒ **桶可能永不恢复**。

**撤回理由（核了限流的消费入口 `is_allowed()`）**：**回填在 Lua 脚本里，而且是对的**：

```lua
local elapsed = now - last_time
local new_tokens = math.floor(elapsed * rate)
tokens = math.min(capacity, tokens + new_tokens)     -- ← 回填在这里
```

⇒ `get_limit_info()` / `get_quota_info()` 是**只读的展示函数**，它算
`reset_time = now + (need / rate)` —— 那个式子**也是对的**（从"现在"起还需 `need/rate` 秒）。
它那个 `last_time` **只是个没用上的局部变量**，**不是"不回填"**。

📌 **教训（本会话第 N 次同型）**：我在 **D1 里只看到"有个变量没用"**，就顺推成"桶不回填"——
**那是从"一个局部现象"跳到"一个系统级结论"，中间没核消费入口**。⇒ 已就地撤回，并把那个死变量删掉（D1 归零）。

⚠️ **保留的教训价值**：这条正好说明**"未使用变量"不等于"功能缺失"** ——
`last_time` 没用上，是因为**真正用它的地方在另一个函数（而且是在 Lua 里）**。
