## 一 · 认证契约

**两种方式，二选一**（`api/deps.py` 的 `get_current_user_hybrid`：**先试 API Key，无则回退 JWT**）。

| 方式 | 怎么带 | 说明 |
|---|---|---|
| **API Key** | 请求头 `X-API-Key: <key>` | 库里存的是 **SHA256 哈希**（`api_keys.key_hash`），不是明文 |
| **JWT Bearer** | 请求头 `Authorization: Bearer <token>` | HS256。**access 15 分钟** / **refresh 7 天** |

> ⚠️ **一条实现细节，调用方会撞到**：`HTTPBearer(auto_error=False)` ——
> 若为默认的 `True`，**缺少 `Authorization` 头时会在依赖解析阶段直接 403**，
> 导致**纯 API Key 调用全部失效**（2026-08-17 修复记录 #6）。
> ⇒ **现在两种方式可以独立使用。**

### 拿 token

```
POST /api/v1/auth/login     { "user_name": "...", "password": "..." }
  → 200 { access_token, refresh_token, ... }

POST /api/v1/auth/refresh   { refresh_token }
  → 200 { access_token, ... }
```

### 角色与配额

| 角色 | 每日调用次数 | 每日 token 预算 | 怎么来的 |
|---|---|---|---|
| `admin` | 不限 | 不限 | 用户名写死 `admin` |
| `premium` | 10 000 | 100 000 | 用户名写死 `test_user` |
| `free` | 100 | 10 000 | **其余全部** |

> 🔴 **角色映射是【按用户名硬编码】的**（`api/permission.py:18-29`），**不是查库**。
> ⇒ **任何新账号都落到 `free`**。这条的修法属 `ROADMAP.md` 的 **R1.3**（见「已知缺口」）。

## 二 · 响应契约

### 成功

**没有统一包装** —— 各端点直接返回业务对象（dict）。
⚠️ **`/rag/search` 这类检索端点，`answer` 字段默认【不存在】**，见 §四。

### 失败 —— **统一结构**（`api/main.py:325-334`）

```json
{
  "error": "人类可读的消息",
  "code": "ERROR_CODE",
  "status_code": 429
}
```

> ⚠️ **中间件层是例外**：限流/配额中间件**直接返回 `JSONResponse`**，
> 且**配额那条会多一个 `extra` 字段**：
> ```json
> { "error": "...", "code": "QUOTA_EXCEEDED", "status_code": 429,
>   "extra": { "role": "free", "daily_limit": 100, "remaining": 0 } }
> ```
> **为什么中间件不一样**：FastAPI 的 `@app.exception_handler(AppException)` **只捕获路由层**的异常；
> 中间件里 `raise AppException` 会落到通用处理器变成 **500**。⇒ 中间件必须直接返回 `JSONResponse`。

### 限流 / 配额的**响应头**（恢复时间在这里，**不在 body 里**）

| 头 | 出现在 |
|---|---|
| `X-RateLimit-Limit` · `X-RateLimit-Remaining` · `X-RateLimit-Reset` | 限流 429 |
| `X-Quota-Limit` · `X-Quota-Remaining` · `X-Quota-Reset` | 配额 429 |

> 🔴 **已知缺口**：**body 里没有 `retry_after` 字段**（全仓 grep 0 命中）。
> `施工单 §8.1` 的 **R3.1** 要求「可识别错误码 **+ 恢复时间**」⇒ **只满足一半**。修法见 `ROADMAP.md`。

## 三 · 错误码表（**全 15 个** · 出处 `api/exceptions.py:11-57`）

| 错误码 | HTTP | 什么时候出现 |
|---|---:|---|
| `UNKNOWN` | 500 | 兜底 |
| `INTERNAL_ERROR` | 500 | 未预期异常 |
| `SERVICE_UNAVAILABLE` | 503 | `/ready` 未就绪、依赖不通 |
| `PARAM_INVALID` | 422 | 参数非法（**含 `mode` 传了枚举外的值**） |
| `PARAM_MISSING` | 422 | 缺必填参数 |
| `AUTH_MISSING` | 401 | 没带凭据 |
| `AUTH_INVALID` | 401 | 凭据无效 |
| `AUTH_EXPIRED` | 401 | token 过期 |
| `AUTH_WRONG_TYPE` | 401 | 认证类型不对 |
| `FORBIDDEN` | 403 | 权限不足 |
| `RESOURCE_NOT_FOUND` | 404 | 资源不存在 |
| `RESOURCE_CONFLICT` | 409 | 冲突（如重复创建） |
| **`RATE_LIMITED`** | **429** | 触发**频率**限流 |
| **`QUOTA_EXCEEDED`** | **429** | 触发**每日配额 / token 预算** |
| `EXTERNAL_API_ERROR` | 502 | 上游（DashScope / DeepSeek）出错 |

> 📌 **两个 429 要分清**：`RATE_LIMITED` = **太快**（等几秒）；`QUOTA_EXCEEDED` = **用完了**（等跨天）。

## 四 · ⚠️ 三个**调用方最容易踩**的点

### 1. `generate_answer` 与 `citations` **默认都是 `false`**

`POST /rag/search` 的请求体（`api/schemas.py:9-20`）：

| 字段 | 默认 | 说明 |
|---|---|---|
| `question` | **必填** | |
| `top_k` | `3` | 范围 `1–20` |
| `mode` | `"accurate"` | ⚠️ **受限枚举**，见下 |
| **`generate_answer`** | **`false`** | 🔴 **不设 `true` ⇒ 只返回 `docs`，没有 `answer`** |
| **`citations`** | **`false`** | 🔴 **不设 `true` ⇒ 不会有 `[来源:n]` 引用** |
| `strict_mode` | `false` | 仅 `generate_answer=true` 时有效 |
| `conversation_history` | `[]` | `[{"role": "user"/"assistant", "content": "..."}]` |

> 📌 **本仓自己在 `docs/demos.md:53-54` 就写着**：
> 「**这是最容易在演示时翻车的点。**」
> 🔴 **2026-09-29 因此栽过一次** —— 见 `docs/复盘/2026-09-29-结果为空就断言能力不存在.md`。

### 2. `mode` 是**受限枚举**，传错会 **422**（不会静默兜底）

实际 **4 种**（`api/api_v1_rag.py:467-476`）：

| mode | 含 BM25 | 查询改写 | 查询扩展 | 重排序 | 依赖 torch |
|---|:--:|:--:|:--:|:--:|:--:|
| `fast` | ✅ | ✗ | ✗ | ✗ | ✗ |
| `accurate` | ✅ | ✅ | ✗ | ✅ | ⚠️ |
| **`accurate_norerank`** ⭐ | ✅ | ✅ | ✗ | ✗ | ✗ |
| `full` | ✅ | ✅ | ✅ | ✅ | ⚠️ |

> ⚠️ **默认值是 `accurate`**（`schemas.py:13`），但它**需要 torch**（重排序）。
> ⇒ **镜像里没装 torch 系**（`DEC-034`）⇒ **容器里请显式传 `accurate_norerank`**。
> ⛔ **`fast` 不是"只查向量"** —— 它**含 BM25 + RRF 融合**。

### 3. **流式端点只有 `/rag/stream_search`**

SSE（`text/event-stream`），**全仓唯一**。⛔ **Agent 的 28 个端点全部非流式**（硬门 A 缺口）。
⚠️ 另有 2 条 **WebSocket**（`/api/v1/ws/agent` · `/api/v1/ws/test`）——
**它们不在 OpenAPI 里**（规范不支持 WS）⇒ **`list_endpoints.sh` 的 57 条不含它们**。

## 七 · 已知缺口（**调用方会撞到，且已有记录**）

| # | 缺口 | 影响 | 出处 |
|---|---|---|---|
| 1 | **body 无 `retry_after`** | 客户端只能读响应头 | `后端补齐清单` **B12** |
| 2 | **限流对匿名：全员共用一个桶**（不按 IP） | 一个爬虫打满 ⇒ 全体匿名 429 | `后端补齐清单` **B9** |
| 3 | **配额对匿名：完全跳过** | 匿名可无限打 | 同上 |
| 4 | **`X-API-Key` 分支不验签**（只取前 8 字符做桶名） | **伪造 key 可拿独立桶** | 同上（§四-①） |
| 5 | **Agent 端点无流式** | 硬门 A 未补 | `后端补齐清单` **B1** |
| 6 | **四条 429 文案里有一条说反了** —— 全局限流返回 `"error": "Internal server error"` | **对方以为系统坏了** | `后端补齐清单` **B12** |

> 🔴 **1–6 全部登记在** `ROADMAP.md` 的「待办总账」（🅐 当前阶段的活）**，属"后端先行"阶段**。
