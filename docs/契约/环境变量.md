# 环境变量 · 契约

> ## 这份文档是什么
>
> **本项目全部环境变量的权威清单。** 换了机器、新克隆下来、要改配置 —— **只看这一份**。
>
> **权威源**：`api/config.py`（⭐ 集中管理）+ 6 处散落的 `os.getenv`（见 §三，**那是已知的不一致**）。
> **模板**：仓根 `.env.example`（⚠️ **它现在缺 4 个键**，见 §四）。
> **实际值**：仓根 `.env`（**⛔ 不入库**，见 `.gitignore`）。

## 三 · ⚠️ 已知不一致：**5 个模块绕过了 `config.py`**

**本仓规矩**（`CLAUDE.md`）：「所有需要 Redis 连接的模块都应**从 `config.py` 导入**……
不要直接用 `os.getenv` 读取，否则本地/Docker 切换会不一致。」

**实测：规矩被违反了 5 处**（🔴 **是代码问题，不是文档问题；真要修另开一轮**）：

| 位置 | 读的键 | 风险 |
|---|---|---|
| `api/agent_checkpointer.py:119` | `AGENT_CHECKPOINT_BACKEND` | 低（无本地/Docker 差异） |
| `api/main.py:557` | `ENABLE_DASHBOARD` | 低 |
| `api/token_tracker.py:283` / `:646` / `:649` | `DEFAULT_DAILY_TOKEN_BUDGET` · `MAX_SINGLE_CALL_COST` · `MAX_THREAD_COST` | 低（同上） |
| `api/evaluate_with_ragas.py:30-32, 45-47, 66` | `EVAL_API_BASE_URL` · `LOGIN_*` · `LLM_*` · `DASHSCOPE_API_KEY` | ⚠️ **中** —— 它是 CLI 脚本，**不走 `config.py` 的 `validate_config()`**，缺键不会快速失败 |
| `api/memory_store.py:33` | `DASHSCOPE_API_KEY` | ⚠️ **中** —— 同上，且它**没有走 `config.py` 的 `IS_DOCKER` 覆盖** |

> 📌 **上面这些键都【不在】`config.py` 的 `validate_config()` 里** ⇒ **缺了不会拒绝启动，只会静默生效默认值**。
> ⇒ **排查"配置没生效"时，先看这一张表。**

## 四 · `.env.example` 的核对（**含一处【本文件自己犯过的错】**）

> 🔴 **2026-09-29 更正**：本文件初稿写「`.env.example` **缺 4 个 `LLM_*` 键**」—— **那是错的**。
> 错因：我用 `grep -oE '^[A-Z_]+='` 统计，**那个模式不匹配注释行**，
> 而那 4 个键**恰好是注释形式**（因为它们可选）⇒ **我数出了"没有"**。
> 📌 **这正是本仓 2026-09-29 复盘里那条错的【同一族】** ——
> 「**拿一个空结果当能力/事实不存在**」，见 `docs/复盘/2026-09-29-结果为空就断言能力不存在.md`。
> ✅ **正确判据**：统计键名要 `grep -oE '^#?\s*[A-Z_]+='`（**把 `#` 也算上**）。

**实测（把注释行也算上）**：`.env.example` **有全部 20 个键** ✅ —— 包括注释形式的 4 个 `LLM_*`。
而且那段注释**写得是对的**：「切 DeepSeek 官方等 OpenAI 兼容端点，填下面三组键
（**embedding 仍走 DASHSCOPE，不受影响**）」。

### ⚠️ 真正剩下的两处（都是小问题）

| # | 项 | 事实 | 该怎么办 |
|---|---|---|---|
| 1 | **`RERANKER_MODEL_NAME`** | **全仓 0 引用**（`grep -rn RERANKER_MODEL_NAME api/` = 0）—— 模型名**硬编码在 `api/reranker.py:17`** | 删掉这个键，或改成真读它。⬜ **待裁** |
| 2 | **`DB_MAX_CONN`** | `.env.example` 与 `.env` **都是 `20`**，而 `api/config.py:78` 的**代码默认是 `30`** | ⚠️ 无害（部署值覆盖了），但**三个地方三个数**容易看混。⬜ **建议统一** |

> 📌 **一处仍然值得提醒**（不是缺陷，是**认知陷阱**）：
> 那 4 个 `LLM_*` 键**注释着 = 可选**，**不填就会静默回落到 DashScope 的 qwen**
> （`api/config.py:52-55` 的 `or` 与默认值）。
> ⇒ **这不是 `.env.example` 的错**，但**排查"LLM 打错地方"时第一个要查的就是它**。

## 五 · 排查「配置没生效」的顺序

```bash
# ① 先确认键在不在（只看键名，别打印值）
grep -oE '^[A-Z_]+=' .env | tr -d '='

# ② 再确认必填 4 个都非空（validate_config 会替你查，这里只是手查）
for k in DASHSCOPE_API_KEY POSTGRES_PASSWORD JWT_SECRET_KEY LOGIN_PASSWORD; do
  grep -q "^${k}=.." .env && echo "  ✅ ${k}" || echo "  🔴 ${k} 缺失或为空"
done

# ③ 确认 .env 在【仓根】而不是 api/
ls -la .env

# ④ 容器里的话，确认 DOCKER_ENV=true（否则 PG/Redis 会去连 localhost）
docker compose exec api printenv DOCKER_ENV
```

> ⛔ **全程不打印凭据值** —— 只看键名与"是否为空"。
