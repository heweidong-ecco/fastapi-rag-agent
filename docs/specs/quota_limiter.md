# `api/quota_limiter.py`

| 项 | 内容 |
|---|---|
| **状态** | 🟡 **可用，但匿名请求完全绕过它** |
| **对外提供** | `QuotaLimiter.increment_and_check()` · `get_remaining()` · `get_quota_info()` |
| **谁在用** | `main.py` 的 `QuotaMiddleware`（`:187-268`） |

## ✅ 做了什么

- **按【用户】【每日】计数** —— Redis key = `quota:{user_name}:{YYYY-MM-DD}`，`INCR` + 首次 `EXPIRE 86400`（Lua 原子）
- 额度来自 `permission.ROLE_QUOTA`（free 100 / premium 10000 / admin 不限）

## 🟡 做到哪 / 缺什么

- 🔴 **匿名请求完全绕过**（见下）
- 🔴 **没有"全局日级"这一层** —— 每个方法第一个参数都是 `user_name`，**没有任何跨用户记账键**
  ⇒ **第 4 层限额不存在 ⇒ 熔断无对象可触发**
- ⬜ **零测试覆盖**（`docs/说明/测试.md` §六 **#8**）
- ⬜ **R2.2 恢复条件未核** —— `EXPIRE 86400` 是**首次 INCR 时**设的（滚动），**没人实测过 TTL**

## ⚠️ 看代码会误判的地方 ⭐

| 看代码会以为 | 实际 |
|---|---|
| 「有配额中间件 ⇒ 所有人都受限」 | 🔴 **`main.py:222` 是 `if user_name:`，没有 `else`** ⇒ **匿名请求落到 `:262` 直接放行，完全绕过配额** |
| 「`EXPIRE 86400` 与 key 里的日期不一致 ⇒ 可能是 bug」 | 🟢 **不是 bug**（2026-09-29 核过）：**key 名含日期 ⇒ 换日即换 key ⇒ 配额确实按日历日重置**；`EXPIRE` 只是**清理孤儿键** |
| 「限流和配额是一回事」 | 🔴 **不是** —— **限流管频率**（`rate_limiter.py`），**配额管每日次数**（本文件）。<br>⚠️ **只限流不熔断 ⇒ 账单照样失控** |
