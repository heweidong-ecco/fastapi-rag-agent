  - 旧口令 `mysecretpassword` → **`FATAL: password authentication failed`** ✅ **旧凭据确已失效**
  - 新口令 → 成功 ✅
- 应用层(`config` 读 `.env`)→ 连库正常,`documents` 70 行 ✅

> ### ⚠️⚠️ 验证口令时最容易犯的错(我第一轮就犯了这个)
>
> **在容器内连 `127.0.0.1` 是测不出效果的。** 该容器的 `pg_hba.conf` 是:
> ```
> local  all  all                 trust           ← socket
> host   all  all  127.0.0.1/32   trust           ← ★ 本机回环 TCP:免口令
> host   all  all  ::1/128        trust
> host   all  all  all            scram-sha-256   ← ★ 其他来源:要口令
> ```
> 我第一轮在容器内 `psql -h 127.0.0.1`,**新旧两个口令都连上了** —— 一度以为"口令没被校验、配置坏了"。
> **实际是走在了 `trust` 那条路上。**
>
> **正确测法:从另一个容器(或另一台机器)连**,源地址非回环才会命中 `scram-sha-256`:
> ```bash
> docker run --rm --network my-fixed-name_app-net -e PGPASSWORD='<被测口令>' \
>   pgvector/pgvector:pg17 psql -h postgres-rag -U postgres -d rag_db -c 'SELECT 1'
> ```

**两个动作的耦合关系(决定执行顺序)**:

| 动作 | 对 `agent-eval-gate` 的 `rag-api-eval` 容器的影响 |
|---|---|
| **改口令** | ⛔ **会断** —— 它的 env 在创建时固化(`run_sut.sh:47` 的 `--env-file`),改 `.env` 不生效,必须**重建该容器** |

**⚠️ 关键坑:改 `.env` 不会改库里的口令。** Postgres 只在**首次初始化数据卷**时读取 `POSTGRES_PASSWORD`;卷已存在就必须显式改:

```bash

# 2. 改本地 .env（本地文件，不入库）
#    POSTGRES_PASSWORD=<新口令>

# 3. 重启 api 让它用到新口令
docker compose restart api     # 或 docker restart rag-api
```

      - "127.0.0.1:5432:5432"

## 5. `JWT_SECRET_KEY` 的形状不对(⬜ 待办,建议项)

**不是泄露**,是配置异味:`.env` 里的 `JWT_SECRET_KEY` 是 **169 字符、以 `eyJhbG` 开头** —— `eyJhbG` 是 JWT 的 base64 头。**这看起来是把某个 token 本身填进了"密钥"字段**,而不是一段随机密钥。

能用(签名不挑内容),但密钥不该是这个形状 —— 它可能来自某处复制粘贴,而那个来源的 token 若是别处签发/可见的,等于密钥可推导。

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
```

> ⚠️ **副作用**:换掉 `JWT_SECRET_KEY` 会让**所有已签发的 access/refresh token 全部失效**,用户需重新登录。这是预期行为。

## 6. 必须记住的一条:轮换改变不了历史

**轮换的作用是"让已经泄露出去的那一份失效",不是"让它消失"。**

这些凭据在 `git log`、GitHub 上的克隆、任何已 fork 的仓库里**仍然存在**:

| 凭据 | 从哪个 commit 开始就在 |
|---|---|
| 登录口令 | `ecb146b`(首次提交) |
| Postman 里那把死值 Key | `ecb146b`(首次提交) |
| Postgres 口令 | `ecb146b` + `2c1a922` |

**要不要清 git 历史(`git filter-repo` 重写历史)是另一个决定** —— 成本高(会打乱所有克隆、所有 fork 的 SHA),多数团队的选择是"**轮换 + 接受历史里的旧凭据已废**"。本项目当前取这一条。
