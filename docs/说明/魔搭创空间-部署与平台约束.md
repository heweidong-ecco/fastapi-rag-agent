## 一 · 前置条件

### 1.1 账号

- 🔴 **Docker 类型必须先完成阿里云账号绑定 + 实名认证** —— 否则镜像**建不起来**。🟢
  见 `https://modelscope.cn/docs/studios/docker`
- ⚠️ **付费硬件**（`paid/<InstanceType>`）会**扣你绑定的阿里云账号的钱**。
  🟢 **官方要求：用付费资源之前必须明确告知用户并拿到明确授权。** ⛔ 别默默选。

### 1.2 Token

```bash
export MODELSCOPE_ENDPOINT='https://modelscope.cn'   # 国际站是 https://www.modelscope.ai
export MODELSCOPE_API_KEY='<你的 token>'
```

拿 token：浏览器打开 `${MODELSCOPE_ENDPOINT}/my/myaccesstoken`。

> 🔴 **`MODELSCOPE_ENDPOINT` 与 token 是【站点绑定】的** —— 国内站的 token 拿去国际站不认。🟢
>
> 🔴 **这条 token 是敏感凭据**：它同时用于 **OpenAPI 鉴权 / git push / 变量配置**三处。 🟢
> ⛔ **别提交进任何 git**、⛔ **别贴进对话/日志**。
> ⚠️ 尤其：下面「同步代码」那一步会把 token **写进 `.git/config` 的 remote URL 里** —— **用完记得删**。

判据（**只看长度，不回显内容**）：

```bash
echo "token 长度: ${#MODELSCOPE_API_KEY}"
```

## 二 · 完整流程（命令级）

> 每一步先给 OpenAPI（**唯一真值来源**），CLI 只是等价别名。
> `${owner}` / `${repo}` 是 Studio 的属主与名字。

### 第 1 步 · 本地已经是 git 仓了吗

```bash
[ -d .git ] && git remote -v 2>/dev/null | grep -E 'modelscope\.(cn|ai)/studios'
```

- 有 · Studio remote ⇒ **从 URL 里取出 `owner` / `repo`，直接跳第 3 步**
- 没有 ⇒ 继续

### 第 2 步 · 定 SDK 类型 + 拿 owner

| 类型 | 判定条件 | 入口文件 | 备注 |
|---|---|---|---|
| `gradio` | `app.py` 里 import gradio | `app.py` | |
| `streamlit` | `app.py` 用 streamlit | `app.py` | |
| **`docker`** | **有 `Dockerfile`** | `Dockerfile` | 🔴 **端口必须 7860** |
| `static` | 有 `index.html`（**已构建**） | `index.html` | ⚠️ **不支持构建步骤** |

> **拿不准就用 `docker`。** 🟢 需要构建的前端项目也只能用 `docker`。

```bash
curl -s "${MODELSCOPE_ENDPOINT}/openapi/v1/users/me" \
  -H "Authorization: Bearer ${MODELSCOPE_API_KEY}"
```

🔴 **⛔ 别取错字段** —— `/users/me` 一次返回好几个像"用户名"的东西：

| 字段 | 是什么 | 能不能当 `owner` |
|---|---|---|
| **`data.username`** | **平台用户名** | ✅ **就是它** —— Studio URL 里的那一段 |
| `data.nickname` | 显示名 | ⛔ **可能含中文/空格** ⇒ 当路径会挂 |
| 别的平台的登录名（如 GitHub 名） | **另一个命名空间** | ⛔ **本平台不认** |

> ⚠️ 例外：Studio 若建在**组织**下，`owner` 填**组织名**，不是你的用户名。

### 第 3 步 · 先查可选硬件（⛔ 别硬编码）

```bash
curl -s "${MODELSCOPE_ENDPOINT}/openapi/v1/studios/hardware?sdk_type=docker" \
  -H "Authorization: Bearer ${MODELSCOPE_API_KEY}"
```

- 取返回项里的 **`name`** 当 `hardware`
- 🔴 **`resource_type == paid` 的别选** —— 见 §1.1
- 🟢 已有 Studio 时，可加 `&studio=${owner}/${repo}` ⇒ 按该 Studio 的额度返回

### 第 4 步 · 建 Studio（或改设置）

先查在不在：

```bash
curl -s "${MODELSCOPE_ENDPOINT}/openapi/v1/studios/${owner}/${repo}" \
  -H "Authorization: Bearer ${MODELSCOPE_API_KEY}"
```

**不在 ⇒ 建**（🟢 官方建议先问用户 public 还是 private，**默认 private**）：

```bash
curl -s -X POST "${MODELSCOPE_ENDPOINT}/openapi/v1/studios" \
  -H "Authorization: Bearer ${MODELSCOPE_API_KEY}" \
  -H "Content-Type: application/json" \
  -d "{\"owner\":\"${owner}\",\"repo_name\":\"${repo}\",\"sdk_type\":\"docker\",\"visibility\":\"private\",\"hardware\":\"${HARDWARE}\",\"display_name\":\"<显示名>\"}"
```

**已在 ⇒ 改设置**：

```bash
curl -s -X PATCH "${MODELSCOPE_ENDPOINT}/openapi/v1/studios/${owner}/${repo}/settings" \
  -H "Authorization: Bearer ${MODELSCOPE_API_KEY}" -H "Content-Type: application/json" \
  -d '{"visibility":"public"}'
```

> 🟢 改 `sdk_type` / `sdk_version` / `base_image` / `hardware` **要重新 deploy 才生效**。
> **建完立刻记住返回里的 `id`**（形如 `owner/repo`）—— 后面所有端点都要它。

### 第 5 步 · 同步代码 ⚠️ **全流程唯一不走 API 的一步**

```bash
# ① 分支必须是 master（平台只认它）
if [ -d .git ]; then git branch -M master; else git init -b master; fi
git branch --show-current          # ★ 判据：必须打印 master

# ② remote —— ⚠️ 这条 URL 里带着 token，会被写进本目录 .git/config
git remote remove modelscope 2>/dev/null || true
MS_HOST="${MODELSCOPE_ENDPOINT#https://}"
git remote add modelscope "https://oauth2:${MODELSCOPE_API_KEY}@${MS_HOST}/studios/${owner}/${repo}.git"

# ③ 先本地提交
git add -A && git commit -m "<你的提交信息>"

# ④ 拉远端并合并（⚠️ 远端【不是】空仓，见下）
git fetch modelscope master
git merge modelscope/master --allow-unrelated-histories -m "Merge Studio 初始骨架"

# ⑤ ★ 只有 ④ 报 CONFLICT 时才跑
git checkout --ours -- README.md   # --ours = 保留本地那版
git add -A && git commit -m "Merge Studio 初始骨架"

# ⑥ 推
git push -u modelscope master
```

> ### 🔴 **首次 push 必被拒 —— 这是【必然】，不是【可能】** 🔵
>
> **建 Studio 时平台自带一个 `README.md`** ⇒ 远端**不是空仓** ⇒ 本地那版与它
> **`add/add` 冲突** ⇒ ④ 停住 ⇒ ⑥ 报 `! [rejected] ... (non-fast-forward)`。
>
> **修法就是上面 ⑤** —— ⛔ **平台禁止强推，只能把合并做完**。
>
> ⚠️ **判据纪律**：⛔ 别把「fetch 失败」和「合并冲突」塌成同一条错误消息
> —— 那会让你在 push 被拒时以为"是远端空"。**这是两个不同的错，修法相反。**

> 🟢 **>100 MB 的文件必须走 Git LFS**（`git lfs install`），否则推不上去。
> **默认分支 `master`，禁止 force push。**

### 第 6 步 · 注入环境变量 / 密钥

🟢 **明文变量**（`variables`）**会返回 value** ⇒ 只放**非敏感**配置。
🟢 **密钥**（`secrets`）**只返回 key，不返回值** ⇒ 放 API key / token / 密码。

```bash
# 明文变量
curl -s "${MODELSCOPE_ENDPOINT}/openapi/v1/studios/${owner}/${repo}/variables" \
  -H "Authorization: Bearer ${MODELSCOPE_API_KEY}"
curl -s -X POST "${MODELSCOPE_ENDPOINT}/openapi/v1/studios/${owner}/${repo}/variables" \
  -H "Authorization: Bearer ${MODELSCOPE_API_KEY}" -H "Content-Type: application/json" \
  -d '{"key":"MY_CONFIG","value":"<非敏感值>"}'

# 密钥
curl -s -X POST "${MODELSCOPE_ENDPOINT}/openapi/v1/studios/${owner}/${repo}/secrets" \
  -H "Authorization: Bearer ${MODELSCOPE_API_KEY}" -H "Content-Type: application/json" \
  -d '{"key":"MY_API_KEY","value":"<敏感值>"}'
```

> 🔴 **删除的姿势和你想的不一样**：要用 `DELETE .../variables`（或 `/secrets`）
> 并把 `{"key":"..."}` 放在 **body** 里 —— ⛔ **不是** `DELETE .../{key}` 这种路径形式。 🟢

### 第 7 步 · 部署

```bash
curl -s -X POST "${MODELSCOPE_ENDPOINT}/openapi/v1/studios/${owner}/${repo}/deploy" \
  -H "Authorization: Bearer ${MODELSCOPE_API_KEY}"
```

### 第 8 步 · 看状态与日志

```bash
# docker 类型：先看 build，build 过了再看 run
curl -s "${MODELSCOPE_ENDPOINT}/openapi/v1/studios/${owner}/${repo}/logs/build" \
  -H "Authorization: Bearer ${MODELSCOPE_API_KEY}"
curl -s "${MODELSCOPE_ENDPOINT}/openapi/v1/studios/${owner}/${repo}/logs/run" \
  -H "Authorization: Bearer ${MODELSCOPE_API_KEY}"
```

🟢 **一直交替看到 `Running` 或报错为止。** 首次 Docker 构建约 **3–5 分钟**。

> **应用的真实地址**：`GET /studios/{owner}/{repo}` 返回里的 **`host`**（形如
> `https://<owner>-<repo>.ms.show`）🔵 —— **不必去网页里找「访问」按钮**。

> ### 🔴 **别拿「接口返回 200」当「跑起来了」** 🔵
> `deploy` 返回成功 **≠** 容器起来了。🔵 实测：build 日志会**停在 `RUN pip install` 中间**、
> run 日志返回 `{"logs":[],"total_count":0}` —— **每一步都"成功"，而应用根本没起**。
> **判据只能是：`host` 打得开、页面真的渲染出来。**

### 收尾 · 清理 token

```bash
git remote remove modelscope
```

## 三 · 🔴 平台硬约束（**设计之前就该读**）

这一节的每一条都能让**架构层面的选择**作废 —— ⛔ **别等写完代码才知道**。

### 3.1 一个 Studio = **一个容器** 🔵

⇒ 🔴 **塞不进老式的「Web 进程 + 数据库进程 + 缓存进程」多容器架构**。
自行评估：**进程能不能合进一个镜像**、**数据库能不能换个形态**（嵌入式文件库？外部托管？）。

### 3.2 端口只能 `0.0.0.0:7860` 🟢

`8080` **被平台占用**，官方明文禁止。⚠️ 这是**写死**的，不是"默认值"。

### 3.3 HTTP 头禁用三类 🟢

`Authorization` · `X-modelscope-*` · `X-studio-*`

### 3.4 🔴🔴 平台会往**每个请求**注入一个 `Authorization` 头 🔵

**这条官方文档没写，但它是真的，而且能静默骗过你的鉴权。**

🔵 实测：浏览器只发了自定义头，容器却收到 `authorization: <449 字符>`（另有
`x-modelscope-studio-session`）。

⇒ **三条连带结论（都必做）**：

1. **自家鉴权必须换头名** —— 实测自定义头（如 `X-API-Key`）**透传成功** ✅
2. 🔴 **绝不能读 `Authorization` 当自家凭据** —— 会把平台注入的 token 当成"用户已登录"
3. 🔴 **绝不能回显 / 落日志请求头** —— 那是**泄凭据**

### 3.5 🔴 容器环境变量里有**云端明文凭据** 🔵

🔵 实测 env 里有 `accessKeySecret` / `securityToken` 等同族变量。

⇒ 🔴 **三条铁律**：⛔ 不打 `os.environ` 的**值** · ⛔ **不做** `/debug`·`/env` 端点 ·
⛔ **关掉框架的 debug traceback**（报错页会把环境变量印出来）。

### 3.6 数据持久化 🟢

- 🔴 **默认每次重启数据即丢**
- 持久目录：`/mnt/workspace`
- 🟢 **转移 / 改名 Studio 时数据同样会丢**
- 🟢 要高可靠 ⇒ **用外部存储**
- 🔵 实测 `/mnt/workspace` **可写** ✅，但 `disk_usage` 返回 **`2^64` 字节的哨兵值**
  ⇒ ⛔ **别据此认为空间无限**

### 3.7 删除 Studio 🟢

🔴 **没有程序化接口**：OpenAPI `DELETE /studios/{id}` 返回 **404**；SDK/CLI 的
`delete_repo` 已废弃且不支持 studio；网页控制台走的是 **cookie 鉴权**的内部接口
（拿 Bearer token 调返回 **401**）。
⇒ **程序上只能 `stop`，删不掉。**

## 四 · 🔵 实测事实（官方文档里**没有**的）

> 这些是 2026-10-07 在免费档上**真跑出来**的。它们直接决定**你能写什么样的应用**。

### 4.1 免费硬件档的**真实**规格

| 项 | 实测值 |
|---|---|
| `name` | `platform/2v-cpu-8g-mem`（**免费档实测只有这一个**） |
| CPU | **2 vCPU** |
| 内存 | `MemTotal` = **8,265,656 kB ≈ 7.88 GiB**；cgroup limit = **8 GiB** |
| **Swap** | 🔴 **0** —— **OOM 直接 kill，没有缓冲** |

🔴🔴 **两个直接后果，必须现在就设计进去**：

1. **`Swap=0` ⇒ 任何"整个文件读进内存"的写法都是一个 DoS 面。**
   🔵 实测某上传端点写成 `tmp.write(await file.read())` ⇒ **一个 200 MB 的文件
   就能把容器打死** —— ⛔ **不需要恶意，不需要并发，一个人一次就够**。
   ⇒ **大小上限必须卡在"读之前"，不是"读完再判"。**
2. **真瓶颈是 2 vCPU**（不是内存）⇒ 任何**逐条调外部 API** 的循环
   （如逐 chunk 调 embedding）都会**慢到超时**。⇒ 要**批量**、要**限条数**。

> ⚠️ **⛔ 别拿平台的宣传值当判据。** 官方对外说免费是「8 核 32GB」——
> 🔵 **那是"空间"的配置，不等于你容器真拿得到。探针实测就是上面这张表。**
>
> 📌 **上面这张表是从哪来的** —— 一次性探针 `demo/probe-创空间最小验证/`
> （⚠️ `demo/` 已 gitignore ⇒ **clone 拿不到**；⚠️ 它是**一次性**的，**⛔ 别为"留个参考"刻意保它**）。
> 🔴 **业务方 2026-10-07 订正**：那是「**验证 CLI 配置的 demo，⛔ 不是本系统项目的 demo**」；
> 「**如果之前的 agent 有把配置写下来，就可以了**」
> ⇒ **要留的是【结论】，而结论就是本文件** —— **本文件在 ⇒ 探针删不删都不影响交付。**
> ⛔ **别把探针与本系统项目的 demo 混为一谈**（它不含业务代码）。见 `DEC-102` §三。

### 4.2 请求来源 IP

🔵 实测 `request.client.host` 是**代理内网 IP**（如 `21.0.0.1`）。
**真实客户端 IP 在 `X-Forwarded-For` 第一跳**（实测 `x-real-ip` 里也有）。

⇒ 要做**按 IP 限流 / 审计**，⛔ **别读 `request.client.host`**。

### 4.3 底层运行时

🔵 实测容器里能读到 `FC_*`（阿里云函数计算）与 `KATA_CONTAINER` 等变量。

⇒ ⚪ **推断：视作 serverless** —— 冷启动 / 休眠行为**要单独测**，
⛔ **别假设进程常驻、别假设内存里的状态还在**。

### 4.4 容器自身的磁盘

🔵 实测容器内 `/app` 约 **9.8 GB**。⚠️ 与 `/mnt/workspace` 是两回事。

## 五 · 🔴 会咬人的坑（附修法）

| 症状 | 真正的原因 | 修法 |
|---|---|---|
| `! [rejected] ... (non-fast-forward)` | 🔵 **建 Studio 自带 README** ⇒ 远端非空 ⇒ 合并停住 | 跑 §2 第 5 步的 ⑤；⛔ **别强推**（禁止） |
| `Address already in use` / 端口冲突 | 没听 `0.0.0.0:7860` | 改端口；**8080 不能用** |
| 页面 404，但状态是 `Running` | 🔵 应用**真起来了**，但访问路径不对 | 用 `GET /studios/{o}/{r}` 的 **`host`** 字段 |
| build 日志停在 `RUN ...` 中间 | 🟢 依赖装不上 / 基础镜像拉不下来 | 查 `requirements.txt` / `FROM` 地址 |
| `MemoryError` | 🔴 **8 GiB 且 Swap=0** | 🔵 **先查是不是"整个文件读进内存"**；再考虑换档（**要用户明确授权**） |
| `ModuleNotFoundError` | 依赖没写全 | 补 `requirements.txt` |
| 变量取不到值 | 🟢 混淆了 variables 与 secrets | **明文配置**用 variables，**密钥**用 secrets |
| 部署成功但行为没变 | 🟢 改了 `sdk_type`/`base_image`/`hardware` 后没重部署 | 再 `POST .../deploy` |

## 六 · 附录：OpenAPI 端点速查

> 🟢 **OpenAPI 是唯一真值来源**；`ms` CLI 是等价别名，本文档只用 OpenAPI。
> 基址：`${MODELSCOPE_ENDPOINT}/openapi/v1`

| 操作 | 方法与路径 |
|---|---|
| 当前用户 | `GET /users/me` |
| 可用硬件 | `GET /studios/hardware?sdk_type=<t>[&studio=o/r]` |
| 可用 SDK 版本 | `GET /studios/sdk-versions?sdk_type=<t>` |
| 可用基础镜像 | `GET /studios/base-images` |
| 建 Studio | `POST /studios` |
| 查详情 | `GET /studios/{o}/{r}` |
| 改设置 | `PATCH /studios/{o}/{r}/settings` |
| 部署 / 重启 | `POST /studios/{o}/{r}/deploy` |
| 停止 | `POST /studios/{o}/{r}/stop` |
| 日志 | `GET /studios/{o}/{r}/logs/{run\|build}` |
| 明文变量 | `GET` / `POST` / `PUT` / `DELETE` `/studios/{o}/{r}/variables` |
| 密钥 | `GET` / `POST` / `PUT` / `DELETE` `/studios/{o}/{r}/secrets` |

**鉴权**：所有请求带 `-H "Authorization: Bearer ${MODELSCOPE_API_KEY}"`。
⚠️ **这是你对平台发的请求** —— 与 §3.4「平台对你注入 `Authorization`」**方向相反**，别混。
