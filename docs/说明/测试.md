## 二 · 怎么跑

```bash
cd api

pytest -v                                              # 全部（⚠️ 需 PG+Redis 都在）

pytest -v -m "not integration and not needs_db"        # ⭐ 离线层（= CI 跑的那套）
                                                       #   只需 Redis，秒级

pytest -v -m needs_db                                  # 需要真 Postgres
pytest -v -m integration                               # 端到端（需真 PG + 外网）

pytest test_auth.py -v                                 # 单个文件
```

### 环境要求（**按层看**）

| 层 | 要 Postgres | 要 Redis | 要外网 | 进 CI |
|---|:--:|:--:|:--:|:--:|
| **离线层**（大多数） | ✗ | ⭐ **要**（限流中间件对每个非公开路径都打 Redis） | ✗ | ✅ |
| `needs_db` | ✅ **真库**（会**真写 `documents` 表且无 cleanup**） | ✅ | ✗ | ⛔ |
| `integration` | ✅ | ✅ | ✅（DashScope embedding） | ⛔ |

> ⚠️ **跑 `needs_db` 前**：**它写的是真库**（`POSTGRES_DB`）。
> 文档建议设 `POSTGRES_DB=rag_test` 跑 —— **别拿生产库跑**。

|---|---|
| `needs_db` | 需真 Postgres（真写表，无 cleanup）⇒ 不进 CI |
| `integration` | 需真 PG + DashScope ⇒ 会 flaky ⇒ 不进 CI |

> ⚠️ **没有 `addopts` / `testpaths` / `asyncio_mode`** —— `api/pytest.ini` **只有 `markers` 一段**。
> ⚠️ **没有 `pytest-asyncio` / `anyio`** ⇒ **所有用例都是同步的**（异步代码靠 `asyncio.run()` 手跑）。

### 🔴 5.1 「本地」和「CI」差在哪 —— **两件事，别混成一件**（2026-10-01 更正）

> ⛔ **本节原话是**：「**反向不存在 —— CI 跑的是本地命令的子集**」。
> **那句话只对了【一半】，而且它读起来就是"本地绿 ⇒ CI 绿"的许可证。**
> 🔴 **2026-10-01 正是栽在这一句上**（详见下方 `.env` 那条）。

| 维度 | 是「子集」吗 | 说明 |
|---|---|---|
| **选哪些测试** | ✅ **是子集** | CI 少跑 **19 条**（`needs_db` **18** + `integration` **1**）<br>⚠️ 原写「11 条（`needs_db` 的 3+2+1 + `integration` 的 4 + `test_health` 的 1）」—— **已随 2026-10-02 重测更正** |
| **跑在什么环境里** | 🔴 **不是** | **同一批测试，跑在另一套环境里** |

> ⇒ **正确说法：CI 跑的【测试】是本地那条命令的子集；但【环境】是另一套，不是子集。**

**三条轴（2026-10-01 实测）：**

| 轴 | 本机 | CI | 后果 |
|---|---|---|---|
| **Redis** | 默认**没有** | `redis:7` service 容器 | 不起 redis 直接跑本地 → **15 条**因连不上而红 |
| **`.env`** | **有**（真实模型名） | **⚠️ 没有** ⇒ 落回 `api/config.py:54/55` 的**代码默认值**（`qwen-turbo`/`qwen-plus`） | 🔴 **CI 红的真凶** —— 见下 |
| 依赖安装 | 本机 venv | 干净 ubuntu + `requirements.txt` | 版本可能不同 |

> 🔴 **`.env` 那一条的实例（2026-10-01）**：一条测试断言「**兜底单价 ≥ 在用模型单价**」。
> 本机 `.env` 走 `deepseek-v4-flash`（0.001/0.002）⇒ **过**；
> CI **无 `.env`** ⇒ 默认 `qwen-plus`（0.008/0.016）⇒ **红**（`assert 0.003 >= 0.008`）。
> ⇒ **同一份代码、两种合法部署、答案相反。** 本地与基线的**差集比对永远抓不到它**
> （它在本地是绿的，不在"新增失败"里）。详见 `CHANGELOG.md` 的 `### Fixed`（2026-10-01 那条）。

### ✅ 5.2 怎么消掉这个差 —— `bash scripts/ci-local.sh`

**一条命令在本机复现 CI 那套环境**：**复用 `redis-rag`** + **rsync 掉 `.env`** + **逐字用 CI 那条命令**
（环境变量与命令**直接从 `ci.yml` 读**，不在脚本里另抄一份）。

**判据**：**跑出来的数字 == CI 日志里的数字**（2026-10-02 本机实测：`191 passed, 3 skipped, 19 deselected`）。
⚠️ **这个数字随测试集变化** —— ⛔ 别把它当固定值抄，**以 CI 日志那次为准**。
⛔ **别只看"绿了"** —— 绿了但条数对不上，说明**还是两套环境**。

> 🔴 **2026-10-02 更正（Redis 这一轴）**：脚本**原先**会 `docker run --rm` 起一个跑完就删的
> `raci-ci-local-redis`。**实测那条路在本机一次都没走过** —— `ci.yml:114` 把 `REDIS_PORT` 钉成 `6379`，
> 而 `6379` **长期被项目自己的 `redis-rag` 占着** ⇒ 永远走"复用"分支 ⇒ 那个容器**从来没被创建过**。
> 业务方 2026-10-02 裁：**就认 `redis-rag`** —— 按名字管理它（在跑就复用 / 停了就 `docker start`），
> **⛔ 永不删除**；镜像以 `ci.yml` 的 `services.redis.image` 为准，**不一致只提示、不擅自重建**。

⚠️ **它【不】复现三条轴** —— 依赖安装（用你现有 venv）· OS（本机 macOS）·
**Redis 不是 pristine**（`redis-rag` 是长期容器，**里头可能留着上一轮的 key**，而 CI 的 service 容器每次全新空）。
**脚本运行时会把"没复现什么"打在自己的横幅里**，⛔ 别默认它等于 CI。

## 七 · 怎么加一个测试

```
1. 放哪：api/test_<模块或功能>.py
2. 要不要真库？
   · 不要  ⇒ 什么都不加（默认进 CI）
   · 要    ⇒ 文件头加 pytestmark = pytest.mark.needs_db
3. 需外网/端到端？ ⇒ 单条加 @pytest.mark.integration
4. ⭐ 本仓的习惯：配一条「能对【修复前形态】判不过」的自证用例
   （见 test_budget_units.py / test_search_tools.py 里的 test_would_have_caught_*）
5. 如果是"守一个约定"（如"不许 import langchain"）⇒ 用 **静态结构锁**（读源码 AST），
   而不是运行时断言 —— 本仓有多个先例
6. ⭐ **建了常量/函数/开关 ⇒ 再配一条「接线守卫」（`test_<模块>_wiring.py`）** —— 见下
```

> ⭐ **第 4 条是本仓的特色**：不只测"现在是对的"，还测"**回到旧的错法会不会红**"。
> 理由：本仓多条修复**没有对应的回归测试**就会悄悄退回去。

### ⭐ 6 号（接线守卫）—— **专治本仓复发最多次的那个陷阱**

> **它长什么样**：`「建好了 X」⇒ 但没有人调用 X` ⇒ **看起来做完了，实际拦不住**。
>
> 📌 **源文档自己都记着它**（`④ 未核`那栏），而且**同一个形状在本仓出现过 3 次**：
> `B7` 之前（常量建好没接）· `B8` 之前（有常量没判定函数）· `B10` 之前（有判定函数没调用点）。
> ⇒ **不是"下次注意"能解决的** —— 人要"记得去接"，而**机器能直接查**。

**做法**（4 个现成范例，照抄结构）：

| 守卫 | 查什么 |
|---|---|
| `test_max_tokens_wiring.py` | **15 处** `ChatOpenAI` 都带 `max_tokens` **∧ 接对值**（答案 2000 / 中间 1024） |
| `test_session_budget_wiring.py` | **该接的 7 条接了 ∧ 不调 LLM 的 4 条没接**（**双向**） |
| `test_global_daily_budget_offline.py` | 单用户那条 SQL **必须有** `user_name` ∧ 全站那条**必须没有**（**配对**） |
| `test_breaker_wiring.py` | **该接的 8 处接了 ∧ 不花钱的 4 条没接**（**双向**） |

> 🔴 **两条设计要点（漏了守卫就是摆设）**：
> 1. **必须双向** —— 只查"该接的接了"，就**查不出"不该接的也接了"**（那会让**不花钱的接口白占额度**）
> 2. **必须能变红** —— 交之前**故意把接线删掉跑一次**，看它是否真的红（本仓叫"变异验证"）。
>    ⛔ **"写了守卫"≠"守卫有效"** —— 一条永远绿的守卫比没有守卫更坏。
