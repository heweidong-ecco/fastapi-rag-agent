## 二 · 怎么跑

```bash
cd api

pytest -v                                              # 全部（⚠️ 需 PG+Redis 都在）

pytest -v -m "not integration and not needs_db"        # ⭐ 离线层（= CI 跑的那套）
                                                       #   只需 Redis，秒级

pytest -v -m needs_db                                  # 需要真 Postgres
pytest -v -m integration                               # 端到端（需真 PG + 外网）

pytest test_auth.py -v                                 # 单个文件
```

### 环境要求（**按层看**）

| 层 | 要 Postgres | 要 Redis | 要外网 | 进 CI |
|---|:--:|:--:|:--:|:--:|
| **离线层**（大多数） | ✗ | ⭐ **要**（限流中间件对每个非公开路径都打 Redis） | ✗ | ✅ |
| `needs_db` | ✅ **真库**（会**真写 `documents` 表且无 cleanup**） | ✅ | ✗ | ⛔ |
| `integration` | ✅ | ✅ | ✅（DashScope embedding） | ⛔ |

> ⚠️ **跑 `needs_db` 前**：**它写的是真库**（`POSTGRES_DB`）。
> 文档建议设 `POSTGRES_DB=rag_test` 跑 —— **别拿生产库跑**。

### marker（**只有 2 个**，定义在 `api/pytest.ini:10-12`）

| marker | 含义 |
|---|---|
| `needs_db` | 需真 Postgres（真写表，无 cleanup）⇒ 不进 CI |
| `integration` | 需真 PG + DashScope ⇒ 会 flaky ⇒ 不进 CI |

> ⚠️ **没有 `addopts` / `testpaths` / `asyncio_mode`** —— `api/pytest.ini` **只有 `markers` 一段**。
> ⚠️ **没有 `pytest-asyncio` / `anyio`** ⇒ **所有用例都是同步的**（异步代码靠 `asyncio.run()` 手跑）。
> 📌 **pytest 配置只在 `api/pytest.ini`** —— 仓根**没有** `pyproject.toml` / `setup.cfg` / `tox.ini`。

### `api/conftest.py`（52 行 · 3 个 fixture）

| fixture | 做什么 |
|---|---|
| （模块级副作用） | `GRADIO_ANALYTICS_ENABLED=False` —— ⚠️ **必须在 `import main` 之前**，否则 Gradio 的非 daemon 遥测线程**卡死进程退出**（实测 20s+ → 11s） |
| `client` | `TestClient(app)` |
| `auth_headers` | **真调 `/auth/login`**，从 `config` 读用户名口令（**不硬编码**） |
| `sample_document` | 一条固定测试文档 |

> 🔴 **`conftest.py:27` 是 `return TestClient(app)` —— 【裸返回，没有 `with`】。**
> Starlette 的 `TestClient` **只在用作上下文管理器时才跑 lifespan** ⇒
> **`startup_event`（建表）在测试里不会跑**（`api/main.py:491-495`）。
> ⇒ **后果**：`needs_db` 类用例**依赖"本机的表已经存在"** ⇒ **换台空机器会红**。
> 📌 这个结论出自 `归档/重构计划-2026-09-15.md §八`，**2026-09-29 复核：仍然成立**
> （⚠️ 只有行号过时：它写 `conftest.py:8`，现为 `:27`）。⬜ 已登记。

## 七 · 怎么加一个测试

```
1. 放哪：api/test_<模块或功能>.py
2. 要不要真库？
   · 不要  ⇒ 什么都不加（默认进 CI）
   · 要    ⇒ 文件头加 pytestmark = pytest.mark.needs_db
3. 需外网/端到端？ ⇒ 单条加 @pytest.mark.integration
4. ⭐ 本仓的习惯：配一条「能对【修复前形态】判不过」的自证用例
   （见 test_budget_units.py / test_search_tools.py 里的 test_would_have_caught_*）
5. 如果是"守一个约定"（如"不许 import langchain"）⇒ 用 **静态结构锁**（读源码 AST），
   而不是运行时断言 —— 本仓有多个先例
```

> ⭐ **第 4 条是本仓的特色**：不只测"现在是对的"，还测"**回到旧的错法会不会红**"。
> 理由：本仓多条修复**没有对应的回归测试**就会悄悄退回去。
