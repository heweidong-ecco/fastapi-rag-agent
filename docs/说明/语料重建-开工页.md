| 项 | 内容 |
|---|---|
| **你要交什么** | **20–40 篇中文 Markdown**，放 **`testdata/demo-corpus/`** |
| **什么时候交** | 分两批（§五）—— ⚠️ **第一批只要 4–5 篇**，先让管线跑通 |
| **验收** | §六 那两条命令 + `docs/说明/语料要求.md` §六（八条判据） |
| 📚 **全文** | **`docs/说明/语料要求.md`** —— **内容层 §一–§七 · 形式层 §八**。<br>⛔ **本页只是入口，不重复它**；两边冲突时**以那份为准** |
| 📄 相关 | `DEC-116`（分档落地）· `DEC-117`（形式层契约）· `DEC-118`（去重） |

---

## 一 · 三句话

1. **从「用户会问什么」反推语料** —— ⛔ 不是把手上的文档一股脑放进去。
2. **一篇 = 一个主题** · **全篇 500–1500 字** · **`##` 分节 4–6 节**（⛔ 不规定每节多少字）。
3. **文件名就是契约**（§二）—— 它决定这篇进哪个 chunk 档位，**⛔ 别随手起名**。

---

## 二 · 🔴 文件名模板（**这一节最重要**）

```
<类别字母>-<序号>-<标题>.md
```

| 字母 | 类别 | 建议篇数 | 这篇会被分到哪一档（`api/chunker.py`） | 它能测什么 |
|---|---|---|---|---|
| **A** | **产品 / 规格** | 5+ | `technical` **600 / 60** | 单跳精确事实（型号 · 数字 · 错误码） |
| **B** | **流程 / 制度** | 5+ | `legal` **800 / 100** | **多跳**（条件要叠加：工龄 + 当地法 + 政策） |
| **C** | **FAQ / 问答** | 5+ | **`faq` 300 / 50** | 复现**用户真实问法**（口语 ≠ 书面） |
| **D** | **数据 / 报告** | 5+ | `report` **800 / 100** | 数字与表 |
| **E** | 🔴 **负样本块**（⛔ **不是第 5 类内容**） | 1–3 | `default` **500 / 50** | 系统**应当拒答**（见 §七） |

**例子**（与仓里那 9 篇同形）：

```
testdata/demo-corpus/A-01-阀门产品规格书.md
testdata/demo-corpus/B-02-入住与接送流程.md
testdata/demo-corpus/C-03-常见问题.md
testdata/demo-corpus/D-01-2026 年度质量报告.md
testdata/demo-corpus/E-01-关于我们.md        ← 负样本块
```

⚠️ **序号两位数、标题自己起**（中文，别用拼音/英文）。**类别字母必须是 A–E 之一**。

---

## 三 · 每篇长什么样

| # | 要求 |
|---|---|
| 1 | **一篇一个主题** · **500–1500 字**（⛔ 别写大杂烩） |
| 2 | **`##` 分节，4–6 节** |
| 3 | **全中文** —— 术语/型号可以**中英对照一次**（首次出现处） |
| 4 | 🔴 **表格写成 Markdown 列表**（每行一条 + **表头在每块重复**）—— 本仓分块器**不认表**，写成表会被切散 |
| 5 | **同一实体只有一种写法**（例：要么全写「机器学习」，要么全写「ML」，⛔ 别混） |
| 6 | **每条事实唯一、可判对错** —— demo 要能一眼看出"答对了" |
| 7 | 不要错别字 / 语法错（中文资料 + 国标口径，`GB/T 36344—2018`） |

---

## 四 · ⛔ 不要有的

| ⛔ | 为什么 |
|---|---|
| **扫描件 / 图片型 PDF** | 解析不出文字 |
| **低质 / 没用的内容** | 业务方原话：「低价值或者没用的就不要烤了」 |
| **一篇里塞多个主题** | 分块会切在主题交界 ⇒ 检索命中"混合体" |
| **`README.md`** | 🔴 目录里**只放 `<字母>-*.md`** —— 判据与去重器**只认这个形状**，README 会被算错 |

---

## 五 · 分批交（**建议**）

| 批 | 交什么 | 为什么 |
|---|---|---|
| **第 1 批** | **每类 1 篇（共 4–5 篇）** | 🔴 **先让管线跑通** —— 落点 · 文件名契约 · 分档 · 去重器 **会被真数据过一遍**；有问题这时候改最便宜 |
| **第 2 批** | **补到 20–40 篇**（每类 ≥5） | 达到 §5.1 的规模（**全文 3–6 万字**） |

⚠️ **第 1 批交完先别继续写** —— 等管线跑完那一轮再说（有问题会在这时暴露）。

## 六 · 交之前，**自己先跑这两条**

```bash
# ① 分节与篇幅（⛔ 别用 awk —— 它数的是【字节】，中文一字 3 字节）
python3 -c "
import sys, re, pathlib
for f in sorted(sys.argv[1:]):
    p = pathlib.Path(f)
    if p.name == 'README.md': continue
    text = p.read_text(encoding='utf-8')
    secs = re.split(r'^## ', text, flags=re.M)
    body = [len(re.sub(r'\s', '', s)) for s in secs[1:]]
    print(f'{p.name:30} 全篇={len(text):4}  节数={len(body)}  各节={body}')
" testdata/demo-corpus/[A-E]-*.md
#   ⇒ 全篇 500–1500 · 节数 4–6

# ② 跨文档去重（跨篇才算；⛔ 它只报不删）
venv/bin/python scripts/check_corpus_dedup.py testdata/demo-corpus
#   ⇒ ①② 应为 0 处；③ 的命中要【逐条判断】是重复还是"同一规则的两个角度"
```

⚠️ **第 ② 条要联网、会花很少的 embedding 额度**（9 篇实测约 ¥0.002 量级）。
⛔ **没网/没 key 时它会【明说那一层跳过了】** —— ⛔ 别把"跳过了"读成"没有重复"。

## 七 · E 那块（负样本）—— 它是**故意**的

* **选一个「A/B/C/D 四类都不覆盖」的主题**（例：公司简介、招聘信息）。
* 目的：**访客问它时，系统应当拒答**（⛔ 不是编）—— 仓里已有现成机制
  （`REFUSAL_SENTENCE` / `no_answer` 帧 / `/trace` 页的解释分支）。
* **档位 = `default`**（⛔ 别用别的档 —— 它不占任何一类的语义）。
* 📌 **它要能"被检索到、但答不出来"** —— 所以语料里**要有它的内容**，⛔ 不是不放。
