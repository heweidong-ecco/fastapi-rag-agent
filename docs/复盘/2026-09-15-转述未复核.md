  **本次对"影响决策"的结论做了复核,对"影响描述"的结论没做 —— 而后者同样进了业务方的判断依据。**

## 二、教训(可复用的判断规则)

1. **信源等级不进格式,就等于没有分级。** 读者只看到表格与行号,看不到我心里那句"这条我没验"。**不确定必须在形态上可见**(打标、去行号、单独分区),不能靠尾注。
2. **"另一个 agent 说的"不构成证据升级。** 多个模型独立得出结论一致,才略微提高可信度;**单个 agent 的输出与我的推断同级**。
3. **转述前先问:这条会改变对方的哪个决定?** 会改变决定的 → 必验;只影响描述的 → **也必验,只是优先级次之**。本次的错在于把后者当成了"可以不验"。
4. **严重性定级只升不降,除非有新证据。** 先报"类型矛盾"、后发现是"可达 500",说明初次定级**不足**;反向的错误(定级过度)代价小得多 —— 所以定级存疑时**取重的那端**,并注明"可能更严重"。
5. **汇报里的"我还没复核"这句话,读者会漏看,我自己也会漏看。** 它不能作为免责声明,只能作为**待办标记**。

## 四、对机制/母体 Kit 的反馈

- **不构成母体 Kit 缺陷**(是执行错误)。
- **指向一个值得进体系的形状**:**多 agent 协作下的信源分级**。既有防错规则多针对"单模型自说自话",未覆盖"**多 agent 流水线**"下特有的失效 —— 后一级会**继承前一级的定级**并把它当成既定前提(本案 E2 正是如此:Plan agent 的价值在于它**没有继承** Explore agent 的定级)。
  ⇒ **建议回写体系**:`06-优化-数据飞轮` 一类的多 agent 流程规范里,可加一条 ——「**下游 agent 必须重新定级,不得继承上游的严重性结论**」。
