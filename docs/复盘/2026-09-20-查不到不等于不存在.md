### 🔴 顺带查到的同类缺陷 —— 本仓最重要的那道门（凭据门）也是这个形状

**`scripts/check_secrets.sh:57`（staged 模式）与 `:53`（`--all` 模式）**：

```bash
SCAN_TEXT="$(git diff --cached -U0 2>/dev/null | grep -E '^\+' | grep -vE '^\+\+\+' || true)"
...
if [ -z "$SCAN_TEXT" ]; then
    echo "[凭据门] staged 区为空 —— 没有要提交的内容。"
    exit 0          # ← 判成"通过"
fi
```

- `2>/dev/null` **吞掉错误**，`|| true` **抹平退出码** ⇒ **`git diff` 失败**与**「暂存区确实为空」不可区分**。
- ⚠️ **精确说法（本段前一版写错了）**：空集那一支打印的是 `[凭据门] staged 区为空 —— 没有要提交的内容。`
  然后 **`exit 0`** —— 它**并不打印** `✅ 凭据门: 通过`。
  **真正恒过的是【退出码】**（这道门的判据本就是"命中即 `exit 1` 中止"）⇒ **要锁的是退出码，不是那句成功文案**。
  （本复盘 §四 的修法已按此改写。）
- 🔴 **还有一个比上面更危险的变体（前一版漏写了）**：若 `git diff` **输出了一部分之后才失败**，
  `SCAN_TEXT` **非空** ⇒ 走正常扫描路径 ⇒ 会打出**货真价实的** `✅ 凭据门: 通过 —— 0 命中`（`:149`），
  而它扫的是**被截断的内容**。⇒ **这个变体"绿得毫无破绽"，靠看输出根本发现不了。**
- `--all` 模式同理（`git grep … 2>/dev/null || true`），且**它的空集还会误报成「staged 区为空」**（消息写死，与模式不符）。
- ⚠️ **与 `v3→v4` 那道「硬币做的门」同形**（`docs/复盘/2026-09-17-一道硬币做的门.md`：SIGPIPE 让真实命中被静默丢弃，实测漏报 9/20）。
  那道门修好才三天，**另一条同类路径就露出来了** ⇒ 说明上次只修了**症状所在的那一处**，没修**形状**。
- 概率上它不像 SIGPIPE 那次那么致命（要 `git diff` 真失败），但**触发条件恰恰是"环境已经不对劲"的时候**
  —— 而那正是你最需要门真的在跑的时候。

## 二、教训(可复用的判断规则)

1. **「查不到」与「不存在」是两个命题。**
   任何"找不到就通过"的判据，都必须显式加一支：**执行失败 ⇒ 不算通过**。
   ⚠️ **本仓同型三例**：
   - `api/test_public_paths.py` 第一版（名单里一条 `/api/` 路径都没有 ⇒ 空集恒过，靠事后补的自证用例才发现）
   - `docs/复盘/2026-09-17-grep模式写错差点报错数.md`（正则一条都匹配不到 ⇒ 计数恒 0）
   - **本次**
2. **失败必须比成功更显眼。** 成功可以静默；**失败一定要打印出来**。
   我这次错在把"失败"**渲染成了 `✅`** —— 这是最坏的一种：它主动消除了怀疑。
3. **清理类操作的完成判据 = 回查结果状态，不是回查命令退出码。** 退出码 0 可能只完成了动作的一半。
4. ⚠️ **别让「重试循环」掩盖失败。** 我的 `for i in 1..3 … break` 里，**判据一旦恒过，第一次就 break**
   ⇒ **三次重试等于一次都没跑**。**重试要重试"动作"，而判据必须独立于重试成立。**
5. **判据的"空集"必须先被证明是一个合法的空集。**
   本仓已有的正解是**自证用例**（positive control）：喂一个**已知该命中**的样本，断言它**必须命中**。
   判据能抓住"已知坏样本" ⇒ 才允许它对着真实输入说"没查到"。

6. 🔴 **"写下来"不等于"生效"—— 这一条今天被当场验证了。**
   本文 §二 的 1~5 是**同一天写下的**,而**写完之后又犯了两次**(§一 #3/#4)。
   ⇒ **复盘本身也是"文字"**,同样受本仓那条规律的支配:**只有绑在【必然发生的动作】上的才会被执行**。
   ⚠️ 这不是"复盘没用",而是说:**复盘的正确产出是一个【动作】,不是一份文档**。
   （本仓的正面先例:凭据门做成**脚本**(命中即 `exit 1`)、A 级 skill 绑到**"开 PR 前"**这个动作。）

## 四、对机制/母体 Kit 的反馈

> 本仓若暴露了治理机制本身的缺陷 → 提请回写体系。本仓不留登记表。

- **KD 候选：门的"失败态"必须和"通过态"在输出上不可混淆。**
  - **线索**：本仓两道门（凭据门 SIGPIPE 版、本次）都是**"看起来在工作、实际可能没跑"**；
    而我的清理判据把**失败渲染成了 `✅`** —— 同一个病的两种表现。
  - **影响**：这类缺陷**不会以"门报红"的形式暴露**，只会以"**事故**"的形式暴露。
    本仓已为此付过一次代价（3 个历史泄露凭据的字面量被写进 PUBLIC 文档）。
  - **最小修复建议**：任何"检查/门"类脚本，**必须有一条不可被空集满足的成功路径** ——
    即 **`exit 0` 只能在"扫描确实执行了 且 确实 0 命中"时返回**；
    **扫描没执行（含"执行了一部分就失败"）⇒ 必须打印"未执行/无法判定"并返回非 0。**
    ⚠️ **锁的是【退出码】，不是成功文案** —— 本文前一版把靶子写成"`通过` 三个字"，**瞄错了**
    （空集那一支根本不打印它，见 §一）。
    （形式化地说：`通过 ⇐ 执行 ∧ ¬命中`，**不许退化成 `通过 ⇐ ¬命中`**。）
