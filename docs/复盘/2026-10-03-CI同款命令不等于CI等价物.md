## 二、根因（**不是"判据不够"，是"门口指向了替身"**）

### 2.1 仓里【早就有】正确的门

`scripts/ci-local.sh`（**2026-10-01 建**，文件头第一句就是我这个病）：

> **它治什么病** —— 2026-10-01：`8a5672b` 推上去后 CI 红，而**本地是绿的**。
> ⇒ 根因**不是"CI 玄学"**，是**本地和 CI 是两套环境**。
> ⚠️ `docs/说明/测试.md` §五 原先只写「CI 跑的是本地命令的子集」——
> **那句话对"选哪些测试"成立，对"跑在什么环境里"不成立。**

它的用法与判据写在 **`docs/说明/测试.md §5.2`**（标题就叫「✅ 5.2 怎么消掉这个差」）。

### 2.2 它确实抓得住这次的 bug（**实测，⛔ 不是推断**）

把修复**临时退回**，跑 `bash scripts/ci-local.sh`：

```
==== 12 failed, 399 passed, 3 skipped, 32 deselected, 56 warnings in 13.55s ====
🔴 ci-local 失败（退出码 1）—— **这个红，就是 CI 会红的那个**。
```

⇒ **与 CI 那次的数字逐字相同。**（还原用 `cp` 备份 + 核 `sha256`，⛔ 不用 `git checkout`）

### 2.3 🔴 那我为什么没跑它 —— **因为我被指向了别处**

会话里最先读、也最常回看的两处，写的都是**裸命令**：

| 位置 | 原文 | 提到 `ci-local.sh` 吗 |
|---|---|---|
| `ROADMAP.md` **自检三问①** | 「跑测试用哪条命令？ ⇒ **CI 的同款**：`python -m pytest api/ -m "not integration and not needs_db" -q`」 | ⛔ **0 处** |
| `docs/规范/开发规范.md` **§2.4·5** | 「推送前跑【**CI 的同一条命令**】」= 同一条裸命令 | ⛔ **0 处** |
| `CLAUDE.md` | —— | ⛔ **0 处** |
| `CONTRIBUTING.md` | —— | ⛔ **0 处** |
| `docs/说明/测试.md` | §5.2 有 | ✅ **2 处** |

**⇒ 门在 `docs/说明/测试.md §5.2`，而 `ROADMAP` / `开发规范` 这两处"推送前该干什么"把它指丢了。**

> ⭐ **这正是本仓反复记的那个病**：
> **「门挂在别处，就等于没有门」**（`CLAUDE.md` · `.claude/README.md`）·
> **「装了 skills ≠ 会用 skills；有结构才执行，只有文字就漏」**（`agent-pitfalls-kb` **A2**）。
>
> ⚠️ **与 09-30 那份的分界**：那份的结论是「判据选错了」⇒ 补一条**文字规矩**。
> **文字规矩补了，今天照样没拦住。** 本份的结论是：**要改的是【指针】** ——
> 让"推送前干什么"这处**直接指向那个脚本**，而不是再抄一遍它内部那条命令。

### 2.4 为什么裸命令是"弱的替身"

| 轴 | 裸命令 | `ci-local.sh` | CI |
|---|---|---|---|
| 选哪些测试 | ✅ 对 | ✅ 对（**逐字从 `ci.yml` 读**） | ✅ |
| `.env` | ❌ **在场** | ✅ **rsync 掉** | ❌ 不存在 |
| Redis | ❌ 本机 `redis-rag`（长期容器） | 🟡 复用 `redis-rag`（**已在文件头声明"这一轴不等价"**） | ✅ 一次性 pristine |
| **Postgres** | ❌ **本机开着 ⇒ 掩盖断连** | ✅ **`POSTGRES_PASSWORD` 随 `.env` 一起没了 ⇒ 连不上库** | ❌ **无此服务** |
| 依赖 / OS | 本机 venv / macOS | 同（**文件头声明不等价**） | 干净 ubuntu + requirements |

> 📌 **`ci-local.sh` 的高明处**：它**不自己拼命令**，而是**把 `ci.yml` 那一整块 `run` 抠出来执行**，
> 环境变量也**从 `ci.yml` 读** ⇒ 连"改了 `ci.yml` 忘了同步脚本"都不会发生。
> **而"手打那条命令"恰恰会把脚本里对齐好的环境整个绕开。**

## 三、怎么修的

### 3.1 代码：把够不着的那个 `get_db` 也 patch 上

`api/test_cancel_propagation.py::_call_rag_stream` 补一行：

```python
import db as db_mod
...
monkeypatch.setattr(rag_mod, "get_db", lambda: _FakeConn())   # 原有：端点自己那处
monkeypatch.setattr(db_mod,  "get_db", lambda: _FakeConn())   # 🔴 乙段后新增：共享层那处
```

⚠️ **没有选「把 `rag_mod.search_similar` 整个换掉」** —— 那会让这条测试**连"共享层还在不在用"都测不到**，
下次谁再把 SQL 挪回端点，这里不会响。**补能到达的那处连接**，检索代码路径仍是真的。

### 3.2 口径：把「推送前干什么」三处**指向脚本**

| 位置 | 改成 |
|---|---|
| `ROADMAP.md` 自检三问① | 第一句就是 **`bash scripts/ci-local.sh`** |
| `docs/规范/开发规范.md §2.4·5` | 同上；并把原写「`-m` 恰好是"把库减掉"」那句**更正**（见 §五） |
| `docs/说明/测试.md` | 表头「**CI 实跑**」加更正（那几列**不是** CI 实跑）· §一 的 `= CI 那套` 标注限定为"**收集口径**" |
| `2026-09-30-本地绿当成了不依赖.md` | **加补正指针**（⛔ 不改其原文） |

## 五、顺带更正的一处【当时就写错】的口径

`docs/规范/开发规范.md §2.4·5` 原来写：

> 「`-m "not ... needs_db"` **恰好是"把库减掉"** ⇒ **只有它能把"偷偷依赖库"暴露出来**」

🔴 **不成立。** `needs_db` 是**人写在测试上的自称**（一个 marker）；
`-m "not ... needs_db"` 减掉的是「**自称**需要库的用例」。

**而这次的 12 条一个 marker 都没有** —— 它们在 `main` 上**确实不需要库**，是**乙段让它们需要了**。
⇒ **这条 `-m` 对它们完全无效**，而本机库开着 ⇒ **照样绿**。

> ⭐ **一句话**：**「跑哪条命令」（轴一）与「跑在什么环境里」（轴二）是两根轴。**
> 09-30 只立了轴一，**把轴二默认成了"CI 的环境"**；今天证明**轴二必须自己动手造** ——
> 而**造它的东西，2026-10-01 就写好了**。

## 七、对机制/母体 Kit 的反馈

- **KD 候选：一个"入口"建好之后，没有东西保证【该指向它的地方】真的指向它。**
  - 线索：`ci-local.sh` 建了 **9 天**（10-01 → 10-03），`测试.md §5.2` 写得很详细，
    但 `ROADMAP` / `开发规范` / `CONTRIBUTING` / `CLAUDE.md`**四处"提示怎么跑测试"的位置一处都没提它**。
  - 证据：本文件 §2.3 的对照表（`grep -c 'ci-local'` 逐份数出来的）。
  - 影响：**工具再好，只要入口没指它，就等于没有** —— 今天就是这么红的。
  - 最小修复建议：**拉一条"入口 → 引用点"的双向清单**（谁建了入口 ⇒ 登记它**必须**被哪几处引用），
    并可做成**可打印的检查**（如 `scripts/check_entry_refs.sh`：清单里的每一对都 `grep` 一遍）。
    ⚠️ **本仓暂不实现**（范围控制 · 待业务方裁）；先记在这里。
  - 📌 **同源**：`CLAUDE.md`「门挂在别处，就等于没有门」· `agent-pitfalls-kb` **A2** ·
    `docs/复盘/2026-09-29-用我做过了当别人找得到.md`（第 8 条：「**建了入口就问「谁指向它」**」）。
