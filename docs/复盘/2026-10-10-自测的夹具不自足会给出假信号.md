## 二、教训（可复用的判断规则）

1. 🔴 **「单独跑绿」与「`ci-local` 绿」证的不是同一件事** ——
   两者环境不同（`GIT_DIR` / `PATH` / 有没有 `venv`），而**夹具的依赖项是从环境里"捡"来的**。
   ⇒ **判据**：**凡是"造夹具"的自测，问一句「它依赖环境里的什么」**；
   要依赖的，**要么自己摘掉、要么自己带上**（两根轴：**摘 `GIT_DIR`** + **拷配置文件**）。
2. 🔴 **`ci-local` 那句「这个红就是 CI 会红的那个」是有边界的** ——
   它成立于「**本地与 CI 的差异不在这次改动面上**」。本次两处红**在真 CI 里根本不会发生**
   （真 CI 没有那个 `env`，也没有 `venv/bin` 在 `PATH` 上）。
   ⇒ **判据**：`ci-local` 红时，先问「**这一步在真 CI 里是什么条件**」，⛔ 别一律当成"CI 也会这样"。
3. 🔴 **夹具仓一定要断言它真的建起来了** —— 被继承的 `GIT_DIR` 下 `git init` 会
   **返回 0 却什么都不建**。⇒ 不钉这一条，后面所有用例都会"**绿得没意义**"。
   📌 同一个手法在 `scripts/test_check_doc_orphans.sh` 里**早就写过**（它还专门拿 T6 钉这条）——
   **本仓记过，但只记在那一份的注释里**，新加的两道门**没照做**。
   ⇒ **「有结构才执行，只有文字就漏」** 的又一例：**同一条教训换个文件就不生效**。
4. ⚠️ **代价是真实的**：这次不是"红一下" —— 它**在真仓上留下了一笔提交**。
   ⇒ 这类"夹具打到真仓"的错误**必须当成有副作用的操作**来对待。

### 判据（可打印 —— ⛔ 只写"下次注意"没用）

```bash
# ① 还有没有"造 git 夹具但没摘 GIT_DIR"的脚本（⛔ 期望输出为空）
for f in scripts/*.sh; do
  grep -qE "git( -C [^ ]+)? init" "$f" 2>/dev/null || continue
  grep -q "unset GIT_DIR" "$f" || echo "🔴 缺 unset: $f"
done

# ② 那两句在不在（实测：**每个文件各 1 处** —— 两道门的自测各一句）
grep -c 'unset GIT_DIR GIT_WORK_TREE GIT_INDEX_FILE' scripts/check_layered_claude_md.sh scripts/test_pre_commit_gates.sh
grep -c '夹具仓没建起来'                                scripts/check_layered_claude_md.sh scripts/test_pre_commit_gates.sh

# ③ 变异自证（⛔ 这条才是"守卫有效"的判据）：把那行 unset 拿掉 ⇒ 必须红且喊出原因
#    （实测：exit 2 并打印「⛔ 夹具仓没建起来：…（GIT_DIR 被继承了？）」）
```

⚠️ **反证检验**：把「夹具不自足」取反（假设它自足），上面 ①② 的输出会变吗？
—— **① 会**（缺的那两个文件不再被点名）；**② 不会**（那两句本来就在）。
⇒ ② 测的是「**修复还在不在**」，⛔ **不是"问题还在不在"** —— 两者要一起看，⛔ 别只跑 ② 就说好了。
