# 复盘 · 2026-10-01 · **`docker ps` 会撒谎 —— 我把「读缓存」当成了「守护进程正常」**

> ## 🔴 一句话
> **Docker 的 Linux VM 已经死了，而 `docker ps` 照样秒回、`docker inspect` 照样给出状态。**
> 我据此判断「守护进程好好的，只是这一个容器起不来」——
> **方向一开始就偏了，后面查磁盘 / 查内存 / 查卷，全是在查错的东西。**

---

## 一 · 当时发生了什么

要跑 7 条 `needs_db` 测试，得先把停着的 `postgres-rag` 起来。于是：

| 命令 | 结果 |
|---|---|
| `docker ps --format '{{.Names}}' \| grep eval` | 秒回（实测 **0.222s**） |
| `docker ps -a` | **正常列出 10 个容器**，名字 / 状态 / "23 hours ago" 全对 |
| `docker inspect -f '{{.State.Status}}' postgres-rag` | **秒回 `exited`** |
| `docker start postgres-rag` | 🔴 **永久挂住** —— 不报错、不退出、不超时 |
| `docker compose up -d postgres` | 🔴 **同样挂住** |

**当时的推理（🔴 错的）**：

> 「`ps` 和 `inspect` 都秒回 ⇒ **守护进程是好的** ⇒ 那问题就在这个容器 / 这个卷上。」

⇒ 顺着这条线，我查了：磁盘空间（`df -h`，445 GB 可用）· 内存（`memory_pressure`，65% 空闲）·
VM 磁盘镜像（`Docker.raw` 60 G）· 端口占用 —— **全都是无关的**。

⚠️ **而且我一度怀疑是沙箱挡了端口**，还特意用 `dangerouslyDisableSandbox` 重跑了一遍才排除。
—— 这个猜想本身没错，只是**它在错误的前提下提出的**。

---

## 二 · 真相：**它读的是缓存，根本没碰 VM**

`~/Library/Containers/com.docker.docker/Data/log/host/com.docker.backend.log` 里两行说明一切：

```
[com.docker.backend.idle][I] cache << GET /containers/json?all=true      ← 就是这一句
{"docker":"running","dockerAPI":"stopped","state":"running"}             ← VM 里的 dockerd 没起来
[com.docker.backend.ipc][W] GET /ping (1.0004s): context deadline exceeded   ← 每秒一次，一直失败
[com.docker.backend.ipc][W] GET /vm/disk-usage (5m0.0007s): context deadline exceeded
```

⇒ **`docker ps` 之所以秒回，是因为它读的是 `com.docker.backend` 的内存缓存**
（日志里明写着 `cache << GET /containers/json`）。**它根本不碰 VM 里的 dockerd。**

**所以「有输出」只证明两件事**：后端进程活着、它记得住上次的容器列表。
**它⛔ 不证明 VM 活着、⛔ 不证明 dockerd 活着、⛔ 不证明那条命令描述的状态是此刻的状态。**

📌 同一份日志里那句 `"dockerAPI":"stopped"` 就是现成的反证 ——
**它在说「docker 引擎 API 是停的」，而我当时没去看这份日志。**

---

## 三 · 根因与修法

**根因**：重启 Docker Desktop 时，**旧的那个 `com.docker.backend`（`-watchdog -native-api`）没有退出**。
实测它已经跑了 **4 小时 54 分**（`ps -p 5465 -o etime`）。
⇒ 新实例撞上这个占着位置的僵尸，起不来 —— **这就是用户看到的「一直 error」**。

**修法**（实测有效）：

```bash
ps aux | grep "[c]om.docker.backend"    # 看 ELAPSED —— 很久的那个就是【重启前遗留的】
kill <pid>                              # 不退就 kill -9
open -a Docker                          # 干净重拉
# 之后：com.docker.virtualization 出现，~/.docker/run/docker.sock 重新出现
```

⚠️ 动手前先确认**没有在跑的容器**（`docker ps` 里全 `Exited` 才安全）。
⛔ **别急着 Reset to factory defaults** —— 那会毁掉镜像与数据卷，而本例根本不需要。

## 四 · 判据（**可打印** —— 下次别再看 `ps`）

```bash
tail -5 ~/Library/Containers/com.docker.docker/Data/log/host/com.docker.backend.log
# 出现下面任意一类 ⇒ 就是 VM / dockerd 的问题，⛔ 别再查容器、卷、端口：
#   {"docker":"running","dockerAPI":"stopped"}
#   GET /ping → context deadline exceeded
```

**另一条更快的判据**：**拿一个「必须碰 VM」的动作去试**，例如
`docker info` / `docker start <停着的容器>` / `docker run --rm hello-world`。
**它们挂住 ⇒ VM 是死的**；**`ps` 说什么都不作数。**
