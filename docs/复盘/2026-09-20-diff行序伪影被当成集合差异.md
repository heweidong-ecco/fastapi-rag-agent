## 二、教训(可复用的判断规则)

> 写成**下次能直接照做的规则**,不写感想。

1. **判「集合差异」用集合运算，不用行序对比工具。**
   问「B 里多了什么 / 少了什么」⇒ `comm -13` / `comm -23`（先规范化：去注释、去版本号、`sort -u`）。
   `diff` 回答的是另一个问题：「从 A 改到 B，改动了哪几行」—— **同一件事重排顺序，它会报成一次删除+一次新增。**

2. **`diff` 的输出里出现 `>`（新增）时，必须再问一句：这行是不是在另一处已经存在？**
   **最少成本的自检**：把那一行的**包名**拿去 `grep` 另一个文件。一行命令的事。

3. **在文件里写下"关于 X 的断言"之前，先 grep 该文件里已有的 X。**
   尤其 **`CHANGELOG`** —— 它只增不改，**历史条目就是权威答案**。
   （本仓已有同型前科：`docs/复盘/2026-09-17-写了必用表自己却没用.md`。）

4. **凡是"我要指出别人写错了"的断言，判据强度要再上一个台阶。**
   指出文档有错 → 若我错了，**是我让正确的文档显得错了**，代价比一般错误高一档
   （本条实际就发生了：把对的 FAQ 判成了错的，还写进了三处）。
