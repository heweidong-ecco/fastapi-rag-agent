# 复盘 · 2026-10-10 · **页面里那段内联 JS，没有任何门会去跑它**

> 📌 本文件记的是**过程错误**（不是决策）。决策在 `docs/decisions/`。
> **纪律**：复盘写「**为什么**」，不写「谁的问题」；每条错误必须有**根因**与**防错措施**。
> **分记原则**：根因不同就分记。⚠️ 同一天还有一件小事（`null` 拼成 `NaN`），
> **不单独立份** —— 它**是被同批写的守卫抓住的**（结构生效了），记在 §五。

- 范围：前端「demo 访客凭据」那一版（`DEC-143`）第 4 步 —— 8 个能力页接共用取凭据逻辑
- 参与：Claude（实现 + 验证）
- 结论：**「用例全绿」与「页面是活的」是两件事**，而这次露出来的**不是一次写错，是一个结构缺口**。

---

## 一 · 发生了什么

| # | 现象 | 测试信号 |
|---|---|---|
| **1** | 8 个能力页（对话 / 检索实验室 / 人工接管 / 成本看板 / 执行轨迹 / 工具与记忆 / 系统与执行器 / 运维探针）**全部是死的** —— 页面里那段内联脚本**一行都不执行** | 🔴 **982 条 pytest + 283 条 node 用例全绿**（与基线逐字一致） |

**怎么发现的（⛔ 不是被任何门发现的）**：按本仓「每刀收尾必起真服务」那条纪律，
起真服务 + **把页面打开** ⇒ 浏览器控制台第一行就是：

```
Identifier 'key' has already been declared
```

⚠️ 这句话是 `SyntaxError` 家族 —— **解析期**就死了，所以那段脚本里**一个函数都没定义**、
**一行都没跑**。页面上看到的是"接口没反应"，⛔ 不是"报错弹窗"。

---

## 二 · 根因（**两层，第二层才是值钱的那层**）

### 第一层 · 直接原因：经典脚本的顶层绑定**是全局的**

`app/static/js/session.js`（本次新加的共用文件）顶层写着：

```js
function key() { return localStorage.getItem(KEY_STORE) || ''; }
```

🔴 **浏览器里 `<script src>` 是经典脚本** ⇒ 那个 `function` 声明落成 **`window.key`**。
而 8 个页面**各自**又有一句 `const key = () => RagSession.key();`
（顶层 `const` 落进**脚本的词法作用域**，与已有的全局 `key` **撞上**）
⇒ `SyntaxError: Identifier 'key' has already been declared` ⇒ **整段作废**。

⚠️ 注意**撞的是两个不同的东西**：一个是 `window` 属性，一个是脚本级 `const` ——
它们**不是**"重复声明同一个变量"，但**照样是语法错**。这一层不直观，值得记。

### 第二层 · 结构原因 🔴 **页面里那段内联 JS，三层门没有一层够得到它**

| 层 | 它管什么 | 为什么够不到 |
|---|---|---|
| `app/tests/test_<页>_page.py`（各页守卫） | 页面**文本**：标记在不在、先后对不对 | **不解析 JS**（正则找字符串） |
| `app/static/js/*.test.js`（node 用例） | **`js/*.js` 自己**的纯逻辑 | ⛔ **从不加载页面里那段内联脚本** |
| 静态检查（ruff 棘轮） | Python | 只管 `.py` |

⇒ **那一段代码没有任何判据。** 它写错了，全世界的门都是绿的。
这正是本仓那句 **「门挂在别处，就等于没有门」** 的字面兑现。

---

## 三 · 为什么第二层比"这次写错了"值钱

⛔ **如果只修第一层（把 `key()` 挪进 IIFE），下次会以另一种形式再来一次** ——
内联脚本里任何一个语法错、任何一次全局撞名，**照样全绿**。

⭐ 判据很干脆：**「这道门能不能测出"页面是死的"？」** —— 当时**一道都不能**。
⇒ 所以修的是**那个缺口**，不是那一行。

---

## 四 · 防错措施（两条，**都做过反证检验**）

| # | 措施 | 落在哪 | 反证（取反 ⇒ 门会红吗） |
|---|---|---|---|
| **1** | 两份共用脚本（`session.js` · `cred.js`）**各包一层 IIFE**，对外**只留一个键**；并加守卫钉「只许漏一个全局」 | `app/static/js/session.test.js` · `app/static/js/cred.test.js` | ✅ 在 IIFE **外**加一句 `var __leak = 1;` ⇒ **当场红** |
| **2** | 🔴 **新增一道门**：每个页面**内联的 `<script>`** 都要过 `node --check` | `app/tests/test_web_pages.py`（它**扫目录**，新页面自动进网） | ✅ 塞一句撞名的 `const key = 1;` ⇒ **红**；写一个纯语法错 ⇒ **红** |

⚠️ **措施 2 的定位要说清**：它钉的是**最外圈、也最便宜**的那一层 —— **「它能解析吗」**。
⛔ 它**不**管逻辑对不对（那是各页用例 + `js/*.test.js` 的事）。
但「解析不了」这一类，**从今天起再也过不去了**。

## 五 · 判据（**可打印** —— ⛔ 只写"下次注意"没用）

```bash
# ① 页面里那段内联 JS，到底跑不跑得起来
./venv/bin/python -m pytest app/tests/test_web_pages.py -q -p no:warnings

# ② 共用脚本有没有往全局多漏东西（漏一个就可能撞死页面）
node --test app/static/js/session.test.js app/static/js/cred.test.js

# ③ 最外圈那把尺子（每个页面自己过一遍解析器）
for f in app/static/web/*.html; do
  ./venv/bin/python - "$f" <<'PY'
import re, sys, pathlib, subprocess, tempfile, os
for i, s in enumerate(re.findall(r"<script(?![^>]*\bsrc=)[^>]*>(.*?)</script>",
                                 pathlib.Path(sys.argv[1]).read_text(encoding="utf-8"), re.S), 1):
    with tempfile.NamedTemporaryFile("w", suffix=".js", delete=False, encoding="utf-8") as t:
        t.write(s); p = t.name
    r = subprocess.run(["node", "--check", p], capture_output=True, text=True); os.unlink(p)
    if r.returncode: print(f"{sys.argv[1]} 第 {i} 段 ❌ {r.stderr.strip().splitlines()[0]}")
PY
done
echo "↑ 一条都不打 = 全过"
```

## 六 · 可复用的判断规则

1. ⭐ **「只有把页面真打开才看得见」≠「只能靠人打开页面」。**
   能写成命令的就必须写成命令 —— 这次那条命令就是 `node --check`。
   📌 本仓同族：**「写不出命令的，就是还没核过」。**
2. ⭐ **一个信号在【每一层】都够不到时，修那一行没用，要补那一层。**
   判据：**「取反之后，有没有哪道门会红？」** —— 一个都没有 ⇒ **没有门**。
3. ⚠️ **修完看到"没变"，先分清「真没变」还是「你看到的还是旧的」。**
   本次第二次打开页面**仍然报同一个错** —— 那是**浏览器缓存**（静态文件没发 `Cache-Control`，
   浏览器按 `Last-Modified` 启发式缓存）。清掉缓存后一切正常。
   ⇒ 判据：**先 `curl` 一下磁盘上/服务真正吐出来的那份**，再下结论。
   📌 本仓同型前科：`git merge --ff-only` 报的「**Already up to date**」**是假的**
   （`origin/main` 这个本地 ref 根本没更新）⇒ 那条也是"拿一个没刷新的视图当事实"。
4. ⚠️ **守卫的靶子是"文本"时，它对"能不能跑"是瞎的** —— 同理，
   靶子是"某一段源码"时，它对"别处新加的东西"也是瞎的（本仓 `N14` 那族）。
