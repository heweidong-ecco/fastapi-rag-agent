## 一 · 三处（按发生顺序）

### ① macOS 的 `find -newermt` **不认相对时间**，静默返回 0 个

**我要判的事**：「Codex 有没有改过本仓的文件？」

**我跑的命令**：`find . -newermt "-3 hours" -type f …`

**结果**：**0 个文件** ⇒ 我差点写下「⛔ 没人动过」。

🔴 **根因**：**BSD 的 `find` 不认 `-time` 这类相对偏移** —— 它把 `"-3 hours"` 当**日期串**解析，
解析失败就**匹配 0 个**，而**退出码仍是 0**（不报错、不警告）。
⇒ 那次「0 个」的意思是「**这条命令根本没在工作**」，⛔ **不是**「没有文件被改」。

**我是怎么发现的**：写报告前顺手加了个**对照组** —— 拿一个**我确定刚改过**的文件再跑一次同一条件。
它**也没被匹配到** ⇒ 立刻知道是**尺子坏了**，不是世界干净。

**改法**：用**绝对时间**，并把对照组**写进命令**：
```bash
find . -newermt "$(date -v-3H '+%Y-%m-%d %H:%M:%S')" -type f -not -path "./.git/*" …
find api/static/web/index.html -newermt "$(date -v-3H '+%Y-%m-%d %H:%M:%S')"   # ← 对照组，应命中
```

### ③ `codex queue` 回一句 `Queued message …`，**那不是"它做了事"**

**我要判的事**：「任务发出去没有？」

**回执**：`Queued message 01a11eb2-… for thread 01a11ead-…` ⇒ 看着像"送达了"。

🔴 **实际**：那条 message id 在 `state_5.sqlite` 与 `thread_history_1.sqlite` 里**都搜不到**，
rollout 文件里也**没有** ⇒ 它待在**桌面端 app-server 的内存队列**里。
**最终事实**：Codex **收到了**任务，但**仓里一个文件都没改**（`git status` 空 · 无新 commit）。

⇒ **判分界**：**回执是"投递"的代理量，不是"执行"**。
真要判"对方动没动"，**只看仓**：`git status --short` + 有没有新 commit。

## 二 · 根因（一条，三处都成立）

> **拿「动作成功」当「结果正确」** —— 这句本仓 2026-09-21 就写过一次
> （`docs/复盘/2026-09-21-拿动作成功当结果正确.md`）。
> ⚠️ **今天三处的共同点是它更隐蔽的形态**：
> **那个代理量不但不等于结果，而且【静默】—— 它 0 报错、0 警告，退出码还是 0。**

| 处 | 代理量 | 它**本该**测的 |
|---|---|---|
| ① | `find` 匹配 0 个 | 「有没有文件被改」 |
| ② | `typeof === 'function'` | 「页面会不会 ReferenceError」 |
| ③ | `Queued message …` | 「对方有没有在干活」 |

## 三 · 判据（⛔ 写得出命令，才算学到）

1. **任何"扫了 0 个"的结论，先问一句「这条命令本身在工作吗」** ——
   跑一个**已知会命中的对照组**。本仓口径：**「空集合断言会一路绿着放行」**（`DEC-065` 那族）。
2. **门的断言要用"要防的那件事"本身，⛔ 不用它的代理量** ——
   放宽/收紧之后**必须做一次反证**（把要防的东西造出来 ⇒ 门要红）。
3. **注释里写路径**：通配符写 `<链>`，⛔ 别把「星号紧挨斜杠」那两个字符拼出来；
   **解释这个坑时也一样**。
4. **判断别的 Agent/系统"做没做"**：⛔ 不看它的回执，
   **只看我们这一侧的可验证痕迹**（`git status` / 产出物 / 命令输出）。
5. 🔴 **最有效的那条还是老话**：**把结论取反，再问「这条命令的输出会变吗？」** ——
   ⚠️ 今天 ①②③ 三处的答案都是「**不变**」。
