### 📌 四条的共同结构

```
我做完一个动作（写锚点 / 建索引 / 改一处 / 拆文件）
        ↓
我默认它【达到目的了】          ← ⛔ 缺的就是这一步
        ↓
没有做「以别人的视角验一遍」
```

**为什么会漏这一步**：因为我用的是**自己的视角** ——
「我写了 → 我读得到」「我建了 → 我知道在哪」「我改了 → 这处是对的」。
⇒ **而验收的视角是别人的**：**新会话读锚点 / 新人找地图 / 别人核口径 / 后来者查内容。**

## 二、教训(可复用的判断规则)

> 写成**下次能直接照做的规则**,不写感想。

### ⭐ 规则 1 · **做完一件"给人接手"的事 ⇒ 立刻以【接手人】的视角验一遍**

**判据**：
* 写了**锚点** ⇒ **从锚点开始，能不能走到"现在该干什么"？**
* 拆了**文件** ⇒ **拆掉的每一块，在别处还在不在？**（逐主题搜，不是抽查）
* 建了**索引** ⇒ **从最外层入口（README）出发，能不能走到它？**

**为什么**：**"我写的"和"别人读到的"是两个东西。**
锚点、索引、拆分后的文档 —— **它们的验收标准里都有"别人"这个变量**，而我四次都用了"我"。

### ⭐ 规则 2 · **建了一个"入口" ⇒ 必须同时问「谁指向它？」**

**判据**：新加一份**索引 / 入口 / 地图**后，**立刻搜一遍谁引用它**；
**没有引用 ⇒ 它是个孤岛。**

**为什么**：本仓对这件事有**明文纪律**：「**门挂在别处，就等于没有门**」
（`docs/复盘/2026-09-16-八个PR跳过了留痕门.md`）。
⚠️ **而这条纪律写在 `CLAUDE.md` 里，我每遍读它 —— 还是犯了。**
⇒ **「写在文档里」≠「会照做」** —— 与 Anthropic 官方那句
「**CLAUDE.md is context, not enforcement**」是同一条（见 `docs/规范/文档体系-外部依据.md` §1.5）。

### ⭐ 规则 3 · **改一处"口径" ⇒ 立刻全仓搜那个词**

**判据**：凡是**改一个说法 / 一个词 / 一个数字**（如"生产级"、"真中断"、"三种模式"），
**改完立刻 `grep` 全仓**，把所有同样的说法一起处理。

**为什么**：**口径类的错误不会只在一处** —— 它是因为**同一个错误认知**被写进了多个文档。
⇒ 改一处 = 只改了**症状**；**全仓搜**才是改**病**。
📌 实例 #3：我改了 `CLAUDE.md`，而 `ROADMAP` 里还有两处 —— **其中一处是我当天写的**。

### ⭐ 规则 4 · **"我这一批改了 N 处" ⇒ 那 N 处【各自】要能被验**

**判据**：一批改动**做完后**，**逐条**问「**这条我怎么知道它生效了？**」。
**答不出可打印的检查** ⇒ **那条还没做完。**

**为什么**：批量改动最容易"整体感觉完成、局部有漏"。
📌 与 `2026-09-21` 复盘规则 2（「批量替换后按**位置**核，别只数替换了几处」）**同族** ——
**但那条说的是"改"，这条说的是"验"。**
