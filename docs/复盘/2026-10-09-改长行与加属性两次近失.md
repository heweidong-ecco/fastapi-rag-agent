# 复盘 · 2026-10-09 · 两次**工具层面**的近失（⛔ 都不是"业务判断错"，是"动手方式差点毁了东西"）

> **怎么发现的**：两次都**当场**发现 —— 一次靠 `git diff --stat`，一次靠**门自己红了**。
> ⚠️ **两次的靶子都是"我以为我在做一件小事"** ⇒ 所以值得记，
> 因为**它们下次会以别的样子回来**（同一族在本仓已有多次记录）。

---

## 近失 ①：在**超长表格行**上做"插入"，`old_string` 写成了整行 ⇒ **整行被吞**

### 发生了什么

`ROADMAP.md` §③ 功能表里，每一行都是一整张表行、`<br>` 一路到底（`接管页` 那一行有 **1000+ 字符**）。
我要在它**前面**插一行新的，于是：

```
old_string = "<那一整行>"
new_string = "| **接管页**（…） | ✅ |"      ← ⛔ 只留了个行首，正文没了
```

`Edit` 忠实执行了「把这一整行替换成那个短头」。
⇒ **那一行的正文（含 `DEC-088` / `DEC-094` / 判据）在我手上消失了几十秒。**

### 怎么发现的

**不是**靠"我记得那一行很长" —— 是靠**下一步就跑了**：

```bash
git diff --stat ROADMAP.md        # ⇒ 输出为空（我明明改过它！）
```

**空输出**这个信号反过来了：说明我那次"替换"与随后的"还原"**正好抵消** ⇒
⇒ 那一刻我才去核"我到底改了什么"。

### 根因

**`old_string` 选得太长** ⇒ 长到"我以为我在锚定"，实际是在**声明要替换整行**。
⚠️ 而 `Edit` **不会因为"新旧长度差太多"而警告** —— 它按字面执行。

### 下次怎么做

1. 🔴 **在长行上做"插入"时，`old_string` 只取【锚点的尾部一小段】**（例：只取 `本行的数字以**现算**为准 |`），
   `new_string` = **那一小段 + 换行 + 新行**。⇒ 插入意图与替换意图**在写法上就分得开**。
2. 🔴 **改完**超长行**立刻跑 `git diff --stat <file>`** —— ⛔ 不是"看一眼觉得对"。
   （本仓原话：**「判据要能打印」** —— 这里的那条判据就是"diff 不为空"。）

## 近失 ②：给元素**加个 `id`**，把两条**无关的**结构型用例一起改成红的

### 发生了什么

`api/static/web/cost.html` 里两个面板要加 `id="cost-overview"` / `id="cost-budget"`（做锚点用）。
加完之后，`api/test_cost_page.py` 的**两条**用例同时红：

```
FAILED test_every_panel_declares_where_its_number_comes_from
FAILED test_each_panel_shows_a_boundary_notice_before_its_run_button
```

它们的正则写的是：

```python
r'<section class="panel" data-cost="[^"]+".*?</section>'
```

⇒ **`class` 与 `data-cost` 之间多了一个 `id=…` ⇒ 一条都匹配不到** ⇒
**切出 0 段** ⇒ 两条用例一起红。

### 怎么发现的

**门自己红的** —— 这一步是**对的**（本仓最想要的形态：错的东西**响亮**）。

### 根因

**判据钉了"属性的书写顺序"，⛔ 没钉"语义"**。
⚠️ 而"属性的顺序"**不是这个页面在保证的东西** —— 它就是**排版自由**。
⇒ 那条正则**测的不是它以为在测的事**（本仓那句：**取反之后输出照样不变 ⇒ 尺子歪了**）。

### 怎么改的（✅ 已改）

```python
r'<section class="panel"[^>]*data-cost="[^"]+"[^>]*>.*?</section>'
```

⇒ **不吃属性顺序**了。⚠️ **⛔ 没有降低严格度**：`class="panel"`、`data-cost="…"` 两个语义标记
**一个都没少**，只是**不再要求它们挨着**。

### 下次怎么做

1. 🔴 **写"按标记切段"的正则，一律用 `<tag[^>]*A[^>]*>` 这个形状** ——
   ⛔ **别写死属性的相邻关系**（HTML 里属性顺序**没有语义**）。
2. ⚠️ **门红的时候，先问「它红得对吗」** —— 这一次答案是"**红得对，但理由不是我想的那个**"：
   它红是因为**它自己的靶子歪了**，⛔ 不是因为页面坏了。
   ⇒ 处置是**把靶子改准**，⛔ **不是把用例删掉、也不是把 `id` 撤回去迁就它**。

## 一句话（两条合起来）

> **两次都不是"我不懂业务"，是"我以为我在做一件小事，而那个动作的【范围】比我想的大"** ——
> ① `Edit` 的范围是**整个 `old_string`**；② 正则的范围是**它钉死的那个形状**。
> ⇒ **判据**：动手之后**立刻跑一条能打印的命令**（`git diff --stat` / 那条用例本身），
> ⛔ 不是等收尾时才发现。
