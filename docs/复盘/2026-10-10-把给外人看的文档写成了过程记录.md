# 复盘 · 2026-10-10 · **把「给外人看的文档」写成了「自己看的过程记录」**

> 📌 本文件记的是**过程错误**（不是决策）。决策在 `docs/decisions/`。
> ⚠️ **一份复盘一个根因** —— 本份只管这一个。

---

## 一 · 发生了什么

`SECURITY.md` 被我写成 **253 行**，其中绝大部分是**过程记录**：

- 逐条列「**哪个缺口收掉了、怎么收的**」（改前是什么、改后是什么、哪几处、少一处就是假的）
- 一节「**变更记录**」（第四次 / 第三次 / 第二次 / 第一次做了什么）
- **⚠️ / 🔴 / ✅ / ⛔ 当结构标记**（⛔ 不是通行写法）
- 还有「**我实测三轮**」「**反证过了**」这类**自证语气**

业务方 2026-10-10 当场指出：

> 「**文档里面不要写过程记录**，过程记录如果需要移走。**联网搜索**别人项目的 SECURITY.md 写法，
> **不要自己编**，**不用 emoji** —— 这不是记录过程的地方。」

---

## 二 · 根因：**动手前没去看「这类文档别人怎么写」**

⛔ **不是"写多了"** —— 是**写到错的容器里去了**。
`SECURITY.md` 的读者是**外部报告者**，他要的只有三件事：**怎么报 · 支持什么 · 你做了什么/不做什么**。
而他**根本不关心**你上一版哪条缺口是怎么修的。

📌 **共同根源**：我把「**我这几轮干了什么**」当成了文档内容。
那是**我在想的事**，⛔ 不是**读者要知道的事**。

⚠️ **它为什么没被门拦住**：本仓的文档门只查**断链 / 孤儿 / 索引 / 长度**
—— ⛔ **没有一条能判"这份文档的写法对不对"**。
（⚠️ **这和「门只能测出它测的那件事」是同一族的**：能机械判的才交给门。）

---

## 三 · 后果（说清楚，⛔ 别只当"格式问题"）

1. **真信息被淹没** —— 「怎么报安全问题」这件事，原文**第一节就叫「报告问题」，但整节只有 10 行**，
   后面 240 行都是内部账。⇒ **读者要的那 4%，藏在 96% 的噪音里。**
2. **它占了「唯一权威」的位置** —— `docs/契约/版本与兼容.md` 把它描述成「**安全缺口**」、
   `docs/威胁模型.md` 写成「（缺口清单）」⇒ **别处照着它写**，错法会**传出去**。
3. **emoji 当结构标记** —— 那是**本仓内部**的书写习惯（复盘 / DEC / CHANGELOG 里到处是），
   ⛔ **但它不是给外人的文体的**。同一个符号在内部是"提醒"，在外面是"不专业"。

## 四 · 防错措施

| # | 措施 | 落在哪 |
|---|---|---|
| **1** | **写"对外文档"前，先找 2–3 份真实范例对齐结构**（⛔ 别自拟） | 本轮取的范例：GitHub 官方模板 · `nodejs/node`（38 KB，**全是政策**）· `microsoft/vscode`（543 B 最小范例） |
| **2** | **先问「这份文档的读者是谁」** —— 读者是外人 ⇒ **过程记录一律不进** | `SECURITY.md` 只留 5 节：Reporting / Supported Versions / Security Measures / Scope and Limitations / Disclosure |
| **3** | **搬走时逐项核「有没有丢」** | ✅ 核过：原「已收掉的」5 条在 `CHANGELOG.md` 里**都有**（`X-API-Key` 8 处 · `is_active` 13 处 · 隔离收口 54 处 · `127.0.0.1` 7 处） |
| **4** | **搬完要改【所有】描述它的地方** | 已改：`ROADMAP.md` · `docs/威胁模型.md` · `docs/契约/版本与兼容.md`（⛔ `CHANGELOG.md` 与 `docs/decisions/` 是**原始记录，不动**） |

**判据（可打印）**：

```bash
# ① 对外文档里不该有 emoji 当结构标记
grep -cE '⚠️|🔴|✅|⛔|📌|🆕' SECURITY.md          # ⇒ 0

# ② 不该有「我做了什么」的痕迹（第一人称过程语气）
grep -nE '我实测|我第一版|反证过|本次|本轮' SECURITY.md   # ⇒ 空

# ③ 修完要核：活文档里还有没有把它描述成【旧形态】的
#
#    🔴 写这条判据的过程本身踩了【四】个坑，⛔ 全记下来：
#    （a）`SECURITY.md.*缺口` 太宽 ⇒ 命中"**不再是**缺口清单"这类**在说这件事已改**的地方。
#    （b）**"在引用这条判据的地方"必须排除** —— 本复盘逐字引用了那串，于是自己命中。
#    （c）🔴 **最要命的一个**：我第一版写的 pattern 是 `SECURITY.md（缺口清单）` 与
#         `SECURITY.md | 安全缺口` —— 而**原串里 `SECURITY.md` 是带反引号的**
#         （`` `SECURITY.md` ``）⇒ 这两个 pattern **对旧串命中 0 处**
#         ⇒ **判据在改之前也是绿的**（"测的不是那件事"）。实测确认过（拿 `git show` 取改前原文当夹具）。
#    （d）`grep -rn … .` 在**本机不打 `./` 前缀** ⇒ 排除用的 `^\./` 锚**永远不匹配**。
#
#    ⇒ 定稿：用【实测对旧串敏感】的窄串 + 排除那三处"本来就该留旧词"的地方。
KEEP='^(docs/复盘/|CHANGELOG\.md|docs/decisions/)'
grep -rn "（缺口清单）\|列全缺口\|安全缺口（决定" --include='*.md' . | grep -vE "$KEEP"   # ⇒ 空
```

**双向验过（⛔ 不是"看着空"）**：

- **对改前原文**（`git show c7b3ca8:…` 当夹具）⇒ **命中 3 处** ⇒ 判据**对旧串敏感，不瞎**
- **对现在的活文档** ⇒ **空**
- 交叉验：宽词 `缺口清单` 会命中 `ROADMAP` 那句「不再是「缺口清单」」⇒
  **这正是必须用窄串的理由**（否则判据把自己的说明也算进去）

⚠️ **第 ③ 条的范围不能放大** —— 2026-09-29 栽过：第一版 grep 太宽，刷出 40 处噪音
（复盘 / CHANGELOG 里本来就该有旧词）⇒ **反而会让人不看**。
