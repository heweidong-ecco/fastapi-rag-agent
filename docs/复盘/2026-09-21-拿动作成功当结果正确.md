## 一、错误清单

### ① 盲替换命中了【注释】，真正的调用点没改到（PR #48 修的就是它）

- **动作**：改 `plan_execute.py`，给 7 个函数加 `user_name` 形参，用脚本做批量替换
  （`s.replace(old, new, 1)`，且**每条替换后都断言"旧串存在"**）。
- **脚本输出**：`✅ 全部 10 处替换完成` —— **没有报错**。
- **实情**：其中一条的旧串 `dynamic_input = generate_dynamic_input(step, context, user_goal)`
  **在 `:283` 的一行注释里也出现过**，而**注释在前** ⇒ `replace(..., 1)` 命中了注释，
  **真正的调用点（`:472`）原样没变**。
- **后果（静默）**：`generate_dynamic_input` 收不到 `user_name` ⇒ 那部分 token
  **全记在 `unknown` 头上** ⇒ **配额管不到真正用的人**。
  而"替换全部完成"的输出让人以为改好了。
- **是怎么被发现的**：**端到端实跑**之后查 `token_usage_logs`，看到
  `admin 5 条 / unknown 4 条` —— **不是靠代码审查，是靠看数据**。
- ⚠️ **静默**：不会报错、不会红。**只有"去查真实产物"才能发现。**

### ② 在 Python heredoc 里写了 ASCII 双引号，截断了字符串（**同一会话 3 次**）

- **动作**：`python3 - <<'PY' ... PY` 里写中文内容，句子里有 `比"收窄"更基本`。
- **实情**：那对引号是 **ASCII `"`**，而外层字符串也用 `"` ⇒ **字符串被提前截断** ⇒ `SyntaxError`。
- **后果**：**脚本整段没跑** —— 而我在看到 traceback 之前，**已经在心里当成"写好了"**。
- **3 次**：`待办登记`（`这不是"这条用例没用了"`）· `ROADMAP`（`比"收窄"更基本`）·
  `git commit` 的 reason 串。
- 📌 **前两次的教训我写了，第三次照犯** —— 说明"记住"不管用，要"**机制**"（见 §二）。

### ③ `git stash` / `pop` 丢了索引 ⇒ 提交几乎是空的（PR #51）

- **动作**：门禁脚本里做"有改动 / 无改动"对照，用了 `git stash` → 跑基线 → `git stash pop`，
  **然后 `git commit`**。
- **脚本输出**：`git commit` **退出码 0**，`git log` 也显示出那条提交。
- **实情**：`pop` **把索引丢成"未暂存"** ⇒ `git add -A` 白做了 ⇒
  **`git commit` 只提交了当时唯一还是暂存态的 1 个新文件（`DEC-029`）**，
  另外 **4 个文件（含那条新用例）根本没进去**。
- **后果**：**PR 合并了，但主干上没有那部分工作**。而我当时已经报了
  「已合并」「零回归 114 vs 113」—— **那 114 是【工作区】的数字，不是我推上去的树的数字。**
- ⚠️ **本仓同型第 2 次**：`docs/复盘/2026-09-17-reset-hard抹掉了未提交工作.md`。
- **是怎么被发现的**：**合并后按纪律核"内容在不在主干上"**（`git show origin/main:… | grep -c`）
  —— 那次核出 `origin/main 命中 0`，而工作区是 `1`。

## 二、教训（可复用的判断规则）

> ### 🔴 **一条根因，三条错误：拿「动作成功」当「结果正确」的判据。**

| # | 我用的判据（**错的**） | 应该用的判据 |
|---|---|---|
| ① | 「脚本说**替换了 10 处**」 | **按位置核**：`grep -n` 逐处看改的是哪一行 |
| ② | 「我**把内容写进去了**」 | **跑一次语法检查**（`compileall` / 直接跑脚本） |
| ③ | 「`git commit`**退出码 0**」 | **`git status` + `git show --stat HEAD`** 看**实际装了什么** |

**可复用的规则（下次直接照做）：**

1. ⭐ **改完必须"看结果"，不能只看"动作返回"**。
   —— 与 `verification-before-completion` 那条「**evidence before assertions**」是同一条，**我引用了它却没照做**。
2. ⭐ **批量替换之后，按【位置】核一遍**（`grep -n` 看命中在哪几行），
   —— ⛔ **别只数"替换了几处"**。**注释里也会出现同样的串。**
3. ⭐ **写了代码/脚本，先跑一次再说话** —— 哪怕只是一行 `compileall`。
4. ⭐ **`git stash` / `pop` 会丢索引** ⇒ **提交前【必须】重看 `git status`**，
   确认每行是暂存态（`M `）而不是未暂存（` M`）。
5. ⭐ **PR 合并之后，核"内容真的在主干上"** —— `git show origin/main:<文件> | grep -c <特征串>`，
   ⛔ **不要只信 `gh pr view --json state`**（那只说明"合并动作完成了"）。
6. **在 heredoc / 命令参数里写中文句子时**：**一律用「」『』，不用 ASCII 引号**；
   或者**写成临时文件再跑**（不拼字符串）。
