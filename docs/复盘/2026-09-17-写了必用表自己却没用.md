- **日期**：2026-09-17
- **类型**：过程错误（机制失效）
- **发现方式**：**业务方问了一句** —— 「切开点 3 是否涉及 skills 的调用，是否有使用 skills」

---

## 一、事实（transcript 硬证据，非印象）

业务方问的是**切开点 3**。我去 transcript 里核（不凭记忆）：

| 类别 | 切开点 3 期间 | 本会话（压缩后） | 工具 |
|---|---|---|---|
| `Skill` 真调用 | **1 次**（`留痕-checks`） | **6 次，全是 `留痕-checks`** | `grep '"type":"tool_use","id":"[^"]*","name":"Skill"'` |
| **superpowers 那 14 个** | **0 次** | **0 次** | 同上 |
| Agent 子代理 | **0 次** | 0 次 | `name":"Agent"`（那 11 次全在**压缩前**，是盘点与追 bug 那批） |

⚠️ **取数过程本身也踩了一次坑**：第一次 `grep` 我写成
`'"type":"tool_use","name":"Agent"'` —— 得 **0**。
但实际 JSON 是 `"type":"tool_use","id":"call_…","name":"Agent"`，**id 夹在中间**。
**我差点据此报了个错的「0 次」。** 换成正确模式才得到 11。
> 📌 这又是一次「**判据写法决定结论**」—— 与 `docs/规则草稿-规则必须绑定路径.md` 同一条道理。

## 三、根因：**表只有「触发条件」，没有「强制检查点」**

对比两件事，差别很清楚：

| | `留痕-checks` | superpowers A 级表 |
|---|---|---|
| 落点 | `ROADMAP.md` 的 PR 纪律 | `CLAUDE.md`（每会话自动加载） |
| 写法 | **「开 PR 前必须先跑 `/留痕-checks`」** | 「**如果命中必须用**」 |
| 性质 | **一个动作**（我必须停下来执行一件事） | **一句判据**（要我自行判断是否命中） |
| 结果 | ✅ **调用了 6 次** | ❌ **0 次** |

> ### **⇒「命中必须用」是一句判据，不是一个动作。没有哪个瞬间逼我停下来核对它。**

**所以表写了，但没接线。**

### 这与本项目已记过的两个错误**同构**

1. **`api/LEARNING_INDEX.md`** —— 定义过一整套治理格式，**全仓库 0 个文件使用、0 个文件引用它**
2. **8 个 PR 跳过留痕门**（`docs/复盘/2026-09-16-八个PR跳过了留痕门.md`）—— 门挂在别处，等于没有门

**这三次是同一个病：把机制写成【文字】，而不是【结构】。**
而 `Product/CLAUDE.md` 里已经写过这条教训：
> 「**文字是软约束，上下文长了之后基本不会遵守**」；**分库的隔离靠目录边界，是结构**

---

## 四、处置（不再只写文字）

**把 A 级 skill 绑到与 `留痕-checks` 同一个检查点上** —— 即 **PR 前那一刻**。
在 `ROADMAP.md` 的 PR 纪律里，紧挨着 `/留痕-checks` 那条，列出**在该时点应当核对的 A 级 skill**，
并要求**逐条写「调了 / 未命中 / 命中未调（说明）」**。

> **关键区别**：从"我应当记得判断" → **"PR 前必须逐条写出来"**。
> 前者的产出物上**看不出来**（本复盘就是证据）；后者**在 PR 里看得见**。

---

## 五、教训一句话

> **一条只在"我应当记得判断"里的规则，等于没有规则。**
> **要问的不是"写清楚了吗"，而是"哪个瞬间会逼我停下来执行它"。**
