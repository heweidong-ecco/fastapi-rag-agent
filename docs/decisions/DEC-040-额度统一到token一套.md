## 决策事项

本仓**同时存在多套额度口径**，单位不同、且**互不知情**：

| # | 口径 | 单位 | 落点 | 拦在哪 |
|---|---|---|---|---|
| ① | **请求次数** | 次/天 | `permission.ROLE_QUOTA`（FREE 100 / PREMIUM 10000 / ADMIN 无限） | `main.py` 的 `QuotaMiddleware` ⇒ 429 |
| ② | **token** | token/天 | `token_tracker.ROLE_TOKEN_BUDGET`（FREE 10000 / PREMIUM 100000 / ADMIN `inf`） | `_invoke_llm` ⇒ `QUOTA_EXCEEDED` |
| ③ | **金额** | 元 | `token_tracker.MAX_SINGLE_CALL_COST` / `MAX_THREAD_COST` | `check_multilevel_budget` |

**`DEC-029` 已实测**：①② 的实际限额**差 35 倍** ——
`plan_execute` 单次 ~3346 token ⇒ 按**次数**能跑 100 次、按 **token** 只能跑 **~3 次**。
**实际生效的是 token 那套，次数配额根本用不完。**

### 为什么现在要定

**R1 四层限额（B7–B10）还没落地** —— 一旦落地，会变成**三套**。
⇒ **必须在 B8/B10 动手之前把口径定死**，否则「会话级」「全局日级」各自挑一套口径，**又是三处真相**。

## 备选方案

| 方案 | 一句话 | 评价 |
|---|---|---|
| **甲 · 统一到 token 一套**（**采纳**） | 次数配额**废掉或降级为「接口权重」**；所有限额一律以 token 计 | ✅ 与 ② 的量纲一致；③ 的"元"是**同一物**的不同单位（`PRICING` 可换算），不算第二套 |
| 乙 · 保留两套但打通 | 让次数配额按"接口贵不贵"加权，与 token 对齐 | ⛔ 要**维护两套的换算关系** ⇒ 换算率一改就再次脱节；本质是**把不一致推后** |
| 丙 · 先不动 | 维持现状 | ⛔ **加 R1 四层后变三套**，且 `ROLE_QUOTA` 对 `plan_execute` 形同虚设（**已经形同虚设了**） |

**业务方 2026-09-30 原话**：

> 「**甲 · 统一到 token 一套**」

## 决策与理由

**甲。** 三条理由：

1. **② 已是实际生效的那套** —— 统一到它，**行为变化最小**（次数配额本来就没拦住过什么）。
2. **① 的语义已经错了** —— "每天 100 次"对 `plan_execute`（单次 9 次 LLM 调用）**等于没管**；
   而同一个数对 `/health` 这种轻接口**又过严**。**"次数"这个量纲本身就不适合 LLM 服务。**
3. **③ 不是第三套** —— `元 = token × 单价`，`PRICING` 就是那个换算表。
   ⚠️ 代码注释 `token_tracker.py:665` 已写明「**别统一掉**」—— 指的是**第一二级用元、第三级用 token**
   这个**呈现选择**，**不是**指"存在两套配额"。两者不矛盾。

### 落地含义

| # | 做什么 | 落点 |
|---|---|---|
| ① | 新建 `api/token_config.py`，**额度常量的唯一来源** | ①a · Task 2（B7） |
| ② | `permission.ROLE_QUOTA` **降级为「接口权重」** —— **不删** | ①b · Task 6（**最后**） |
| ③ | `admin` 去 `inf` ⇒ **= `premium` = 100000/天**（业务方 2026-09-30 裁） | ①a · Task 2 |
| ④ | B8 会话级 / B10 全局日级，**一律以 token 计** | ①b |

**⚠️ ②「不删」的理由**：`QuotaMiddleware` **还挂在它上面**（`api/main.py`）。
删常量 = 中间件立刻崩。⇒ **先让 token 那套接管（B8/B10 落地），再降级它** —— 见下方「顺序陷阱」。

### 🔴 顺序陷阱（本条是 ①b 的开工依据）

**「降级旧机制」和「上线新机制」必须【新先旧后】。**

`决策一` 要撤掉次数计数，而 token 那套的**会话级（B8）与全局日级（B10）在 ①b 里**。
⇒ 若**先撤次数、后接 token** ⇒ **中间出现一段"谁都不拦"的窗口** ——
一个能上线跑的服务**开了个日限额的洞**，且**没人会立刻发现**。

📌 **同型前科**：`docs/复盘/2026-09-20-同源的两个输入不能互相作证.md` —— 讲的也是「两个都在，但谁都不真拦」。

## 反悔成本

**低。** 取值全靠 `api/token_config.py` 一处：
回退 = 把 `ROLE_QUOTA` 改回数字 + 恢复 `QuotaMiddleware` 的计数分支。
（⚠️ `get_user_quota()` 在降级后会**抛异常**，正是为了**逼调用点显式处理** —— 不会静默变成别的语义。）

## ⬜ 遗留 / 未决

1. 🔴 **`ROLE_QUOTA` 降级后到底怎么用**（当权重？还是干脆删？）—— **未定**。
   本 DEC 只定「**它不再是配额**」，**怎么用它留到 ①b · Task 6 时定**。
2. **角色档位体系**（分几档 / 各档多少）—— 业务方 2026-09-30：「**还没有想好**」⇒ **留第二轮**。
   ⚠️ **理由**：`决策一` 本来就要动 `ROLE_TOKEN_BUDGET` ⇒ **此时定型 = 白做**。
3. **`admin` 的 `inf`** ⇒ 本轮只**换值**，⛔ **不重塑档位结构**。
4. **全局日级（B10）必须独立于角色统计** —— 因为 per-user 检查**永远看不到「大家加起来超了」**
   （`admin` 去 `inf` 只是**顺带**缓解，**不是** B10 的替代）。
