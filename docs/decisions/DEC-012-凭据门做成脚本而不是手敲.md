# 决策记录:DEC-012 · 凭据门做成脚本,而不是继续手敲 grep

- 日期:2026-09-17
- 状态:已采纳
- 关联:`scripts/check_secrets.sh` · `ROADMAP.md` PR 纪律 · `CHANGELOG.md` · `docs/CODE_INVENTORY.md`

## 决策事项

一句话:凭据扫描此前是**我每次临时手敲的一行 grep**。它**报过命中,但 commit 照样落地**。
**要不要把它固化成一道真正的门?固化成什么形态?**

## 背景与约束

**事故(2026-09-17)**:我把 **3 个历史泄露凭据的字面量写进了 PUBLIC 文档**。
手敲的 grep **报了 `hits=1`×3** —— **但脚本没中止,commit 落地了**,靠 `git commit --amend` 才救回(**未 push**)。

**同一事故的第 3 次**:起草 PR 正文时我又写了一遍,**被 Claude Code 的外部分类器拦住**。
⇒ **是外面的门救的,不是我自己的门。**

**根因(本仓第 N 次同型)**:**手敲的 grep 是【报告】,不是【门】** —— 它打印,不中止。
与 `LEARNING_INDEX.md`、8 个 PR 跳过留痕门、A 级 skill 命中 0 次**是同一个病**:
**把机制写成判据,而不是动作。**

**约束**:脚本**自身不得含任何凭据字面量** —— 否则它自己就是新的泄漏源。

## 备选方案

| 方案 | 思路 | 优点 | 缺点 |
|---|---|---|---|
| **甲** | **仓内脚本,命中即 `exit 1`**;凭据从 `.env` 现读,存量黑名单从 gitignored 文件现读 | 成为**动作**;不含凭据;可被 PR 纪律引用 | 需要维护 `.secret-denylist` |
| 乙 | 继续手敲 grep | 零成本 | **就是本次失败的形态** |
| 丙 | 放进 CI(提交后跑) | 自动 | ⛔ **太晚** —— 一 push 就已外泄,「删了 ≠ 没发生」 |
| 丁 | 用 `pre-commit` hook | 最难绕过 | 本项目无该基建;且改了别人 clone 后的行为 |

## 评估标准

是否构成**动作** / 脚本自身是否安全 / 拦截时机(提交前 vs 提交后) / 维护成本。

## 方案对比

**丙被否的关键**:本仓是 **PUBLIC**,而**泄漏的不可逆性**在"推上去"那一刻就锁死了。
**必须拦在 commit 之前**,不能在 CI 里事后发现。

**乙是本次事故的形态本身**,无讨论价值。

**甲 vs 丁**:丁 更强,但会改变任何人 clone 后的 git 行为;甲 只需跑一条命令,且能被 PR 纪律引用(与 `/留痕-checks` 挂同一时点)。

## 最终决策 + 理由

**✅ 采纳甲。**

三条设计约束:
1. **脚本自身不含凭据** —— 真实凭据读 `.env`;存量黑名单读 `.secret-denylist`(**该文件也被 gitignore** —— 否则就是拿泄漏源去防泄漏)
2. **报告只写【名字】,绝不写【值】** —— 打印了值,这份日志本身就成了新的泄漏源
3. **只扫新增行** —— 见下

## 影响与后续行动

- 新建 `scripts/check_secrets.sh`;`ROADMAP.md` 的 PR 纪律第 ③ 项改为**跑它**,并注明**不许再手敲 grep**
- 🔴 **门第一次真上岗就抓到了它自己的设计缺陷(v1)**:v1 扫**整份 diff**(含 `-` 删除行),
  于是**我在删掉一个存量字面量时,门报了红** —— 因为我正在删它。
  **"删掉密钥"是好事,不该拦。** ⇒ 已改为**只扫新增行**。
  📌 **泄漏只可能发生在"写进去"的时候** —— 这是 v1 没想清楚的一句话。
- 验证四条:**本次提交 exit 0** · 删除行不触发 · 通用模式 exit 1 · **真实凭据 exit 1 且只报名字**

## 反悔成本

**低。** 删掉脚本、退回手敲即可。
⚠️ 但那就退回"报命中却照样提交"的状态 —— 而这**已被证实发生过一次**。

## ⚠️ 更正(2026-09-17 同日补)—— 本文「验证四条」那一段**不足以支撑"已验证"**

**本文上方「影响与后续行动」里写的**:

> 验证四条:**本次提交 exit 0** · 删除行不触发 · 通用模式 exit 1 · **真实凭据 exit 1 且只报名字**

**问题:那四条每一条都只跑了【一次】。**

**当天晚些时候发现:这个脚本自建起就是一枚硬币** ——
三处判定写成 `printf '%s' "$X" | grep -q…`,而 `grep -q` **命中即退出**会让上游 `printf` 收到
**SIGPIPE(141)**,`set -o pipefail` 再把整条管道**上升为失败** ⇒ `if` 判成"没命中" ⇒ **命中被静默丢弃**。

| 同一份暂存内容 | 结果 |
|---|---|
| 修复前连跑 **20** 次 | **拦住 11 · 漏报 9** |
| 修复后连跑 **30** 次 | **拦住 30 · 漏报 0** |

⇒ **那四条"验证通过",是四次单跑恰好都落进了"拦住了"的那一半。**

手敲的 grep 是**确定性地**不中止,而脚本是**概率性地**工作;**概率性 > 确定性为零**,
且 v4 修复后已恢复确定性。
