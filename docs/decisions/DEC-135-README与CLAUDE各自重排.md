## 三 · 决策点 2 · **README 的顺序**

按**标准 README** 排：**简介 → 快速开始 → 核心功能 → 模型端点 → 技术栈 → 架构 →
性能目标 → 评估 → 已知限制 → 文档导航 → License**。

🔴 **一处不能按"文档习惯"排**：**「快速开始」必须在前面**（原来它在第 149 行，前面压着
性能目标 / 架构 / 技术栈 / 功能 / 评估五节）—— **clone 下来的人第一件事是"怎么跑起来"，不是"你的架构多漂亮"**。

## 四 · 决策点 3 · **CLAUDE.md 的编号怎么收**

改前是**嵌套错乱**的（`②` 的引用块里长着 `③`、`④`，而 `# 🔴🔴🔴` 是 H1）。
⇒ 收成**八个平级章**：一 最高判据 · 二 先读哪份 · 三 主线与终点 · 四 两条约束 ·
五 推送节奏 · 六 判据纪律 · 七 更新 spec · 八 skills 表。

🔴 **保住一条硬约束**（文件里自己写着的）：
**「三个直接入口必须留在顶部」** —— 理由：**新会话常常只读顶部就动手**，入口写在下文 = 等于没写。

⚠️ **顺带去掉一处重复**：改前「三个直接入口」与「最常去的三个入口」**内容相同、出现两遍** ⇒ 合成一处。
（本仓立场：**一份内容只在一处**。）
