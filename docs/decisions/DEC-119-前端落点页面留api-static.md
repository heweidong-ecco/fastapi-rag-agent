## 二 · 🔴 硬技术约束：**移出去，镜像里就没有它**

**判据（可打印）**：

```bash
grep -n -A3 '^  api:' docker-compose.yml     # ⇒ build: context: ./api
grep -n 'COPY . \.' api/Dockerfile           # ⇒ :96  WORKDIR /app 之后再 COPY . .
```

⇒ **Docker 只能 `COPY` 【构建上下文内】的文件**，而上下文 = **`api/` 一个目录**。
⇒ **仓根的 `frontend/` 在上下文之外** ⇒ 就算把页面搬过去，**镜像里也不会有它** ⇒ 容器起来**页面 404**。

**要走"搬"这条路，必须连着做五件**：

| # | 改什么 | 代价 |
|---|---|---|
| 1 | `build.context: ./api` → `.`（仓根） | 🔴 **构建上下文瞬间变成整个仓** |
| 2 | **新建仓根 `.dockerignore`** | ⛔ 现在**没有**（只有 `api/.dockerignore`）⇒ 不加的话 `venv/`（几百 MB）· `logs/` · `.git/` · `testdata/` **全被送进 Docker daemon** |
| 3 | 重排 `api/Dockerfile` 的 `WORKDIR` / `COPY` | `COPY . .` 会变成"把整个仓拷进 `/app`" ⇒ 路径全变 |
| 4 | `main.py:783` 的 `app.mount(...)` 指向 `../frontend` | 应用装配改口径 |
| 5 | 4 条 302 跳转 · `ci.yml` 的 node glob · **5 个测试文件** · 4 份 spec | 机械但**面很宽** |

⚠️ **还有一条连带的**：`fastapi-rag-agent:latest` 这个镜像名被
**`agent-eval-gate` 的评测 harness**（`tools/sut-harness/run_sut.sh`）依赖，而它
**只 `docker run`、从不 `build`** ⇒ **构建方式一变，那边的镜像语义跟着变**。

## 三 · 裁定：**页面留在 `api/static/`**

**理由一句话**：**这两类是【生命周期不同】的东西，⛔ 不该因为名字像就并到一起。**

| | `api/static/` | `frontend/` |
|---|---|---|
| 是什么 | **运行时资源** —— 跑起来要用的页面/JS/CSS | **设计资产与规范** —— 人看的 |
| 进镜像吗 | ✅ **随 `api/` 一起进**（`COPY . .`） | ⛔ **不进**（在构建上下文外） |
| 谁用 | **服务进程**（`app.mount("/static", …)`） | **人**（读规范、看风格稿） |
| 改了它 | **要重新构建镜像** | 不影响运行 |

## 四 · ✅ 最终路径（业务方要的那一句）

```
api/static/                       ← 🔴 【页面与运行时资源】都在这（随 api/ 进镜像）
├── app.css                       ← 共享样式表（设计系统的实现）
├── web/                          ← 4 个面向人的页面
│   ├── chat.html                 ←   GET /chat
│   ├── approvals.html            ←   GET /approvals
│   ├── trace.html                ←   GET /trace
│   ├── eval.html                 ←   GET /eval（占位页 · DEC-097）
│   ├── eval_gate.html            ←   被 eval.html 引用的子页
│   └── websocket_test.html       ←   调试页
└── js/                           ← 3 个纯逻辑模块 + 3 份 node 用例

frontend/                         ← 🔴 【设计资产与规范】（⛔ 不进镜像、不参与构建）
├── README.md                     ← 设计系统规范（token · 排版 · 组件 · 分页 · 红线）
└── *.fig                         ← 风格稿原件（⛔ 已 gitignore · §六）
```

## 五 · 备选与反悔成本

| 决策点 | 备选 | 为什么没选 | 反悔成本 |
|---|---|---|---|
| **落点** | **甲（选）** 页面留 `api/static/` · `frontend/` 放规范 | — | **低** —— 改回来就是执行 §二 那五件 |

| | 丁 `frontend/` 放源、构建时拷进 `api/static` | ⛔ 引入**构建步骤** —— 与本仓「**全仓无构建**」的红线正面冲突（`frontend/README.md §七`） | — |

## 六 · ⛔ 本裁定**没有**改变的

1. 🔴 **风格稿 `.fig` 仍⛔ 不入库**（8.6 MB · 别人的模板 · `fig-kiwi` 解不出 token）——
   要留的是 `frontend/README.md` 里那套 **token / 排版 / 组件**（见那份 §二）。
2. 🔴 **`.fig` 仍在仓根 `frontend/`**（业务方放的位置）—— 本裁定**⛔ 不搬它**。
3. ⚠️ **设计系统仍是"落地第一步"** —— 只有 `chat.html` 接了 `app.css`；
   另外 4 个页面**仍是各带内联 `<style>`**。
