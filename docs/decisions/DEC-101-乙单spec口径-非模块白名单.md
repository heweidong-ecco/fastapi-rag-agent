## 一 · 这条要裁什么

乙单要处置 **30 个没有 spec 的模块**，其中 **3 个**（`api/preprocess.py` · `api/plan_constraints.py` ·
`api/evaluate_with_ragas.py`）**根本不是产品模块，是手动 / 离线脚本**。

> **裁单原文**：「给"**不是模块的东西**"建 spec，等于**为了让计数器归零而造文档** ——
> 这与本表那句「**这是【信息】，不是债**」**正好相反**。」

⇒ 判 **从对账口径里移出**。本 DEC 记的是**用什么办法移出**，以及**为什么不许改成自动判**。

---

## 二 · 🔴 本 DEC 存在的主要理由：**机械规则被实测证伪**

原打算写成规则：**「没人 import 它 ⇒ 它不是模块」**（听着像"可打印的判据"，比白名单优雅）。

**实测把它否了。** 全仓**零 import 的是 5 个，⛔ 不是 3 个**：

| 文件 | 零 import？ | **实际上是** |
|---|---|---|
| `api/preprocess.py` | ✅ | **手动脚本**（docstring 自己写着「运行 `cd api && python preprocess.py`」） |
| `api/plan_constraints.py` | ✅ | **手动脚本**（同上；原名 `test_plan_constraints.py`，它**不是 pytest 用例**） |
| `api/evaluate_with_ragas.py` | ✅ | **RAGAS 离线评测脚本**（有 `__main__`，不在服务路径上） |
| `api/browser_tools.py` | ✅ | 🔴 **是模块** —— 两个导入点（`api_v1_agent.py:44` · `mcp_server.py:19`）**都被注释掉了**，等 chromium ⇒ **停放的能力**，不是脚本 |
| `api/tools_with_cache.py` | ✅ | 🔴 **是模块** —— 业务方 2026-10-07 裁：「**⛔ 不删，要接回 LangGraph 调用链**」 |

⇒ 机械规则**把「脚本」与「模块，只是没接上」混成一类**。
**"没人用"和"不是模块"是两件事**，而这两件事在 `grep` 下**长得一样**。

**判据（可打印，与上表同源）**：`bash scripts/spec_status.sh` 的 **`🧩 非模块脚本`** 一行 —— 现在是 **3**；
若当年那条机械规则生效，它会打成 **5**（把停放/待接的模块一起吞掉）。

## 三 · 裁：**白名单 + 两条自检 + 单一来源**

### 3.1 白名单：逐条给理由，⛔ 不给一个裸名字

`NON_MODULE_FILES = {名字: 一行理由}` —— 理由**写在表里**，因为它就是"为什么它不算模块"的证据。

### 3.2 自检：白名单**不许静默过期**（本仓立场：「**从不命中**」与「**没人违规**」在机器痕迹上一样）

| # | 自检 | 命中意味着 |
|---|---|---|
| ① | 表里的名字**必须还在** `api/` 下 | 文件删了 ⇒ 白名单烂了 |
| ② | 表里的名字**不许有 spec** | 有 ⇒ 有人给了它"模块"待遇，**两边口径打架** |

⚠️ **实测过它们【能红】**（⛔ 不是"写了就算"）：往副本里塞
`__no_such_file__` 与 `static_frontend`（后者**已有 spec**）⇒ 两条 🔴 **各按预期打出**。

### 3.3 单一来源：第 ④ 道门**去问脚本**，⛔ 不自己再存一份名单

🔴 **改前是个真缺陷**：那道门自己有 `NOT_A_MODULE = ("conftest.py",)`，
**看不见** `NON_MODULE_FILES` ⇒ 新增一个脚本人**过不了门、又不知道怎么过**，
只剩"⛔ 绕门（`--no-verify`，禁止）"或"**为一个脚本造一份假 spec**"两条路 —— 两条都坏。

⇒ 改成 `non_module_files()` **现调** `bash scripts/spec_status.sh --non-modules`。
**理由是本仓的现成教训**（`DEC-051`）：**一个名字两个来源必然漂移，而漂移是静默的。**
⚠️ **读不到就返回空集**（= 退回"一律要求 spec"）—— **⛔ 不猜、不放过**：
放过的代价是"悄悄少拦一个"，而那与"本来就没这条门"在机器痕迹上完全一样。

## 五 · 边界（⛔ 别把本 DEC 读成"乙单做完了"）

1. 🔴 **本 DEC 只管乙-3 的 3 个** —— **乙-1（9 个写 spec）· 乙-2（17 个不写）· 乙-4（1 个）不在此**。
2. 🔴 **`🔴 没 spec` 现在是 27，⛔ 不是 0** —— 移走 3 个只让它从 30 变 27。
   ⚠️ **裁单里写的那句「⇒ 判据变成 `🔴 没 spec 0`」【算不过来】**（30 − 3 = 27）——
   **该表述已作废**，见 §六。
3. 🔴 **白名单只是"它不是模块"，⛔ 不是"它没问题"** ——
   这 3 个脚本**自己没有测试、也没人跑过它**，那是另一件事（本 DEC 不涉及）。
4. ⚠️ **`api/static/` 那条 `NON_PY_MODULES` 与本节是两回事** ——
   那条管「**模块在别处**（非 `.py`）」，本条管「**根本没有这个模块**」。

## 六 · 🔴 顺带发现：裁单乙-3 那句「判据变成 `🔴 没 spec 0`」**算不过来**

`裁单` §乙-3 原文：「移进非模块白名单 ⇒ **判据变成 `🔴 没 spec 0`**」。

**实际**：30 − 3 = **27**。**移走 3 个到不了 0。**

要让 🔴 真的到 0，**还必须给乙-2 那 17 个（+ 乙-4 那 1 个）一个【显式处置】**——
它们**是模块**，只是裁定"不写 spec"。**"不写"是个决定**，而**"🔴 缺"在 README 里的含义是"还没人核过"**
（原文：「`spec` 列写「🔴 缺」的，就是"**还没人核过**这个模块做到哪" —— 那本身就是信息」）。
⇒ 核过了、裁定不写，就**不再属于"还没人核过"**，**不该继续占着 🔴 那一格**。

**⛔ 本 DEC 不做这件事**（那是乙-2 的落点，且"用什么机制表示『已核・不写』"要业务方点头）。
**⇒ 本条留作【欠账】登记**：🔴 **乙单收尾时，`🔴 没 spec N` 要能到 0；到不了就说明还差一个处置口径。**
