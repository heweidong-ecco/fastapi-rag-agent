## 二 · 决策点 1 · **装哪些工具**

业务方问「**这两个工具你都需要吗**」⇒ **答：不需要。**

🔴 **D2 与 Mermaid 是两套 DSL**，装两个 ⇒ 每张图都要先决定"用哪套"，**维护面翻倍**，而收益只是布局略好。
⇒ **只装 Mermaid**（业务方已定），**D2 不装**。

⚠️ **一处要如实说的**：`DEC-136` 里我写过「⛔ 不装 graphviz / mermaid CLI」，
**那条现在被推翻** —— 理由是同一条：「**别为出图给本机加依赖**」当时被我摆到了「**用对工具**」之上。

## 三 · 决策点 2 · **怎么装（省掉 150 MB 的重复下载）**

`mermaid-cli` 依赖 puppeteer，默认会**自己下一份 Chromium（~150 MB）**。
🔴 **本机已有一份**（Playwright 的缓存：`~/Library/Caches/ms-playwright/chromium-1228/`）⇒ 复用它。

```bash
PUPPETEER_SKIP_DOWNLOAD=true npm i -g @mermaid-js/mermaid-cli
```

⚠️ **`出图.sh` 里 Chromium 路径【自动探测】**（先 Playwright 缓存 → 再 `/Applications`），⛔ **不写死版本号** ——
写死的话 Playwright 一升级换了目录名，脚本就**静默跑不了**（本仓对"静默失败"有明文忌讳）。

## 四 · 🔴 决策点 3 · **图里只放【结构】，说明放 README**（**这条是踩出来的**）

改 `.mmd` 的过程里，**布局出了四轮问题**，每一步都实测过：

| 试法 | 结果 | 比例 |
|---|---|---|
| 长标签塞进节点 + 三个互不相连的子图 | 中间一大片空 | — |
| 9 节点一条 `LR` 长链 | **横条，读不了** | **5.93** |
| 同上，子图改 `direction TB` | **竖条，读不了** | 0.24 |
| 两个子图**之间连边** | **被拉成横条** | **12.83** |
| 父 `TB` + 子图 `direction TB` | ⚠️ **子图的 `direction` 被忽略** | — |
| ✅ **父 `LR` + 子图 `TB` + 子图之间不连边** | 两列竖排，可读 | ✅ |
| ✅ **分叉图**（起点 → 两条链 → 同一结论） | 可读 | ✅ 1.40 |

🔴 **结论（写进 `图源/CLAUDE.md`）**：
- **节点标签一长，Mermaid 的自动布局就把图撑散** ⇒ **图只画结构，说明写进 README 的表**
- **目标比例 0.9–1.7**，用 `PIL` 量
- 三个排布坑：**子图之间别连边** · **父 `TB` 会让子图 `direction` 失效** · **`wrappingWidth` 太小会在节点里断词**

⚠️ **换句话说**：`DEC-136` 那种"把说明也塞进图里"的做法，**在 Mermaid 上直接不成立** ——
这从另一面证明**做法要换**，⛔ 不是"换个渲染器"。
