# 决策记录：DEC-068 · **未登记角色的兜底日预算 `100_000` → `10_000`** —— 兜底不许等于最高档

| 项 | 内容 |
|---|---|
| **状态** | ✅ **已实施**（2026-10-04） |
| **触发** | 业务方 2026-10-04 裁 **「丁 · 同意你的建议，做好记录」** |
| **类型** | 🔴 **安全取向收口**（fail-open → fail-closed）+ ⚙️ **行为变更**（**未登记角色**的额度降 10 倍） |
| **落点** | `api/token_config.py`（一行值）· `api/test_token_config.py`（**+3 条守卫**）· `docs/契约/环境变量.md` · `docs/specs/token_tracker.md` |

---

## 一 · 它是什么

```python
# api/token_config.py（改前）
ROLE_DAILY_TOKEN = {"free": 10_000, "premium": 100_000, "admin": 100_000}
DEFAULT_DAILY_TOKEN_BUDGET = _int("DEFAULT_DAILY_TOKEN_BUDGET", 100_000)   # ← 兜底
```

而 `api/token_tracker.py:374` 是：

```python
return ROLE_TOKEN_BUDGET.get(role, DEFAULT_DAILY_TOKEN_BUDGET)
```

⇒ **兜底值不是摆设，它是这条 `.get()` 的落点**：只要 `role` 不在那三个键里，
这个数字**就是**用户的日预算。

**改前的实际取值 = `100_000` = `premium` = 最高档。**

---

## 二 · 为什么这是错的（⛔ 不是"数字不合适"，是**取向反了**）

**角色名一旦对不上，用户拿到的不是"少一点"，是"最多"。**

三条都能走到那里：

1. **角色名拼错** —— `get_user_role()` 返回的字符串与 `ROLE_DAILY_TOKEN` 的键对不上；
2. **新增角色忘了登记** —— `permission.UserRole` 加了成员，额度表没跟着加；
3. **将来 `get_user_role()` 接上 DB 之后**（`DEC-046` §遗留 4，目前挂起）——
   从库里读回来的角色字符串**多一个空格 / 大小写不同**，就静默落进兜底。

🔴 **而这三条共同的形状是：不报错、不告警、日志里看不出来。**
用户只是**莫名其妙拿到最高额度**。

📌 **与本仓一路的取向正好相反**：

| 处 | 取向 |
|---|---|
| `DEC-040` / `DEC-046`（额度统一到 token 一套） | 单位**必须唯一** —— 宁可删掉一套，也不许两套并存 |
| `DEFAULT_MODEL_PRICING` 那段注释 | 兜底价**偏高估**（偏保守） |
| `DEC-051`（审批白名单） | 名字不存在 ⇒ **拒绝启动**（⛔ 不是"当作没问题"） |
| **本处（改前）** | 🔴 **兜底 = 最高档** ⇒ 出错时**多给** |

⇒ **改后**：兜底锚在 **`free` = 现存最低档**，即**出错时少给**。

⚠️ **注意这不是"把 `100_000` 抄成 `10_000`"** —— 见 §四，守卫是**推导的**（`兜底 ≤ min(各档)`），
⛔ 不是把数字写死。将来真加了比 `free` 还便宜的一档，兜底**必须跟着降**。

## 四 · 做法（TDD：**先看它红**）

**① RED —— 先写三条守卫**（`api/test_token_config.py`）：

| 用例 | 判据 | 改前 |
|---|---|---|
| `test_every_role_has_a_registered_budget` | **推导型**：`UserRole` 里每个角色**都**登记在 `ROLE_DAILY_TOKEN` | 🟢 **本来绿**（见下⚠️） |
| `test_unregistered_role_falls_back_to_the_LOWEST_tier_not_the_highest` | **推导型**：`兜底 ≤ min(各档)` | 🔴 **红** |
| `test_an_unregistered_role_actually_gets_the_lowest_budget` | 走**真函数** `get_user_token_budget()` | 🔴 **红** |

实测 RED（**⛔ 不是"我以为它会红"**）：

```
E  AssertionError: 未登记角色拿到了 100000，最低档是 10000 ⇒ 兜底没有 fail-closed
E  assert 100000 == 10000
2 failed, 11 passed
```

⚠️ **坦白一条**：`test_every_role_has_a_registered_budget` **从建立起就是绿的**
（三个角色当天都登记了）。它钉的是**不变量**，⛔ **不是"修了某个 bug"** ——
别把它读成"抓到过什么"。它在的值是**下次有人加角色忘了登记时**才体现。

**② GREEN —— 再改那一行值**（`100_000` → `10_000`）⇒ **13 passed**。

**③ 证伪 —— 证明守卫真的会红**（⛔ 光看它绿不算）：

```bash
DEFAULT_DAILY_TOKEN_BUDGET=100000 venv/bin/python -m pytest api/test_token_config.py -q
# ⇒ 2 failed, 11 passed（正是那两条，⛔ 不是别的）
venv/bin/python -m pytest api/test_token_config.py -q
# ⇒ 13 passed
```

📌 **为什么能这么证伪**：该值读的是 `os.getenv` ⇒ **把旧值从环境注入回去**，
就在**同一份代码**上重现了改前的行为（⛔ 不需要改代码再改回来）。

### ⚠️ 一条**测不出东西的写法**，已避开（值得记）

**第一版我是这么写的**，跑完发现它**改前也是绿的**：

```python
budget = get_user_token_budget("__no_such_user__")   # ⛔ 错的
```

**为什么错**：`get_user_role()` 对未知用户名**返回 `FREE`** —— 而 `free` **是登记过的**
⇒ 那条走的是**正常路径**，**根本碰不到兜底**。
⇒ 必须**强行**让"取角色"那一步返回一个不存在的角色（`monkeypatch.setattr(permission, "get_user_role", …)`）。

⚠️ **这个形状值得单独记一笔**：它**看起来**在测兜底，实际测的是 `free` 那一档 ——
**用例名与它真正覆盖的代码路径不是一回事**。本仓同族：
`DEC-061`（锚点指向不存在的用例）· `docs/复盘/2026-09-29-用我做过了当别人找得到.md`。

## 六 · 本份【没有】解决什么（别读成"额度这套收拾好了"）

1. 🔴 **档位体系本轮【一点没动】** —— `free / premium / admin` 还是三档，`admin` 仍 = `premium`。
   **为什么不在这轮定档位数**：定档要先知道「**一次问答花多少 token**」，
   而本仓这个数**只有一份实测**（`DEC-029`：`plan_execute` 一次 ≈**3346** token），
   因为 **RAG 侧零记账**（`ROADMAP.md:245` 实测 `grep -c record_usage api/api_v1_rag.py` ⇒ **0**）。
   ⇒ **一个样本 + 零记账的情况下定的档位数字，就是编的。**
   📌 **触发条件（⛔ 不是日期）**：**RAG 侧记账接上之后**（`DEC-053` §遗留·2）——
   那时手里才有"真实用户一次问答花多少"的分布。
   > ✅ **2026-10-06 触发条件【已满足】** —— RAG 侧记账已全部接上
   > （非流式 `DEC-073` · 流式 `DEC-084` · `/ws/agent` `DEC-075`）
   > ⇒ **"档位数"这件事现在可以做**，要的是**攒一段真库分布**（⛔ 不是"条件还没到"）。

2. ⚠️ **`get_user_role()` 仍是硬编码**（`admin` 特判 + 两个探针身份 + 其余 `FREE`），
   **接 DB 仍挂起**（`DEC-033` 🅱️ 后端先行；重新挂点见 `DEC-046` §遗留 4）。
   ⇒ 本份改的是**它对不上时的兜底**，⛔ **不是**把角色接上真实来源。
   ⚠️ **而恰恰是"接 DB"这件事最可能触发兜底**（§二 第 3 条）—— 所以本份是它的**前置**，
   ⛔ 不是它的替代。

3. ⚠️ **两处失效的行号指针本份没碰**（`docs/契约/环境变量.md:142` · `docs/原理/架构.md:316`
   都还写着 `token_tracker.py:283`）—— 按「⛔ 不顺手清理」留着。

4. ⚠️ **本份没有做任何"真服务"验证** —— 改的是一个常量 + 加守卫，
   离线用例（`ci-local`）就是全部判据。⛔ **别把「测试绿了」读成「额度策略验证过了」。**
