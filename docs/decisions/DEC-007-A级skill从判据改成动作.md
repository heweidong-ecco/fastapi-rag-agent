# 决策记录:DEC-007 · A 级 skill 怎么接线 —— 从「判据」改成「动作」

- 日期:2026-09-17
- 状态:已采纳
- 关联:`ROADMAP.md` PR 纪律 · `CLAUDE.md` superpowers 必用表 · `docs/复盘/2026-09-17-写了必用表自己却没用.md`

## 决策事项

一句话:`CLAUDE.md` 里那张 A 级表写着 9 个「**命中必须用**」,但**切开点 3 期间命中 4 个、一个都没调**。
**这张表该怎么接线,才能真的被用起来?**

## 背景与约束

**事实(transcript 硬证据,非印象,业务方 2026-09-17 提问后才去核的)**:

| 类别 | 切开点 3 期间 | 本会话(压缩后) |
|---|---|---|
| `Skill` 真调用 | **1 次**(`留痕-checks`) | **6 次,全是 `留痕-checks`** |
| **superpowers 那 14 个** | **0 次** | **0 次** |

切开点 3 期间**明确命中 4 个 A 级 skill**(`verification-before-completion` · `requesting-code-review` · `finishing-a-development-branch` · `executing-plans`),**一个都没调**。

**根因对照**:

| | `留痕-checks` | A 级表 |
|---|---|---|
| 写法 | 「**开 PR 前必须先跑**」 | 「**如果命中必须用**」 |
| 性质 | **一个动作** | **一句判据** |
| 结果 | ✅ 调用了 **6 次** | ❌ **0 次** |

⇒ **「命中必须用」是一句判据,不是一个动作。没有哪个瞬间逼我停下来核对它。**

**约束(本项目已犯过两次同型错误,第三次不能再只写文字)**:
1. `api/LEARNING_INDEX.md` —— 定义整套治理格式,**全仓 0 个文件使用、0 个引用**
2. **8 个 PR 跳过留痕门**
3. **本次** —— A 级表写了当天就被自己违反

`Product/CLAUDE.md` 有原话:「**有结构才执行,只有文字就漏**」。

## 备选方案

| 方案 | 思路 | 优点 | 缺点 |
|---|---|---|---|
| **甲** | **绑到与 `/留痕-checks` 同一个检查点**(PR 前那一刻),**逐条写出结论** | 产出物上**看得见**(写在 PR 里);复用已有的动作触发器 | PR 报告变长 |
| 乙 | 只在 `CLAUDE.md` 里把表写得更醒目 | 零改动 | **就是本次失败的写法** —— 再醒目也是判据 |
| 丙 | 每个 skill 单独加 hook 强制拦截 | 最强约束 | 本项目无此基建;**且 9 个 skill 各拦一次会严重打断** |

## 评估标准

**产出物上是否看得见** / 是否复用已有触发器 / 是否与"非必要的不要做"冲突 / 维护成本。

## 方案对比

**关键判据(本次复盘得出的)**:问的不是「**写清楚了吗**」,而是「**哪个瞬间会逼我停下来执行它**」。

- 乙 恰恰是**已经被证伪**的那个写法
- 丙 的强制力最强,但会与业务方的「**非必要的不要做**」正面冲突(9 个 skill 每次插一刀)
- 甲 把成本放在**PR 那一刻一次结清**,且**结论写在 PR 里** —— 这是"看得见"的关键

## 最终决策 + 理由

**✅ 采纳甲。**

绑到 PR 纪律里、紧挨 `/留痕-checks` 那条,要求**逐条三选一**:「调了」/「未命中(为什么)」/「命中未调(说明原因)」。

⛔ **不许只写"已核对"** —— 那等于没写(本次复盘就是证据:产出物上看不出判据被跳过)。

## 影响与后续行动

- `ROADMAP.md` PR 纪律新增该段(含一张"时点 → 该核的 A 级 skill"对照表)
- **本决策之后立刻执行了两次**(PR #19、#20),**两次都真的调了 skill**:
  - PR #19:`verification-before-completion` 当场抓到「验证跑在上一条消息里」
  - PR #20:`executing-plans` 的 Step 1 逼出「计划收益表述与自身机制矛盾」
- 📌 **两次都证明接线是有效的** —— 且两次抓到的都是**原本会被漏掉的东西**

## 反悔成本

**中。** 撤销 = 删掉 ROADMAP 那段。
但⚠️ **撤销会退回"命中 4 个、调用 0 次"的状态** —— 而那是已被实测证明的失败态。
