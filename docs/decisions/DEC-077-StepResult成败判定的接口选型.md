## 一 · 病

`:362` 与 `:557` 靠**中文子串**判成败：

```python
if "执行失败（已重试" in step_result:   # :362 —— 触发重规划
if "执行失败" in step_result:           # :557 —— 连质量检查都跳过
```

那条判据与 `:587` 那句**格式化文案**耦合，坏法两种：

| # | 坏法 | 后果 |
|---|---|---|
| ① | 改一个字的措辞 | 失败判定**静默失效** —— 看起来在重试、其实没有 |
| ② | 工具【正常】返回的正文里恰好含那四个字 | 正常结果被判成失败、**凭空触发一次重规划** |

②是**决定性**的：本批的回归用例就是拿它驱动的（改前 `assert [1] == []` 红）。

---

## 二 · 选型（**四个备选**）

| # | 方案 | 评估 |
|---|---|---|
| **甲** ✅ | `execute_step_with_retry` / `execute_step_with_quality_check` **返回 `StepResult(ok, text, error)`** | **选中** —— 见下 |
| **乙** | 失败时**抛 `StepFailedError`** | ⛔ **否** —— 把异常当**控制流**。重规划循环里「这一步失败了」**不是异常终止**，而是要走「重规划」这个**正常分支**；抛出去就得在 `:399` 再包一层 `try/except`，等于把 `execute_step_with_retry` 内部**刚捕获的东西再扔出去**。 |
| **丙** | 返回 `(ok, text)` 元组 / `NamedTuple` | ⛔ **否** —— 失败原因（**不带格式化前缀的异常原文**）没地方放；硬塞成三元组则**每处都得记住位置**。`NamedTuple` 最接近甲，但少了 `frozen` 语义与一处写 docstring 的落点（⚠️ 本仓注释极厚，「为什么这么设计」要有地方写）。 |
| **丁** | 保持 `str`，另加一个**回传参数**（`out: dict`） | ⛔ **否** —— 回传参数在 Python 里弱于返回值；且 3 个调用点**都要改签名**（甲乙只要改返回值），改动量不比甲小、可读性更差。 |

**选甲的理由**：

1. ⛔ **不动用户可见文案**（本批硬约束）—— `text` 原样保留那句话，`ok` 只是**并列**多出来的一个字段；
2. ✅ **「成功 / 失败」成为字段**，⛔ 不再藏在文案里；
3. ✅ `error` 单独放**异常原文** —— 上游要拿它做判断/上报时，不必去 `text` 里截字符串；
4. ✅ 改动面最小（3 个调用点 + 3 条既有用例的替身）。

### ⚠️ 一处必须澄清的口径：**这不与「失败一律抛异常」矛盾**

`execute_single_step` 的 docstring（`:602-605` 附近）明文写：

> **失败一律【抛异常】，不吞成错误字符串** —— 上游两条路都是靠异常工作的。

**现在 `execute_step_with_retry` 却返回一个"失败对象"** —— 看代码**会以为**这两条自相矛盾。**实际不是**，两条契约**分管不同层**：

| 层 | 谁 | 失败时 | 为什么 |
|---|---|---|---|
| **真调用工具的**那一层 | `execute_single_step` | 🔴 **必须抛** | 不抛 ⇒ **重试机制静默失效**（看起来在重试、其实没有） |
| **重试已经耗尽**的那一层 | `execute_step_with_retry` | ✅ **返回 `StepResult(ok=False)`** | 重试**已经做完**了，现在要做的是**把结论交给上层判定**（重规划 / 收尾），不是继续中止 |

📌 **判据**：`ok=False` 只在 `attempt == max_retries`（重试**用尽**）那一条分支上产生 ——
即**「异常已经走到了它的处理终点」**。⛔ 不是"把异常吞掉"。

## 三 · ⚠️ `ok` 与 `text` **不总是同向**（⛔ 下一个改的人最容易踩这条）

`execute_step_with_quality_check` 有一条出口是「**跑通了、但没通过质量检查**」——
它返回 **`ok=True`**，只在 `text` 末尾加一句提醒：

```python
return StepResult(ok=True, text=step_result.text + "\n[注意：此步骤经过多次重试，质量可能不达标]")
```

**理由**：「**质量差**」≠「**这一步失败了**」。改前这条出口**也不触发重规划** ⇒ 行为一字符未变。
⛔ **别顺手把它改成 `ok=False`** —— 那是**改行为**，不在 `S10` 的定义里。

## 四 · 判据与**变异自证**

三条回归用例（`api/test_plan_execute_tools.py`）：

| 用例 | 管什么 | 改前 |
|---|---|---|
| `test_工具正常返回里恰好含那句失败文案时不许触发重规划` | **决定性** —— 驱动**真函数**（只让 `_TOOL_HANDLERS` 里那一个 handler 是假的） | 🔴 **RED**（`assert [1] == []`） |
| `test_真失败仍然会触发重规划` | 反向守卫 —— 防「换成字段」最典型的坏形态：**恒 False** | ✅ 绿（前后都绿，**有意**） |
| `test_重试耗尽返回结构化结果且文案逐字不变` | 类型 + **文案逐字**契约 | 🔴 RED（`AttributeError: StepResult`） |

**变异自证（实测）**：把 `:399` 改回 `if "执行失败（已重试" in step_result.text:`
⇒ **只有决定性那条转红**，反向守卫仍绿 —— 说明它**恰好卡在两种实现之间**。
（📌 本仓立场：「**只有文字就漏，结构才执行**」；一条**从没红过**的用例，与「没有这条用例」在机器痕迹上完全一样。）

**全量**：`bash scripts/ci-local.sh` ⇒ **605 passed**（基线 602 + 3）。

## 五 · 反悔成本

| 想改成 | 代价 |
|---|---|
| **乙**（抛异常） | 改 3 个调用点 + 3 条既有用例**替身** + 上面那 3 条新用例；⚠️ 还要在重规划循环里补 `try/except` 把异常**翻译回**正常分支 —— 净增复杂度 |
| **丙 / 丁** | 同上量级，且 `error` 字段会丢 |
| **回退到子串判定** | 改回 2 行 —— 但**那条决定性用例会立刻转红**（这正是它存在的意义） |

**迁移成本≈0**：`StepResult` 是 `frozen` dataclass，无副作用、无 I/O、无全局状态。
