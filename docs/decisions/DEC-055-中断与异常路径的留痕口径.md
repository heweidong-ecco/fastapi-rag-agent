## 二 · 决策事项

**一条**：一轮问答**没能正常走完**时（**取消 / 异常 / 进程被杀**），要在存储里留下什么，
才够两家用：① **下一轮 prompt** 能接上；② **断点续接**（LangGraph checkpoint）能接上。

---

## 三 · 决策

### 决策 1 · 记三样：**提问** + **已生成部分（带标记）** + **status**

| 记什么 | 值 | 为什么 |
|---|---|---|
| **提问** | 用户原话 | ⛔ 不记 ⇒ 用户下一轮说"接着上面说"，历史里**没有任何来由**（`DEC-053` 已裁：成对写） |
| **已生成部分** | 已产出的文本 + `INTERRUPTED_SUFFIX` | 标记是**故意进 prompt** 的：不标 ⇒ 模型把**被截断的回答**当成"上一轮我说完了" |
| **status** | `cancelled` / `error` / `done` 等 | 🔴 **这是本 DEC 相对 `DEC-053` 的新增** —— 只存文本，**读的人分不清"说完了"还是"被打断了"**（`DEC-053` 靠尾部标记，那是**文本约定**，不是**结构化字段**；模型能读，脚本/看板读不了） |

⚠️ **status 要能被机器读**（落成字段），不能只靠"结尾那串中文"。理由：断点续接要**判断该不该续**，
而那个判断**不该让一个 LLM 去读中文尾注再猜**。

### 决策 2 · **所有非正常出口共用同一段收尾**，⛔ 不是只修取消

现状（查过）：

| 出口 | 现在 | 应当 |
|---|---|---|
| 正常跑完 | ✅ 记提问 + 完整答案 | 不变（+ status=`done`） |
| **取消**（客户端断） | ✅ 记提问 + 半截 + 标记（`DEC-053`） | 不变（+ status=`cancelled`） |
| 🔴 **异常**（`except Exception`） | ❌ **提问和半截一起丢** —— 只 `print` + 发一帧 `error` | **同一段收尾**：记提问 + 半截 + 标记（status=`error`） |
| 进程被杀（SIGKILL / 容器重启） | ❌ **什么都没** | ⚠️ **本轮不解决**（见 §遗留·1） |

> 🔴 **业务方点的正是第三行**：「`except Exception` 那条路仍然丢」——
> `DEC-053` 当时**有意留着**（写明"属另一件事"），本 DEC 就是那件事。

### 决策 3 · **status 的落点：进对话历史条目，⛔ 不新开一张表**

`chat_history:{user}` 的条目由 `{"role", "content"}` 扩成
`{"role", "content", "status", …}`（字段**可选**、老条目没有 ⇒ 读取端要有默认值）。

- ⛔ **为什么不新开表**：这张历史**就是**下一轮 prompt 的来源（`api_v1_rag.py:628 → :694`），
  另开一张 ⇒ **两处状态会漂移**，而且读取端要 join。
- ⚠️ **兼容**：老条目没有 `status` ⇒ 默认按 `done` 读（它们在 `DEC-053` 之前只可能是完整答案）。

### 决策 4 · **断点续接：⛔ 不是"把半截接着说完"，是"知道该从哪接"**

业务方提的「LangGraph 不是有 checkpoint 吗」——✅ **有，但要分清两条路**：

| 路径 | checkpoint | 能续吗 |
|---|---|---|
| `agent_graph.py`（`/agent/langgraph_chat[/stream]`） | ✅ 有（`MemorySaver` 默认；`AGENT_CHECKPOINT_BACKEND=sqlite` 才落盘） | ✅ **能** —— 已有现成机制：`invoke(None, config)` **从 checkpoint 续跑**（`B6` 已落地，见 `/agent/approve`） |
| `agent_checkpointer.py`（`/agent/memory_chat`） · `agent_graph_advanced.py`（`/agent/mcp_chat`） | ✅ 有（**`MemorySaver`，进程内存**） | ⚠️ **能，但重启即丢** |
| 🔴 **`/rag/stream_search`** | ⛔ **没有图、没有 checkpointer** | ⛔ **接不回来** —— 那半截**只能当文本读**，没有"从第 N 步继续"的对象 |

⇒ **两件事别混**：
1. **留痕**（本 DEC 的 decision 1–3）：**三条流都要**，因为**都要给下一轮 prompt 用**；
2. **续接**（checkpoint）：**只有走图的那些才有**；RAG 那条**永远只有文本**。

⚠️ ⇒ **RAG 侧的 `status` 不是"续接用"的**，是**给读的人（下一轮 prompt / 看板 / 脚本）分辨真假**用的。

## 四 · 备选，与为什么没选

| 备选 | 为什么不选 |
|---|---|
| **只靠尾部中文标记**（`DEC-053` 现状） | ⛔ 机器读不了 ⇒ 断点续接的判断要**过一遍 LLM 去猜**；⚠️ 且标记**嵌在正文里**，用户若把半截复制走会带走它 |
| **异常路径直接丢**（现状） | ⛔ 业务方点名的正是这条；丢提问 ⇒ 下一轮完全接不上 |
| **新开一张 `turn_status` 表** | ⛔ 两处状态会漂移；读取端要 join（见决策 3） |
| **把 status 放进 SSE 的最后一帧** | ⛔ 客户端**已经走了**（取消时没人收）—— 这正是 `DEC-052` 修掉的坑（在 `except CancelledError` 里 `yield`） |
| **给 RAG 侧也加 checkpointer** | ⛔ 范围外且**没有对象**：RAG 那条是"一次 LLM 调用"，没有"步骤"可断点 |
