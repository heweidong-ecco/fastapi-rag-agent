## 二 · 决策

### 2.1 三个工具：**本地纯函数**，走既有的三层形状

| 工具 | 签名 | 干什么 | TTL |
|---|---|---|---|
| `date_calc` | `(start_date: str, days: int) -> str` | 日期加减 → `YYYY-MM-DD（星期X）` | 86400 |
| `json_extract` | `(json_text: str, path: str) -> str` | 按 `a.b[0].c` 取字段 | 86400 |
| `stats` | `(numbers: str) -> str` | 个数 / 和 / 均值 / 最小 / 最大 / 中位数 | 86400 |

**形状（⛔ 不新建模块）**：纯逻辑进 `simple_tools_impl.py`（**只 import 标准库**）·
`@tool` 外壳 + 缓存进 `simple_tools.py` · 注册进 `mcp_server.TOOLS`。
⇒ **四条执行路径一处未改** —— 它们全部**派生**自 `mcp_server.TOOLS`（`DEC-107` 的成果）。

### 2.2 第 11 条：**选 ① —— `execute_python` 【不进】`SENSITIVE_TOOLS`**

**理由不是「容器兜住了就完事」**，而是 **本仓对「敏感工具」的语义早就写死了**：

> 「『敏感』的现实定义 = **这个工具会把数据发到本机之外**」
> —— `fastapi-rag-agent-TODO待办/后端补齐清单-待裁-20260929.md`（`web_search` 那一节）

`web_search` 进名单，是因为它把**用户问题原文**发出去。三个新工具与 `execute_python`
**都不外发数据**（`execute_python` 跑在批② 的**无网容器**里）⇒ **按既有判据都不属于那一类**。

🔴 **「不进」不等于「不用管」**：

| 仍然要守的 | 在哪 |
|---|---|
| **硬化容器**（只读根 · 无网 · 非 root · 无 cap · 5s/256MB/pids） | 批② · `DEC-108`，**⛔ 无论如何不能撤** |
| demo 模式下**不注册** `execute_python` | 批② Task 6 · `mcp_server.py` |

⚠️ **选 ② 的代价（没选的理由）**：所有路径（含 `plan_execute` / 各 Agent 图）**每次调代码都停下等人批**
⇒ 等于废掉这个工具的用途，而它本来就是**给 Agent 用**的。
⚠️ **选 ③ 的代价**：「谁触发的」在**工具层看不出来** ⇒ 要另立一套机制，为一件 demo 里根本不注册的工具不划算。

### 2.3 三条设计红线

1. 🔴 **`date_calc` 的 `start_date` 必填，⛔ 不做「默认今天」** ——
   一默认，「（今天, 1）」这组入参在**跨天**时会给出不同答案，而缓存键**只含入参**
   ⇒ 只能靠「不默认」消除（⛔ 不是靠把 TTL 设成 0）。要今天几号 ⇒ 先调 `date_today`。
   ⚠️ **反悔成本**：哪天给它加了默认值 ⇒ **必须同时把 `TTL_BY_TOOL["date_calc"]` 改成 0**。
2. 🔴 **三个都⛔ 不挂 `should_cache`** —— 它们是**纯函数**，失败结果也是**稳定的**
   （同一组入参永远同一个错）⇒ 缓存它无害。**对比 `web_search`**：它的「搜不到」是**瞬时**的
   ⇒ 那边**必须**用 `should_cache` 挡。⛔ 别把两种情形混成一种。
3. 🔴 **⛔ 不新建模块** —— 新建会触发 `pre-commit-gates.py` 的新模块 spec 硬拦，
   还会搅乱乙单（spec 口径）那笔**待裁的**账。

### 2.4 🔴 **可见行为变更：LLM 看到的工具表变了**（⛔ 必须显式声明 —— 照 `DEC-107` §3.3 的规矩）

| 变更 | 影响 |
|---|---|
| `mcp_server.TOOLS` **4 → 7** | 四条链的 `llm.bind_tools(tools)` **多绑了 3 个工具**；经 MCP 动态取表的 `agent_graph_advanced` 同理 |
| 新增 3 段**工具描述（docstring）** | 🔴 **那是【写给 LLM 的文本】** —— 改它 = 改产品行为（`simple_tools.py` / `code_executor.py` 里都写着这句） |
| 3 个新 `inputSchema`（由 `mcp_tool_factory` 从类型提示派生） | `date_calc` = `{start_date, days}` · `json_extract` = `{json_text, path}` · `stats` = `{numbers}` |
| `SENSITIVE_TOOLS` | ⛔ **不变**（默认仍是 `web_search`）—— 见 §2.2 |

🔴 **本仓【没有】`eval/` 评估集**（实测：`ls -d eval` ⇒ **不存在**）⇒ 留痕体检的
「**Agent 变更回归**」那一项**没法按 eval 跑**。⇒ 按本仓既有做法，用**显式声明 + 既有守卫**替代：

| 要守的 | 谁守 |
|---|---|
| 工具**定义**只有一处（⛔ 不再手抄第 N 份） | `api/test_tool_registry_single_source.py` |
| 四条链拿到的是**同一批对象**（`is` 同一） | 同上（`test_all_graphs_share_the_same_tool_objects`） |
| **五处登记**都不漏 | 🆕 `api/test_tool_registration_completeness.py` |
| 工具真的能调通 | `api/tool_health.py` 探测表（三个新工具已登记 —— §六 ② 的「无缺口」） |

⚠️ **诚实边界**：以上**没有一条**在测「模型见了这三个工具之后**会不会用得对**」——
**那件事本仓现在测不了**（没有评估集）。⛔ 别把这句读成「已经验过了」。

## 三 · 🔴 登记面：从「**两处**」更正为【**五处**】

**`DEC-107` §六·1 原文（现已更正）**：

> ⛔ **新工具要加两处**：`mcp_server.TOOLS` 加一行 + `test_tool_registry_single_source.py`
> 的 `DEFINITION_HOMES` 登记它的**定义处**（否则守卫红 —— **这是有意的**）。

**它错在两处**：

| 错 | 说明 |
|---|---|
| **数错** | 实测是**五处**（下表） |
| **分类错** | `DEFINITION_HOMES` 是**守卫自己的名单**，⛔ **不是工具的功能登记**；而真正会**静默失效**的那几处**一处没提** |

**实际的五处 + 各自的失效形态**：

| # | 落点 | 忘了登记会怎样 | 守卫 |
|---|---|---|---|
| 1 | `api/simple_tools.py` 的 `@tool` 定义 | 工具不存在 | ✅ `test_only_home_modules_define_tools` |
| 2 | `api/mcp_server.py` 的 `TOOLS` | 工具不存在 | ✅ 同上（下面几处会连带红） |
| 3 | `api/tool_cache.py` 的 `TTL_BY_TOOL` | 运行时 **`KeyError`** | ✅ `test_every_mcp_registered_tool_has_a_ttl` |
| 4 | `api/tool_health.py` 的 `TEST_ARGS_MAP` | 🔴 **永远不做健康检查**（静默） | 🆕 `test_tool_registration_completeness.py` |
| 5 | `api/token_tracker.py` 的 **两张**成本表 | 🔴 按默认 **500 token** 预估一个**免费**工具（静默） | 🆕 同上 |

**另有一处是守卫名单本身**（`test_tool_registry_single_source.py` 的 `TOOL_NAMES` + `DEFINITION_HOMES`）——
⚠️ **它不在上面的计数里**，因为它**不是工具的功能登记**，是**尺子**。
🔴 但它同样会**静默失效**：名字不在 `TOOL_NAMES` 里 ⇒ `_tool_definitions()` 的**过滤条件**就把它滤掉
⇒ `test_only_home_modules_define_tools` 对新工具**是瞎的**（不是「少一条测试」，是「**尺子量不到**」）。

## 四 · 备选与反悔成本

| 决策点 | 没选的备选 | 为什么 | 反悔成本 |
|---|---|---|---|
| 放哪 | **新建 `data_tools.py` 模块** | 会触发新模块 spec 硬拦 + 搅乱乙单待裁的账；而 `simple_tools.py` 的自述职责（「不依赖外部服务的独立工具」）**正好覆盖**这三个 | **低** —— 搬走是纯位移，`DEFINITION_HOMES` 改一行 |
