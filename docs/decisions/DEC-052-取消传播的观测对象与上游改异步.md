## 决策事项（三条，外加一条附带修掉的）

计划原文（`docs/specs/api_v1_agent.md` Task 5）要补三件：① 检测客户端断开 ② 主动关上游
③ `finally` 兜底。**执行下来，①不用补，②③照做，而计划里的验收判据【落空了】。**

### ① 判据③「token 计数在该时间点停止增长」**没有可执行对象** ⇒ 换观测对象

**计划写的判据**（业务方 2026-09-30 裁定「先以本机证据为准」）：

> **判据 = 日志有 cancel 事件 + token 计数在该时间点【停止增长】**
> 之后 `/agent/token/recent` 的计数不再增长

**实测：这个"计数"在流式路径上根本不存在。**

```bash
grep -ci token api/metrics.py            # ⇒ 0   （Prometheus 三个指标全是 HTTP 层：请求数/延迟/进行中）
grep -c prometheus api/token_tracker.py  # ⇒ 0   （记账走 PG token_usage_logs，与 Prometheus 无关）
```

而记账那条链（`token_tracker.record_usage()` → PG）**只在生成结束后整笔写**，
⇒ **流式生成阶段一行都不写**。真服务日志可以佐证（2026-10-03 实测）：

```
每条流式请求只出现一行：  [Token] embedding | text-embedding-v2 | … tokens   ← 那是【前置嵌入】
LLM 那一行：              从来没有（无论正常跑完还是被取消）
```

⇒ **判据落空不是因为"没测"，是因为被测对象不存在。**
⚠️ 这条比"漏测"更危险：硬门 C 自标「**最容易假完成**」，
而它**写在计划里的判据本身无法证伪** —— 拿一个恒为 0 增长的数当"停止增长"的证据，
**任何实现都能通过**。

**决策**：新增 `api/metrics.py::STREAM_CANCELLED`（`stream_cancelled_total{endpoint}`）
+ `track_stream_cancel()`。

- ⚠️ **它证的不是"账单停了"** —— 它证的是「**我们的生成器在跑完之前被终止了**」
  （见 ③ 的 `outcome` 判据：跑完会置 `"done"`，只有没跑完才留 `"cancelled"`）。
- ⚠️ **Grafana 固定看板要手工加一格** —— provisioning 缺口仍在（`ROADMAP` 阻塞项 #2），
  counter 不会自动变成面板。临时查：`sum(rate(stream_cancelled_total[5m]))`。

### ② 上游从 `stream()` 改成 `astream()`

原实现 `for chunk in get_llm_stream().stream(messages)` 是**同步迭代**跑在协程里
⇒ **阻塞事件循环** ⇒ 取消只能在"下一块到达"的间隙才送得进来
⇒ **上游越慢，停得越晚；上游卡住不吐字时，取消完全不生效**（正是"继续烧钱"的形态）。

改 `astream` 后每块之间都是 await 点。（`api/test_cancel_propagation.py::test_rag_uses_async_upstream`
钉住：`astream_calls` 非空 ∧ `stream_calls` 为空。）

### ③ 记账必须放 `finally` + `outcome`，⛔ 不能只写 `except CancelledError`

Starlette 关闭生成器有**两条**路径（按 `spec_version` 分叉）：

| `asgi.spec_version` | 怎么关的 | 抛进生成器的是什么 |
|---|---|---|
| **2.3**（**uvicorn 实测报的就是这个**） | `create_collapsing_task_group` + `listen_for_disconnect` ⇒ **取消任务** | `asyncio.CancelledError` |
| **≥ 2.4** | `except OSError: raise ClientDisconnect` ⇒ 生成器被 `aclose()` | **`GeneratorExit`** |

**`GeneratorExit` 不是 `CancelledError` 的子类** ⇒ 只在 `except CancelledError` 里记账，
换条 Starlette 分支就**静默不记**（不改代码、不报错、指标不动）。

⇒ 用状态变量 `outcome`（初值 `"cancelled"` / 正常跑完置 `"done"` / 异常置 `"error"`）
+ `finally` 统一做「关流 + 记账」。

⚠️ 这同时让判据变强：`outcome == "cancelled"` ⇒ **循环没跑完** ⇒
比"计数涨了"更接近「**上游真停了**」。（可打印：
`api/test_cancel_propagation.py::test_rag_closes_upstream_when_client_disconnects`）

### 附带修掉：`except CancelledError` 里的 `yield "data: [DONE]"`

旧实现在取消分支里还 `yield` 了一帧 `[DONE]`。**我原本以为它发不出去，实测它会真的发出一个帧**
（`test_rag_sends_nothing_after_disconnect` 先红后绿照出来的）。已删。理由两条：

1. 接收方已经走了，发出去没人收；
2. 它让「**已取消**」和「**正常收尾**」在**帧层面长得一模一样** —— 调用方无从分辨。

## 🔴 ①不用补：断开检测是**框架给的**

计划的要补三件里的第①件（`request.is_disconnected()`）**不需要我们写**：
uvicorn 报 `spec_version 2.3` ⇒ Starlette 已经替我们监听 `http.disconnect` 并取消生成器。
⇒ **真正的缺口只有"停并关掉上游"这一件**。⚠️ 这一点写进两个 spec 的「看代码会误判」表：
**自己去轮询 `is_disconnected()` 是多余的，而且会掩盖真正的缺口。**

### ⚠️ 两个坑（写下来，免得下一个人再踩）

1. 🔴 **中间件记的时长不是"生成时长"** —— 它记到**响应开始返回**为止。
   实测：`0.019s` 的那条客户端收了 **27KB**、`0.004s` 的那条 **3 秒后**才 cancel。
   ⇒ ⛔ **别拿它当"生成提前停了"的证据**（我第一版就误读了；`1.340s` / `3.516s`
   那两条 RAG 的是**检索+嵌入**的耗时）。
2. 🔴 **本机有语义缓存** —— 问句只差两个字（"基线"/"切断"）就会被当成**同一个问题**，
   `0.006s` 返回全量 ⇒ **测取消必须换语义上不同的问句**，否则测的是缓存命中。
