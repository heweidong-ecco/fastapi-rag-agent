# 决策记录:DEC-006 · `/留痕-checks` 在本仓怎么裁剪(8 项 → 5 项 + #7 改双判据)

- 日期:2026-09-17
- 状态:已采纳
- 关联:`ROADMAP.md` PR 纪律 · `CHANGELOG.md` · PR #17 · PR #19

## 决策事项

一句话:`/留痕-checks` 是**用户级** skill,查 **8 项**。拿到本仓来跑时,**哪些该报、哪些该改判据、哪些该砍?**

## 背景与约束

**起因**:业务方问「切开点 3 是否涉及 skills 的调用」。核查时发现该 skill 的 check 7 引用
`contracts/tools-mcp` · `总纲.md` · `eval/README.md` · `eval/阈值.md` —— 这些路径**存在,但相对 `agent-eval-gate`,不是本仓**。

**判定依据 —— 不是印象,是【实际产出】**:该 skill 在本仓**真跑过 4 次**(PR #13/#14/#15/#16),逐项看它到底产出了什么:

| 项 | 4 次运行的产出 |
|---|---|
| ① commit 规范 / ③ 密钥 / ④ CI / ⑥ 误提交 / ① 未跟踪 | 每次都**真抓到东西**(如 `api/_tmp_olddb.py` 残留、密钥扫描) |
| ⑤ issue 关联 | **4 次输出逐字相同**：「缺——本仓无 open issue」。**本仓没有 issue 体系** |
| ⑧ eval-gate | **4 次输出逐字相同**：「⚠️ 未见」。这是**已登记**的延期状态(`ci.yml:4` 待 M6) |
| ⑦ Agent 变更回归 | **原判据失效**:按**路径**触发(`prompts/`),而**本仓 prompt 内联在 `.py` 里** ⇒ **永不命中** |

**约束**:skill 是用户级的,别的仓库可能正好适用 ⇒ **不宜改 skill 本身**,只宜在本仓落地适配。

## 备选方案

| 方案 | 思路 | 优点 | 缺点 |
|---|---|---|---|
| **甲** | **仍调 skill,但只报 5 项**,另 3 项一行带过 | skill 本体不动(别的仓照用);PR 报告干净 | skill 里那套别仓路径**仍会每次进上下文** |
| 乙 | 本仓另写一份清单,**不再调用** skill | 最贴合本仓 | 丢掉「`/` 命令」这个**动作触发器**;skill 给别的仓用不上 |
| 丙 | 照旧全报 8 项 | 改动最小 | **#5/#8 会继续每次输出逐字相同的「缺」「未见」** |

## 评估标准

报告信噪比 / 是否保留"动作触发器" / 是否影响别的仓库 / 判据是否可检验。

## 方案对比

**砍 #5/#8 的核心理由**:它们**不是"发现了问题",是每次重新发现同一个事实** ——
问的是"本仓有没有 X",而答案**恒为没有**。

> **一个每次都红的门,会被读成已知噪音然后被忽略** —— 连带**稀释掉真正有用的那 5 项**。

**甲 vs 乙的取舍**:乙更干净,但会**丢掉 skill 那个"动作"**。
而 2026-09-16 的复盘(`八个PR跳过了留痕门.md`)证明:**门必须是一个动作**才有人跑它。

## 最终决策 + 理由

**✅ 采纳甲。**

**业务方原话(2026-09-17)**:「仍调 skill,但只报 5 项」

**#7 的判据业务方裁决为「两者都要」**:文件清单(快)+ 内容兜底(不会漏)。

- ⛔ **原判据在本仓失效**(路径相对别仓 + 路径式触发永不命中)
- ✅ **判据 A(快·文件清单)**:本仓 prompt/工具/记忆 的**真实分布**,**实测得来**(附可重生成的 grep 命令,不靠记)
- ✅ **判据 B(慢·内容兜底)**:不看路径,直接看 diff 有没有改 prompt 文本 / 工具 schema / 记忆策略
