`①b · Task 6` 要落 `决策一`（撤掉「每日请求次数」配额）。**动手前核实况，发现三处在计划里没定死** ——

### 为什么现在要定

- **第一处**：`ROLE_QUOTA` 是**一套配额口径的物理载体**。它留着的每一天，「到底哪套在拦」就是
  一个**没人答得上来的问题**（这正是 `DEC-029` / `DEC-040` 要解决的）。
- **第二处**：`ROADMAP.md` 早就标着 **`R1.3`（用户日级）= ⬜ 没有**。
  ⇒ 若「撤次数」和「补 `R1.3`」**分两轮做**，**中间就是一段"谁都不拦"的窗口** ——
  这正是 `①a` 那份计划**自己写下的「顺序陷阱」**（「先撤次数、后接 token ⇒ 中间有一段谁都不拦的窗口」）。
  ⚠️ 计划以为 `B8/B10/B11` 已补上这个位置，**实测没有**。
- **第三处**：留着零调用者的模块 = 让下一个人以为它是活的。

## 备选方案

### 一 · `ROLE_QUOTA` 的下场

| 方案 | 一句话 | 评价 |
|---|---|---|
| **甲 · 直接删**（**采纳**） | 连同 `get_user_quota()` 一起删 | ✅ 没有任何不可替代的信息 —— token 口径的日预算**早已存在**（`token_config.ROLE_DAILY_TOKEN`：free 10k / premium 100k / admin 100k）<br>✅ 仓里不留"看着像配额、实际没人读"的表 |
| 乙 · 字符串哨兵 | `ROLE_QUOTA = "deprecated-见-DEC-040"`，`get_user_quota` 抛异常 | ✅ 能挡住「静默变成别的语义」<br>⛔ 长期挂一个**没有语义的字符串**；而且**它本来就没有别的语义可退化**（调用点只有三个，全在本任务改） |
| 丙 · 改成「接口权重」表 | 保留数字，语义改为"哪些端点更贵" | ⛔ **没有任何代码消费权重** ⇒ 等于**新建一个零调用点机制** —— 本仓「建好没接上」的**第四次** |

### 二 · 撤掉次数配额后，那一层怎么办

**实测的覆盖面**（`grep` 过的落点，⛔ 不是从计划抄的）：

| 层 | 覆盖 | 换会话 / 换人就管得住吗 |
|---|---|---|
| **次数配额**（`QuotaMiddleware`） | **所有非公开路径 · 按用户 · 按天** | ✅ 管得住 |
| 会话级 `B8`（`check_session_token_budget`） | 按 **`(user_name, thread_id)`** | ❌ **换个 `thread_id` 就重置** |
| 全局日级 `B10` / `B11` | **全站合计**（`SUM` 无 `user_name`） | ❌ **看不到「某一个人」** |
| `check_token_budget`（按用户按天 · token） | 只接了 `agent_graph_advanced`（mcp_chat 链）与 `/agent/available_tools` **3 处** | ❌ **不是全路径** |

| 方案 | 一句话 | 评价 |
|---|---|---|
| **甲 · 原位置换成 token 口径**（**采纳**） | 在 `QuotaMiddleware` 原位，把「次数上限」换成「按用户按天 **token** 上限」 | ✅ **撤旧的同时接新，无空窗**（符合「新先旧后」）<br>✅ 覆盖范围**不变** —— 仍是"所有非公开路径 + 按用户 + 按天"<br>✅ **顺带把 `R1.3` 做掉**，无需再排一轮 |
| 乙 · 先单独做 `R1.3`，再撤次数 | 拆两个 PR | ✅ 每步可单独验<br>⛔ 多一轮；且**风险不小反大** —— 两轮之间 `QuotaMiddleware` 与新的按用户日级**同时在拦**，正是要消除的"两套并存" |
| 丙 · 直接撤，`R1.3` 留后面 | 最小改动 | ⛔ **开一个真实存在的洞**：已登录用户可**跨会话无限花**（只受全站日级约束） |

## 决策与理由

**业务方 2026-10-03 裁定：一 ⇒ 甲（直接删）· 二 ⇒ 甲（原位置换成 token 口径）· 三 ⇒ 甲（同批删 + 归档 spec）。**

一句话：**`决策一` 的字面是「统一到 token 一套」，而它缺的那一块就是 `R1.3`** ——
把「按用户按天的**次数**上限」换成「按用户按天的 **token** 上限」，**在同一个位置、同一次改完**。

### ⚠️ 五条必须一起写下来的（否则下一个人会当成 bug）

1. 🔴 **`X-Quota-*` 响应头：名字**没变**，但**语义从「次数」变成「token」**。**
   ⚠️ 头名**故意不改** —— 客户端已经在读它们，**改名的破坏面比改语义更大**。
   但 `X-Quota-Limit` 现在是**每天的 token 预算**，⛔ 不再是次数。
   `X-Quota-Reset` 仍是「次日 0 点的 Unix 时间戳」（日预算由 SQL 的 `created_at >= CURRENT_DATE` 翻页）。
2. 🔴 **这一层是 fail-open 的**（`get_daily_token_usage` 查库失败 ⇒ 返回内存缓存值 ⇒ 放行），
   与 `B8` / `B10` / 既有 `get_daily_token_usage` **同取向**（四处一致）。
   ⛔ **别"顺手统一"成 `deps.py` 鉴权的 fail-closed** —— 额度是**成本控制**，不是安全边界。
3. ⚠️ **新增成本：每个请求一次 DB 查询**（原先次数那套是 Redis `INCR`）。
   ⚠️ `B10`（`B11` 接线 8 处）也已每请求一次 `SUM` ⇒ 本层的增量与它同量级。
   📌 **这是"用 DB 换掉 Redis"的有意取舍**：次数与 token **口径不同**、无法用同一个计数器表达。
4. ⚠️ **匿名请求仍绕过这一层**（中间件只在识别出 `user_name` 时判定）。
   **这是既有行为，本任务⛔ 不改** —— 「匿名可打」是另一个问题（`B9`）。
   📌 判据（可打印）：`grep -n "if not user_name" api/main.py` ⇒ 命中 QuotaMiddleware 里那个提前 return。
5. ⚠️ **查的是「已经超了」，不是「这次会超」** —— 与改动前的次数配额**同一语义**
   （旧的那层也是 `INCR` 之后判 `count <= limit`）。
   ⛔ 别读成"它做了预估" —— **预估**是 `check_token_budget(estimated_tokens=…)` 那一族的事。

### 🔹 一处由测试自己抓出来的错（本仓「判据写歪了不报错」的又一例）

本任务新加的守卫用例，**第一版判据写错**：它用**文本匹配** `"ROLE_QUOTA" in 源码` 去禁残留，
结果把 `token_config.py` / `permission.py` 里**正当的历史注释**也判成违规
（那些注释写的正是「这里曾经有什么、为什么删」）。
⇒ 改了**两次**才对：
  1. 改用 **AST**（禁的是**引用**，不是**提及**）；
  2. 自证用例抓出扫描器**漏了 `ast.alias`** —— `import` 走的**不是 `ast.Name`**，
     漏掉这一支 ⇒ **最典型的引用形态完全测不出来**。
📌 前者见 `docs/复盘/2026-10-02-判据写歪了不报错.md`；后者由 `test_reference_scanner_catches_code_but_not_comments` 钉住。
