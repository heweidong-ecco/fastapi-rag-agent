## 背景与约束

- **要换的其实很少**：真执行点只有 `execute_single_step()` 一处（外加 `execute_plan_with_replan()`
  里那处失效工具降级也调它）。
- **但上游必须一起改**：`generate_dynamic_input()` 产的是**给 LLM 读的一句话**，
  而真调用需要**按工具 schema 的结构化参数** ⇒ 只换执行点是接不上的。
- **约束一**：本仓已证明 `_impl` 拆分**兑现不了收益**（§3.6：`code_executor_impl` / `simple_tools_impl`
  声称"可脱离 langchain 单测"，但**没有任何测试在用**）⇒ **同一个坑不踩第二次**。
- **约束二**：`main` 有分支保护，两个必需检查全绿才合。

## 🔑 动手前核出的地基（改变了方案的规模）

实测四个工具的参数 schema —— **全是单一字符串字段**：

| 工具 | 字段 |
|---|---|
| `calculator` | `expression: str` |
| `date_today` | `query: str` |
| `web_search` | `query: str` |
| `execute_python` | `code: str` |

⇒ **字段名可以从 `args_schema` 派生，不必手写映射**（与 §三·C1「工具清单同源」同一个做法）。
⇒ 也让 `generate_dynamic_input()` 的改造从"重写"降为"说清楚要产哪个字段的值"。

| # | 选择 | 采纳 | 理由 |
|---|---|---|---|
| **①** | **代码落在哪**：甲 就地重写 `plan_execute.py` ／ 乙 新建 `plan_executor.py` | **甲** | 本仓已证明 `_impl` 拆分**兑现不了收益**（§3.6）。diff 集中在一个文件 |

## 执行内容

**`api/plan_execute.py`**：

| 改动 | 内容 |
|---|---|
| 新增 `_tool_arg_field()` | 从 MCP 注册表**派生**工具唯一入参的字段名（多字段/无字段 ⇒ 返回 `None`，**不猜**） |
| 重写 `execute_single_step()` | 从 `TOOL_HANDLERS` 取**真 handler** → `handler({字段名: 值})` |
| 改 `generate_dynamic_input()` | 产出**要直接塞进 handler 的字段值**（说清工具 + 字段 + 期望形态） |
| 新增 `_strip_code_fence()` | 去掉 LLM 常加的 ` ``` ` —— 否则 `execute_python` 直接语法错 |

⚠️ **失败一律【抛异常】，不吞成错误字符串** —— 上游 `execute_step_with_retry()` 靠异常触发
"重新生成输入再试"，吞成字符串会让它**看起来在重试、其实没有**。

## 🔴 执行中撞出的真缺陷：**沙箱里不能 `import`**（已修）

实测：

```
import math            → ❌ ImportError: __import__ not found    ← LLM 最常写的写法
不 import，直接用 math  → ✅ 4.0                                  ← 模块是【直接注入全局域】的
```

**而 `execute_python` 的工具描述对 LLM 说的是「允许的模块：math, json, datetime…」** ——
那会让 LLM 写 `import math` ⇒ **必炸**。

- **性质**：与 §三·A 那一类「**注释说 A、代码做 B**」**同型**，但**后果更重** ——
  它**直接导致 LLM 写出来的代码跑不了**。
- **为什么以前没暴露**：那时是「LLM 模拟执行」，写什么都不真跑。
  **真执行层一上线，这个坑立刻变成现实。** ⇒ 这正是「真调」与「模拟」的差别第一次显形。
- **修法**：把工具描述改成 **「不要写 `import`，模块已直接可用」** 并给了正反例。
  ⛔ **没有**选择"放开 `__import__`" —— N18 的边界论证已定它是**逃逸通道**，不能放。
- ⚠️ **这是【工具 schema 变更】**（`execute_python` 的 description 是 LLM 读的那份），已在 PR 里声明。
