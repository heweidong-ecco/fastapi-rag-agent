## 一 · 这条要解决什么

`R3` 的验收原文（`fastapi-rag-agent-TODO待办/施工单-本项目.md`）：

| # | 要求 | 验收标准 |
|---|---|---|
| `R3.1` | 熔断时返回**结构化错误** | 响应里带**可识别的错误码 + 恢复时间**，不是裸 500 |
| `R3.2` | 前端渲染**明确卡片** | 证据：卡片上写清四件事 —— **现状 / 这不是故障 / 何时恢复 / 怎么联系** |
| `R3.3` | ⛔ **不许**退化成 500、白屏、或通用错误页 | 同上，用**同一份证据**对照 |

**本刀之前**，`api/static/web/chat.html` 的 429 分支只有一行字：

```js
if (status === 429) return { msg: '今日额度已用完 / 会话额度已用完', relogin: false };
```

四件事**一件都没有**，而且这一行**本身就是个缺陷**（见下）。

## 二 · 🔴 探出来的三件事（两个缺口 + 一处真缺陷）

### 缺陷：那一行把**两种恢复条件完全不同**的熔断混成了一句

| 熔断 | 后端原文案 | 恢复条件 |
|---|---|---|
| **全站日级**（`B11`） | `今日全站额度已用完（已使用 X / 上限 Y tokens），请明日再试` | **跨天**。全站共享 ⇒ 用户**做什么都救不回来** |
| **会话级**（`B8`） | `本会话预算已用完（已使用 X tokens，会话上限 Y tokens）` | ⛔ **不是只能等** —— 额度按 `(user_name, thread_id)` 计 ⇒ **开个新会话立刻能继续**（`chat.html:70` 就有「＋ 新会话」按钮） |

两者 `ErrorCode` **都是 `QUOTA_EXCEEDED`**（`api/exceptions.py` 就一个枚举）
⇒ **前端不看文案就分不出是哪种** ⇒ `R3.2` 要的第三件事（「何时恢复」）**写不出来**。

> ⚠️ 这不是"两句话写得不够礼貌"，是**把人引到错误的处置上** ——
> 被会话级熔断的人看到「请明日再试」，会**白等一天**。同 `DEC-082`/`N9` 那条口径。

### 缺口 A：「何时恢复」后端没给

`AppException(ErrorCode.QUOTA_EXCEEDED, why)` **没传** `retry_after`
⇒ 响应体里**没有**恢复时间字段，只有文案里一句模糊的「请明日再试」。
（`R3.1` 要求的「可识别错误码 + **恢复时间**」，**恢复时间这半也是缺的**。）

### 缺口 B：「怎么联系」全仓没有

⇒ 本刀只能放**占位符**（业务方 2026-10-06 裁「先用占位符，后面我再设置」）。
⛔ 写成 `admin@example.com` 那种**看着像真的**假邮箱 = **假话**（本仓：宁可空着不编数）。

## 三 · 为什么是「后端补 `scope`」而不是纯前端（业务方 2026-10-06 裁定）

| 方案 | 为什么没选 |
|---|---|
| **甲 · 纯前端，不分** | 零后端改动，但「何时恢复」只能写**一句通用话** ⇒ `R3.2` 那一条**写不精确**。且两种熔断的**出路本来就不同**，混着写就是上面那个缺陷换个地方犯 |
| **丙 · 后端补 `retry_after`（秒）** | `retry_after` 的语义是"**等 X 秒**"。全站级讲得通（跨天确实是个时间点），**会话级根本对不上** —— 它的出路是**开新会话**，不是等。⇒ **拿一个时间字段表达一件非时间的事** |
| **乙 · 后端补 `scope`** ✅ | 直接答"**这是哪一种**"，恢复口径由前端按 `scope` 查表。与现成的 `retry_after` **同一套路**（不传 ⇒ 字段整个不写）。**改动面最小**（见 §四） |

## 四 · 实施

### 后端 · 3 处 / 约 8 行（⛔ 有意只接**对话页这一条链**）

| 文件 | 改什么 |
|---|---|
| `api/exceptions.py` | `AppException.__init__` 加可选 `scope`，与 `retry_after` 同套路 |
| `api/main.py` `app_exception_handler` | `getattr(exc, "scope", None)` 非 `None` 才写进 body |
| `api/api_v1_rag.py` | `stream_search` 那**两处** raise：`:711` 会话级 → `scope="session"` · `:718` 全站级 → `scope="global"` |

🔴 **为什么只接这一条链**：全仓有 **35 处** `raise AppException(ErrorCode.QUOTA_EXCEEDED, …)`。
卡片只服务对话页一个入口，而这个端点**只有两处**熔断
（`grep -n 'QUOTA_EXCEEDED' api/api_v1_rag.py` 里属于 `stream_search` 的就是那两行）。
⇒ 其余 **33 处一律不动**（bounded · 本仓「⛔ 不顺手清理」）。

> ⚠️ **这个数被我自己错过一次**：先写的是「39 处」—— 那是
> `grep -c 'ErrorCode.QUOTA_EXCEEDED'` **不筛 `raise`** 的结果（41 行），
> 里面混着 docstring / 枚举映射 / 中间件共 6 行。⇒ 真 `raise` 是 **35**。
> 📌 同 `DEC-085` 抄表头旧数那条：**数集合本身，⛔ 别拿一个截过/混过的集合当计数**。
> 判据：`grep -rn 'ErrorCode.QUOTA_EXCEEDED' api/ --include='*.py' | grep -v '^api/test_' | grep -c raise` ⇒ **35**
**代价（知道再选）**：别的端点发出去的 429 **没有** `scope`，前端据此画 `—` —— **这是已知且有意的**。

⚠️ **没给默认值**（比如 `scope` 缺省成 `"global"`）：那会让中间件的限流 429
（它**没有**日级额度这回事）也长出「明日起恢复」来，**前端就再也分不出"不知道"**。

### 前端 · 纯逻辑进 `sse.js`，DOM 留在 `chat.html`

- `sse.js` 加 **纯函数** `breakerCard(scope, message)` → `{title, items}`，四件事：

| 事 | 值 |
|---|---|
| **现状** | **后端原话**（含「已使用 X / 上限 Y tokens」）—— ⛔ 前端不重编（重编 = 数字口径两份，会漂移且**页面上不报错**） |
| **这不是故障** | 固定：额度上限是**成本控制**，不是服务坏了；超出后一律拒绝，⛔ 不是变慢 |
| **何时恢复** | `global` ⇒「明日起自动恢复（按自然日重置 · 全站共享 · ⛔ 无法提前）」<br>`session` ⇒「开一个新会话立刻可继续（额度按会话计 · 跨天也会重置）」<br>认不出 ⇒ `—`（**⛔ 不猜**） |
| **怎么联系** | `BREAKER_CONTACT` = **占位符**（见 §二 缺口 B） |

- `chat.html`：`.breaker` **另起一个元素**（⛔ 不与 `.card` 共用 —— 引用卡片由 `_openIndex`
  驱动、每次重画都被清空，共用一个容器会互相抹掉）；`explainStatus(429)` 改成
  `{ msg:'', relogin:false, breaker:true }`；新增 `readErrorBody`（读不出就 `{}`）
  与 `showBreaker`（全部 `textContent`，`error` 是后端自由文本）。

> ⚠️ 顺带发现：会话级那个 `get_session_token_usage` 的 SQL 也带 `created_at >= CURRENT_DATE`
> ⇒ **两种都是"今日"窗口**。差别**不在时间窗**，在**能不能自救**。
