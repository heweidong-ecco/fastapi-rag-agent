## 二 · 四个契约

### 契约 A · `sources` 帧补 `index` 与 `content`

**现状（改前）**：

```python
# api/api_v1_rag.py:728-735（基准 e8e53b9）
for i, doc in enumerate(contexts, start=1):
    context_parts.append(f"[文档{i}来源：{doc.get('source', '未知')}]\n{doc['content']}")
    sources_list.append({
        "id": doc.get("id"),          # ← 🔴 数据库 id
        "source": doc.get("source", "未知"),
        "content_preview": doc["content"][:100]
    })
```

**🔴 这是一条真实的断链**：prompt 让模型吐的编号（`:740`）是
`[来源:X]`，其中 **X = `enumerate(..., start=1)` 的 `i`**；
而帧里现有的 `id` 是**数据库主键**。⇒ **前端拿不到"X 对应哪一条"**，硬门 B 的「点开引用」**做不到**。

**改法**：加两个字段，**不动 `id`、不动 `content_preview`**（纯追加）：

```python
sources_list.append({
    "index": i,                       # 与 [文档{i}] 同源 —— 见下方不变量
    "id": doc.get("id"),
    "source": doc.get("source", "未知"),
    "content": doc["content"],        # 全文
    "content_preview": doc["content"][:100],
})
```

**🔴 不变量（本条的核心，⛔ 别当注释）**：**`index` 与 `[文档{i}]` 必须来自同一个 `i`**。
一旦有人在两处各写一遍编号，就会**静默错位**（引用点开是对的文档、内容是错的那篇）。
⇒ 判据必须是**推导型**的：从**同一轮**同时取 `sources` 帧与 prompt 里的 `[文档…]`，逐条比对。

**⚠️ 同款第二处（别漏）**：`api/answer_with_citations.py:50-56` 也造同构的 `sources`（`return ... , sources` 在 `:73`），
供非流式链用。**它是同一份契约的另一个出口** ⇒ 一并加 `index` / `content`，并**共用同一条判据口径**。

### 契约 B · `/rag/stream_search` 末尾追加 `usage` 汇总帧

**改后的完整帧序**（⚠️ 前四段是**现有**的，逐字不动）：

```
data: {"content": "……"}        × N     ← 增量
data: [DONE]
data: {"sources": [ … ]}                ← 仅当 citations=true 且非空
data: {"usage": { … }}                  ← 🆕 本刀新增（最后）
（连接关闭）
```

**`usage` 帧的字段**：

| 字段 | 来源 | ⛔ 不许 |
|---|---|---|
| `model` | **从 llm 对象取**（`getattr(llm_obj, "model_name", None) or getattr(llm_obj, "model", "unknown")`） | **写死字符串** —— 本仓因写死 `"qwen-turbo"` 按错单价记过两次账（`DEC-072` 的 docstring 有前科） |
| `prompt_tokens` / `completion_tokens` | `usage_metadata` 的 `input_tokens` / `output_tokens` | 自己数 token |
| `cost_usd` | **复用抽出来的公共算式**（见下） | 在端点里**写第三份公式** |

**数字从哪来**：`_StreamUsageTap`（`DEC-084` 建的，现于 `:786` 的 `tap.record(...)`）
在收尾出口**已经把聚合块交给 `record_from_response`** ——
本刀只是**把同一块里的数字顺便拿出来放进帧**，⛔ 不新开一条取数路径。
⇒ 判据：**记账了就必须出帧、没记账就不许出帧**（两者同源）。

**⚠️ 取消 / 出错时【没有】这一帧** —— 见 §六·2。前端必须**容缺**。

**⚠️ 抽公共算式（顺手做，理由充分）**：计价公式在 `api/token_tracker.py` 里**已经有两份**
（`:86` 与 `:233-234`，同一个算式）。本刀**不写第三份**：
抽出 `_compute_cost(model, prompt_tokens, completion_tokens) -> float`，三处共用。
> 📌 这不属于「顺手清理」—— 是因为**本刀要用的**那个数，除了抽取没有别的复用方式。

### 契约 C · 历史键从 `{user}` 改成 `{session_key(user, thread)}`

**现状**：`api/cache.py:45/59` 是 `f"chat_history:{user_name}"` —— **只按用户**。
`thread_id` 在 `/rag/stream_search` 上**只用于 B8 额度**（`:694`），**不切分历史**。

**改法**：键换成 `f"chat_history:{session_key(user_name, thread_id)}"`。

**为什么复用 `session_key` ⛔ 而不是新发明一种拼法**：
`api/session_key.py:47` 是丙段给 LangGraph 图键造的**无歧义**复合键
（长度前缀 ⇒ 切分点唯一），而且它 **两个形参都必填、都没有默认值**（`:50-52`），还带守卫用例
（`api/test_session_key.py::test_both_params_are_required_positional`）⇒ 漏传即 `TypeError`，
⛔ 不是静默串号。**再造一套 = 造第二个可能漂的实现。**

**⚠️ `thread_id` 必须是关键字参数、必填、无默认值** —— 与 `DEC-055` 对 `status` 的同一条口径：
「留痕字段一旦有默认值，『忘了传』会**静默**变成假信号」。

**连带面（改前必须知道）**：

1. `get_chat_history` / `append_chat_history` / `persist_turn` **签名各加一个 `thread_id`**；
2. **`persist_turn` 有 16 个调用点**（`api_v1_agent.py` **14** 个 + `api_v1_rag.py` **2** 个）
   —— ✅ **好消息**：**5 条 agent 流式端点本来就都有 `thread_id` 查询参数**
   （`api_v1_agent.py:211/279/683` 等）⇒ **不用新造参数**，只是把它继续往下传；
3. `api_v1_rag.py:689-690` 那行回落（`get_chat_history(user_name)`）跟着加 `thread_id`；
4. Agent 5 条链**不读** `chat_history`（它们的下一轮 prompt 来自 **checkpoint**，`api_v1_agent.py:74` 明写）
   ⇒ 对它们**只改"留痕落在哪个键"**，⛔ **不改行为**；
5. `api/conftest.py:55` 的假 redis 键要跟着改；
6. **老键 `chat_history:{user}` 变孤儿** —— 它自带 24h TTL ⇒ **自清，⛔ 不做迁移**。

> 🔴 **这一条动到 `DEC-055` 的地盘**（`persist_turn` 的三出口口径），
> 所以它虽然写在本份里，**实施时必须单独一个 commit**，便于单独回退。

### 契约 D · 🔴 点活 `api_keys.is_active`

**现状（改前）**：

```python
# api/auth.py:110-114（基准 e8e53b9 · `#102` 未碰到本文件）
user_name, expires_at = row
if expires_at < datetime.now():
    return None
return user_name          # ← ⛔ 从不看 is_active
```

**`is_active` 是个死列**：

```bash
grep -rn "is_active" --include='*.py' api/ | grep -v "^api/alembic"
#   api/db_metadata.py:12   ← 注释（且它自己就在说这是"既有差异"）
#   api/db_metadata.py:41   ← Column 声明
#   ⇒ 全仓【没有一处读它】
```

而它**三处都在**：DDL（`api/schema.sql` 的 `api_keys` 块）· 迁移 `828721f77ef2` · `db_metadata.py:41`。
⇒ **发出去的 key 收不回来**，只能 `DELETE` 行。

**改法**：`SELECT` 带上 `is_active`，非激活即 `return None`。

**🔴 必须防 NULL（这是本条最容易栽的地方）**：
迁移写的是 `sa.Column('is_active', sa.Integer(), server_default='1', nullable=True)`
—— **`nullable=True`**。⇒ **不能写 `WHERE is_active = 1`**：
那一行的 `is_active` 只要**是 NULL**，就会被**静默排除** ⇒ **老 key 集体失效**，
而报错只有一句"凭据无效"，**查不到点上**（同 `deps.py:127-128` 剥空白那条的教训）。

```sql
-- ✅ 防 NULL：NULL 一律当"激活"（列语义上的默认值是 1）
SELECT user_name, expires_at FROM api_keys
WHERE key_hash = %s AND COALESCE(is_active, 1) = 1
```

> ⚠️ **本机真库当时没起**（`docker exec` 报 `Container … is not running`）
> ⇒ **"现网有没有 NULL 行"这条【没验过】**。
> 正是**因为没验过**，写法才必须**防 NULL** —— ⛔ 不是"我认为没有"。

**⚠️ 与撤销的配套**：点活之后，"收回一把 key"= `UPDATE api_keys SET is_active = 0 WHERE ...`。
⇒ `scripts/issue_api_key.py` **同时带一个 `--revoke` 子命令**（否则点活了列也没有能用它的手）。
> ⚠️ 防呆：脚本改 `is_active` 时写 **`0`/`1`**，⛔ 不写 `NULL`（写 NULL 在"防 NULL 当激活"的判据下 = **没撤销**）。

### 3.3 一次提问的完整帧序 + 状态机

```
POST /api/v1/rag/stream_search?thread_id=<uuid>
body {"question":"…", "citations": true}
← data: {"content":"……"}            × N   ← 增量，前端累加
← data: [DONE]
← data: {"sources":[{index,id,source,content,content_preview}, …]}
← data: {"usage":{model,prompt_tokens,completion_tokens,cost_usd}}
← 连接关闭
```

🔴 **三条前端必须遵守的**：

1. **直到连接关闭才收工** —— 见 `[DONE]` 就 `return` ⇒ **引用与费用整段丢**
   （`[DONE]` 排在 `sources` 之前是**线上契约**，`api_v1_rag.py:779` 明写、⛔ 不是笔误）；
2. **`citations` 默认 `False`**（`api/schemas.py:16`）⇒ 不显式传 `true`，**根本没有 `sources` 帧**；
3. **`conversation_history` 由后端按 `(user, thread)` 取**（`:689-690`）⇒ 前端**不用**自己传，
   ⛔ 也别传 `[]` 去"清空"（`if not …` 是 falsy 判断，`[]` 会被无视）。

**状态机**：

```
idle ──提问──▶ 请求中 ──首帧──▶ 流式中 ──┬─ 连接关闭且见 [DONE] ──▶ 完成
                                        ├─ 用户点「停止」      ──▶ 已中断
                                        └─ 收到 {"error":…}（无 [DONE]）──▶ 出错
```

- **出错判据**：收到 `error` 帧 **且没有 `[DONE]`**（RAG 端点**故意**不要 `[DONE]`，见 `_on_error` 的 docstring）。
- **首字延迟前端自己测**（发出请求 → 第一帧 `content`），⛔ **不伪装成服务端指标**（本仓有"性能数字必须先说清是目标还是实测"的前科）。

### 3.4 多会话

- `thread_id` 由前端 `crypto.randomUUID()` 生成；`localStorage["rag_threads"]` 存
  `{threads:[{id,title,createdAt}], current}`；标题 = 首问前 20 字。
- 「新会话」= 追加一个 uuid；左侧列表可切换。
- ⚠️ `session_key` 两参必填 ⇒ **`thread_id` 不许为空串**。

## 四 · 备选，与为什么没选

| 备选 | 为什么没选 |

| **上 React/Vue + 构建** | 本仓无 `package.json`、CI 是纯 Python、Docker 里也没有 node 构建阶段 ⇒ 要么引一整条构建链，要么走 CDN（外网依赖，而主线是"上公网"）。**已有原生先例**（`api/static/` 3 页） |

| **取消时也估算一笔 token 记进账** | ⛔ `DEC-084` 已裁：**宁可空着，不编数**（往账本写假数比漏记更坏） |

| **把 `usage` 帧做成独立查询接口** | 多一次往返、多一个要鉴权的面；而且"这一轮花了多少"最准的来源就是**这条流自己** |
