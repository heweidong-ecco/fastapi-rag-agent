# 决策记录：DEC-024 · markdown 图片规则「死代码」怎么处理（N14）

- 日期：2026-09-21
- 状态：**已采纳并执行**（**但留下一个独立待裁项「甲′」**）
- 关联：`docs/待办登记-2026-09-20-全仓审计与方向更正.md` **§三·3.7**

## 决策事项

`document_preprocessor.remove_noise_markers` 里那条 markdown 图片规则
（`re.sub(r'!\[([^\]]*)\]\([^)]+\)', r'\1', text)`），登记文件判它「**从未生效**」⇒ 该怎么处理？

## 背景与约束

- **登记文件原结论**：「URL 规则先跑把输入打残，后面就匹配不上 ⇒ **这条规则的意图实际从未达成**」
  ⇒ 处置建议是「**删掉那条死规则**」（业务方 2026-09-21 一度裁「乙·删」）。
- **约束**：改它 = 改**文本预处理输出** ⇒ 影响**检索结果与已有语料**。删代码本身零风险，但删错就有。
- **本仓纪律**：**动手前把判据重跑一遍**（本仓已多次证明"孤儿/死代码"的结论会错）。

## 🔴 关键：动手前重跑判据，**把原结论推翻了**

**原结论错在哪**：当时**只测了 `default` 一个域**，就下了**全局**结论。
而 `domain` 是**用户传的**（`api_v1_rag.py:259` · `/rag/upload_document` · **无白名单**）
⇒ `legal` / `medical` **生产可达**。

**实测三个域**（2026-09-21）：

| 域 | `![图](http://x/y.png)` | `![图](local.png)` | 那条硬编码规则 |
|---|---|---|---|
| `default` | 🔴 `看图 ![图](  结束`（**残废**） | ✅ `看图 图 结束` | **多余**（配置里有逐字等价的，且**先跑**） |
| **`legal`** | ✅ `看图 图 结束` | ✅ `看图 图 结束` | ⭐ **正在生效**（该域配置里【没有】图片规则） |
| **`medical`** | ✅ `看图 图 结束` | ✅ `看图 图 结束` | ⭐ **同上** |

⇒ **它不是死代码。删了会弄坏 `legal`/`medical` 两个域。**
⇒ **准确的陈述是**：「**在 `legal`/`medical` 生效；在 `default` 被 URL 规则打残**」。

## 备选方案

| 方案 | 一句话 | 行为变更 |
|---|---|---|
| **甲′** | **修 `default` 域** —— 让图片规则排到 URL 规则**之前** | ⚠️ **有**（影响已有语料） |
| **乙′**（**采纳**） | **不删代码，只改注释 + 加回归用例** | ✅ **零** |
| 丙 | 把图片规则补进 `legal`/`medical` 配置，**然后**才删硬编码那条 | ✅ 理论零（要两步 + 验证） |
| ~~原「乙」· 直接删~~ | **⛔ 不能做** —— 实测证明会弄坏 legal/medical | 🔴 有 |

## 决策与理由

**乙′。** 三条理由：

1. **原方案「删」的事实前提是错的** —— 它不是死代码，实测已证。
2. **零行为变更** —— 不动预处理输出 ⇒ 不影响已有语料 ⇒ 无连带成本。
3. **🆕 但只写注释不够** —— 本仓规矩是「**有结构才执行，只有文字就漏**」（`Product/CLAUDE.md` §二）。
   光在那行代码上写"别删"，**下一个会话照样会删**。⇒ **同时加回归用例**把三域行为锁住。

## 执行内容

- `api/document_preprocessor.py` 原处加准确注释（三域实测结论 + "删不得"的理由 + 真问题在哪）
- 🔒 `api/test_audit_fixes.py::test_markdown_image_rule_is_not_dead`：
  - ① `legal`/`medical` **必须收敛成功** ⇒ 谁删了那条规则，这条会红
  - ② `default` 相对路径收敛（配置里那条等价规则在做）
  - ③ **故意锁住 `default` 域的坏行为** —— 哪天它红了，说明有人把顺序修好了 ⇒ 提示更新记录
- ✅ **已做"会红"验证**：把那条规则临时注释掉 ⇒ 用例红，报
  「domain=legal 的图片收敛坏了（得到 '看图 ![图](http://x/y.png) 结束'）」

## 反悔成本

**极低。** 只加了注释 + 一条用例；删掉即可，**零行为变更**。

## 🔴 遗留：仍待裁的是「甲′」

**`default` 域的 `http(s)://` 图片仍然是残废的**（输出残留 `![图](`）。
修法明确（把图片规则提到 URL 规则之前），但它是**行为变更**：

> 会改变 `default` 域的文本预处理输出 ⇒ **影响检索结果与已有语料** ⇒
> 除非**重灌/重新向量化全部文档**，否则新旧语料形态不一致。

⇒ **属独立决策，本次未做。** 登记在 `待办登记` §三·3.7 与 `ROADMAP` 的待裁表里。

## 教训（值得单独记）

**这条决策的真正价值不在改动本身，而在"动手前重跑判据"救回了一次错误删除。**

- 我（Agent）当时的报告用的是**单域证据**下**全局结论** —— 这是本仓反复出现的同型错误：
  **判据的适用范围没写清**（"我测了什么" ≠ "我证明了什么"）。
- 业务方已经据此裁了「删」。**如果直接执行，就会删掉一条正在两个域里干活的规则。**
- ⇒ **可复用的动作**：凡结论是「**X 从未生效 / X 是死代码**」，**先问"我测了几个输入/几个域/几个调用路径"**，
  再决定要不要删。
