## 决策事项

`③` Task 4（`B1` 真流式）跑**真服务**时，照出**两条既有 bug**（⛔ 不是 B1 引入的）。
两条都在 `②` 刚做完的**硬门 D（人工接管）**路径上，**都不报错**，且**都是同一类病**：

| # | 症状 | 为什么它能活到今天 |
|---|---|---|
| **①** | `tool_execute` 按**硬编码字符串**分派：`if tool_name == "search"`，而真工具名是 `duckduckgo_search` | 落 `else` 时**如实返回** `未找到工具: duckduckgo_search` ⇒ 模型以为"搜过了没结果" ⇒ **不崩溃、不报错**。实测后果：模型**反复重试**（`DEC-050` 现场记的就是这个） |
| **②** | `SENSITIVE_TOOLS` 默认值是**变量名** `"search_tool"`，不是工具名 | `validate_approval_config()` **只查"非空"、不查"名字存在"** ⇒ 交集恒空、**审批永不触发**，而**照常启动** |

**可打印的判据**（2026-10-03 实测）：

```
真实工具名     : ['duckduckgo_search', 'calculator', 'date_today']
SENSITIVE_TOOLS: ['search_tool']
交集           : []   <-- 空 = 审批永不触发
tool_execute 判的串: []   <-- 空 = 分派永远落 else
```

### 🔴 为什么"现在"结它，而不是排在 `③` Task 5 之后

**②让硬门 D 名存实亡。** 默认配置下 `should_continue` **永远不会**返回 `"approval"`
⇒ 待接管队列（`B5`）**永远是空的** ⇒ 硬门 D 的验收演示
（「构造一个会被判为需接管的请求 → 系统自动暂停」）**根本构造不出来**。

而 `DEC-048 §四` 自己点名要防的正是这个形态：

> 「把「静默永不触发」换成「**根本没起来**」—— **失败从'验收时才发现'提前到'部署那一刻'**」

⚠️ **但它只把「空名单」做了硬拦，没做「名字不存在」** ⇒ 同一个失败**换了个形状**
（"名字全都对不上"）**绕过了它自己设的闸**。这正是本仓反复记的那种病：
**防线只盖住了它当时想到的那一种形状。**

## ⚠️ 勘误的边界：`DEC-048` 的原意**是对的**，坏的是标识符

`DEC-048:50` 明文写「`search_tool`（`DuckDuckGoSearchRun`）✅ **进白名单**」——
意图毫不含糊就是"**那个出网的工具**"，判据「**敏感 = 把数据发到本机之外**」也**原样成立**。

⇒ 🟢 **本 DEC 是勘误 + 加固**：`DEC-048` 的四条裁定（白名单语义 / 敏感定义 / 写在 `.env` / 空名单硬拦）
**一条都不改**。⛔ **不是推翻它。**

⚠️ 但 `DEC-048` 里有**一句话现在是假的**，本 DEC 一并改掉：
> ~~「有默认值 `search_tool` ⇒ 不设 `.env` 也能跑，**且跑的是对的那个**」~~（`:66`）

**"跑的是对的那个"从来就没成立过** —— 它当时的"对"是**意图**，不是**实测**。

## 备选方案

### 一 · 分派怎么写

| 方案 | 评价 |
|---|---|
| **甲 · 查表 `{t.name: t for t in tools}`**（**采纳**） | ✅ **工具名只有一个来源** ⇒ 改名不会再漂<br>✅ 与 `DEC-049` 的收口姿势同族（**把"抄了一份"改成"指向唯一来源"**）<br>⚠️ 要保证查不到时**如实报错**，⛔ 不是 `KeyError`（否则一次"模型调错名字"会升级成整条请求 500） |
| 乙 · 只把字面量改成 `"web_search"` | ⛔ **保留病根**：名字仍写在两处，下次改名**照样静默失效**。⚠️ 而**同型 bug 在本仓是第二次**了 —— `plan_execute.py:101-110` 记着上一回（prompt 写 `search`、注册表里叫 `web_search`）。**第一次是偶然，第二次是模式** |
| 丙 · 改用 `ToolNode` / `create_tool_calling_executor` | ⛔ 动**图的结构** ⇒ 与 `④` 的"6 套 Agent 实现待收敛"纠缠，**超出本任务范围** |

### 二 · 启动自检的力度

| 方案 | 评价 |
|---|---|
| **甲 · 硬拦（名字不存在 ⇒ `raise EnvironmentError`）**（**采纳 · 业务方 2026-10-03 裁**） | ✅ **唯一能在第一天就抓住本 bug 的判据**；与 `DEC-048 §四` 的既定哲学一致<br>✅ 报错**点名**那个不认识的名字 + **列出可用工具名** |
| 乙 · 只警告 | ⛔ 本仓明文说过「**恒响的警告 = 把真警告淹掉**」（`pending_approvals.py:71`）⇒ 等于没拦 |
| 丙 · 硬拦"空名单 + 全不匹配"，警告"部分不匹配" | ⚠️ 只杀"必然失效"、放过"部分裁量"。**本次没选** —— 部分不匹配同样是静默失效（那一个工具永不审批），且没有真实用例需要它 |

> ⛔ **甲方案的代价（明说）**：在 `.env` 里写了错名字的部署**会直接起不来**。
> ⚠️ 这是**有意的** —— 与 `DEC-048` 同一个取舍：**"部署那一刻失败"好过"验收时才发现接管从来没发生过"**。
> 📌 缓解：默认值是对的 ⇒ **不显式设 `.env` 的人根本遇不到**；`.env.example` 里也已改对。

### 三 · 搜索工具换不换

| 方案 | 评价 |

| **甲 · 换成 `search_tools.web_search`（Bing 版）**（**采纳 · 业务方 2026-10-03 裁**） | ✅ `api/search_tools.py:47` 记着 2026-09-21 实测：**`duckduckgo.com` 本机完全不通**、`cn.bing.com` 是当时唯一可达的 ⇒ **旧那份在本机部署下必定失败**<br>✅ `web_search` **已经在** `mcp_server.TOOLS` / `tool_health.TEST_ARGS_MAP` / `token_tracker` 的成本与 token 两张表里；而 **`duckduckgo_search` 三张表一个都没有** ⇒ 换掉顺带修好**成本统计的漏账**<br>✅ 两者都是**同步**、都返回 `str` ⇒ `tool_execute` **不必**变 async |

## ⚠️ 本 DEC **不声明**"搜索能用了"（⛔ 不能含糊过去）

换掉工具**不等于**搜索在本机能跑。📌 本 DEC 只声明 **「分派走对了」**（**离线可验证**）：

```bash
# 修复前 ⇒ []（空 = 审批永不触发）；修复后 ⇒ ['web_search']
venv/bin/python -c "import sys;sys.path.insert(0,'api');import agent_graph as g;print(sorted({t.name for t in g.tools} & g.SENSITIVE_TOOLS))"
```

⛔ **不声明「`web_search` 能搜到东西」** —— 那要真联网，**本机不可验证**，真收益在有网的部署环境。
（本仓纪律：引用任何性能/能力数字前，先说明它是**目标**还是**实测**。）

## 这次学到的（写进本仓判据族）

- **①是"防线盖住了想到的形状"的又一例**：`DEC-048` 拦了"空名单"，没拦"名字不存在"。
  ⇒ 📌 **判据：设计一道防线时，问一句「同一个失败还有什么别的形状能绕过它？」**
- **②是"我做了 ≠ 别人验得出来"的又一例**：测试文件**自己钉着那个错名字**
  （`test_approval_trigger.py:13`），⇒ 它**不可能**发现这个 bug。
  ⇒ 📌 **判据：测试里的常量，必须能在被测对象里找到同一个真值**（本 DEC 的守卫用的就是这条：
  断言"名单里的名字 ∈ 真实工具名"，⛔ 不是断言"名单非空"）。
