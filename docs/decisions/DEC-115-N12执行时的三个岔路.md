## 岔路 ① · 「先真跑一次 approve」——**不做，而且不能做**

**`N12` 原文写的顺序**：「先**真跑一次 approve**（表是惰性的），再 `pg_dump`」。

**执行时实测**：本机真库 `approval_events` **已经有 456 行** ——
表**早就被惰性建出来过了**（判据：`SELECT count(*) FROM approval_events` ⇒ `456`）。
列与类型**逐格等于** `api/approval_audit.py` 的 `_DDL`（判据：`\d approval_events`）。

| 备选 | 为什么没选 |
|---|---|
| **甲（选）** 只做 DDL 侧的重导，**不动真库数据** | ✅ 要它进快照，前提只是"那个库上**发生过**一次 approve" —— **已经发生过了** |
| 乙 再跑一次真 approve（走 HTTP 端点或探针） | 🔴 **`approval_events` 是审计留痕表** ⇒ 为了导出一次 DDL 而补写一条 = **假留痕**（伪造"批过"）。<br>本仓立场：`docs/specs/approval_audit.md`「**表里少一条 ≠ 那次裁决没发生**」—— **反过来同样成立** |
| 丙 在 `rag_db` 里 `CREATE TABLE` 完再 `DELETE` 那行 | ⚠️ 仍是往真库写；且**留痕表删行本身就是另一件要裁的事**（无保留期 / 无清理任务，见 spec） |

**反悔成本**：**低** —— 将来换个全新的库上云时，"惰性表不进 `pg_dump`"**会原样复现**；
那条注意事项**已写进 `docs/specs/approval_audit.md`**（一句"全新的库上仍要先真跑一次"）。

---

## 岔路 ② · 生成物里那处【手改】——**不加回来**

重导会**抹掉**旧 `api/schema.sql` 里的一处手改：
`api_keys.is_active` 行尾挂着 `-- DEC-086：auth.py 按 COALESCE(is_active,1)=1 过滤；写侧是整数 0/1`。

🔴 **这正是该文件头第 1 条警告说的那件事**（手改生成物 ⇒ 下次一跑生成命令就**静默抹掉**）。

| 备选 | 为什么没选 |
|---|---|
| **甲（选）** 不加回来，**把这件事本身写进文件头** | ✅ 那条说明**已经有三个家**：`api/db.py:80-90`（DDL 源头）· `docs/契约/数据模型.md`（`api_keys` 节）· `DEC-086`（整份）。生成物里那份是**第四份冗余** |
| 乙 加回来 | ⛔ **留给下一次同一个坑** —— 下一个重导的人会再抹一次，而且那次**不会有人告诉他** |
| 丙 把 `api/schema.sql` 改成"头手写 + 正文生成"的两段式并加个小脚本 | ⚠️ **本轮不做**：为一个注释引入一条生成链，成本/收益不成比例。**但它是个真缺口**，已记在 §五 |

**反悔成本**：**低** —— 把那一行贴回去即可（内容在 `api/db.py:80-90`）。

## 岔路 ③ · 🔴 判据用哪个串 —— **这条尺子被写歪过两次**

**`N12` 原写**：`grep -c 'approval_events' api/schema.sql` ⇒ **应为 1**。

🔴 **那个数【是猜的】** —— 写它的人**从没见过真的 dump**。实测：

| 版本 | 命令 | 实测 | 病 |
|---|---|---:|---|
| 初版 | `grep -c 'approval_events'` | **11**（只算 dump 正文）→ 写完说明后 **13** | 把**说明文字自己**也数了进去 |
| 第二版 | `grep -c 'CREATE TABLE public.approval_events'`（**无 `^`**） | **2** | **同一个病** —— 我**又**把那串原样写进了说明 |
| ✅ **第三版（定稿）** | `grep -c '^CREATE TABLE public\.approval_events'` | **1**（改前 **0**） | 无 —— dump 是**行首**输出，说明里那串在**行中** ⇒ **再怎么写说明都不动这个数** |

⇒ ✅ **定稿判据 = `grep -c '^CREATE TABLE public\.approval_events' api/schema.sql` ⇒ 1（改前 0）**。

⚠️ **本仓同族**（**第 3 次**）：
`docs/复盘/2026-10-05-拿代理量当判据.md` · `docs/复盘/2026-10-02-判据写歪了不报错.md`。
🔴 **新学到的一格**：**"我写了一段描述这条判据的说明"这件事本身，会改变判据的输出** ——
所以钉子必须选**不会被自己的说明撼动**的形状（**行首锚**就是其中一种）。

**反悔成本**：**低** —— 换一条命令而已。

## 四 · 判据（**可打印**）

```bash
# 主判据（N12 的正身）
grep -c '^CREATE TABLE public\.approval_events' api/schema.sql        # ⇒ 1

# 尺子不自我指涉的【反证】：在文件任意处再写几行含该串的说明，上面那个数【不变】
#   （⛔ 无锚版做不到 —— 见 §三 的表）

# 真库用例
POSTGRES_DB=rag_test venv/bin/python -m pytest api/test_approval_events_db.py -q -m needs_db   # ⇒ 6 passed

# 真库那一侧的事实（岔路①）
docker compose exec -T postgres psql -U postgres -d rag_db -tAc \
  "SELECT count(*) FROM approval_events"                              # ⇒ 456（表早就建出来了）
```

> 🔴 **「改前 ⇒ 0」是【事实】，⛔ 不是一条命令** ——
> 那条命令本来是 `grep -c … tmp/schema.sql.before-20261008`，而 **`tmp/` 在 `.gitignore` 里**
> ⇒ **换个会话、换台机器就没有那个文件** ⇒  **它只对当时那台机器能跑**。
> ⇒ 本 DEC 把它**降级成事实陈述**（改前的文件确实没有那段 `CREATE TABLE`），
> ⛔ 不留一条**看起来能跑、实际只有我这儿能跑**的命令（那正是本仓最恨的"假判据外观"）。
