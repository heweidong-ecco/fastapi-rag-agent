## 一 · 这批的一句话

**图里"预算不够"不再是一句【答案】，而是一个【信号】—— 端点层据此回 429 / error 帧。**

```
图节点：拦下 ⇒ 在 state 上写 `budget_intercept = <原因>`
端点层：读到非空 ⇒ 拼文案 ⇒ 非流式 429 / 流式 error 帧
```

### 真正的洞是**两种**（都要治）

1. **入口侧可复现**：中间件只在 `remaining <= 0` 时拒（`api/main.py:329 quota_reject_payload`，
   **纯库存**判定）；图节点调的是 `check_token_budget(user_name, estimated_tokens=500)`
   ⇒ **`0 < remaining < 500` 的用户穿得过中间件**，进图后被**入口节点立刻**软返回。
2. **跑一半才超**：请求进来时预算够，图跨多节点把预算烧穿 ⇒ 后续节点的软返回接管。
   中间件**只在入口查一次**。

⇒ **修的是「出口形状」，⛔ 不是「再加一道门」。**

## 三 · 裁定 · `🅐` **复用** `budget_intercept`，契约 = **原因**，文案由端点层**统一**拼

| 项 | 决定 |
|---|---|
| 图的契约 | `budget_intercept` 存 **原因**（`str`），⛔ **不是**整句给调用方的话 |
| 端点的契约 | 读到非空 ⇒ 用**模块级纯函数** `api_v1_agent.agent_budget_intercept_message(why)` 拼 ⇒ 非流式 `raise AppException(QUOTA_EXCEEDED, msg)`（**429**）· 流式发**一帧** `{"error": msg}` + `[DONE]` + `persist_turn(..., status="error")` |

### 为什么是「复用」而不是新键

`DEC-078` §六 已明文留下：「**无论走哪条，`budget_intercept` 与"入口清零"都该留下** ——
它不是为硬拦截而生的，它是「**拦截这件事发生在图里、而调用方在端点**」这个结构本身要求的通道。」
⇒ 两个键 = **两处清零** = 破坏 `DEC-078` §四 的单一来源。

### 为什么**不**把整句话写进图里

那样要改 `tool_execute`（`S13` 刚落地的代码），而
`api/test_budget_hard_intercept.py:88` 的 `assert out["budget_intercept"] == REASON` **是精确相等**
⇒ `S13` 的 11 条守卫要跟着改。
走端点层拼文案 ⇒ **`S13` 的 11 条守卫一行都不用动**（它只断言 `REASON in message`，`:275`）。
📌 **实测：本批收工后那 11 条仍全绿，且 `git diff` 对该文件为空。**

### ⚠️ 代价（已知、接受）：`/agent/mcp_chat` 那句中文**变了**

| | 改前 | 改后 |
|---|---|---|
| 前缀 | `预算拦截，本次工具调用未执行：` | `预算拦截，**本轮**未继续执行：` |

**理由**：本批新增的 8 处软返回**根本没有工具调用**（入口节点在调 LLM **之前**就拦下了）
⇒ 旧句对它们**不准**（说了一个没发生的事）。
⚠️ **"哪个工具没执行"这个信息没有丢** —— `check_multilevel_budget` 的 reason 里本来就带（形如「工具 `x` 将超出…」）。
📌 本仓规矩：**改既有判据不许静默** ⇒ 本条即声明，`CHANGELOG` 同步记。

### 🔴 **语义翻转**（`mcp_agent.agent_decide` 的软返回出口）

改前它写 `**cleared`（**显式清零**）—— 那时"拦截"**只有** `tool_execute`（工具触发）那一种，
入口节点的任务仅仅是"别让上轮的值串过来"。
**本批新增的正是"入口节点自己就是拦截点"** ⇒ 该出口必须写**本轮的原因**，
⛔ 再写 `None` 就等于**把这次拦截藏起来**（而那正是本批要治的病）。

⇒ 对应的守卫用例**改名 + 改断言**：
`test_软返回那一轮的出口也要清零标志` → `test_软返回那一轮的出口也要带上本轮的值`
（断言从"是 `None`"改成"**不是上一轮那个值**"）。
⚠️ **守的东西没变**（上轮的值不许串过来）⇒ 这不是"改断言让它变绿"，是**含义真的翻了**。
📄 原文出处已加墓碑 ⇒ `docs/decisions/DEC-078-…md:83` 下方。

### 🔴 三个非显然的坑（都已在代码里核过）

1. **`supervisor` 的正常出口是 `return state`**（返回**整个** state 并原地改），⛔ 不是返回增量
   ⇒ 清零必须写成 `state["budget_intercept"] = None`。
2. **`supervisor` 的软返回必须继续带 `intent="CHAT"`** —— `route_by_intent` 读 `state["intent"]`，
   少了它当场 `KeyError` = **500**（而不是一句"预算用完了"）。本批**只加一个键**。
3. **`agent_graph.py` / `agent_checkpointer.py` 的软返回返回 `AIMessage` 而【不是】`final_output`**
   （`should_continue` 读 `messages[-1].tool_calls`）⇒ 本批**只加键、⛔ 不改返回形状**。

> ### 🔴 勘误（2026-10-05 收口自检 —— **原判据是假的**）
>
> 本节原写：
>
> ```bash

> git diff --stat api/test_budget_hard_intercept.py     # 应为空

> **实测该文件改了 26 行** —— `git diff --stat` **不为空**。它把**一条假判据**写成了
> "可打印命令 + 期望输出"，而那个期望输出**与事实相反**：
>
> | 事实 | 值 |
> |---|---|
> | 改动行数 | **26**（`git show --stat HEAD` 实测） |
> | 用例**条数** | **11 → 11**（没变，⛔ "条数没变"≠"文件没改"） |
> | 改的是哪条 | `test_软返回那一轮的出口也要清零标志` → `test_软返回那一轮的出口也要带上本轮的值`（`:220`），断言 `is None` → `!= "上一轮被拦了"` + 非空 |

> ⛔ 不是 `grep -c "^def test_"`。
