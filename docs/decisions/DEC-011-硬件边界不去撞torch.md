# 决策记录:DEC-011 · 硬件边界 —— 不去撞 torch / reranker 那条路

- 日期:2026-09-17
- 状态:已采纳
- 关联:`ROADMAP.md` 本机硬件实况 · 重构计划 §七「明确不做」

## 决策事项

一句话:**本机跑不了 `mode=accurate/full` 与 `rerank_search`**(要 torch + 2.3GB 模型)。
**要不要去撞一次,把这块验证补上?**

## 背景与约束

**本机硬件实测(2026-09-17)**:

| 项 | 值 |
|---|---|
| 物理内存 | **8.0 GB** |
| CPU | 4 核 Intel i5-7600 |
| 磁盘可用 | **452 GB —— 磁盘不是瓶颈** |
| Docker 配额 | **3.84 GiB** |
| **当前空闲内存** | **≈ 105 MB** |

**被挡住的两条路**:
1. `docker build` 完整镜像(宿主 8GB + Docker 只分到 3.84GB)
2. `mode=accurate/full` 与 `rerank_search` —— 需 torch(~1GB)+ 模型 `bge-reranker-v2-m3`(**2.3GB**)

**⚠️ 关键澄清(业务方此问触发的最重要一条)**:**这不是代码/业务问题**。
`reranker.py:14` 是**真懒加载**、默认 mode 是 `accurate_norerank`
⇒ **默认路径根本不碰 torch**,所以"没装 torch"**不会让应用起不来**。**这是设计好的。**

**已实测确认**:torch / transformers / sentence_transformers / cv2 / ragas / datasets / locust **一个都没装**;
gradio 与 matplotlib **有**。

## 备选方案

| 方案 | 思路 | 优点 | 缺点 |
|---|---|---|---|
| **甲** | **不撞**,把边界如实登记 | 零成本、零风险 | rerank 面**验证永远空着** |
| 乙 | 在 scratch venv 里装 CPU torch + 拉 2.3GB 模型,跑一次 `mode=accurate` | 能把验证洞补上 | **预计十几到几十分钟,可能把机器拖到卡死**(当前只剩 ~105MB) |
| 丙 | 换台大内存机器再做 | 最彻底 | 不在本次可及范围 |

## 评估标准

补齐的验证价值 / 对本机可用性的影响 / 时间成本 / 是否阻塞当前工作。

## 方案对比

**⚠️ 准确的说法是「没有余量、高风险」,不是「物理上不可能」。**
8GB 里塞 torch(~1GB)+ 模型(2.3GB)≈ **3.3GB 峰值**,**理论上塞得下** —— 但此刻只剩 105MB,**会疯狂 swap**。

**收益面**:被挡住的**只有 rerank 相关**,其余(默认路径、`import main`、pytest、评测、4 个切开点)**全部已在本机跑通**。

## 最终决策 + 理由

**✅ 采纳甲。**

**业务方原话(2026-09-17)**:「**不值**」

理由:
1. **收益面窄** —— 只补 rerank 一块,而它**不是默认路径**
2. **代价实在** —— 可能把机器拖死,而当前工作(⑥ 切模块)还没做完
3. **有一条更好的路** —— 这条边界**如实登记**即可,换机器再补
