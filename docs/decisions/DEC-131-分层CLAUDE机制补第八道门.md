## 一 · 背景（**这是缺口，不是新功能**）

2026-10-09 起本仓用「**每层目录一份 `CLAUDE.md`**」这套机制（规范 ⇒ `docs/规范/目录结构与分层CLAUDE规范.md` §六）。

**实测（2026-10-10 · `git ls-files`）**：

```
含 CLAUDE.md 的目录层：52 / 53（唯一没有的是 archive/ —— 在规范 §六 的豁免名单里）
⇒ 覆盖是【满的】
```

🔴 **但全仓 7 道门里，没有一道管目录层**：

| 门 | 它管什么 | 管目录吗 |
|---|---|---|
| ③ 孤儿门 | 「**`.md` 文档**必须被指向」 | ⛔ 不管 |
| ④ 模块 spec 门 | 「新增 **`.py` 模块** ⇒ 必须有同目录 spec」 | ⛔ 不管 |
| 其余五道 | 凭据 / 链接 / 路由鉴权 / ruff / 过期导入 | ⛔ 不管 |

⇒ **新加一个目录、忘了写 `CLAUDE.md`，不会有任何信号** ——
下一次 agent 进到那层**什么都读不到**，而**所有门都不会红**。

本仓立场（就写在根 `CLAUDE.md` 里）：
- **「门挂在别处，就等于没有门」**
- **「只有文字就漏，结构才执行」** —— 在补这道门之前，规范 §六 **只有文字**

---

## 二 · 决策点 1 · **新开一道，还是并进第 ④ 道**

| 备选 | 评估 |
|---|---|
| **甲 ✅ 新开一道（第 ⑧）** | 判的对象**不同**（**目录** vs **`.py` 模块**）· 豁免名单**不同**（规范 §六 那份 vs `NON_MODULE_FILES`）· 触发面也不同（第 ④ 只看 `--diff-filter=A`）⇒ 混在一起**红的时候说不清是哪一类** |
| 乙 并进第 ④ 道 | 少一道编号，但**两套判据 + 两份豁免**塞一个函数里 ⇒ 下一次改一边**会碰到另一边** |

**选甲**。**反悔成本：低**（合并成一道是删除 + 挪代码）。

---

## 三 · 决策点 2 · **判据的阈值**

「什么算一个需要 `CLAUDE.md` 的目录」？

| 备选 | 实测 |
|---|---|
| **甲 ✅ 含 ≥1 个 tracked 文件** | 实测 **1 个缺**（`archive/`）—— 而它在**豁免名单里** ⇒ **净 0** |
| 乙 含 ≥2 个 | 实测 **0 个缺** —— 🔴 **但它会漏掉"只有一个文件的目录"**（那种目录恰恰最容易被忘） |

**选甲**。⚠️ **理由不是"甲更严"**，是：**豁免名单已经能表达"这个目录不该有"** ——
再加一层数量阈值 ⇒ **同一个判断有两个来源**（本仓教训：**一个名字两个来源必然漂移**，`DEC-051`）。

---

## 四 · 决策点 3 · **豁免名单从哪来**

| 备选 | 评估 |
|---|---|
| **甲 ✅ 抄自规范 §六**（并在规范里写明"**这份就是门的名单**"） | 单一来源 ⇒ 改一处即可；⚠️ **代价：两边必须同批改**，而不一致的表现是「**门放行了规范不许放的东西**（或反之）」，**不报错** |
| 乙 在脚本里另立一份 | 🔴 **两份名单必然漂移**（本仓明文教训） |

**选甲**。📌 **已落在规范 §六 的一句引用块里** —— 那里写死了「这份就是门的豁免名单」。

## 五 · 决策点 4 · **接进哪几处**

| 位置 | 接不接 | 理由 |
|---|---|---|
| `.claude/hooks/pre-commit-gates.py` | ✅ **接** | 这是"提交前门"的**唯一登记处** |

| `.claude/README.md` | ✅ **接** | **本层规矩**：「新加一道门，**必须登记进 `README.md`**」 |

| 规范 §六 / §八 | ✅ **接** | 判据只有变成**可打印命令**才算数 |

> ⚠️ **`ci-local.sh` 自动跟上**：它**逐字读 `ci.yml` 那块 `run`** ⇒ ⛔ 我**没有**另开一个 step（那样它就跑不到）。

## 六 · 决策点 5 · **退出码**

沿用本仓已有的**三态**约定（第 ⑥/⑦ 道门立的）：

| 码 | 含义 | 门怎么显示 |
|---|---|---|
| `0` | 通过 | ✅ |
| `1` | **有缺**（点名到目录） | 🔴 拦 |
| **`3`** | **没跑**（不是 git 仓 / git 读不到） | **⏭ 未跑** —— ⛔ **不是 ✅** |

🔴 **为什么非要第三个码**：本仓原话 —— **「『从不命中』与『没人违规』在机器痕迹上完全一样」**。
只有 0/非 0 两分时，一个**根本没跑**的门会被汇总行打成 `✅`。

⚠️ **CI 那边任何非 0 都算失败** ⇒ 兜底成立。

## 七 · 自测（**这条不是可选项**）

本仓立场：**「一条测不出『不成立』的守卫 = 没有守卫」**（`DEC-061`）。

`.sh --self-test` **5 条**（⚠️ **它是脚本自带的 `--self-test`，⛔ 不像别家另开 `test_*.sh`** ——
判据简单，不需要夹具文件）：

| # | 造什么 | 期望 |
|---|---|---|
| **T1** | 每层都有 `CLAUDE.md` | **绿** |
| **T2** | 加一个有内容、没 `CLAUDE.md` 的目录 | **红，且【指名】到它** |
| **T3** | 把 `CLAUDE.md` 补上 | **回绿** —— **证明 T2 钉的真是那一件**（⛔ 不是"随便红一下"） |
| **T4** | 豁免目录（`archive/`）有内容、没 `CLAUDE.md` | **不报**（否则门会天天误报 ⇒ 形同没有） |
| **T5** | 不是 git 仓 | **`3`**（⛔ 不是 0，也不是 1） |

📌 判据（可打印）：`bash scripts/check_layered_claude_md.sh --self-test` ⇒ **5 通过 / 0 失败**。
