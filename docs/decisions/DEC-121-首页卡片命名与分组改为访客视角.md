## 二 · 外部依据（⛔ 不是我的印象）

📄 **全文与出处 ⇒ `frontend/行业口径-导航与信息架构.md` §二**。三条要点：

1. **按模块/组织分导航是公认反模式**，行业叫 **"shipping the org chart"**。
   资料里有个形状几乎一样的例子：约 **140 页**的产品文档**按内部模块结构组织**，
   标签写「Orchestration Engine」而不是读者要做的事 ⇒ **工单问的都是"其实早写过了"的内容**。
2. 🔴 **一条关键反例**：**Elsevier 从"组织结构"换到"流程结构"，也没解决** ——
   用户对流程的了解并不比对部门多。
   ⇒ ⚠️ **「把接口换成模块」也是内部逻辑 —— 换了等于没换。**
3. **推荐做法**：**任务导向（outside-in）** —— 按**用户真的会问的问题**分。
   一个真实改法：`Products/Solutions/Services/Resources`（内部团队划分）
   ⇒ `Get Started/Pricing/Support/Learn`，**「页面一个都没变，只换了分组的镜头」**，走错路大幅减少。

## 三 · 被裁的那一条

> **业务方 2026-10-09 选择：甲 —— 改【命名 + 分组】。**

**⛔ 不动**：页面划分（11 页不变）· 接口归位（60 条不变）· 已裁的「主要 5 类」。
✅ **只动**：**13 张卡的标题** + **「其他功能」那 8 张的分组**。

### 3.1 🔴 一条**同时**满足两句要求的口径

业务方有**两句必须同时成立**的话：

> ① 「**95% 的人不会去看代码**……只会看你**做了哪些功能、哪些接口**」
> ② 「看 demo 的人**也不是技术人员，也不懂这些**」

⇒ **两句的解法是同一条**：

> ⭐ **标题 = 访客的话（他会问的问题）**
> ⭐ **模块名 / 接口名降为「副标题」—— 用来证明"我真做了"，⛔ 不是删掉**

⇒ **⛔ 不是"把模块名删掉"**。删了就违反 ①（他看不到你做了哪些接口）。

## 五 · 落地的对照表

**「主要功能」5 张**（✅ 保持 —— 它们本来就是人话；只补副标题）

| 标题 | 副标题（= 模块 / 接口 · 证明"做了"） |
|---|---|
| 对话 | `POST /rag/stream_search`（SSE 流式）· 引用 · 停止 |
| 三种检索方式 | `pg_search` · `hybrid_search` · `rerank_search` · `rewrite_search` |

**「其他功能」8 张** ⇒ **按访客会问的问题，重分成 3 组**

| 组（= 访客的问题） | 标题 | 副标题（模块名 / 接口） |
|---|---|---|
| **A · 答案是怎么来的** | 传我自己的文档 | `POST /rag/upload_document`（带 `doc_type` 分档）· `DELETE /rag/documents/{id}` |
| | 它会去网上查吗 | `GET /agent/available_tools` · `mcp_tools_dynamic` |
| | 它记得住上一轮吗 | `POST /agent/memory/add` · `GET /agent/memory/search` |
| **B · 它会不会乱来** | 它会写代码跑代码吗 | `POST /agent/execute_code`（⛔ 无网 · 只读根 · 非 root） |
| | 花太多会怎样 | `GET /agent/budget/check` · `estimates` · `intercepts` |
| | 限流真的在跑吗 | `GET /debug/rate_limit/{user}` · `debug/cache_stats` |
| **C · 它靠不靠谱** | 现在服务正常吗 | `GET /health` · `/ready` · `/metrics` |
| | 你怎么知道它做得对 | 评测门（`agent-eval-gate`）· `GET /eval` |
