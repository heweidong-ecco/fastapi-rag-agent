### ② 「半截答案怎么了」—— 现在是**直接丢**，而且**不是决定**

`api/api_v1_rag.py` 的收尾段（改动前）：


## 二 · 决策

### 决策 1 · **存**，不是丢

**理由（排序即权重）**：

1. **代码原作者的意图本来就是这个** —— `api_v1_rag.py:691` 那行注释早就写着
   「如果有停止当前消息先放历史，如果没有即为空，再放当前提示词 **真停止按钮的调用
   （使它支持历史补偿）**」。⇒ **我们不是加了个新行为，是把一个没接上的意图接上。**
2. 丢的代价**不止半截答案** —— 连**用户那句提问**一起丢（见上）。
3. 与 Agent 端**不对称**：Agent 端图中途状态由 checkpointer（`MemorySaver`）持有，
   取消时**半路状态已经在里面**；RAG 端却什么都没有 ⇒ 同一件事两种后果，说不通。

### 决策 2 · 存的形态：**提问 + 半截 + 中断标记**，成对写

- **成对**：只写答案不写提问 ⇒ 历史里会出现一条**没有来由**的助手消息。
- 🔴 **必须带标记**：历史会被**原样拼进下一轮的 prompt**（`:692-694`）——
  不带标记 ⇒ 模型会把一段**被截断的回答**当成"我上一轮说完了"，行为跟着变。

```python
INTERRUPTED_SUFFIX = "…（本次回答被中断，以上为已生成部分）"
```

### 决策 3 · 落点是 `finally`，⛔ 不是 `except CancelledError`

**与 `DEC-052` 同一个理由**：Starlette 有两条关闭路径 ——
`spec_version 2.3`（uvicorn 实测值）抛 `CancelledError`，`2.4` 抛 **`GeneratorExit`**
（**不是**前者的子类，**不进那个 `except`**）⇒ 写在 `except` 里的实现在换分支后会**静默不存**。

⚠️ `append_chat_history` 是**同步**的（`api/cache.py:39`）—— 正好：取消已经在传播了，
这个收尾动作**不该再引出新的 await 点**（那等于又给"取消被打断"多留一次机会）。

### 决策 4 · 边界：**一块都没生成 ⇒ 什么都不写**

写一条**空的**助手消息只会污染下一轮 prompt（模型看到"回答是空的"）。
判据落在 `collected_parts` 拼出的字符串上（`:strip()` 后为空即不写）。

## 三 · 备选，与为什么没选

| 备选 | 为什么没选 |
|---|---|
| **丢掉，但写进文档当作"已裁定"** | 最省事，但**代价没消**（提问一起丢）而且**与作者原意相反**（§二·决策 1·理由 1） |
| **存，不带标记** | 下一轮 prompt 会拿到一段**看着完整、其实是断的**回答 ⇒ 模型行为被静默改变。比不存更难查 |
| **存进另一个"草稿"键**（⛔ 不进主历史） | 更干净，但**本轮没做**：`get_chat_history` 只读 `chat_history:{user}` 一个键，加第二套等于**新开一条数据流**（谁读？谁清理？24 小时过期怎么算？）⇒ 不是不能做，是**它得自己一个决策**，不该塞进 `B3` |
| **同时补上 token 记账** | ⛔ **做不到**（§一·① 末段：取消时协议上拿不到 usage）⇒ 硬做等于**写估算值进账本**。业务方 2026-09-30 已裁「先以本机证据为准」⇒ **宁可空着，不编数** |
