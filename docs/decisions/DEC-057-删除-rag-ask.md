## 一 · 它是什么（**三条理由，都可打印地核过**）

### 1. 自述与行为不符 —— 桩却读真库

`tags=["模拟类测试"]`，函数名 `ask_question`，但函数体是：

```python
cur.execute(
    "SELECT content FROM documents WHERE requested_by = %s LIMIT %s",
    (user_name, req.top_k),
)
```

⇒ **查的是真库真文档**，不是 mock。

> 📌 **教训（本条的普遍意义）**：`tags` 是**自述**，⛔ 不能当"这条是桩"的判据。
> 同组的 `/rag/async_ask` · `/rag/parallel_ask` 倒是真 mock（`asyncio.sleep(2)` 后返回硬编码串），
> **三条挂着同一个 tag，行为却分成两类** —— 这正是"标签不可信"的现场证据。

### 2. 结果不可复现 —— 有 `WHERE`、有 `LIMIT`，**唯独没有 `ORDER BY`**

没有 `ORDER BY` 的 `LIMIT` ⇒ **取哪几行由物理顺序决定** ⇒ 同一个问题两次可能拿到不同的行。

> 🔴 **这正是本仓反复记的那种形态**：「**看着像检索、其实不是**」。
> 对照：`/rag/pg_search` 与它**同形**（同样 `WHERE requested_by`），但**带 `ORDER BY`**。

### 3. 能力被覆盖 + 无消费者 ⇒ 没有存在的理由

**能力覆盖**（业务方当日的追问：「它的能力是否被其他接口覆盖」）：

| | `/rag/ask` | `/rag/pg_search` |
|---|---|---|
| 鉴权 | `get_current_user_hybrid` | **同** |
| 入参 | `QuestionRequest` | **同** |
| embedding | ⛔ 无 | ✅ 有 |
| `ORDER BY` | ⛔ 无 | ✅ 有 |
| 输出 | `content` 4 列，**含一个重复的 `"requested_by"` 键** | 更丰富 |

⇒ **`/rag/ask` 唯一独有的是「零成本」**（不调 LLM、不调 embedding）。
⚠️ 而**这恰恰是它该被删的理由**：一个不花钱的端点，返回的却是**不可复现**的结果 ——
"便宜"不能替代"正确"。

**消费者清点**（⚠️ **判据必须是清点，⛔ 不是"我试了一次没反应"** ——
本仓有前科：`docs/复盘/2026-09-29-结果为空就断言能力不存在.md`，当时在 **4 处**写下
「`/rag/ask` 不存在」，**全错**）：

| 面 | 结果 | 判据 |
|---|---|---|
| 仓内前端 | **无前端** | 本仓没有前端目录 |
| 兄弟仓引用 | **0 处** | 全仓 + 兄弟仓 grep |
| Postman 集合 | **3 处**（⚠️ **同一个请求里的 `raw` 重复**） | 已一并删除 |
| 测试引用 | **只有 2 份接线守卫测试**提到它（都不是"在用"，是**"钉住它不该被接上限"**） | `api/test_breaker_wiring.py` · `api/test_session_budget_wiring.py` |

## 二 · ⚠️ **删它⛔ 与隔离无关**（最容易被读错的一条）

`/rag/ask` **一直有 `WHERE requested_by`** ⇒ **在隔离账上它从来不欠**。

⇒ 别把本份读成 `DEC-056` 的一部分。`DEC-056` 乙段记的只是
「**它的定位已裁待删**」（一句待办），**删它的理由全部与隔离无关**。

📌 **为什么两个月都没人删它**：它**不欠隔离账**（有 `WHERE`）、**不欠额度账**（不接上限是对的）、
**测试全绿** —— 它身上**没有一条会自动报警的账**。真正的问题（桩读真库 / 结果不可复现）
**只有人去读代码才看得出来**。这是"账本管不到的地方"的一个样本。

## 五 · 反悔成本（**低，但不是零**）

**结论**：**低**。理由是**删的是能力被覆盖的端点** —— 没有消费者，所以没有"回不来就断了谁"。
另有 git 历史兜底（`git revert` 即可）。

⚠️ **但"恢复"不是 `git revert` 一条命令就完事** —— 上面那 **7 处必须逐条反向恢复**，
⛔ **少一处测试就红**（尤其是 ②③ 那两份**双向守卫**：端点回来了而清单没加回 `ask_question`，
会报「**这条链对全量熔断完全不设防**」—— 方向反了，报错信息会误导人）。

**逐一对照**：

| 项 | 反悔成本 |
|---|---|
| 端点代码 | 低（git 历史里有；墓碑注释里记了它原来在哪） |
| ②③ 守卫清单 + **用例名** | 低，但**容易漏** —— 用例名已从 `four` 改 `three`，恢复时要一并改回 |
| ④ Postman | 低（**整个文件夹**删的，恢复要重建 3 处 `raw`） |
| ⑤⑥⑦ 文档 | 低 |
| **用户可见的影响** | **零** —— 无消费者（见 §1.3） |

**最坏情况**：若将来有人需要"零成本的文档列表接口"⇒ **正确的做法不是恢复它**，
而是**在 `/rag/pg_search` 上提供一个不调 embedding 的模式** —— 那样**结果可复现**（有 `ORDER BY`）。
📌 **本仓立场**：`DEC-057` **不反对**一个便宜的检索接口，**反对的是一个便宜而不可复现的接口**。
