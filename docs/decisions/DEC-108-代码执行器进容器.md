# DEC-108 · `execute_python` 进**独立执行器容器** —— 应用⛔ 不碰 `docker.sock`

| 项 | 内容 |
|---|---|
| **状态** | ✅ **已实施（2026-10-08 · 批②）** |
| **触发** | 业务方 **2026-10-07** 原话：「`execute_python` 这个代码执行器要在 **docker 容器中执行**，使用 docker 容器**热启动**的方式，**预先加载**……**不要暴露在系统中执行，是安全事故**」 |
| **类型** | **安全边界** · 架构落点 · 可用性取向 |
| **落点** | 新增 `api/executor_server.py` · `api/executor.Dockerfile`；改 `api/code_executor_impl.py`（远端路径）· `docker-compose.yml`（`executor` 服务）· `api/mcp_server.py`（demo 过滤） |
| **判据** | 见 §五（逐条可打印，**含容器里的实测**） |

---

## 一 · 要裁的是什么

`execute_python` 跑的是**任意代码**。改前它跑在**与宿主同权限**的子进程里，
只有「**AST 白名单 + 5 秒硬杀**」两层 —— ⛔ **没有任何 OS 级隔离**。
白名单一旦被绕过（沙箱逃逸是有先例的），**拿到的就是宿主**。

⇒ **要一层容器。** 但"怎么接"有三条路。

## 二 · 三个备选

| 备选 | 评价 |
|---|---|
| **甲 · 独立执行器容器**（**选中**） | ✅ 应用**只发 HTTP**，⛔ 不认识 Docker；✅ 执行器**出不了网**、只读根、非 root、无 cap；✅ 每次请求起**新子进程**<br>⚠️ 代价：多一跳 HTTP、多一个容器要维护 |
| 乙 · **应用挂 `/var/run/docker.sock`，每次 `docker run` 一个新容器** | ✅ 隔离**最强**（每次全新容器）<br>🔴 **但代价大得多**：`docker.sock` = **宿主 root 等价** —— 拿到它就能起特权容器、**把宿主根文件系统挂进来**。而**本应用自己就在容器里** ⇒ **等于把"代码执行逃逸"的洞，换成更大的"容器逃逸"洞**。**前者的前提是被攻破的应用，后者只要拿到那个文件。** |
| 丙 · 维持现状（宿主子进程 + 白名单） | ✅ 零改动<br>⛔ 业务方已明确否掉：「**是安全事故**」 |

**⇒ 选甲。**

---

## 三 · 决策内容

### 3.1 应用侧只发 HTTP —— `EXECUTOR_URL` 有值走容器，没值回落本地

- 容器里由 `docker-compose.yml` 的 `api` 服务注入 `EXECUTOR_URL=http://executor:8000`
- **没值** ⇒ 回落本地子进程 ⇒ **本机开发 / 离线 CI ⛔ 不被这个功能拖成"必须有容器"**
- 🔴 **回落只由【配置】决定，⛔ 绝不由【失败】触发** —— 见 3.4

### 3.2 🔴 每次请求起一个**新**子进程，⛔ 不是常驻解释器

「热启动 / 预先加载」（业务方原话）落在**容器常驻**上 —— 省掉的是**容器启动的 1–3 秒**，
⛔ **不是**"把解释器也留着"。

**为什么后者不行**：常驻解释器会让 `exec` 的 `globals` **跨请求活着** ⇒
**访客 A 定义的名字，访客 B 看得见**，且 B 的行为**取决于 A 跑过什么**。**这是安全缺陷，不是性能取舍。**

📌 守卫：`test_executor_server.py::test_execute_does_not_leak_state_between_requests`
（**反证已做**：写一个"常驻 globals"的漏实现 ⇒ 判据输出 `True` ⇒ 该用例红）。

### 3.3 容器硬化（逐条，⛔ 别"简化"掉任何一条）

| 项 | 值 | 挡什么 |
|---|---|---|
| `read_only` | `true` | 被执行的代码写不了任何地方（实测：往 `/` 写 ⇒ `Errno 30`） |
| `tmpfs` | `/tmp:size=64m,noexec,nosuid` | 给一个能写的地方，但**不许在里面执行东西** |
| `cap_drop` | `ALL` | ⛔ 丢掉全部 Linux capabilities |
| `security_opt` | `no-new-privileges:true` | ⛔ 不许通过 setuid 提权 |
| `user` | `65534:65534`（nobody） | ⛔ 不以 root 跑（实测 `uid=65534`） |
| `mem_limit` | `256m` | ⚠️ 本机 Docker 只 3.84 GB |
| `pids_limit` | `64` | ⛔ 防 fork 炸弹 |
| `cpus` | `0.5` | ⛔ 防它把 CPU 吃光（死循环仍会被 5 秒硬杀） |
| `ports` | **⛔ 不写** | 只在内部网络里被 api 调，⛔ 不对宿主暴露 |

### 3.4 🔴 网络：**偏离施工单原稿** —— `network_mode: none` → `internal: true`

施工单 Step 1 写的是 `network_mode: "none"`，并**要求实测**（"若不通 ⇒ 改…并在 DEC 里写明"）。

🔴 **实测结论：`none` 用不了。** 它的含义是「**连内部网都没有**」⇒ **api 也连不上它** ⇒
「隔离」与「能调用」在这个值上**不可兼得**。

⇒ 改用**新建的 `exec-net`（`internal: true`）**：

- **对"出网"的隔离效果相同** —— 该网**没有对外网关** ⇒ 执行器**出不了互联网**（✅ 实测 `URLError`）
- 同时**保住**"api 能调它"（用户自定义网络自带 DNS ⇒ `api` 解析得到 `executor`）

⚠️ **本条的准确表述是**：「执行器**没有**互联网通路」，⛔ **不是**「执行器没有任何网络」。
⛔ 别把这两句读成一回事 —— 后者本仓**没做到**。

### 3.5 🔴 远端失败 ⇒ **如实报错**，⛔ **绝不静默回落本地**

若"远端挂了就悄悄回落"，那么：

> **运维把执行器停了 / 地址配错了 ⇒ 一切照常工作** ——
> 代码**又回到宿主同权限的进程里跑**，而**没有一个人会发现**。

⇒ **那层隔离是装饰性的**。（本仓原话：**「『从不命中』与『没人违规』在机器痕迹上完全一样。」**）

📌 **实测**（把执行器停掉，再从 api 容器里调）：
返回值 = `无法访问**执行器容器**（URLError: Name or service not known）`，
且 **`'42' in out` = False** ⇒ **确实没有偷偷本地跑**。

### 3.6 🔴 并发上限 = **2**，且它与 `cpus:` **是一对，⛔ 别单独调**

🔵 **这条是实测推翻了我第一版的拍脑袋**（我原先写的是 4）。

实测（宿主 4 核 · 容器 `cpus: 0.5`）：`for i in range(20000000): pass` 单体 **1.38s**。

| 上限 | 4 个并发时 | 结果 |
|---|---|---|
| **4** | 各拿 0.125 核 ⇒ ≈**5.5s** | 🔴 撞上 `MAX_EXEC_TIME` 的 **5 秒硬杀** ⇒ 4 个全报"超时"——**而那 4 个错全是假的**（活儿 1.5 秒就能完） |
| **2**（选中） | 各拿 0.25 核 ⇒ ≈**2.8s** | ✅ **4 个全部 `ok`**（实测两批：~2.7s / ~5.6s） |

⇒ **上限与 CPU 配额配套**：想提吞吐就**两个一起抬**（如 cap=4 + `cpus: 1.0`），
抬完**必须重跑**那次实测，确认最坏情况仍在 5 秒内。

**放哪一侧**：**执行器侧**（收口点 —— 谁来调都从这儿过）。应用侧也可以放，但**这一侧是硬上限**。

⚠️ **排队超时 ⇒ `503`**（⛔ 不是 200）：形状**故意与 `{ok,out}` 不同** ——
「执行器忙不过来」和「你的代码错了」是**两件事**。
⛔ **排队不能无限等**：`/execute` 是同步端点，占 Starlette 线程池（默认 40）；
无限等 ⇒ 线程池填满 ⇒ **连 `/health` 都拿不到线程** ⇒ 容器被判不健康并重启。

### 3.7 🔴 demo（魔搭创空间）上 **不注册** `execute_python`

**为什么**：创空间 **一个 Studio = 一个容器**（实测）⇒ **没有第二个容器**能跑执行器
⇒ `EXECUTOR_URL` 为空 ⇒ 它会**回落本地沙箱** ⇒ **又回到宿主同权限**。

⇒ **「没有容器」与「跑在宿主上」之间，⛔ 不选后者。**
落地：`mcp_server.py` 在 `TOOLS` 建好后按 `DEMO_MODE` 过滤。

## 四 · 反悔成本

| 项 | 成本 |
|---|---|
| 撤掉整个容器方案（回到丙） | **低** —— 去掉 `EXECUTOR_URL` ⇒ 立刻回落本地；⛔ 但等于**放弃这层隔离** |
| 改成乙（挂 `docker.sock` 每次 run） | **中** —— 要重写执行路径；⚠️ **且引入更大的风险面**（见 §二） |
| 调并发上限 | **低** —— 一个 env var；⚠️ **必须连 `cpus:` 一起调**（§3.6） |
| 放开 demo 注册 | **低** —— 去掉那个 `if`；⛔ 但等于让访客**在创空间的容器里**跑任意代码 |
| 放开"远端失败回落本地" | **低** —— 几行；⛔ 但**隔离变成装饰性的**（§3.5） |

## 五 · 判据（**逐条可打印**）

```bash
# ① 单元层
cd api && ../venv/bin/python -m pytest test_executor_server.py test_code_executor_remote.py -q
#   ⇒ 7 + 4 passed

# ② 容器硬化（六条实测）
docker exec rag-executor id                      # ⇒ uid=65534(nobody)
docker exec rag-executor python -c "open('/pwned','w')"   # ⇒ OSError [Errno 30] Read-only file system
docker exec rag-executor python -c "import urllib.request;urllib.request.urlopen('https://pypi.org',timeout=5)"
#   ⇒ URLError（出不了网）
docker inspect rag-executor --format 'CapDrop={{.HostConfig.CapDrop}} Readonly={{.HostConfig.ReadonlyRootfs}} Memory={{.HostConfig.Memory}} PidsLimit={{.HostConfig.PidsLimit}}'

# ③ 🔴 应用**真的**走容器（不是"配置里写了"）
docker exec rag-api python -c "
import os, json, urllib.request
u=os.environ['EXECUTOR_URL']+'/execute'
req=urllib.request.Request(u,data=json.dumps({'code':'print(6*7)'}).encode(),headers={'Content-Type':'application/json'})
print(urllib.request.urlopen(req,timeout=10).read().decode())"    # ⇒ {"ok":true,"out":"42\n"}

# ④ 🔴 **没有静默回落**：把执行器停掉，同样的调用必须**报错**、⛔ 不许返回 42
docker stop rag-executor
docker exec rag-api python -c "
import code_executor_impl as C
out = C.execute_python_impl('print(6*7)')
print(repr(out)[:120]); print('有没有偷偷跑出 42？', '42' in out.replace('6*7',''))"   # ⇒ False

# ⑤ demo 过滤
cd api
../venv/bin/python -c "import mcp_server,json;print(json.dumps([t['func'].name for t in mcp_server.TOOLS]))"
DEMO_MODE=1 ../venv/bin/python -c "import mcp_server,json;print(json.dumps([t['func'].name for t in mcp_server.TOOLS]))"
```

⚠️ **③④ 是最要紧的两条**：③ 证明"接上了"，④ 证明"**没有偷偷回落**"。
**只有 ③ 而没有 ④，隔离就可能是装饰性的。**

## 六 · 边界

1. ⛔ **执行器没有鉴权** —— 前提是它**只在 compose 的内部网络里**。
   **改这个前提（给它开 `ports:`）⇒ 先加鉴权。**
2. ⛔ **任何时候都不许挂 `/var/run/docker.sock`** —— 见 §二乙。
3. ⚠️ **白名单（`create_safe_globals`）保留** —— 容器是**第二层**，⛔ 不是替代品。
4. ⚠️ **`MAX_CONCURRENT_EXECUTIONS` 与 `cpus:` 是一对** —— 见 §3.6。
5. ⚠️ **执行器镜像刻意做小**（只装 `fastapi`+`uvicorn`，只复制 2 个 `.py`）——
   「这个容器里有什么」=「逃出去的人能拿到什么」。⛔ 别 `COPY . .`。
6. ⛔ **`code_executor_impl` 只 import 标准库** —— 远端路径用的是 `urllib.request`，
   ⛔ 不许为了省事改成 `requests`。
