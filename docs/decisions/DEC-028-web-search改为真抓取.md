## 决策事项

**`web_search` 到底怎么实现？**

## 🔴 触发：核 N15 的遗留「`web_search` 没离线验证过」时，一验就爆

**实测三次调用（2026-09-21），没有一次是真的在搜索：**

| 查询 | 实际返回 |
|---|---|
| `2026年 诺贝尔物理学奖` | `<tool_call>{"name":"search","arguments":{...}}</tool_call>` ← **原始 tool_call 文本** |
| `今天北京天气` | 「北京今天（**2026年3月18日**）…晴转多云…14℃」 ← **编的**（当天是 **2026-09-21**，**差半年**） |
| `Python 是什么` | `<context>我需要了解用户所说的"Python"是指什么…` ← **模型的思考草稿** |

**根因**：`enable_search` 是**阿里百炼私有扩展**，而本机 `.env` 走的是 **DeepSeek** ⇒ **被静默忽略**。
而**兜底只写在 `except` 里** —— 那次调用返回的是 **200，兜底永远不触发**
⇒ 于是把**未标记的模型输出**当成搜索结果返回了。

⚠️ **三条里最危险的是天气那条**：格式漂亮、语气笃定、**日期全错**，**调用方会直接采信**。

📌 这类「**看起来能用、其实不能用**」正是本仓反复在防的形态
（`README` 的诚实清单 · §一·B「`/docs` 声明与代码相反」· N13「LLM 手里握着必炸的工具」都是同一族）。

## 背景与约束

- **上游已证明**：`plan_execute` 现在**真调工具**（`DEC-026`）⇒ 这个假搜索**会真的进到执行链里**。
- **业务方 2026-09-21 澄清**：`DASHSCOPE_API_KEY` **是阿里云的、没有额度、不能用**；
  若走 LLM 那条路，改用 DeepSeek 云端 API。
- ⚠️ **但实测证明 DeepSeek 那条路【不行】**：DeepSeek 的 API **不提供内置搜索**
  （`enable_search` 是阿里百炼私有扩展）⇒ 走它**只能拿到模型知识**，**就是上面那个假搜索的根因**。

## 动手前核出的地基

**"不用 LLM 的真搜索"需要什么？**

| 需要 | 现状 |
|---|---|
| **chrome / 浏览器** | ❌ **不需要** —— 搜索引擎结果页是**服务端渲染**的（浏览器只在抓 **JS 渲染**页面时才必要，那是已摘掉的 `browser_tools`） |
| **新依赖** | ❌ **不需要** —— `httpx` / `beautifulsoup4` / `lxml` **本仓都有、venv 里都装了** |
| **API key / 注册 / 额度** | ❌ **不需要** —— 那是**公开网页** |
| **网络可达** | ⚠️ **这个才是真门槛** |

**本机网络实测**：

```
cn.bing.com        HTTP 200  ✅ ← 唯一直接可达的
www.baidu.com      302（跳验证）
www.sogou.com      302（跳验证）
duckduckgo.com     000  ❌ 完全不通
www.google.com     000  ❌ 完全不通
```

⚠️ **`ddgs`（已在依赖里）本机也跑不了** —— 实测**超时**，因为它打的是 google。

## 备选方案

| 方案 | 依赖 | **本机能不能真搜** |
|---|---|---|
| **甲 · 抓 `cn.bing.com` 结果页**（**采纳**） | **0 新增** | ✅ **实测拿到 8–10 条真结果** |
| 乙 · `ddgs`（已在依赖里） | 0 | ❌ **超时**（打 google） |
| 丙 · DashScope `enable_search` | 0 | ❌ **403 额度耗尽** |
| 丁 · DeepSeek 云端 API | 0 | ❌ **它不搜索**（实测证据见上） |

## 决策与理由

**甲。** 三条理由：

1. **甲是唯一在本机真能搜的**（另外三条实测都不行）。
2. **它把"撒谎"的可能性从结构上拿掉了** —— 新 `search_tools.py` 里
   **没有任何 LLM 客户端** ⇒ **不可能再返回"模型编的内容"**。
3. **零新增依赖** —— 三个库本仓早就有。

## ⛔ 硬要求：**解析不到结果就如实报失败**

抓 HTML 是**逆向做法**，**必应改版就会坏**。所以：

> **坏掉那天【必须明说"搜不到"】，⛔ 不许悄悄退回"让模型编一个"** ——
> 那正是这次重写要根除的病。

已固化成**两条**用例：
- `test_honest_failure_when_nothing_parsed`：解析不到 ⇒ 必须「搜索失败」开头 **且明说没编**
- `test_honest_failure_when_network_fails`：网络挂了 ⇒ 同上（并把真实原因报出来便于排查）
- `test_search_tools_has_no_llm_client`：**用 `ast` 查真实 import** ——
  `openai` / `config` 都不许进来。📌 本仓教训：**「写注释说别这么干」是软约束**
  （`Product/CLAUDE.md` §二：「有结构才执行，只有文字就漏」）⇒ 所以用结构判据。

**另外把失败语义写进了【工具描述】**（LLM 读的那份）：
明写「返回以『搜索失败』开头时，**如实告诉用户暂时搜不到**，⛔ 不要拿自己的知识假装是搜索结果」。
📌 与 `execute_python` 那条「不要 `import`」同一个道理 —— **工具的失败语义必须写进给 LLM 的描述**。
⚠️ **这是一次【工具 schema 变更】**，已在 PR 里声明。
