## 一 · 它是什么

复盘记的那件事逐字是：

> 我打印了 **`✅ 本地 main 已与远端同步`**，而**远端真值（API）是 `f748ef81`、本地停在 `a1839cbb`**

当时的判据是：

```bash
[ "$(git rev-parse main)" = "$(git rev-parse origin/main)" ]     # ⛔ 错
```

🔴 **`main` 与 `origin/main` 都是【本地仓库的视图】** ⇒ 相等**只说明本地自洽**，
**不携带任何远端信息**。而当时 `git fetch` 已经失败 ⇒ **两个输入来自同一个陈旧快照** ⇒
比较**必然"相等"**。

⇒ 本脚本把判据改成**跨来源三方比对**：

| 记号 | 是什么 | 怎么取 | **新鲜度由谁保证** |
|---|---|---|---|
| **L** | 本地分支 | `git rev-parse refs/heads/<b>` | 无（就是本地现状） |
| **V** | 本地**视图** | `git rev-parse refs/remotes/origin/<b>` | 🔴 **上一次 `git fetch` 的时刻** —— 会陈旧且**不声明** |
| **R** | **远端真值** | `git ls-remote origin refs/heads/<b>` | ✅ **本次真的连上了远端** |

> 📌 **判据里第 3 列是本份的重点** —— 复盘 §四 的 KD 候选写的正是
> 「写判据时**同时写出每个输入的【来源】与【新鲜度保证】**；两手都写不出的输入 ⇒ **该判据不成立**」。

---

## 二 · 🔴 一条硬规矩：**取不到真值必须报「未知」，⛔ 不许报绿**

**这是本份唯一不能省的设计。**

它的理由很直白：**本脚本最容易的失败模式，恰好是它要防的那个错** ——
`git ls-remote` 失败时**输出为空**；若把"空"当成"没问题"⇒ **又是一个假 ✅**。

⇒ 裁决加了**第五态**：

| 退出码 | 含义 |
|---|---|
| `0` | 三方一致（同步） |
| `1` | 不一致（`view-stale` / `drift` / `diverged` / `no-remote-branch` / `no-local-branch`） |
| `2` | 用法错误 |
| **`3`** | ⚪ **未知** —— 取不到远端真值。⛔ **不许把它当 0 读** |

### ⚠️ 顺带修掉复盘漏掉的一半：「空」与「取不到」**是两件事**

复盘记了「`ls-remote` 空」这个假 ✅，但**没写清怎么分**。⇒ 本份**靠退出码分**：

| `git ls-remote` 的退出码 | 输出 | 结论 |
|---|---|---|
| **0** | 无 | ✅ **远端确实没有这个分支** —— 这是**一个确定的事实**（本地还没推过？） |
| **≠ 0** | 无 | ⚪ **连不上 / 认证失败** ⇒ **未知** |

⛔ **把这两行合并读，就会回到"结果为空就断言不存在"**（本仓 2026-09-29 那份复盘）。

### 还有一处**自纠**（写这份时才发现的）

输出里原本写「ahead/behind：左边=本地独有 / 右边=**远端**独有」——
🔴 **那句话是假的**：`branch...origin/branch` 比的是 **本地 vs 【本地视图】**。
**我把本脚本要治的那个病（拿本地视图冒充远端）又写进了自己的输出里。**
⇒ 已改成明写「**⛔ 不是远端**」，并在视图陈旧时**标注这个数不可用**（要真数得先 `fetch`）。

## 三 · 💰 你问的三件事（**实测，不是估计**）

### ① 作用是什么

**在"推完 / 收工前"代替那句 `git rev-parse` 比对**，把「本地是不是真跟远端一致」变成一条**可打印的判据**。
一次运行告诉你三件事：三方各是什么、不一致时**是哪两个对不上**、以及**你的本地视图是不是陈旧的**。

### ② 会频繁调用 GitHub API 吗 —— **不会：0 次 REST 调用**

`git ls-remote` 走的是 **git 传输协议**（本仓 `origin` 是 **SSH**），**不碰 `api.github.com`**。

🔬 **实测（2026-10-04）**：

```bash
gh api rate_limit --jq .rate.used          # ⇒ 0
for i in 1 2 3 4 5; do git ls-remote origin refs/heads/main >/dev/null; done
gh api rate_limit --jq .rate.used          # ⇒ 0      # ⛔ 配额一点没动
```

⇒ **一次运行的网络量 = 一次 `git fetch` 的同量级**，而本仓每次推送**本来就要 fetch**
（`DEC-039`：推送前先 fetch）。**它是日常 git 流量，不是 API 调用。**

### ③ 是否会造成封号 —— **我不知道，而且我要标明这是推理**

⚠️ 按本仓规矩「**凡说风控，先问一句：这是 GitHub 说的，还是谁推的？**」
（`CLAUDE.md`「推送节奏」· `DEC-039`）：

- **GitHub 从没说过**什么行为会触发它的自动风控 —— 2026-09-24 那次封停**至今没有官方解释**
  （`fastapi-rag-agent-TODO待办/GitHub账号封停-事件记录-20260924.md` 里全是**候选**，不是结论）。
- **我能负责的只有两件**：① **配额实测为 0**（上面）· ② **量级与 `git fetch` 相同**（推理）。
- ⇒ **"所以不会被封"这句话我说不出口** —— 它是**推断**，⛔ 不是保证。

📌 **真正降低风险的是用法，不是脚本本身**：
**它不自动跑**（⛔ 不在 hook、⛔ 不在 CI）⇒ **调多少次完全由你决定**。
你一天跑一次，它就只产生一次 `fetch` 级别的流量。

## 四 · ⛔ 为什么**不挂 CI 门**（这是本份的主要备选）

> 复盘的原文选项是「**落成脚本 + CI 门** / 只留文字判据」。我裁的是**第三种**。

| | 做法 | 评估 |
|---|---|---|
| ① | **落成脚本 + 挂进 `pre-commit-gates.py`** | 🔴 **在 CI 里"本地"就是刚 checkout 出来的那份** ⇒ L、V、R **恒等** ⇒ **跑了等于没跑**，还平白给 CI 加一个网络依赖（网络抖动就变红 ⇒ **门会被绕过**，本仓有前科） |
| ② | **只留文字判据**（= 复盘当初标「⬜ 未做」的状态） | 复盘自己写着：**「⚠️ 按本仓已三次的教训，只写在文档里等于没写」** ⇒ **这就是现状，它已经被证明无效** |
| **③** | ✅ **落成脚本，⛔ 不当门** —— 定位为**本机收尾工具**（推完 / 收工前跑） | **本份所裁** |
| ④ | 折中：挂进 hook 但**允许它失败** | 一个"允许失败的门"**不是门**，是噪音（同 ① 的绕过风险） |

⇒ **判据**：**它是工具，不是门。** 工具坏了你换一个；门坏了你绕过去。

### ⚠️ 但要分清：**进 CI 的是 `--self-test`，⛔ 不是三方比对**

| | 进不进 CI | 为什么 |
|---|---|---|
| **三方比对**（`check_remote_sync.sh` 本跑） | ⛔ **不进** | 上面 §四 的整段理由 —— **CI 里三方恒等** |
| ⭐ **裁决逻辑自测**（`--self-test`） | ✅ **进**（`ci.yml` 的 `syntax` job 加一步） | **不连网、不需凭据、约 0.05 秒** —— 它验的是**判决**，与网络无关 |

📌 **为什么值得加这一步**：那条裁决里最要紧的一支是「**取不到真值 ⇒ 未知，⛔ 不是通过**」——
而"**守卫必须能测出自己会红**"是本仓已经记过两次的教训（`DEC-061` 幽灵锚点 · `DEC-066` 守卫形状盲区）。
一个**从没被跑过**的自测会悄悄烂掉。

⚠️ **明确划清，免得被读成自相矛盾**：**"不做 CI 门"说的是那条三方比对，⛔ 不是这个自测。**

## 五 · 证据（⛔ 不是"我觉得它对"）

### `--self-test`：8/8（**逐个走一遍裁决分支**，⛔ 不连网）

```
✅ 三方一致 ⇒ synced        ✅ 视图陈旧 ⇒ view-stale
✅ 本地落后/领先 ⇒ drift    ✅ 三者互不一致 ⇒ diverged
✅ 🔴 真值取不到 ⇒ unknown  ✅ 真值取不到② ⇒ unknown
✅ 远端确实没这个分支 ⇒ no-remote-branch   ✅ 本地没这个分支 ⇒ no-local-branch
```

📌 **为什么必须有这一项**：本仓立场（`DEC-061`「幽灵锚点」）——
**一条测不出"不成立"的守卫 = 没有守卫**。

### 🔬 在**真仓**上复现复盘那个 bug（`/tmp` 探针仓，⛔ 不碰本仓）

造出「远端前进了、本地没 fetch」：

| 局面 | 脚本输出 | 退出码 |
|---|---|---|
| ① 三方一致 | `✅ 三方一致 —— 都是 ad941e9` | **0** |
| ② **远端前进、本地没 fetch** | `🔴 本地视图陈旧 —— 本地与 origin/main 都是 ad941e9，而远端真值是 4a1b785` | **1** |
| ③ 远端不可达 | `⚪ 未知 —— 取不到远端真值`（**3.5 秒就返回**，⛔ 没挂死） | **3** |

🔴 **局面 ② 就是复盘那次**：**L 与 V 相等**，老判据（`[ local = origin/main ]`）在这一刻**会打出 ✅**。

### 网络加固（⛔ 不许"静静地挂着"）

加了 `GIT_SSH_COMMAND` 的 `ConnectTimeout=8` + **`BatchMode=yes`**、
以及 `GIT_HTTP_LOW_SPEED_*`。
⚠️ **`BatchMode=yes` 是关键**：不然 SSH 若要口令会**把脚本挂在交互提示上** ——
那既不是 ✅ 也不是「未知」，**是"没有结论"**，比报错更难发现。

## 六 · 本份【没有】解决什么

1. ⚠️ **它只核对**，⛔ **不修** —— `view-stale` 了它只叫你 `git fetch`，**不会替你 fetch**
   （有意：本脚本的活是**判断**，⛔ 不是**替你改本地状态**）。
2. ⚠️ **它说的是「这一刻」** —— 跑完之后远端任何一次提交都会让它过期。
   ⛔ **别把它当成"以后都不用管了"**。
3. 🔴 **它管的是 commit 层面**，⛔ **不含工作区** —— 有未提交改动时会打一行提示，
   但**那是提示，不是裁决**。
4. ⚠️ **`CONTRIBUTING.md:75` 那句「本地 commit 随便攒；推送以『一个可验证单元』为界」**
   **是【已作废】的口径**（`DEC-039`，2026-09-30 改版）。
   ⇒ **本份没改它**（按「⛔ 不顺手清理」）。**登记在此，供下一轮裁。**
   📌 它是**入库的公开文档**，克隆者会照着做 ⇒ 建议**尽快**处理。
