## 一 · 三个决策点

### 1.1 `langchain-community` —— **删**（业务方裁）

| 备选 | 判断 |
|---|---|
| **甲（选）：从清单与 venv 里删掉** | ✅ |
| 乙：留着（钉 `0.3.31`） | ⛔ 不选 |

**选甲的依据（三条，都实测过，⛔ 不是"看着像没用"）**：

1. **全仓零 import** —— `grep -rn --include='*.py' 'langchain_community' app/` ⇒ **空**。
2. **没有任何包硬依赖它** —— 声明它的四个（`langchain` · `langchain-classic` · `mem0ai` · `posthog`）
   **全都写在 `extra` 里**（`extra == 'community'` / `'extras'` / `"test"`）。
3. 🔴 **最关键的一条：卸掉它之后真身还起得来** ——
   `pip uninstall langchain-community` 之后调 `get_agent_executor()` ⇒
   **照常建出 `AgentExecutor`，工具仍是 `['calculator','date_today','web_search']`**。
   ⚠️ 这是必需的，因为 `langchain_classic/agents/__init__.py:60-72` 里**确实有**
   `from langchain_community.agent_toolkits…` 的字样 —— 只看那段会"以为卸不掉"；
   实测证明它们在 `try/except` 里，且真用法走的是**懒加载映射表**（同文件 `:85-93`）。

**反悔成本**：**极低** —— 加回一行的成本。
⚠️ **触发条件写清**：若哪天用到 `langchain_classic` 的**懒加载**工具
（`create_sql_agent` / `load_tools` / `create_pandas_dataframe_agent` 之类）
⇒ 那时缺的就是它。已在 `requirements.txt` 原地留了这段话。

### 1.2 `langgraph-sdk` / `langgraph-prebuilt` —— **补进清单**（业务方裁）

> ⚠️ **这一条与我给的建议相反**（我建议"不补"）。**业务方的裁定优先**，⛔ 但依据与代价如实记。

| 备选 | 判断 |
|---|---|
| **甲（选，业务方）：写进 `app/requirements.txt`，就地钉 `0.4.6` / `1.1.0`** | ✅ |
| 乙（我的建议）：不写，继续由 `langgraph` 的区间管 | ⛔ 未被采纳 |

**选甲的理由**：本仓「**依赖清单单一化**」的口径 —— 凡会进 demo 镜像的包，
**版本要在一份里看得见**（清单外的东西 = 没人盯）。
📌 顺带：`langgraph-sdk` **曾是漏洞包**（`PYSEC-2026-2194/2575` · `CVE-2026-104873`），
现在这版是干净的 —— 而"干净"这件事**只有看得见版本才说得出**。

🔴 **代价（⛔ 别只记好处）**：这两行会**跟着 `langgraph` 一起动** ——
下次升 `langgraph` 时，若它要的区间与这两行冲突，**解析会直接报错**。
⚠️ 这不是假设：`DEC-127` 实测过同型（`langgraph-sdk 0.4.4` 与 `langgraph 1.0.10` **互斥**）。
⇒ **那时先改这两行，⛔ 别怀疑是网络问题。**（这段话已写进 `requirements.txt` 原地。）

### 1.3 「过期导入」扫描 —— **做成门**（业务方裁）

| 备选 | 判断 |
|---|---|
| **甲（选）：做成提交门** | ✅ |
| 乙：留在复盘里当一次性探针，用时手跑 | ⛔ 不选 |

**选甲的理由**：本仓原话「**门挂在别处，就等于没有门**」。

而这类断裂**当天就发生了两次**（见 `docs/复盘/…测试全绿而活路径坏了两次.md`）。

## 二 · 门长什么样

`scripts/check_stale_imports.sh`（**bash 里嵌 python** —— 同 `check_doc_orphans.sh` 的做法；
因为提交门的执行器是 `bash <path>`，`.py` 直接挂不上）。

**判据**：对 `app/` 之外的每个 `.py` 解出 `import` 的**裸名**：
在 `app/` 根 / 是模块组名 ⇒ 正常；**搬到了某一组下面**（且 `app/` 根已无同名 `.py`）⇒ 🔴 过期。

| 三态 | |
|---|---|
| `0` | 没有过期导入 |
| `1` | **有**（点名 `文件:行` 与**新家**） |
| **`2`** | **判不了**（拿不到 git / `app/` 不在 / 一个模块组都找不出来）—— ⛔ **不算通过** |

⚠️ **判不了必须与"干净"分开** —— 本仓为此栽过（`check_dep_vulns.sh` 曾把"网络超时"
报成"有已知漏洞"）。

**两条设计选择（都有理由，⛔ 别顺手改）**：

1. 🔴 **文件清单来自 `git ls-files`**（同断链门/孤儿门：「那才是**克隆者拿得到什么**」）。
   ⚠️ **实测教训**：初稿按**目录名**跳过，结果**漏了 `venv-ragas/`**（本仓有**第二个**虚拟环境）
   ⇒ 扫了 **7870** 个文件而不是 **13** 个。**"按目录名列举"永远会漏。**
   📌 副作用：新文件**要先 `git add`** 才在射程内 —— 这与另两道门**同款**（已写进注释）。
2. **用 `ast` ⛔ 不用正则** —— 正则会把**注释与 docstring 里**的同一行也算进去。

**豁免只有两类**（都在索引里、但确实可以烂着）：`archive/`（留痕，⛔ 不改）·
文件名含「探针」（一次性探针，⛔ 不维护）。

### ⚠️ 它【不覆盖】什么（⛔ 别读成"搬家的坑都堵了"）

* **只查 `import`，不查字符串里的陈旧路径** —— 同一次重构还留下过
  `API_DIR = REPO_ROOT / "api"`（`api/` 已改名 `app/`）。
  拿字符串猜路径**误报太高**，**本门故意不猜**。
  📌 **但那次断裂仍会被本门捕获**（同一个文件里有 `from chunker import …`）。
* **只查 `app/` 之外的 `.py`** —— `app/` 内部的过期导入由 `ruff`（`E9`/`F`）与 pytest 兜。
