## 二 · 为什么撤：**"两个目录"要同时维护两条纪律，而它俩的分工没人真在用**

| | 撤掉前（`DEC-102` §二） | 撤掉后（本节） |
|---|---|---|
| 仓根的 demo 目录数 | **2** | **1** |
| 归档区 | `未进demo/`（✅ 入库 · 铁律「只进不出 · 永不删除」） | **无** |
| 施工区 | `demo/`（⛔ gitignore） | **`demo/`（同左，不变）** |
| 读者要先知道什么 | 得先分清"**这俩用途相反**"才看得懂结构 | 只有一处，无所谓分辨 |

🔴 **撤掉的那条铁律本身没错，错在它挂在了一个【没人往里放东西】的目录上** ——
`未进demo/README.md` 的索引表**自 2026-10-07 建起一直是空的**（判据：该文件删除前 `ls -R 未进demo/` 只列 `README.md` 一项）。
⇒ **一条"为了让人看见"的纪律，配一个空表 ⇒ 看见的是"什么都没有"。**
⚠️ **这不是"纪律写得不好"，是"这个格子没有内容"** —— 本仓立场：**先有内容，再有格子**。

> ⚠️ **别把本节的结论反读成「归档不重要」** —— **要归档的东西照样得有个去处**，
> 只是**现在这个仓根不预置空目录**。将来真有"做完可用但没进 demo"的东西，
> 再按当时的实际情况**先有内容、再定落点**（⛔ 不许现在替将来发明一个新目录）。

## 三 · `pre-demo/` 的来龙去脉（**它是【搬家中转站】，不是一条约定**）

2026-10-08 早，业务方把 `demo/` 的内容搬去 `pre-demo/`、并把 `.gitignore` 的 `demo/` 行改成 `pre-demo/`
——**本意是"把 `demo/` 这个名字腾出来给 Agent 用"**（原话：「`demo/` 文件夹已释放，如果你需要使用，可以使用 `demo/` 这个文件夹给你用」）。

⚠️ **技术上它是一次【改名】** —— 判据（本次实测，`git diff -- .gitignore`）：
改前 `demo/` **就在** `.gitignore` 里，业务方的改动是 `-demo/` `+pre-demo/` `+tmp/`。

⇒ 现在裁定「`pre-demo/` 不要就删」，**等价于把那行改回 `demo/`** ——
`git diff -- .gitignore` 应当只剩 `+tmp/` 与末尾换行。

🔴 **顺带修了一个真缺陷**：业务方那次编辑**末尾没留换行**（`\ No newline at end of file`）⇒ 已补。

```bash

# ② demo 仍在、且仍被忽略

  | grep -v '^\./\.git/' | grep -v 'CHANGELOG.md' | grep -v 'DEC-102\|DEC-103'

```

> **再**删原目录 —— 因为 `rm` 是不可逆的，而 `.git/` 里可能有历史。
> ⚠️ 归档后的**凭据扫描**：`grep -raoE 'oauth2:[^@[:space:]]+@'` 与 `grep -r 'modelscope'` **均为空**
