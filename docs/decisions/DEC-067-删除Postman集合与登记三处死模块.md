## 三 · 裁决与做法

**业务方 2026-10-04 裁：删。**

**为什么删（而不是留着）**：

1. **零消费者**（§二 的清单）；
2. 但它**不是零成本** —— 它是**每次端点删除都要再付一次的手工同步税**（§一 那张表，四天三次）；
3. **留着它还有一个隐性代价**：它让"删端点"这件事的**耦合面清单**虚高一项 ⇒
   以后每次都要有人（我）去判断"这次要不要动 Postman"，而答案永远是"要"，
   然后在**一个没人读的文件**里做 150 行 JSON 手术。

📌 **一句话**：**删掉它，是把一笔持续支出换成了一次性支出。**

### ⛔ 本份**不做**的相邻动作

**`archive/artifacts/rag-api-openapi.json`（17 KB）** —— `DEC-003` 把它与本文件并称
「**同一次导出**的两份，且都已失效」。

⚠️ **但业务方这次只裁了 Postman 那一份** ⇒ 本份**只删 Postman**。
**为什么不一并删**：本仓规矩「⛔ 不顺手清理」（`~/.claude/CLAUDE.md`）——
`api/` 下这份是**被持续维护**的（所以有"税"），`archive/` 下那份**四天来无人动过**（所以没税），
**两者的理由不同，⛔ 不能因为"长得像"就一起删**。

### ⑤ 为什么多改了 `.gitignore`（**报备，不是顺手**）

**它是本份做事时【撞出来的】，不是我想起来的。**

本份要 `git add -A` 才能跑那四道门 —— 一跑，git 打了一串警告，并且**真的把
`.claude/worktrees/gate-push-draft` 暂存了**（`git status` 显示 `A?`）：

```
warning: adding embedded git repository: .claude/worktrees/gate-push-draft
hint: You've added another git repository inside your current repository.
```

🔴 **危害不是"多一个目录"**：`git worktree add` 建的工作树**自带 `.git`** ⇒
外层仓看到的是一个**嵌入式仓**，`git add -A` 会把它当作 **gitlink** 暂存
⇒ **别人克隆后拿到一个空壳**（外层只记一个 sha，内容不入库）——
**与 `Product/` 外层仓把 15 个嵌套仓记成 gitlink 是同一件事。**

⚠️ **判据（可打印）**：

```bash
git check-ignore -v .claude/worktrees/gate-push-draft   # ⇒ .gitignore:59:.claude/worktrees/
git add -A && git status --short                        # ⇒ 不再出现 .claude/worktrees/
```

📌 **为什么放结构而不是写一句纪律**：`git add -A` **不会读纪律**。
此条与本仓「**有结构才执行，只有文字就漏**」同源。

⛔ **本份没有动**那个 worktree 本身（它是 `DEC-039`/门禁草案的接续点，**还在用**）——
只加了**忽略规则**。
