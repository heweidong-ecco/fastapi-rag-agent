# 决策记录：DEC-023 · 代码执行沙箱**放开类定义**（N18）

- 日期：2026-09-21
- 状态：**已采纳并执行**
- 关联：`docs/待办登记-2026-09-20-全仓审计与方向更正.md` **§十四·14.3**（N18）· 前一条同族：**§三·N17**（放开异常类）

## 决策事项

沙箱白名单里**没有 `__build_class__`** ⇒ 被执行的代码**不能定义类**：

```python
execute_python_impl("class Mine(Exception): pass")
# → 代码执行出错: NameError: __build_class__ not found
```

**要不要放开？**

## 背景与约束

- **沙箱怎么做的**：`create_safe_globals()` 返回 `{"__builtins__": {}}`（**空 builtins**），
  然后只注入 `ALLOWED_BUILTINS` 里列到的名字 + `ALLOWED_MODULES` 那 9 个模块。`exec(code, safe_env)`。
- **约束一（安全）**：这是**代码执行沙箱**，放宽白名单 = 动**安全边界**，必须业务方裁。
- **约束二（诚实）**：`execute_python` 的 docstring 是**给 LLM 读的工具描述** ——
  ⚠️ 已核实**它没有提"不能定义类"** ⇒ 本次改动**不需要动工具 schema**（省掉一次 schema 变更声明）。
- **触发**：做 N17（放开异常类）时**顺带撞出**，当时**未动**（那次授权范围只有异常类）。
- **N17 的先例**：放开异常类时用的理由是「**异常类本身不提供逃逸能力，是类型对象**」。

## 关键证据（**改变判断的那一条**）

**我原本以为这是"新开一个能力" —— 实测证明不是。**

| 写法 | 放开前 |
|---|---|
| `class Mine(Exception): pass` | ❌ `NameError: __build_class__ not found` |
| `Mine = type("Mine", (Exception,), {})` | ✅ **`ok Mine`** —— **早就能用** |
| `type("M", (), {"f": lambda self: 42})` | ✅ **`ok 42`** —— **早就能用** |

⇒ **白名单里本来就有 `type`**，所以「**动态建类**」这个能力**早就在沙箱里可达**。
加 `__build_class__` **不是新开能力**，只是让 `class` **这种写法**也成立。

## 备选方案

| 方案 | 一句话 |
|---|---|
| **甲 · 放开**（**采纳**） | 白名单加 `__build_class__` + 执行全局域加 `__name__` |
| 乙 · 不放开 | 维持现状；LLM 写 `class` 就报错，但可以用 `type()` 绕 |
| 丙 · 放开 + 同时收紧 `type` | 把 `type` 也从白名单拿掉，让"建类"这件事**彻底不可达** |

## 决策与理由

**甲。** 三条理由：

1. **不增加能力**（上面的实测）—— 这是决定性的一条。**"放开"与"不放开"在能力面上是同一个集合**，
   差别只在**语法**是否成立。
2. **与 N17 同一条逻辑**：放开的是**语言构造**，不是**逃逸通道**。
3. **不放开反而制造了一个"沉默的坑"**：`type()` 能建类、`class` 不能 ——
   而 LLM 写 `class` 是**最常见**的写法。不放开 = 让最常见写法失败、让罕见写法成功。

**🔴 执行时发现：N18 实际是【两件事】，不是一件。**
只加 `__build_class__` **不够** —— 实测报的是 `NameError: name '__name__' is not defined`
（`class` 语句要用它填 `__module__`）。⇒ 还要给**执行全局域**加 `__name__`
（是个字符串，无逃逸能力；**必须放全局域、不是 builtins**，放错位置无效）。

## 反悔成本

**低。** 撤回到乙 = 从 `ALLOWED_BUILTINS` 删一行 + 从 `create_safe_globals` 删一行；
回归用例会红，提醒去更新记录（**这正是 N17 那条用例"按预期完成使命"的同款设计**）。

## 本次**没有**放宽的（已写成可执行断言，不是文字承诺）

`api/test_impl_modules.py::test_sandbox_allows_class_definition` 锁死两件事：

1. **逃逸面未变** —— `__import__` / `open` / `eval` / `exec` / `compile` / `globals` / `locals`
   **仍然不在白名单里**；
2. **不是"没列出来"，是"跑不了"** —— 实测三种逃逸尝试（`__import__("os").system(...)` /
   `open("/etc/passwd")` / `eval("1+1")`）**全部报错**。

⛔ **仍然【不】放开**（沿用 N17 的边界）：`BaseException` / `SystemExit` / `KeyboardInterrupt` / `GeneratorExit`
—— 它们是**退出机制**，让被执行代码能捕获它们 = 允许它**吃掉执行器的中断信号**。
