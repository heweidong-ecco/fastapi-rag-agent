# 决策记录:DEC-005 · Gradio 门控的默认值取 A（保持现状）还是 B（默认关面板）

- 日期:2026-09-17
- 状态:已采纳
- 关联:`ROADMAP.md` ⑥ 切开点 4 · `CHANGELOG.md` · PR #20

## 决策事项

一句话:**切开点 4 给 Gradio 挂载加环境门控时,默认值取哪个?** 这决定了"省掉 gradio+matplotlib"这件事**发生在默认路径上,还是只在显式配置时**。

## 背景与约束

**问题的形状**:`main.py:512` 的 `from cost_dashboard import create_dashboard` 在**模块层**执行,而 `cost_dashboard.py:5,6,8` 是模块层 `import gradio` / `import matplotlib` ⇒ **`import main` 必拉这两个包**。

**⚠️ 动手前的关键发现(靠 `executing-plans` 的 Step 1「批判性审计划」才逼出来的)**:

计划 §三 的收益栏写的是「**import 不再必拉** gradio+matplotlib」,但计划自己的 R5 又写「**默认取 `"true"` 保持现状**」。
**两条放一起 ⇒ 默认路径上仍然会拉。** 计划的收益表述**与它自己的机制自相矛盾**。

**技术约束(决定了还有没有第三条路)**:
Starlette 的路由在**首次请求后就冻结** ⇒ `mount` **必须发生在 import 期**,搬不进 lifespan/startup。
⇒ **第三条路(延迟到启动时挂载)技术上不成立**,已排除。

## 备选方案

| 方案 | 思路 | 优点 | 缺点 |
|---|---|---|---|
| **A** | 默认 `"true"`(**保持改动前行为**),收益仅在显式设 `false` 时兑现 | 默认分支**与改动前逐位一致**,零回归风险 | 收益**不在默认路径上** —— 要真省必须显式配置 |
| **B** | 默认 `"false"`(面板默认关) | `import main` **默认真不拉** gradio+matplotlib,收益立刻兑现 | **改变默认行为** —— 面板默认不可用,可能影响现有使用者 |
| ~~C~~ | 把挂载搬进 lifespan/startup | —— | ⛔ **技术上不成立**(Starlette 路由首次请求后冻结) |

## 评估标准

默认分支的回归风险 / 收益是否在默认路径 / 是否改变对外可见行为 / 技术可行性。

## 方案对比

**A 与 B 的分歧点只有一个:** 「省掉两个重包」与「保持默认行为」**哪个更值**。

- B 的收益是**实打实**的:`import main` 少拉 gradio(~6.27.0)+ matplotlib
- 但 B 的代价是**对外行为变化** —— dashboard 默认消失,而**当前所有文档/习惯都假定它开着**(`CLAUDE.md` 就写着访问 `http://localhost:8000/dashboard`)

## 最终决策 + 理由

**✅ 采纳 A。**

**业务方原话(2026-09-17)**:「A」

理由:
1. **本仓是 PUBLIC 仓库,且已有使用者习惯** —— 改默认行为的影响面比"少拉两个包"大
2. **收益并未丢失**,只是**从"默认"变成"可选"** —— 谁想省,设一个环境变量即可
3. 🔴 **但配套要求:必须把收益口径改写正确** —— 不许再写"不再拉",要写「**可以**不拉」

## 影响与后续行动

- `main.py` 的门控默认值 = `"true"`,并**在代码注释里写明收益口径**(不只写在 CHANGELOG)
- ⚠️ **`main.py:516` 会重绑定 `app`** —— 门关时该重绑定不发生 ⇒ `/dashboard` 路由消失、`len(app.routes)` 从 14 掉到 13。**这是应有语义**,已实测确认
- 两条分支都测了(只测默认分支等于没测收益分支)

## 反悔成本

**低。** 改一个默认字符串即可(`"true"` ↔ `"false"`),无迁移、无数据副作用。
⚠️ 唯一注意:若日后改默认值,**必须同步改文档与 `CLAUDE.md` 里"面板默认开着"的表述**,否则文档与现实不符。
