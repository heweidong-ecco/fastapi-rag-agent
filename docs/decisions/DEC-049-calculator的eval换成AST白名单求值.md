# 决策记录：DEC-049 · `calculator` 的 `eval(expression)` 换成 **AST 白名单求值**（5 处收口）

- 日期：2026-10-03（**发现 + 裁定 + 落地同日**）
- 状态：**已采纳** —— 本条独立于 `②`，是自己的一个任务（`DEC-039 §🅴`：一个完整任务一个 PR）
- 关联：`DEC-048 §遗留 #1`（**就是它把这件事记下来的** —— 本条把它**结掉**）·
  `docs/specs/safe_math.md`（**落点模块的 spec**）·
  `docs/specs/agent_graph.md`（⚠️ 表里那条"`calculator` 不进白名单≠它安全"）

## 决策事项

**`calculator` 工具的求值实现**。改动前它长这样，**在 5 个文件里各有一份**：

```python
try:
    return str(eval(expression))
except Exception as e:
    return f"计算错误: {e}"
```

业务方 2026-10-03 裁定：**换成 AST 白名单求值 + 5 处收口**，**排在 `③` 之前**。

## 为什么现在要动（🔴 不是"理论上危险"）

`expression` **不是用户直接给的，是 LLM 生成的**；而 LLM 的输入包含
**用户提问 / 检索到的 RAG 文档 / `search_tool`（DuckDuckGo）搜回来的网页**
（⚠️ 工具名是**当时的**；`DEC-051` 起换成 `web_search`，但"**外来网页进模型上下文**"这条触达面**不变**）。

### 实测（改前，本机跑的，不是推演）

```
calculator("__import__('os').system('touch /tmp/pwned_by_eval')")
⇒ 返回 '0'，且 /tmp/pwned_by_eval **被创建了**
```

⚠️ **两个细节比"能执行命令"更糟**：
1. **它返回的是 `'0'`** —— `system()` 的返回值被 `str()` 成了 `"0"` ⇒ **模型收到的是一条正常的"答案是 0"**，没有任何异常信号，**没有任何人会注意到**；
2. 同一份代码**被复制了 5 次**（见下表）⇒ 修一处不够。

### 触达面（**这条决定它多急**）

| 路 | 需要凭据吗 | 说明 |
|---|---|---|
| 拿 key 的人直接打 | ✅ 要 | `/agent/*` 都要 Bearer token，且**没有自助注册**（只能 admin 用 `/admin/create_user` 建）⇒ **不是"公网随意打"** |
| 🔴 **间接注入** | ⛔ **不要** | `search_tool`（`DEC-051` 起叫 `web_search`）把**任何人发布的网页**内容带回模型上下文（RAG 文档同理）⇒ 一个**正常用户**问一句话，就可能被那段内容诱导出一次恶意调用。**发起的人不需要任何凭据** |

⇒ **这是"上线前必须结掉"那一类**：本仓的目标是**上公网**（`DEC-033` 🅰️/🅱️）。

## 备选方案

### 甲 · AST 白名单求值（**采纳**）

先 `ast.parse(expression, mode="eval")`，**只放行算术那几种节点**，名单外一律拒。

| 好处 | 代价 |
|---|---|
| **不依赖黑名单** —— 新出现的逃逸形状也进不来（"只认算术"比"过滤危险词"结实） | 要写一个模块 + 测试（已落地：`api/safe_math.py` + 78 条测试） |
| **无第三方依赖**（`ast` / `math` / `operator` 都是标准库） | ⚠️ **可接受的算式变窄了**：`'a'*3` / `len([1])` 这类**以前"能算"**（虽然没人这么用）现在会被拒 |
| 可加**上限**，顺手把 DoS 面一起堵了 | |

### 乙 · 直接删掉 `calculator` 工具

| 好处 | 代价 |
|---|---|
| **攻击面直接归零**，一行代码都不用写 | 🔴 **改了 LLM 看到的工具表** ⇒ 是**行为变更**，要单独评估（本仓对"工具表变更"有明文要求：`PR` 模板 §二 必须写） |
| | 算术只能靠模型自己算 ⇒ **多位数算错**（而"算错"是用户唯一会当场发现的那类错） |
| | `simple_tools` → `mcp_server` 那条 MCP 路也少一个工具 |

⇒ **否掉**：本仓已经把"工具表变更"列为敏感面，为修一个求值实现去动它**代价错配**。

### 丙 · `eval` + `{"__builtins__": {}}` + 正则字符白名单（**⛔ 明确否掉**）

**这是"看着修了"的典型。实测（本机，2026-10-03）：**

```
eval('1+1',                        {'__builtins__': {}}, {})  ⇒ 2            （放行）
eval('__import__("os")',           {'__builtins__': {}}, {})  ⇒ NameError    （拦住了）
eval('().__class__.__bases__[0].__subclasses__()[:1]',
                                   {'__builtins__': {}}, {})  ⇒ [<class 'type'>]  🔴 放行！
```

🔴 **空 `builtins` 只挡住了 `__import__`**；**链式属性访问**根本不经过 builtins
—— 从 `()` 的 `__class__` 爬到 `object`，再 `__subclasses__()` 就能把**所有已加载的类**摸出来，
一路能走到任意可用的执行原语。**⇒ 不能采纳**（采纳它比不修更坏：它会让人以为修过了）。

### 丁 · 只把 `calculator` 加进 `SENSITIVE_TOOLS`（**否掉**）

改一行 `.env` 就"兜住"了 —— 但那是**拿人眼当沙箱**：要审批人**每次**都盯着
`expression` 里有不有 `__import__`；且它给 `DEC-048` 那条判据
（「敏感 = 出网」）开了个例外 ⇒ **把一条能陈述的线搅浑**。
⇒ **否掉**。⚠️ 但注意：**这不等于"丁毫无价值"** —— 若甲哪天被推翻，丁是**降级兜底**的候选。

## 落地形状（甲）

**新建 `api/safe_math.py`**，三道闸（缺一不可）：

| 闸 | 挡什么 | 为什么不能省 |
|---|---|---|
| **表达式长度 ≤ 200** | 超长式子 | 成本最低，先拦 |
| 🔴 **指数 ≤ 1000 且预判结果位宽** | `9**9**9`（右结合 ⇒ 指数 **387420489**） | **必须在算之前拦** —— 算完再查就已经卡死了 |
| **结果 ≤ 4096 位** | `10**1000*10**1000*…` | 指数都合规、但结果爆掉那类 |

⚠️ **另有一条容易被忽略的**：**`bool` 要特判** —— Python 里 `isinstance(True, int)` 为真
⇒ 不特判 `True+True` 会算出 `2`。

**5 处收口**（⛔ 名单就是"收口的定义"，将来再复制一份要加进来）：

| 文件 | 活/死 | 生产可达路径 |
|---|---|---|
| `api/agent_graph.py` | **活** | `/agent/langgraph_chat` |
| `api/agent_checkpointer.py` | **活** | `/agent/memory_chat` |
| `api/agent_graph_advanced_learning.py` | **活** | `build_advanced_agent()` + 子图节点 |
| `api/simple_tools_impl.py` | **活** | `simple_tools` → `mcp_server` ⇒ **MCP 也露出来了** |
| `api/tools_with_cache.py` | ⚰️ **死** | `api_v1.py:36` 导入了但**全文件只用这一次** ⇒ 生产不可达。**仍然收口**：本仓的拷贝文化是真的（这份就复制了 5 次），留一处就是留第 6 份的样板 |

> ⚠️ **依赖方向没被破坏**：`simple_tools_impl.py` 的模块 docstring 写着「**只 import 标准库**」
> —— `safe_math` **自己也只有标准库**（`ast`/`math`/`operator`）⇒ 那条不变量**仍然成立**。
> 该 docstring 里已**明文记下这个例外**（⛔ 别再往里加第二个）。

## 反悔成本

| 若将来要改成… | 要动哪里 | 成本 |
|---|---|---|
| **放宽可接受的算式**（比如想支持 `sqrt(2)`） | `safe_math._eval_node` 加一条**具名函数白名单**（`ast.Call` + 函数名在白名单里） | **中**。⚠️ ⛔ **不许直接放开 `ast.Call`** —— 那等于又回到 `eval` |
| **换第三方库**（`simpleeval` / `numexpr`） | `safe_math.evaluate` 一个函数 | **低**（5 个调用点一行都不用动 —— 这正是收口的意义） |
| **撤掉某道闸** | 删对应常量 + 删它的用例 | **低**，但 🔴 **不建议**：`9**9**9` 那条闸拆掉就是**一次 CPU DoS**，不是"少个检查" |
| **整个推翻甲、回到乙（删工具）** | 删 5 处调用 + 改 `mcp_server.TOOLS` + **按 `PR` 模板 §二 声明工具表变更** | **中** |

## ⚠️ 遗留（**本 DEC 不处理，但必须留痕**）

1. ⚠️ **`tools_with_cache.calculator` 只进静态守卫，没进行为守卫** ——
   它被 `@cached_tool` 包着 ⇒ 调一次就要连 Redis，放进离线 CI 会让**测试依赖外部服务**。
   实情已写在 `api/test_safe_math_wiring.py` 的文件 docstring 里，**⛔ 别假装它也验了行为**。
2. ⚠️ **`api/code_executor_impl.py` 不在本次范围** —— 它用 `subprocess.run` + `exec(create_safe_globals())`，
   是**另一类**（有超时、有 globals 白名单）。**业务方 2026-10-03 裁「单列」** ⇒ 它**仍然没被审过**，
   那条 globals 白名单**够不够**是**另一个问题**，⛔ 别因为本次收口了 `eval` 就以为它也没事。
3. ⚠️ **错误文案有一处**变了：改前 `eval("abc")` 给模型的是
   `计算错误: name 'abc' is not defined`，现在是 `计算错误: 不支持的语法: Name（只认数字与 + - * // % ** 组成的算式）`。
   **判断：这是改善**（新文案说得清"能算什么"），但它**是行为变更** —— 已写进 `CHANGELOG`。
   ✅ **可打印的判据**：`1/0` 那条**没变**，仍然是 `计算错误: division by zero`
   （`api/test_impl_modules.py` 与给模型的提示都依赖它）。
