## 一 · 代码规范

### 1.1 这些是**已存在的事实**（从代码里抽出来的，不是我希望的）

| 项 | 现状 |
|---|---|
| 缩进 | **4 空格** |
| 命名 | 函数 `snake_case` · 常量 `UPPER_CASE` · 类 `PascalCase` |
| 文件编码 | **UTF-8**，**注释用中文** |
| 导入 | 标准库 → 第三方 → 本地模块，**分组但无强制排序工具** |
| 类型注解 | 🟡 **部分有**（路由签名基本都有，内部函数常缺） |
| 文档字符串 | 🟡 路由函数**普遍有**（会显示在 `/docs`）；内部函数**不强制** |

### 1.2 注释：**本仓最有特色的规矩**

这不是"风格偏好"，是**本仓用血换来的**：

#### ⭐ 规矩 A · 注释写「**为什么**」，不写「**是什么**」

```python
# ✅ 本仓的写法（api/db.py:53-54）
# 注意：仅保留上方基于连接池的 get_db()（自动提交/回滚/归还连接）。
# 历史版本曾在下方重复定义 get_db() 覆盖连接池版本，导致写入不提交、连接池失效，已删除。

# ❌ 不会出现在本仓
# 定义 get_db 函数
```

**判据**：**删掉这行注释，后来的人会不会重犯同一个错？** 会 ⇒ 写。

#### ⭐ 规矩 B · 更正类注释要带**日期 + 出处**

```python
# ⚠️ 2026-09-20 删（§三·B7）：此处原有 `DB_CONFIG = {...}` —— **全仓零引用**
```

**格式**：`⚠️ YYYY-MM-DD <动作>（<出处>）：<原因>`
**出处**指：`DEC-0XX` / `§三·B7`（待办登记的节号）/ `复盘 <文件名>`

**为什么**：**注释也会过期**。带日期的注释**能判断它是不是还有效**；
不带日期的注释，后人只能猜。

#### ⭐ 规矩 C · 删除代码时，**留一行说明"删了什么、为什么"**

```python
# 50:# ⚠️ 2026-09-20 删（§三·B7）：此处原有 `DB_CONFIG = {...}`
```
而不是**静默删掉** —— 否则 `git blame` 到这一行时，看到的是一个凭空多出来的空行。

### 1.3 错误处理（**硬规矩**）

| 规矩 | 为什么 | 出处 |
|---|---|---|
| 业务错误一律 `raise AppException(ErrorCode.XXX, msg)` | 统一错误码与 HTTP 映射 | `CLAUDE.md` |
| ⛔ **中间件里【不许】抛 `AppException`** —— 必须直接返回 `JSONResponse` | `@app.exception_handler` **只捕获路由层**；中间件里抛会变成 **500** | 2026-08-17 修复记录 #12 |
| 数据库一律用 `get_db()` 上下文管理器 | 自动 commit/rollback/归还连接 | `api/db.py:36-48` |
| ⛔ **禁止直接创建原始数据库连接** | 会绕过连接池 | 同上 |

### 1.4 配置（**硬规矩**）

| 规矩 | 为什么 |
|---|---|
| 环境变量**从 `api/config.py` 导入**，⛔ 不要直接 `os.getenv` | 否则**本地/Docker 切换会不一致**（`config.py` 会按 `IS_DOCKER` 覆盖主机名） |

| 敏感配置**不设默认值** | 启动时 `validate_config()` 缺了就拒启 ⇒ **fail-closed** |

#### 🔴 两个"看代码会误判"的坑（**都真栽过**）

**坑 A · 「有中间件 ⇒ 受保护」**
`RateLimitMiddleware` / `QuotaMiddleware` **只管频率与配额**，⛔ **都不校验身份**。

**直接遍历 `app.routes` 会漏掉所有子路由**（本仓实测：58 条里只能看到 **5 条**）。

```python
# ✅ 正确：递归进去，且属性名是 `original_router`（实测出来的，不是 .routes）
def collect(routes, out):
    for r in routes:
        if type(r).__name__ == "_IncludedRouter":
            collect(r.original_router.routes, out)
        elif type(r).__name__ == "APIRoute":
            out.append(r)
```

## 二 · 提交规范

> 📌 **这一节的详细版在 `CLAUDE.md` 的「推送节奏」与「判据纪律」两节** —— 此处只列要点，不复制。

### 2.1 提交信息

**格式**：`<类型>(<范围>): <一句话>`

| 类型 | 用在哪 |
|---|---|
| `feat` | 新功能 |
| `fix` | 修 bug |
| `docs` | 只改文档 |
| `chore` | 杂项（依赖、配置、gitignore） |
| `refactor` | 重构（不改行为） |

**本仓的实际写法**（从 `git log` 看）：中文描述 + 必要时多行展开"为什么"。

### 2.2 **两个门的两问**（⛔ 每次 commit 都要答）

1. **「这次改动里，有没有在多个方案之间做过选择？」**
   有 ⇒ **建一份 `DEC-nnn`**（含备选方案 / 评估标准 / 反悔成本）
   无 ⇒ **在 commit message 里写明「本次无决策事项」**
2. **「CHANGELOG 写了吗？」** 没写 ⇒ **先补，再 commit**

### 2.3 推送节奏（**2026-09-30 改版**）

* 🔴 **推送：小批多次** —— **按段推，别攒成一大批**。
  **为什么**：**GitHub 自动风控对「批处理」形态敏感**（2026-09-24 账号被封 5 天）。
  📄 `docs/decisions/DEC-039-推送节奏改为小批多次.md`
* ✅ **提交：仍然【攒着】—— ⚠️ 推送分次 ≠ 提交分次**

  > **一个 PR 的活儿，提交可以攒着一次建；⛔ 不必"一个文档一个 commit"。**
  >
  > ⚠️ **这条是 2026-09-30 补的** —— 当天 **AI 把 `G5`（推送给分成多次）错误地延伸成了
  > "每个文档一个 commit"**，被业务方当场指出「**一个文档没必要一个 commit**」。
  > **改版只动【推送】，没打算动【提交】。**

* 🔴 **❌ 一件事没处理完，不 commit。**（2026-09-30 加 · **同一天栽了两次后才写死**）

  > **判据（一条，可当场问自己）**：
  > ### 「我这条 commit 发出去，**接手人会不会以为这件事结束了**？」
  > **会 ⇒ 还不到 commit 的时候。**
  >
  > 📌 **本仓 2026-09-30【同一天栽了两次】**：
  > | 第几次 | 怎么栽的 |
  > |---|---|
  > | **第一次** | 改完一份文档就 commit 一次 ⇒ 业务方：「**一个文档没必要一个 commit**」 |
  > | **第二次** | **刚记下上面这条**，转头又**在 B1–B14 还没裁完时就 commit** ⇒ 业务方：「**不是还没有处理完吗，等下一起 commit**」 |
  >
  > ⇒ ⚠️ **第一次的措辞（"可以攒着"）不够狠** —— 它读起来像"**也可以不攒**"。
  > **现在改成禁止式**：**没处理完 = 不许 commit**，不是"建议攒着"。
  > ⚠️ **反过来说**：**"处理完"由【业务方要的那件事】界定，不是由"我手上告一段落"界定。**

* ✅ **「一个可验证单元」这条没变** —— 但**它管的是「做完没做完」，不是「多久推一次」**。
* ⛔ **`git` 挂了先分清「抖动」还是「拦截」** —— 处置相反（重试 vs 换通道）
* ⚠️ **本地 = 不 durable** ⇒ **当天结束前至少推一次**

> 📌 全文见 `CLAUDE.md`。

### 🔴 2.5 「**本地绿**」**不许**用来宣称「不依赖某个外部服务」

| 想宣称 | 唯一有效的判据 |
|---|---|
| 「这个测试**不需要 DB**」 | ⭐ **把 DB 拿掉再跑一次**（如 `POSTGRES_PORT=1 POSTGRES_HOST=127.0.0.1 pytest …`） |
| 「这段代码**不碰 Redis**」 | 同上，**把 Redis 拿掉** |
| 「它**不联网**」 | 同上，**断网跑** |
| 🔴 「**我跑的是 CI 同款命令，所以 = CI**」 | ⛔ **不成立** —— **"跑哪条命令"与"跑在什么环境"是两根轴**。同款命令跑在**有真服务**的机器上，**照样掩盖断连**。见 §2.4·5 的补正 |

> ⛔ **"我本地跑通了"证明的是「在这些依赖都具备的机器上它能过」**，
> **不证明「它不需要这些依赖」**。**这两句话差得很远，而它们看起来几乎一样。**
>
> 📌 **新增测试文件时，问一句**：「**它碰不碰 DB / Redis？判据是什么？**」
> —— 判据**不能是"我跑通了"**。
> 💡 **做法**：在文件里加一个 **autouse fixture**，把"碰库"变成**明确的失败**
> （范例：`api/test_rate_limit_identity.py` 的 `_no_db`），**并给它写一条自证用例**。

### 🔴 2.5·5 **不连库的用例 ⇒ 裸 `TestClient(app)`**（2026-10-03 立 · `DEC-058`）

> **背景**：`with TestClient(app) as client:` 的**唯一效果**就是**跑 lifespan 的 startup**
> ⇒ 它会拉起**整个应用的启动流程**（含 `init_pool()`）⇒ **真去连 Postgres**。
> ⚠️ **本机看不出来**（本机 Postgres 真开着 ⇒ 连得上 ⇒ 照样绿）；**CI 没有 Postgres ⇒ `Connection refused`**。
> 📌 **2026-10-03 实测**：N6 新写的反向守卫用例就是这么红的（`bash scripts/ci-local.sh` ⇒ `1 failed, 411 passed`）。

| 用了 | 就必须 | 否则 |
|---|---|---|
| **裸** `TestClient(app)` | **不该**标 `needs_db` | ⚠️ 把原本能进 CI 的用例摘出去了 |
| **`with TestClient(app) as …`** | **必须**标 `needs_db`（它**是真·集成用例**） | 🔴 **CI 上必红** |

**可打印判据**（两个集合应当 **A ⊆ B**）：

```bash
grep -rlnE '^[[:space:]]*with TestClient' api/*.py                 # A · 用了上下文管理器
grep -rln 'pytestmark = pytest.mark.needs_db' api/*.py             # B · 自报需要真库
# A 里有、B 里没有的 ⇒ 上了 CI 必红
```

⚠️ **⛔ 判据别写成 `grep -rn 'with TestClient' api/*.py`** —— 那会命中 **docstring 里**那句
「⛔ 别把这里改成 `with TestClient(app) as client:`」的提醒 ⇒ **数成 1**（**实测，栽过一次**）。
⇒ 判据纪律第 2 条：**按位置核，注释 / 文档串里也有同样的串**。
**判据自证**：把修复退回 ⇒ `1 命中`；修后 ⇒ `0 命中`。（已实测）

📄 备选（标 `needs_db` · patch `init_pool`）与逐条评估 ⇒ `docs/decisions/DEC-058-不连库的用例用裸TestClient.md`

### 2.6 ⭐ **删已合并分支 —— 三条判据**（2026-10-02 立 · **当天绕了几个来回**）

> **背景**：本仓一律 **squash-merge**（一个任务一个 PR ⇒ 主干上一个 commit）。
> 那之后想删掉那条来源分支，**`git` 自带的两个提示全都是错的。**

### 🔴 两条【看起来行、其实不行】的

| ⛔ 看起来能判 | 它实际在说什么 |
|---|---|
| **`git branch -d <分支>` 报「not fully merged」** | **squash 造的是一个【新提交】** —— 主干上**根本没有那个 commit id** ⇒ `git` 判它"未合并"。<br>⚠️ **这不是"真没合"，是这条命令量不到 squash。** 它会**劝你用 `-D` 强删** —— 而 `-D` 是**真盲删** |
| **`git diff <主干>..<分支>` 非空** | **两种形式都答非所问**：<br>· **两点 `main..feat`** 比的是**两个末态的差异** —— 主干在合并后往前走一步，它就非空，**与分支合没合无关**<br>· **三点 `main...feat`** 自 `merge-base` 比 —— **任何做过事的分支都非空**，**连"已合并"的也非空** ⇒ **永远分不出来**<br>📌 同理 `git log main..feat` 也非空（它比的是 commit id，不是内容） |

> ### ⭐ 概括：**它们回答的都是「主干和分支的【提交 id】像不像」，而我要问的是「分支上的【内容】进没进主干」。**
> **⬆️ 与 §3.0·6 同一个病**：判据的实现与意图不一致，**而它不报错，只给一个数。**

### ✅ 三条真判据（**全部要过** —— 已在 `/tmp` 探针仓里实测过）

| # | 判据 | 命令 |
|---|---|---|
| **1** | **该分支的 PR 已 `MERGED`** | `gh pr view <n> --json state,mergedAt` ⇒ `"state":"MERGED"` |
| **2** | **分支 tip 的时间【早于】合并时间** | 分支在 PR 合完**之后又提交过** ⇒ 那些提交**不在 PR 里** ⇒ **不许删** |
| **3** | ⭐ **分支 tip 的【树哈希】能在主干历史里找得到** | 见下 —— **这是最强的一条** |

```bash
# 判据 3：树哈希（squash 之后，【树】应当一致 —— 提交 id 不同，树相同）
TIP_TREE=$(git rev-parse "<分支>^{tree}")
git log --format='%T' -n 200 origin/main | grep -qF "$TIP_TREE" \
  && echo "✅ 内容在主干上" || echo "⛔ 分支上有东西没进主干 —— 别删"
```

- **为什么用【树】不用【提交】**：**squash 换掉了提交 id，但没换内容** ⇒ **树哈希相等正是"内容一样"的定义**。
- **判据 3 顺带覆盖 2**：分支若在合并后又提交过，**它的 tip 树就不会出现在主干历史里** ⇒ 直接拦下。
- ⛔ **别用 `-D` 绕过** —— 它的语义是「**我确认要盲删**」。
  **要删就说明三条判据过了**，而不是"git 不让我删所以我强删"。

> 📄 **同族**：`docs/复盘/2026-10-02-判据写歪了不报错.md` · §3.0·6（**判据自证：如果它错了会表现成什么样？**）

### 2.7 ⭐ **栈式 PR 的收尾 —— 三条坑**（2026-10-03 立 · 实测于 `#71` → `#72`）

> **什么场景**：子 PR 的基分支是**父 PR 的分支**（本仓用它的理由：业务方裁「排在 `③` 之前」的**插单**，
> ⛔ 不能折进父 PR —— 那会让父 PR 的差异面变成两件事）。
> 父 PR 被 **squash** 合进 `main` 之后，子 PR 要收尾。**三条都不是想得出来的，是实测出来的。**

| # | 坑 | 症状 | ✅ 做法 |
|---|---|---|---|
| **1** | **GitHub 不会**自动把子 PR 的基分支改指 `main` | 子 PR 仍指着父分支 —— 那个分支「已并入主干、但它的 SHA 不在主干上」⇒ **合不进 `main`** | 显式 `gh pr edit <n> --base main`<br>⚠️ 它**只在基分支被【删掉】时**才自动改指 —— 「父 PR 合了」**不算** |
| **2** | ⛔ **别用 `git merge origin/main` 收尾** | 实测在 **6 个文件**上冲突（`CHANGELOG.md` · `ROADMAP.md` · `docs/decisions/DEC-048-*.md` · `docs/specs/agent_graph.md` · `docs/待办总表.md` · `docs/说明/测试.md`）<br>**根因**：merge 的 3-way 基是**旧 main** ⇒ **父 PR 的改动在两边都成了「新增」** ⇒ 全冲突 | `git rebase --onto origin/main <父分支的原 tip sha>`<br>—— 只把子 PR 那**一条** patch 重放到新 main 上。<br>**实测零冲突**；rebase **前后树哈希一致**（`1a08df4…`）⇒ **内容一条没丢**（验证方式就是比树哈希，见 §2.6 判据 3）<br>然后 `git push --force-with-lease` |
| **3** | ⛔ **`gh pr edit <n> --base main` 【不会】触发 CI** | 改基分支发的是 `pull_request` 的 **`edited`** 事件，**不在默认活动类型里**（默认只有 `opened` / `synchronize` / `reopened`）<br>⇒ `main` 有 required checks ⇒ PR 卡在 **`mergeStateStatus: BLOCKED`**，而 `gh pr checks` 报 **「no checks reported」**——⛔ **别误判成「CI 挂了」** | `gh pr close <n>` + `gh pr reopen <n>`（发 `reopened`，在默认类型里）<br>⛔ **不用**往分支塞空提交 —— **no-op push 不产生 `synchronize`** |

> ### 🔴 收尾后**必须按内容核**，⛔ 别只看 `state`
> ```bash
> gh pr view <n> --json state,mergedAt,mergeCommit   # ① 只是"它说合了"
> git fetch origin main -q
> git cat-file -t <squash sha>:api/新文件.py          # ② 内容真在主干上吗（读树，不读工作区）
> ```
> 📌 本仓有「**合并已成功却报错**」的前科（`gh pr merge` 退出码非 0 而实际已合）——
> **两个方向都要防**：既防「报成功却没合」，也防「报成功只合了一半」。
> ⚠️ 合并**必须**带显式 `--subject` / `--body`，否则 `--squash` 会把分支上**所有** commit 的正文
> 拼进主干那条 commit（实测过一次 **114 KB**，不可逆）。

> 📄 **同族**：§2.6（**删已合并分支 —— 三条判据**，同为 squash 之后的收尾） ·
> `docs/复盘/2026-09-30-判据在手边却没查.md`

### 四条（**照做**）

| # | 规矩 | 为什么 / 怎么做 |

| **2** | ⭐ **数【代码里的调用】⇒ 先剥注释** | `grep -v '^\s*#'` **只挡整行，⛔ 挡不住行内 `# ...`** ⇒ **要挡行内就得真剥**：<br>`python -c "… print(l.split('#',1)[0].count('ChatOpenAI(')) …"`<br>📌 **本仓纪律早有同款**（`CLAUDE.md` 判据 #2「别只数'替换了几处'，注释里也有同样的串」）<br>⚠️ **但那条只管到"替换"** —— **"数"同样适用，这次就是栽在把"数"漏出去** |
