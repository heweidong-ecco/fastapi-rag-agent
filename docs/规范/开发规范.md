# 开发规范

> ## 这份文档是什么
>
> **本仓「怎么写代码 / 怎么提交 / 怎么写文档」的规矩。**
>
> 🔴 **必须先说一件事**：
>
> ```
> 本仓【没有任何自动化的规范检查】——
> 没有 ruff · flake8 · black · mypy · pre-commit · editorconfig · pyproject.toml
> 唯一的自动门是 scripts/check_secrets.sh（凭据门）与 scripts/check_doc_links.sh（链接检查）
> ```
>
> ⇒ **下面的规矩全部是【靠人遵守】的，没有一条会被 CI 挡住。**
> ⚠️ **这不是好事** —— 它意味着"新人不会知道有这些规矩"（本仓在 skills 上吃过同样的亏：
> 「**门挂在别处，就等于没有门**」，见 `docs/复盘/2026-09-16-八个PR跳过了留痕门.md`）。
>
> 📌 **建议**（⬜ 待裁，见 §六）：至少加一个 `ruff` 的**最小配置**（只开 `E9`/`F` 这类真错误），
> 让"明显的错"自动被挡，而不是靠读这份文档。

## 一 · 代码规范

### 1.1 这些是**已存在的事实**（从代码里抽出来的，不是我希望的）

| 项 | 现状 |
|---|---|
| 缩进 | **4 空格** |
| 命名 | 函数 `snake_case` · 常量 `UPPER_CASE` · 类 `PascalCase` |
| 文件编码 | **UTF-8**，**注释用中文** |
| 导入 | 标准库 → 第三方 → 本地模块，**分组但无强制排序工具** |
| 类型注解 | 🟡 **部分有**（路由签名基本都有，内部函数常缺） |
| 文档字符串 | 🟡 路由函数**普遍有**（会显示在 `/docs`）；内部函数**不强制** |

### 1.2 注释：**本仓最有特色的规矩**

这不是"风格偏好"，是**本仓用血换来的**：

#### ⭐ 规矩 A · 注释写「**为什么**」，不写「**是什么**」

```python
# ✅ 本仓的写法（api/db.py:53-54）
# 注意：仅保留上方基于连接池的 get_db()（自动提交/回滚/归还连接）。
# 历史版本曾在下方重复定义 get_db() 覆盖连接池版本，导致写入不提交、连接池失效，已删除。

# ❌ 不会出现在本仓
# 定义 get_db 函数
```

**判据**：**删掉这行注释，后来的人会不会重犯同一个错？** 会 ⇒ 写。

#### ⭐ 规矩 B · 更正类注释要带**日期 + 出处**

```python
# ⚠️ 2026-09-20 删（§三·B7）：此处原有 `DB_CONFIG = {...}` —— **全仓零引用**
```

**格式**：`⚠️ YYYY-MM-DD <动作>（<出处>）：<原因>`
**出处**指：`DEC-0XX` / `§三·B7`（待办登记的节号）/ `复盘 <文件名>`

**为什么**：**注释也会过期**。带日期的注释**能判断它是不是还有效**；
不带日期的注释，后人只能猜。

#### ⭐ 规矩 C · 删除代码时，**留一行说明"删了什么、为什么"**

```python
# 50:# ⚠️ 2026-09-20 删（§三·B7）：此处原有 `DB_CONFIG = {...}`
```
而不是**静默删掉** —— 否则 `git blame` 到这一行时，看到的是一个凭空多出来的空行。

### 1.3 错误处理（**硬规矩**）

| 规矩 | 为什么 | 出处 |
|---|---|---|
| 业务错误一律 `raise AppException(ErrorCode.XXX, msg)` | 统一错误码与 HTTP 映射 | `CLAUDE.md` |
| ⛔ **中间件里【不许】抛 `AppException`** —— 必须直接返回 `JSONResponse` | `@app.exception_handler` **只捕获路由层**；中间件里抛会变成 **500** | 2026-08-17 修复记录 #12 |
| 数据库一律用 `get_db()` 上下文管理器 | 自动 commit/rollback/归还连接 | `api/db.py:36-48` |
| ⛔ **禁止直接创建原始数据库连接** | 会绕过连接池 | 同上 |

### 1.4 配置（**硬规矩**）

| 规矩 | 为什么 |
|---|---|
| 环境变量**从 `api/config.py` 导入**，⛔ 不要直接 `os.getenv` | 否则**本地/Docker 切换会不一致**（`config.py` 会按 `IS_DOCKER` 覆盖主机名） |
| ⚠️ **实测有 5 处违反** | 见 `docs/契约/环境变量.md` §三 —— **那是已知欠账，不是范例** |
| 敏感配置**不设默认值** | 启动时 `validate_config()` 缺了就拒启 ⇒ **fail-closed** |

## 二 · 提交规范

> 📌 **这一节的详细版在 `CLAUDE.md` 的「推送节奏」与「判据纪律」两节** —— 此处只列要点，不复制。

### 2.1 提交信息

**格式**：`<类型>(<范围>): <一句话>`

| 类型 | 用在哪 |
|---|---|
| `feat` | 新功能 |
| `fix` | 修 bug |
| `docs` | 只改文档 |
| `chore` | 杂项（依赖、配置、gitignore） |
| `refactor` | 重构（不改行为） |

**本仓的实际写法**（从 `git log` 看）：中文描述 + 必要时多行展开"为什么"。

### 2.2 **两个门的两问**（⛔ 每次 commit 都要答）

1. **「这次改动里，有没有在多个方案之间做过选择？」**
   有 ⇒ **建一份 `DEC-nnn`**（含备选方案 / 评估标准 / 反悔成本）
   无 ⇒ **在 commit message 里写明「本次无决策事项」**
2. **「CHANGELOG 写了吗？」** 没写 ⇒ **先补，再 commit**

### 2.3 推送节奏（**2026-09-30 改版**）

* 🔴 **推送：小批多次** —— **按段推，别攒成一大批**。
  **为什么**：**GitHub 自动风控对「批处理」形态敏感**（2026-09-24 账号被封 5 天）。
  📄 `docs/decisions/DEC-039-推送节奏改为小批多次.md`
* ✅ **提交：仍然【攒着】—— ⚠️ 推送分次 ≠ 提交分次**

  > **一个 PR 的活儿，提交可以攒着一次建；⛔ 不必"一个文档一个 commit"。**
  >
  > ⚠️ **这条是 2026-09-30 补的** —— 当天 **AI 把 `G5`（推送给分成多次）错误地延伸成了
  > "每个文档一个 commit"**，被业务方当场指出「**一个文档没必要一个 commit**」。
  > **改版只动【推送】，没打算动【提交】。**

* ✅ **「一个可验证单元」这条没变** —— 但**它管的是「做完没做完」，不是「多久推一次」**。
* ⛔ **`git` 挂了先分清「抖动」还是「拦截」** —— 处置相反（重试 vs 换通道）
* ⚠️ **本地 = 不 durable** ⇒ **当天结束前至少推一次**

> 📌 全文见 `CLAUDE.md`。

### 2.4 提交前跑这两个（**目前是唯一的两道自动门**）

```bash
bash scripts/check_secrets.sh        # 凭据门（扫 staged 的新增行）
bash scripts/check_doc_links.sh      # 链接检查（改了文档才需要）
```

> ⚠️ **凭据门的口径**：它**只扫 staged 的新增行**。没 `git add` 就跑，
> 会打印「staged 区为空」然后 **exit 0** —— **那不是"通过"，是"没扫"**。

## 三 · 文档规范

| 规矩 | 出处 |
|---|---|
| **一份文档只有一个权威** | `DEC-035` |
| **接口清单不写进文档** —— 跑 `scripts/list_endpoints.sh` | `DEC-036` |
| 文档按**四层**放（入口 / 契约 / 指南 / 原理 / 规范 / 过程 / 历史） | `DEC-036` · `DEC-037` · `docs/文档地图.md` |
| **加/改文档后跑链接检查** | `scripts/check_doc_links.sh` |

| ⛔ **锚点/决策文档里写结论前，先 `grep` 一遍仓里有没有现成说法** | `docs/复盘/2026-09-29-结果为空…` 规则 3 |

| ⛔ **`grep` 出 0 命中时，先问「我的模式会不会漏」** | 同上 规则 4 |

### 3.0 ⭐ **「用路径指向别处」—— 减重的【唯一】正确做法**（2026-09-29 立）

**判据**：**一份文档太重时，把内容移到别处，本处只留【反引号里的路径】。**

> ⚠️ **关键区分（官方原文，`curl` 取回）—— 两种写法结果相反**：
>
> | 写法 | 官方怎么说 | 结果 |
> |---|---|---|
> | **裸 `@import`** | 「imported files **load at launch**」<br>「helps organization but **doesn't reduce context**」 | ❌ **不减重，反而加重** |
> | **反引号里的路径** | 「Import parsing **skips code spans**…**keeps the text literal**」 | ✅ **这才是"指向别处"** |
>
> ⇒ **本仓一律用后者**（纯文本指针，⛔ **不用 `@import`**）。
> 📄 出处：`docs/规范/文档体系-外部依据.md` §1.3

**已这么做的**：
* `ROADMAP` 的「待办总账」→ 摘要表 + 指针（内容在 `docs/待办总表.md`）
* `CLAUDE.md` 的 🅱️ / 判据纪律 / 冲突与例外 → 各留**结论 + 指针**（细节在 `DEC-033` / 复盘 / `ROADMAP` 的 PR 纪律段）
* 「做完模块更新 spec」→ 指针到 `docs/specs/README.md`

### 3.0·5 ⭐ **数字别写死 —— 写成一条命令**（2026-09-29 立 · **当天栽了 3 次**）

**判据**：**凡是要写「几个 / 多少 / 第几次 / 多少行 / 是否达标」，一律写成那条能算出它的命令。**

| ⛔ 别写 | ✅ 写成 |
|---|---|
| 「**8+ 个 commit 未推送**」 | `git rev-list --count origin/main..HEAD` |
| 「`CLAUDE.md` **550+ 行**」 | `wc -l CLAUDE.md` |
| 「**首次达到官方 200 行目标**」 | `wc -l CLAUDE.md`（**跑一次才知道**） |

> ### 🔴 2026-09-29 一天里栽的 3 次
>
> | 次序 | 哪 | 写的是 | 实际 |
> |---|---|---|---|
> | 1 | `docs/文档地图.md` | `CLAUDE.md 550+` / `ROADMAP 784+` / `README 335` | **218 / 258 / 319** |
> | 2 | `ROADMAP.md` | 「**8+ 个** commit 未推送」 | **15** |
> | 3 | `CHANGELOG.md` | 「压到 **197** 行，**首次达标**」 | **204**（**仍差 4 行**） |
>
> ⇒ **共同点：三次都是"我以为的数字"，一次都没跑命令。**
> ⇒ **修法**：**把那列【删掉】**（`文档地图` 的行数列就是这么处理的），或**换成命令**。

### 3.1 ⭐ 「**一份内容只在一处**」—— 判据是脚本，不是记忆

> **2026-09-29 立。** 立它的直接原因是 **同一天实撞了三次**：
> `CLAUDE.md` 的架构节 vs `docs/原理/架构.md` · `ROADMAP` 的「生产级」vs `README` 已删该词 ·
> `ROADMAP` 里「阶段②」**两份完全相同的拷贝**。

**判据一句话**：
> **「删掉这句，另一处还能不能查到？」**
> * **能** ⇒ 这里是**多余的** ⇒ 改成**指针**
> * **不能** ⇒ 这里就是**权威** ⇒ **别处不许再写**

```bash
# 查一句话是不是被写了两遍（把整句贴进去搜）
grep -rn "要查的那句话" --include="*.md" . | grep -v "归档\|历史/\|CHANGELOG"
```

**为什么这条要写成规矩**：**它的形态很隐蔽** —— 「两边都写了」**不会报错、不会变红**，
而且**往往是同一个人（我）在修一边的时候，另一边正在被写**。

### 3.1·5 ⭐ **写「占位符」时，别把它写成像真路径的样子**（2026-09-29 立）

**判据**：凡是要写**示意性的文档名**（**不是真路径**），**别把它写成"目录 + 后缀"的样子** ——
**链接检查器会把那个名字当成本仓的一个真文件去解析**，然后报「🔴 真断链」。

✅ **正确写法**：**用文字描述**，例如

> 「`docs/specs/` 下**与模块同名的那份**」
> 「`api/` 下的某个**模块**」

⛔ **错误写法**：**把示意名写成"目录 + 后缀"**（即看起来像一个真文件路径）。

> ### 😅 **本节【故意不举例】** —— 因为**举例本身就会被自己的门拦**。
>
> 📌 **这不是偷懒，是这条规矩的最好说明**：**"看起来像路径"就是会被解析成路径。**
> ⚠️ **而 `Bash`/`Edit` 那一侧不受影响** —— 门只查**反引号里的 `.md`**。
> （所以 `api/` 下的 `.py` 示意名**不会**被拦；**只有 `.md` 会**。）

> ### 🔴 它是怎么被发现的：**同一个错，一天之内犯了【4 次】**
>
> | 次序 | 在哪 |
> |---|---|
> | 1 | `CLAUDE.md` |
> | 2 | `docs/specs/README.md` |
> | 3 | `.claude/README.md` |
> | 4 | `docs/decisions/DEC-038-…md` |
>
> ⚠️ **每次都是被链接检查当场抓住的** —— 但**每次都只改了眼前那一处**。
> 📌 **这恰好违反本规范 §3.2 的规则 3**：「**改一处口径 ⇒ 立刻全仓搜那个词**」。
> ⇒ **所以这条规矩不只是"怎么写占位符"，还是一条"发现了一个模式 ⇒ 立刻全仓 grep 它"的提醒。**

### 3.2 ⭐ **接手人视角** —— 四条（出自 `docs/复盘/2026-09-29-用我做过了当别人找得到.md`）

> **根因一句话**：**「完成」的判据不是「我做了」，而是「别人来验，会不会发现不对」。**
> ⚠️ 那一天**四次都用了前者**：锚点停更 · 三入口没指向索引 · 口径残留 · 拆完丢内容。

| # | 规则 | 判据（**照做**） |
|---|---|---|
| **1** | **做完一件"给人接手"的事 ⇒ 立刻以【接手人】视角验一遍** | 写了**锚点** ⇒ 从锚点能不能走到"现在该干什么"？<br>拆了**文件** ⇒ 拆掉的**每一块**在别处还在不在？（**逐主题搜，不是抽查**） |
| **2** | **建了一个"入口" ⇒ 必须同时问「谁指向它？」** | 新加**索引 / 入口 / 地图**后**立刻搜谁引用它**；**没有引用 ⇒ 它是个孤岛**<br>📌 本仓对其有明文纪律：「**门挂在别处，就等于没有门**」 |
| **3** | **改一处"口径" ⇒ 立刻全仓搜那个词** | 凡是改**一个说法 / 一个词 / 一个数字**（"生产级"、"真中断"、"三种模式"），<br>**改完立刻 `grep` 全仓**，把所有同样的说法一起处理 |
| **4** | **"我这一批改了 N 处" ⇒ 那 N 处【各自】要能被验** | 逐条问「**这条我怎么知道它生效了？**」——**答不出可打印的检查 ⇒ 那条还没做完** |

> 📌 **规则 2 与本仓一段老教训是同一件事**：
> **`docs/复盘/2026-09-16-八个PR跳过了留痕门.md`** 写着「门挂在别处，就等于没有门」——
> **而那条纪律一直写在 `CLAUDE.md` 里，我每遍都读，还是犯了。**
> ⇒ **与 Anthropic 官方那句一致**：「**CLAUDE.md is context, not enforcement**」
> （`docs/规范/文档体系-外部依据.md` §1.5）。
> ⭐ **⇒ 结论是：这类规矩要【做成命令】，不能只写在文档里。**

> 📌 **上面 3.1 与 3.2 的规则 2，其实是同一个病的两种形态**：
> **「我做完了一个应该被指向 / 被引用 / 被同步的东西，但没人指它。」**
>
> ⬜ **待办**：把它做成**一条可跑的命令**（本仓已有先例：`check_doc_links.sh`
> 就是把「引用对不对」从靠人变成靠命令）。

## 五 · 新加一个文件的检查清单

```
□ 它属于哪一层？（入口 / 契约 / 说明 / 过程）
□ 有没有【同一个问题】已经有文档了？（一份文档只有一个权威）
□ 它里面的路径引用是不是全的？（跑 check_doc_links.sh）
□ 它要不要在 docs/文档地图.md 里登记？
□ 改了行为的话，CHANGELOG 写了吗？
□ 做了选择的话，DEC 建了吗？
```
